# 6. Permisos NTFS en Windows

En Windows, los permisos sobre ficheros y carpetas los gestiona el sistema de archivos **NTFS** (Unidad 2). A diferencia del modelo UGO de Linux, NTFS se basa desde el principio en **listas de control de acceso**: cada fichero y cada carpeta pueden tener permisos para tantos usuarios y grupos como se quiera.

> [!NOTE]
> Los sistemas de archivos **FAT32** y **exFAT** (habituales en memorias USB) **no admiten permisos**: cualquier usuario puede leer y modificar todo su contenido. Si copias ficheros protegidos a una memoria FAT32, pierden sus permisos.

## 6.1 Conceptos

| Concepto | Descripción |
| --- | --- |
| **Descriptor de seguridad** | Información de seguridad asociada a cada fichero o carpeta: propietario, DACL y SACL. |
| **Propietario** | Usuario (o grupo) dueño del objeto. Siempre puede **cambiar los permisos**, aunque no tenga ningún otro. Normalmente es quien lo creó. |
| **DACL** (*Discretionary ACL*) | Lista de permisos: quién puede hacer qué. Es lo que habitualmente se llama "los permisos". |
| **ACE** (*Access Control Entry*) | Cada una de las entradas de la DACL: un usuario o grupo (su SID), unos permisos y un tipo, **Permitir** o **Denegar**. |
| **SACL** (*System ACL*) | Lista de **auditoría**: qué accesos se registran en el Visor de eventos (apartado 10). |
| **Herencia** | Las ACE de una carpeta se propagan automáticamente a su contenido. |

## 6.2 Permisos estándar

Son los que aparecen en la pestaña **Seguridad** de las propiedades de un fichero o carpeta. Cada uno es en realidad un **conjunto** de permisos especiales.

| Permiso | Sobre una carpeta | Sobre un fichero |
| --- | --- | --- |
| **Control total** | Todo, incluido cambiar permisos y tomar posesión. | Todo, incluido cambiar permisos y tomar posesión. |
| **Modificar** | Leer, crear, modificar y **eliminar** contenido; también eliminar la propia carpeta. | Leer, modificar, ejecutar y **eliminar** el fichero. |
| **Lectura y ejecución** | Ver el contenido y recorrerla; los ficheros que contiene se pueden leer y ejecutar. | Leer el fichero y ejecutarlo si es un programa. |
| **Mostrar el contenido de la carpeta** | Igual que *Lectura y ejecución*, pero solo se hereda en las **carpetas**, no en los ficheros. | (No existe para ficheros.) |
| **Lectura** | Ver los nombres de ficheros y subcarpetas, sus atributos y sus permisos. | Leer el contenido, los atributos y los permisos. |
| **Escritura** | Crear ficheros y subcarpetas. | Modificar el contenido y los atributos. |

Hay que distinguir bien dos casos que suelen confundirse:

- **Escritura** permite crear y modificar, pero **no eliminar**.
- **Modificar** incluye la escritura **y además eliminar**. Es el permiso adecuado para que alguien trabaje normalmente con unos ficheros. *Control total* solo se debe dar a quien deba administrar los permisos.

### Permisos especiales (avanzados)

En **Opciones avanzadas > Mostrar permisos avanzados** aparecen los permisos individuales de los que están formados los estándar:

| Permiso especial | Descripción |
| --- | --- |
| Recorrer carpeta / ejecutar archivo | Atravesar una carpeta para llegar a otra / ejecutar un programa. |
| Mostrar carpeta / leer datos | Listar el contenido de una carpeta / leer el contenido de un fichero. |
| Leer atributos / Leer atributos extendidos | Ver atributos como *oculto* o *solo lectura*. |
| Crear archivos / escribir datos | Crear ficheros en una carpeta / modificar un fichero. |
| Crear carpetas / anexar datos | Crear subcarpetas / añadir datos al final de un fichero. |
| Escribir atributos / Escribir atributos extendidos | Cambiar los atributos. |
| Eliminar subcarpetas y archivos | Borrar el contenido de una carpeta aunque no se tenga *Eliminar* sobre cada fichero. |
| Eliminar | Borrar el objeto. |
| Permisos de lectura | Ver los permisos. |
| Cambiar permisos | Modificar la DACL. |
| Tomar posesión | Convertirse en propietario. |

## 6.3 Cómo se combinan los permisos

Un usuario puede recibir permisos por varias vías: directamente, por cada uno de sus grupos y por herencia. Windows los combina así:

1. Los permisos **Permitir** son **acumulativos**: si `ana` tiene *Lectura* y su grupo `dam1` tiene *Modificar*, `ana` tiene *Modificar*.
2. Un permiso **Denegar** prevalece sobre un **Permitir** del **mismo nivel**.
3. Los permisos **explícitos** (asignados directamente al objeto) prevalecen sobre los **heredados**.

El orden de evaluación, de mayor a menor prioridad, es:

```text
1. Denegar explícito   >   2. Permitir explícito   >   3. Denegar heredado   >   4. Permitir heredado
```

Así, un *Permitir* asignado directamente a un fichero gana a un *Denegar* heredado de la carpeta.

> [!TIP]
> Usa **Denegar** lo menos posible. Es más fácil de mantener **no conceder** un permiso que concederlo y denegarlo después. Además, denegar a un grupo amplio como *Usuarios* o *Todos* puede bloquear también a los administradores, porque ellos también pertenecen a esos grupos.

## 6.4 Herencia

Por defecto, cada fichero y carpeta **hereda** las ACE de su carpeta padre. En la pestaña *Seguridad*, los permisos heredados aparecen con las casillas en gris y no se pueden modificar directamente.

En **Opciones avanzadas**, cada ACE indica a qué se aplica:

| Aplicar a | Abreviatura en `icacls` |
| --- | --- |
| Esta carpeta, subcarpetas y archivos (por defecto) | `(OI)(CI)` |
| Esta carpeta y subcarpetas | `(CI)` |
| Esta carpeta y archivos | `(OI)` |
| Solo subcarpetas y archivos | `(OI)(CI)(IO)` |
| Solo esta carpeta | (sin indicadores) |

`OI` (*Object Inherit*) se hereda en los ficheros, `CI` (*Container Inherit*) en las subcarpetas e `IO` (*Inherit Only*) indica que no se aplica a la propia carpeta.

Para que una carpeta tenga permisos propios distintos de los de su padre, se **deshabilita la herencia** (*Opciones avanzadas > Deshabilitar herencia*). Windows pregunta qué hacer con los permisos heredados:

- **Convertir los permisos heredados en permisos explícitos**: se conservan como punto de partida y luego se modifican. Es la opción habitual.
- **Quitar todos los permisos heredados**: la carpeta se queda sin permisos heredados (cuidado: si no añades ninguno, nadie podrá acceder salvo el propietario).

### Copiar y mover

| Operación | Permisos resultantes |
| --- | --- |
| **Copiar** (en el mismo volumen o en otro) | El fichero copiado es un objeto nuevo: **hereda** los permisos de la carpeta de destino. |
| **Mover dentro del mismo volumen** | Conserva sus permisos explícitos. |
| **Mover a otro volumen** | Equivale a copiar y borrar: hereda los del destino. |

## 6.5 Gestión gráfica

{{% steps %}}
1. ## Ver los permisos

   Clic derecho sobre la carpeta > **Propiedades** > pestaña **Seguridad**. Selecciona un usuario o grupo en la lista superior para ver sus permisos en la inferior.

2. ## Añadir un usuario o grupo

   Pulsa **Editar** > **Agregar**, escribe el nombre (por ejemplo, `dam1`), pulsa **Comprobar nombres** y **Aceptar**. Marca los permisos en la columna *Permitir* (o *Denegar*).

3. ## Opciones avanzadas

   En la pestaña *Seguridad*, pulsa **Opciones avanzadas**. Desde aquí puedes cambiar el **propietario** (enlace *Cambiar*), **deshabilitar la herencia**, editar a qué se aplica cada entrada y asignar permisos especiales.

4. ## Comprobar el acceso efectivo

   En *Opciones avanzadas*, pestaña **Acceso efectivo**, pulsa *Seleccionar un usuario*, elige uno y pulsa **Ver acceso efectivo**. Windows calcula los permisos reales combinando grupos, herencia y denegaciones.
{{% /steps %}}

## 6.6 Gestión con `icacls`

`icacls` muestra y modifica las DACL desde CMD o PowerShell. Funciona en todas las ediciones de Windows.

```bat
icacls C:\Proyecto
```

```text
C:\Proyecto BUILTIN\Administradores:(I)(OI)(CI)(F)
            NT AUTHORITY\SYSTEM:(I)(OI)(CI)(F)
            BUILTIN\Usuarios:(I)(OI)(CI)(RX)
            NT AUTHORITY\Usuarios autentificados:(I)(OI)(CI)(M)
```

`(I)` indica que la entrada es **heredada**. Los permisos se abrevian así:

| Abreviatura | Permiso |
| --- | --- |
| `F` | Control total (*Full*) |
| `M` | Modificar |
| `RX` | Lectura y ejecución |
| `R` | Lectura |
| `W` | Escritura |
| `D` | Eliminar |

| Opción | Función |
| --- | --- |
| `/grant usuario:permiso` | Añade permisos *Permitir* (se suman a los que ya tenga). |
| `/grant:r usuario:permiso` | Concede **sustituyendo** los permisos explícitos anteriores de ese usuario. |
| `/deny usuario:permiso` | Añade un *Denegar*. |
| `/remove usuario` | Quita todas las entradas explícitas de ese usuario. |
| `/inheritance:e` \| `d` \| `r` | Habilita (`e`), deshabilita copiando (`d`) o deshabilita quitando (`r`) la herencia. |
| `/setowner usuario` | Cambia el propietario. |
| `/reset` | Elimina los permisos explícitos y deja solo los heredados. |
| `/T` | Aplica la orden a todo el contenido (recursivo). |
| `/save fichero` y `/restore fichero` | Guarda y restaura las ACL. |

```bat
:: Carpeta de proyecto con permisos propios
mkdir C:\Proyecto
icacls C:\Proyecto /inheritance:d
icacls C:\Proyecto /remove "Usuarios autentificados"
icacls C:\Proyecto /remove Usuarios
icacls C:\Proyecto /grant "dam1:(OI)(CI)M"
icacls C:\Proyecto /grant "marta:(OI)(CI)RX"
icacls C:\Proyecto
```

> [!WARNING]
> Igual que en el apartado 2, los nombres de los grupos integrados dependen del idioma. Para scripts que deban funcionar en cualquier Windows, usa el SID precedido de `*`:
>
> ```bat
> icacls C:\Proyecto /remove *S-1-5-11            :: Usuarios autentificados
> icacls C:\Proyecto /grant "*S-1-5-32-545:(OI)(CI)RX"   :: Usuarios
> ```

Propiedad:

```bat
icacls C:\Proyecto /setowner marta /T     :: marta pasa a ser propietaria de todo
takeown /F C:\Datos\viejo.txt             :: El usuario actual toma posesión (requiere el privilegio)
```

Copias de seguridad de permisos (muy útiles antes de hacer cambios masivos):

```bat
icacls C:\Proyecto\* /save C:\Temp\acl-proyecto.txt /T
icacls C:\Proyecto /restore C:\Temp\acl-proyecto.txt
```

> [!NOTE]
> Fíjate en que `/save` se aplica a `C:\Proyecto\*` (el contenido) y `/restore` a `C:\Proyecto` (la carpeta que lo contiene): las rutas guardadas en el fichero son relativas a esa carpeta.

## 6.7 Gestión con PowerShell: `Get-Acl` y `Set-Acl`

```powershell
# Ver las entradas de la DACL en forma de tabla
(Get-Acl C:\Proyecto).Access |
    Format-Table IdentityReference, FileSystemRights, AccessControlType, IsInherited -AutoSize
```

Para añadir una entrada se crea un objeto de la clase **`FileSystemAccessRule`** (del espacio de nombres .NET `System.Security.AccessControl`). Su constructor recibe cinco datos:

| Argumento | Ejemplo | Significado |
| --- | --- | --- |
| Identidad | `"dam1"` | Usuario o grupo. |
| Derechos | `"Modify"` | Valor de la enumeración `FileSystemRights`: `FullControl`, `Modify`, `ReadAndExecute`, `Read`, `Write`… |
| Herencia | `"ContainerInherit, ObjectInherit"` | Equivale a `(CI)(OI)`. |
| Propagación | `"None"` | `InheritOnly` equivale a `(IO)`. |
| Tipo | `"Allow"` | `Allow` (Permitir) o `Deny` (Denegar). |

```powershell
$ruta = "C:\Proyecto"
$acl  = Get-Acl -Path $ruta                     # 1. Leer la ACL actual

# 2. Crear la regla: dam1 puede Modificar en la carpeta, subcarpetas y archivos
$regla = [System.Security.AccessControl.FileSystemAccessRule]::new(
    "dam1", "Modify", "ContainerInherit, ObjectInherit", "None", "Allow")

$acl.AddAccessRule($regla)                      # 3. Añadirla al objeto en memoria
Set-Acl -Path $ruta -AclObject $acl             # 4. Escribir la ACL en el disco

# Deshabilitar la herencia conservando los permisos heredados como explícitos:
# SetAccessRuleProtection(proteger, conservarHeredados)
$acl = Get-Acl $ruta
$acl.SetAccessRuleProtection($true, $true)
Set-Acl -Path $ruta -AclObject $acl
```

El patrón es siempre el mismo: **leer** la ACL con `Get-Acl`, **modificar** el objeto en memoria y **guardar** con `Set-Acl`. Para operaciones sencillas, `icacls` suele ser más rápido de escribir; PowerShell es preferible en scripts complejos porque trabaja con objetos.

## 6.8 Atributos frente a permisos

No hay que confundir los **permisos** con los **atributos** de un fichero. Los atributos son marcas que tiene el propio fichero, independientes de quién acceda:

| Atributo | Letra | Efecto |
| --- | --- | --- |
| Solo lectura | `R` | Los programas no deberían modificarlo. Cualquier usuario con permiso para cambiar atributos puede quitarlo, así que **no es una medida de seguridad**. |
| Oculto | `H` | No se muestra en el Explorador salvo que se activen los elementos ocultos. |
| Sistema | `S` | Fichero del sistema operativo. |
| Archivo | `A` | Indica que el fichero ha cambiado desde la última copia de seguridad. |

```bat
attrib notas.txt              :: Muestra los atributos
attrib +H +R notas.txt        :: Oculto y de solo lectura
attrib -H -R notas.txt
```

NTFS ofrece además **compresión** (`compact /c fichero`) y **cifrado EFS** (`cipher /e carpeta`, en las ediciones Pro, Education y Enterprise). Con EFS, aunque alguien extraiga el disco o tenga permisos de lectura, solo el usuario que lo cifró puede leer el contenido.

## 6.9 Comparativa Linux / Windows

| Concepto | Linux | Windows (NTFS) |
| --- | --- | --- |
| Modelo básico | UGO (`rwx` para propietario, grupo y resto) | DACL con tantas ACE como se quiera |
| Permisos para usuarios adicionales | ACL POSIX (`setfacl`) | ACE en la DACL |
| Denegar explícitamente | No existe (solo se deja de conceder) | ACE de tipo *Denegar* |
| Herencia | Grupo con SGID; ACL por defecto (`setfacl -d`) | Herencia de ACE (`OI`, `CI`) |
| Ver permisos | `ls -l`, `getfacl` | Pestaña *Seguridad*, `icacls`, `Get-Acl` |
| Cambiar permisos | `chmod`, `setfacl` | `icacls`, `Set-Acl` |
| Cambiar propietario | `chown` | `icacls /setowner`, `takeown` |
| Permisos efectivos | `getfacl` (columna `#effective`) | Pestaña *Acceso efectivo* |
| Atributos | `chattr`, `lsattr` | `attrib` |

## Ejercicios resueltos

### Ejercicio 6.1. Calcular permisos efectivos

`ana` pertenece a los grupos `dam1` y `Usuarios`. Sobre `C:\Notas\examen.docx`:

- `Usuarios` tiene *Lectura* heredada.
- `dam1` tiene *Modificar* heredado.
- `ana` tiene *Denegar Escritura* explícito.

¿Qué puede hacer `ana` con el fichero?

{{% details "Ver solución" %}}
- Por acumulación de *Permitir*, `ana` tendría *Modificar* (lectura, escritura, ejecución y eliminación).
- El *Denegar Escritura* es **explícito** y tiene la máxima prioridad: elimina la escritura.

Resultado: `ana` puede **leer**, **ejecutar** y **eliminar** el fichero, pero **no modificar su contenido**. Fíjate en que puede borrarlo, porque *Eliminar* es un permiso distinto de *Escritura*. Si se quisiera impedir también el borrado, habría que denegar *Modificar*. Puedes comprobarlo en la pestaña *Acceso efectivo*.
{{% /details %}}

### Ejercicio 6.2. Carpeta con permisos diferenciados

Crea la carpeta `C:\Confidencial` de forma que:

- `john` pueda entrar y leer su contenido, pero no escribir.
- `doe` no pueda hacer nada.
- `admin` pueda hacerlo todo.
- El resto de usuarios no tenga acceso.

Hazlo con `icacls` y comprueba el resultado.

{{% details "Ver solución" %}}
```bat
mkdir C:\Confidencial
icacls C:\Confidencial /inheritance:d
icacls C:\Confidencial /remove *S-1-5-11 *S-1-5-32-545
icacls C:\Confidencial /grant "john:(OI)(CI)RX" "admin:(OI)(CI)F"
icacls C:\Confidencial
```

1. Se deshabilita la herencia **copiando** los permisos (`/inheritance:d`), para conservar los de *Administradores* y *SYSTEM*.
2. Se quitan *Usuarios autentificados* (`S-1-5-11`) y *Usuarios* (`S-1-5-32-545`), que daban acceso a todo el mundo.
3. Se concede *Lectura y ejecución* a `john` y *Control total* a `admin`.

Para `doe` **no hace falta ningún Denegar**: como no tiene ninguna entrada (ni él ni sus grupos), no tiene acceso. Añadir un *Denegar* solo sería necesario si `doe` perteneciera a algún grupo con permisos sobre la carpeta.

Comprobación: en *Opciones avanzadas > Acceso efectivo*, o iniciando sesión con cada usuario e intentando crear y abrir un fichero.
{{% /details %}}

### Ejercicio 6.3. Lo mismo con PowerShell

Escribe un script que cree la carpeta `C:\Practicas\dam1`, deshabilite la herencia conservando los permisos, conceda *Modificar* al grupo `dam1` y muestre la ACL resultante.

{{% details "Ver solución" %}}
```powershell
$ruta = "C:\Practicas\dam1"
New-Item -ItemType Directory -Path $ruta -Force | Out-Null

$acl = Get-Acl $ruta
$acl.SetAccessRuleProtection($true, $true)        # Herencia deshabilitada, se conservan como explícitos

$regla = [System.Security.AccessControl.FileSystemAccessRule]::new(
    "dam1", "Modify", "ContainerInherit, ObjectInherit", "None", "Allow")
$acl.AddAccessRule($regla)

Set-Acl -Path $ruta -AclObject $acl

(Get-Acl $ruta).Access |
    Format-Table IdentityReference, FileSystemRights, AccessControlType, IsInherited -AutoSize
```

En la salida, `IsInherited` debe ser `False` en todas las entradas y debe aparecer `EQUIPO\dam1` con `Modify, Synchronize` (el permiso *Synchronize* lo añade Windows automáticamente).
{{% /details %}}

### Ejercicio 6.4. Copiar frente a mover

En `C:\Proyecto` (con permisos para `dam1`) creas `informe.txt`. Lo **copias** a `C:\Confidencial` y después lo **mueves** a `C:\Users\Public`, ambas en la unidad `C:`. ¿Qué permisos tendrá cada copia?

{{% details "Ver solución" %}}
- La **copia** en `C:\Confidencial` es un fichero nuevo y **hereda** los permisos de `C:\Confidencial` (`john` lectura, `admin` control total…). `dam1` ya no tiene acceso a esa copia.
- Al **mover** el original a `C:\Users\Public` dentro del mismo volumen, **conserva** sus permisos. Si alguno de ellos era heredado de `C:\Proyecto`, Windows lo recalcula según la nueva ubicación cuando se vuelven a propagar los permisos, por lo que conviene comprobarlo siempre con `icacls` después de mover ficheros entre carpetas con permisos distintos.
{{% /details %}}
