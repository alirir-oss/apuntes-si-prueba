# 11. Mantenimiento y optimización

Un sistema recién instalado funciona bien, pero con el uso se acumulan actualizaciones pendientes, ficheros temporales, programas que arrancan sin necesidad y, a veces, errores en el disco. El **mantenimiento** es el conjunto de tareas periódicas que mantienen el sistema **seguro, estable y rápido**. En este apartado verás las tareas básicas y aprenderás a **evaluar** las utilidades que se usan para hacerlas.

| Tarea | Frecuencia orientativa | Objetivo |
| --- | --- | --- |
| Aplicar actualizaciones de seguridad | Automática o semanal | Corregir vulnerabilidades. |
| Liberar espacio en disco | Mensual o al superar un umbral | Evitar que se llene el disco. |
| Revisar la salud de los discos | Mensual | Detectar fallos antes de perder datos. |
| Revisar los programas y servicios de arranque | Al instalar software | Arranque rápido y menos superficie de ataque. |
| Revisar los registros | Semanal o automatizada | Detectar errores y accesos sospechosos (apartado 10). |
| Comprobar las copias de seguridad | Mensual | Asegurarse de que se pueden restaurar (Unidad 3). |

## 11.1 Actualizaciones

### Linux

En la Unidad 2 viste cómo funcionan los gestores de paquetes. Estas son las órdenes de mantenimiento en Debian/Ubuntu:

```bash
sudo apt update                     # Descarga la lista actualizada de paquetes de los repositorios
apt list --upgradable               # Qué paquetes tienen versión nueva
sudo apt upgrade                    # Actualiza los paquetes sin eliminar ninguno
sudo apt full-upgrade               # Actualiza aunque haya que instalar o eliminar dependencias
sudo apt autoremove --purge         # Elimina dependencias que ya no necesita nadie (y núcleos antiguos)
sudo apt clean                      # Vacía la caché de paquetes descargados (/var/cache/apt/archives)
[ -f /var/run/reboot-required ] && echo "Hay que reiniciar"   # Tras actualizar el núcleo, por ejemplo
```

Los programas instalados con otros formatos se actualizan aparte:

```bash
sudo snap refresh                   # Paquetes Snap (también se actualizan solos varias veces al día)
flatpak update                      # Paquetes Flatpak
```

Ubuntu instala por defecto **`unattended-upgrades`**, que aplica automáticamente las actualizaciones de seguridad cada día. Su configuración está en `/etc/apt/apt.conf.d/50unattended-upgrades` y su registro en `/var/log/unattended-upgrades/`.

```bash
systemctl status unattended-upgrades
sudo unattended-upgrade --dry-run --debug     # Simulación: qué actualizaría ahora
```

### Windows

- **Windows Update** (*Configuración > Windows Update*): actualizaciones de seguridad, de calidad y de características. En *Opciones avanzadas* se configuran las **horas activas** (en las que no se reinicia el equipo) y las actualizaciones de otros productos de Microsoft.
- **Microsoft Store**: actualiza las aplicaciones instaladas desde la Tienda.
- **winget**, el gestor de paquetes de Windows, actualiza muchas aplicaciones de escritorio desde la línea de comandos:

```powershell
winget upgrade                      # Lista las aplicaciones con versión nueva
winget upgrade --all                # Las actualiza todas
winget upgrade --id Git.Git         # Actualiza una concreta
winget list                         # Programas instalados que winget reconoce
```

## 11.2 Liberar espacio en disco

### Localizar qué ocupa espacio

En Linux, además de `du` y `df` (apartado 9), la utilidad **`ncdu`** muestra un navegador interactivo de directorios ordenados por tamaño:

```bash
sudo apt install ncdu
ncdu ~                      # Navega con las flechas; 'd' borra, 'q' sale
sudo ncdu -x /              # Todo el sistema de archivos raíz (-x: sin entrar en otros montajes)
```

En Windows, **Configuración > Sistema > Almacenamiento** muestra cuánto ocupa cada categoría (aplicaciones, archivos temporales, documentos…).

### Limpieza en Linux

```bash
sudo apt autoremove --purge && sudo apt clean     # Paquetes
sudo journalctl --vacuum-time=4weeks              # Registros antiguos del journal (apartado 10)
rm -rf ~/.cache/thumbnails/*                      # Miniaturas de imágenes
du -sh ~/.cache                                   # Revisa la caché de tu usuario
```

Como desarrollador, las herramientas de trabajo suelen ser las que más espacio acumulan:

```bash
docker system df                  # Espacio que ocupan imágenes, contenedores y volúmenes
docker system prune               # Borra contenedores parados, redes sin uso e imágenes huérfanas
find ~ -type d -name node_modules -prune -exec du -sh {} + | sort -h   # Dependencias de proyectos Node
```

### Limpieza en Windows

- **Sensor de almacenamiento** (*Configuración > Sistema > Almacenamiento > Sensor de almacenamiento*): borra automáticamente los ficheros temporales y vacía la papelera periódicamente.
- **Recomendaciones de limpieza** (en la misma pantalla): ficheros temporales, ficheros grandes o no usados, archivos de actualizaciones anteriores.
- **Liberador de espacio en disco** (`cleanmgr`): herramienta clásica, todavía disponible. Con el botón *Limpiar archivos del sistema* incluye restos de actualizaciones.

```powershell
# Tamaño de la carpeta de temporales del usuario
"{0:N0} MB" -f ((Get-ChildItem $env:TEMP -Recurse -File -ErrorAction SilentlyContinue |
                 Measure-Object Length -Sum).Sum / 1MB)
```

> [!CAUTION]
> No borres a mano el contenido de `C:\Windows` (por ejemplo, `WinSxS` o `Installer`) ni de `/usr` o `/var/lib` en Linux. Para liberar espacio del sistema, usa siempre las herramientas oficiales: el sistema sabe qué se puede eliminar sin romper nada.

## 11.3 Salud y optimización de los discos

### Estado SMART

Los discos duros y SSD incorporan **SMART** (*Self-Monitoring, Analysis and Reporting Technology*), un sistema que registra indicadores de su propio estado: sectores reasignados, errores de lectura, horas de uso, temperatura, desgaste en los SSD…

```bash
sudo apt install smartmontools
sudo smartctl -H /dev/sda        # Valoración global: PASSED o FAILED
sudo smartctl -a /dev/sda        # Todos los atributos (en discos NVMe: /dev/nvme0)
```

```powershell
Get-PhysicalDisk | Select-Object FriendlyName, MediaType, HealthStatus, OperationalStatus
Get-PhysicalDisk | Get-StorageReliabilityCounter |
    Select-Object DeviceId, Temperature, Wear, ReadErrorsTotal
```

> [!NOTE]
> En las máquinas virtuales, los discos son ficheros del anfitrión y normalmente **no ofrecen datos SMART**. Prueba estas órdenes en un equipo físico.

### Comprobar el sistema de archivos

| Sistema | Herramienta | Observaciones |
| --- | --- | --- |
| Linux (ext4) | `fsck` | El sistema de archivos debe estar **desmontado**. Para la raíz, el sistema lo comprueba al arrancar si detecta problemas. |
| Windows (NTFS) | `chkdsk` | `chkdsk C: /scan` comprueba en línea, sin reiniciar. `chkdsk C: /f` corrige errores (en la unidad del sistema, al reiniciar). |

```bash
sudo umount /dev/sdb1
sudo fsck -f /dev/sdb1           # Comprueba y repara una partición de datos
```

### Optimizar las unidades

- **Discos duros mecánicos (HDD)**: con el uso, los ficheros se **fragmentan** (sus trozos quedan dispersos por el disco) y el acceso se vuelve más lento. La **desfragmentación** los reordena.
- **SSD**: no se deben desfragmentar (no mejora el rendimiento y aumenta el desgaste). En su lugar se usa **TRIM**, que informa al SSD de qué bloques ya no se usan para que pueda gestionarlos eficientemente.

En Linux, ext4 apenas sufre fragmentación, y el TRIM se ejecuta semanalmente mediante un *timer* de systemd:

```bash
systemctl status fstrim.timer
sudo fstrim -av                  # Ejecuta TRIM ahora en todos los sistemas de archivos que lo admiten
```

En Windows, la herramienta **Desfragmentar y optimizar unidades** (`dfrgui`) aplica automáticamente desfragmentación o TRIM según el tipo de disco, de forma programada:

```powershell
Optimize-Volume -DriveLetter C -Analyze -Verbose     # Analiza el estado
Optimize-Volume -DriveLetter C -ReTrim -Verbose      # TRIM (SSD)
Optimize-Volume -DriveLetter D -Defrag -Verbose      # Desfragmentación (HDD)
```

### Reparar archivos del sistema de Windows

Si Windows se comporta de forma extraña (errores al abrir herramientas del sistema, actualizaciones que fallan), se puede comprobar la integridad de sus ficheros. Ejecútalo en este orden, en una consola de administrador:

```bat
DISM /Online /Cleanup-Image /RestoreHealth   :: Repara la imagen de Windows descargando lo necesario
sfc /scannow                                 :: Comprueba y repara los archivos protegidos del sistema
```

## 11.4 Optimizar el arranque

Cada programa o servicio que arranca con el sistema **retrasa el inicio**, **consume memoria** y es una posible **vía de ataque**. Conviene revisar qué se inicia automáticamente.

### Linux

```bash
systemd-analyze                     # Tiempo total de arranque (firmware, cargador, núcleo, espacio de usuario)
systemd-analyze blame | head        # Unidades que más tardan en arrancar
systemd-analyze critical-chain      # Cadena de dependencias que determina el tiempo de arranque
systemctl list-unit-files --type=service --state=enabled   # Servicios habilitados
```

Si encuentras un servicio que no necesitas (por ejemplo, un servidor que instalaste para una práctica), deshabilítalo: `sudo systemctl disable --now nombre`. En el escritorio, las aplicaciones de inicio de sesión se gestionan con la aplicación *Aplicaciones al inicio* o en `~/.config/autostart/`.

### Windows

- **Administrador de tareas > Aplicaciones de arranque**: lista de programas que se inician con la sesión y su **impacto** en el inicio (alto, medio, bajo). Clic derecho > *Deshabilitar*.
- **Configuración > Aplicaciones > Inicio**: la misma lista con interruptores.
- `services.msc`: servicios con inicio automático (apartado 8).

```powershell
Get-CimInstance Win32_StartupCommand | Select-Object Name, Command, Location, User
```

## 11.5 Evaluar utilidades de mantenimiento

El criterio de evaluación **g** pide no solo instalar utilidades, sino **evaluarlas**. Antes de instalar una herramienta, y sobre todo antes de darle privilegios de administrador, analízala con criterios objetivos:

| Criterio | Preguntas |
| --- | --- |
| **Necesidad** | ¿Resuelve un problema que tengo? ¿Lo resuelve ya una herramienta del sistema? |
| **Origen** | ¿Se instala desde el repositorio oficial de la distribución, `winget` o la Microsoft Store? ¿Su web es la oficial? |
| **Licencia** | ¿Es software libre, gratuito o de pago? ¿Permite el uso que le voy a dar (por ejemplo, en una empresa)? |
| **Mantenimiento** | ¿Cuándo se publicó la última versión? ¿Tiene una comunidad activa? |
| **Privilegios y riesgos** | ¿Qué permisos necesita? ¿Qué puede borrar o modificar? ¿Se puede deshacer lo que hace? |
| **Recursos** | ¿Cuánta memoria y CPU consume? ¿Se queda ejecutándose en segundo plano? |
| **Resultado medible** | ¿Puedo comprobar, con datos, que ha mejorado algo (espacio liberado, tiempo de arranque)? |

> [!WARNING]
> Desconfía de los programas que prometen "acelerar el PC", "limpiar el registro" u "optimizar la RAM". Los **limpiadores del registro** de Windows no mejoran el rendimiento de forma apreciable y pueden dañar el sistema; Microsoft no los recomienda. Muchos de estos programas, además, incluyen publicidad o software no deseado. Las herramientas integradas del sistema cubren la gran mayoría de las necesidades.

Algunas utilidades fiables y habituales que puedes evaluar en las prácticas:

| Utilidad | Sistema | Función | Licencia |
| --- | --- | --- | --- |
| `htop`, `btop` | Linux | Monitorización de procesos y recursos. | Libre (GPL / Apache) |
| `ncdu` | Linux | Análisis interactivo del espacio en disco. | Libre (MIT) |
| `smartmontools` | Linux y Windows | Estado SMART de los discos. | Libre (GPL) |
| BleachBit | Linux y Windows | Limpieza de cachés y temporales de muchas aplicaciones. | Libre (GPL) |
| Microsoft PowerToys | Windows | Conjunto de utilidades oficiales (entre ellas, ver qué proceso bloquea un fichero). | Libre (MIT) |
| Sysinternals (Process Explorer, Autoruns…) | Windows | Herramientas avanzadas de Microsoft para analizar procesos y programas de inicio. | Gratuita (propietaria) |
| WinDirStat | Windows | Mapa gráfico de lo que ocupa el disco. | Libre (GPL) |

## Ejercicios resueltos

### Ejercicio 11.1. Plan de mantenimiento en Linux

Escribe un script `mantenimiento.sh` que actualice los paquetes, elimine los que no se necesitan, limpie la caché de `apt` y el *journal* de más de 4 semanas, muestre el espacio libre de `/` antes y después, e indique si hace falta reiniciar. Programa su ejecución los domingos a las 3:00.

{{% details "Ver solución" %}}
```bash
#!/usr/bin/env bash
# mantenimiento.sh - Mantenimiento semanal de un equipo Debian/Ubuntu
set -euo pipefail                          # Detener el script ante cualquier error (Unidad 3)

if [[ $EUID -ne 0 ]]; then                 # EUID: UID efectivo; 0 = root
    echo "Ejecuta este script como root" >&2
    exit 1
fi

libre() { df -h --output=avail / | tail -n 1; }   # Espacio disponible en la raíz

antes=$(libre)
export DEBIAN_FRONTEND=noninteractive      # Evita que apt haga preguntas

apt-get update -q
apt-get upgrade -y -q
apt-get autoremove --purge -y -q
apt-get clean
journalctl --vacuum-time=4weeks -q

despues=$(libre)
logger -t mantenimiento "Mantenimiento completado. Libre en /: antes $antes, después $despues"
echo "Espacio libre en /: antes $antes, después $despues"

if [[ -f /var/run/reboot-required ]]; then
    logger -t mantenimiento "Es necesario reiniciar el equipo"
    echo "AVISO: es necesario reiniciar"
fi
```

```bash
sudo install -m 750 mantenimiento.sh /usr/local/sbin/
sudo crontab -e
# 0 3 * * 0 /usr/local/sbin/mantenimiento.sh
```

En los scripts se usa `apt-get` en lugar de `apt`, porque la salida de `apt` está pensada para personas y puede cambiar entre versiones (el propio `apt` lo advierte con *WARNING: apt does not have a stable CLI interface*).

### Ejercicio 11.2. Medir el arranque

En tu máquina virtual Linux, mide el tiempo de arranque e identifica las tres unidades que más tardan. Instala un servicio que no necesites (por ejemplo, `apache2`), vuelve a medir, deshabilítalo y mide de nuevo.

{{% details "Ver solución" %}}
```bash
systemd-analyze
systemd-analyze blame | head -n 3

sudo apt install apache2          # Se habilita y arranca automáticamente al instalarlo
sudo reboot
systemd-analyze blame | grep apache2

sudo systemctl disable --now apache2
sudo reboot
systemd-analyze
```

Anota los tiempos en una tabla. La diferencia puede ser pequeña en una máquina virtual con un disco rápido, pero el procedimiento es el mismo que se sigue en un servidor real para decidir qué servicios deshabilitar. Fíjate también en que, en Debian/Ubuntu, instalar un servicio suele **habilitarlo** automáticamente; en otras distribuciones, como Fedora, no.
{{% /details %}}

### Ejercicio 11.3. Evaluar una utilidad

Evalúa `ncdu` frente a `du` para encontrar los directorios que más ocupan en tu directorio personal, aplicando los criterios del apartado 11.5. Mide el tiempo que tarda cada uno.

{{% details "Ver solución" %}}
```bash
time du -h --max-depth=2 ~ 2>/dev/null | sort -h | tail -n 10
sudo apt install ncdu
time ncdu -o /tmp/ncdu.json ~      # -o: exporta el análisis a un fichero sin abrir la interfaz
ncdu -f /tmp/ncdu.json             # -f: abre el análisis guardado
```

| Criterio | `du` | `ncdu` |
| --- | --- | --- |
| Necesidad | Siempre instalado. | Hay que instalarlo, pero es más cómodo para explorar. |
| Origen | Paquete `coreutils` del sistema. | Repositorio oficial de la distribución. |
| Licencia | GPL. | MIT. |
| Privilegios | Ninguno extra. | Ninguno extra; permite borrar ficheros desde la interfaz (precaución). |
| Uso | Ideal para scripts e informes. | Ideal para explorar interactivamente. |
| Tiempo | Similar: los dos recorren el árbol completo. | Similar. |

Conclusión razonada: `du` es la herramienta adecuada para automatizar y `ncdu` para investigar manualmente. No sustituye a `du`, lo complementa.
{{% /details %}}

### Ejercicio 11.4. Mantenimiento en Windows

Con PowerShell como administrador: lista las aplicaciones que se pueden actualizar con `winget`, comprueba el estado de salud de los discos, analiza si la unidad `C:` necesita optimización y muestra los programas que se ejecutan al inicio.

{{% details "Ver solución" %}}
```powershell
winget upgrade
Get-PhysicalDisk | Select-Object FriendlyName, MediaType, HealthStatus
Optimize-Volume -DriveLetter C -Analyze -Verbose
Get-CimInstance Win32_StartupCommand | Select-Object Name, Command, Location
```

En la salida de `Optimize-Volume -Analyze`, Windows indica el porcentaje de fragmentación y si recomienda optimizar. Si `MediaType` es `SSD`, la optimización consistirá en TRIM, no en desfragmentar.
{{% /details %}}
