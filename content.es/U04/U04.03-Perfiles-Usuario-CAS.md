# 3. Perfiles de usuario

El **perfil de usuario** es el conjunto de ficheros y de configuración que definen el **entorno de trabajo** de una persona: sus documentos, el fondo de escritorio, el idioma, las variables de entorno, el historial de órdenes o la configuración de sus programas (por ejemplo, las extensiones de Visual Studio Code o la configuración de Git).

Gracias a los perfiles, cada usuario encuentra el equipo tal y como lo dejó, aunque otras personas lo usen también.

## 3.1 Perfiles en Linux

En Linux, el perfil de un usuario está formado por:

1. Su **directorio personal** (`/home/usuario`), con sus ficheros y sus **ficheros ocultos de configuración** (los que empiezan por `.`).
2. Los **ficheros de inicio de la shell**, que se ejecutan al abrir una sesión o una terminal.

### El directorio personal

```bash
echo "$HOME"          # /home/ana
ls -la ~              # Ficheros ocultos incluidos
```

| Fichero o directorio | Contenido |
| --- | --- |
| `~/.bashrc` | Configuración de Bash para terminales interactivas: alias, *prompt*, funciones. |
| `~/.profile` | Se ejecuta al **iniciar sesión**: variables de entorno como `PATH`. |
| `~/.bash_history` | Historial de órdenes. |
| `~/.bash_logout` | Se ejecuta al cerrar una sesión de inicio. |
| `~/.config/` | Configuración de las aplicaciones modernas (estándar *XDG*). |
| `~/.local/share/` | Datos de las aplicaciones. |
| `~/.cache/` | Caché; se puede borrar sin perder información importante. |
| `~/.ssh/` | Claves SSH y lista de servidores conocidos. Debe tener permisos `700`. |
| `~/.gitconfig` | Configuración global de Git (nombre, correo…). |

### `/etc/skel`: la plantilla de los perfiles nuevos

Cuando se crea un usuario con `useradd -m` o `adduser`, su directorio personal se rellena con una **copia** del contenido de `/etc/skel` (de *skeleton*, esqueleto). Si el administrador modifica `/etc/skel`, todos los usuarios que se creen **a partir de ese momento** recibirán esos ficheros.

```bash
ls -la /etc/skel      # .bash_logout  .bashrc  .profile
```

> [!NOTE]
> Los cambios en `/etc/skel` **no afectan a los usuarios ya existentes**. Para aplicar una configuración a todos los usuarios, actuales y futuros, se usan los ficheros globales de `/etc` que se explican a continuación.

### Ficheros de inicio de Bash

Bash lee unos ficheros u otros según el tipo de shell:

| Tipo de shell | Cuándo ocurre | Ficheros que lee (en orden) |
| --- | --- | --- |
| **De inicio de sesión** (*login shell*) | Al entrar por consola de texto, por SSH o con `su -` | `/etc/profile` (y los ficheros de `/etc/profile.d/`), y después el **primero que exista** de `~/.bash_profile`, `~/.bash_login` o `~/.profile`. |
| **Interactiva sin inicio de sesión** | Al abrir una terminal dentro del escritorio | `/etc/bash.bashrc` y `~/.bashrc`. |

En Ubuntu, `~/.profile` incluye a su vez `~/.bashrc`, de modo que en la práctica la configuración interactiva se pone en `~/.bashrc` y las variables de entorno en `~/.profile`.

| Ámbito | Ficheros de configuración |
| --- | --- |
| **Todos los usuarios** | `/etc/profile`, `/etc/profile.d/*.sh`, `/etc/bash.bashrc`, `/etc/environment` |
| **Un usuario** | `~/.profile`, `~/.bashrc` |
| **Usuarios futuros** | `/etc/skel/` |

```bash
# ~/.bashrc  (fragmento)
alias ll='ls -lah'                       # Alias: atajo para una orden larga
alias actualizar='sudo apt update && sudo apt upgrade'
export EDITOR=nano                       # Editor por defecto para crontab, visudo…
```

```bash
# ~/.profile  (fragmento)
# Añade al PATH la carpeta de programas del usuario, si existe
if [ -d "$HOME/.local/bin" ]; then
    PATH="$HOME/.local/bin:$PATH"
fi
export JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64
```

Los cambios en estos ficheros se aplican al abrir una terminal o sesión nueva. Para aplicarlos en la terminal actual:

```bash
source ~/.bashrc        # Equivale a: . ~/.bashrc
```

> [!TIP]
> Para configuraciones globales, en lugar de modificar `/etc/profile` crea un fichero propio en `/etc/profile.d/` (por ejemplo, `/etc/profile.d/aula.sh`). Así, las actualizaciones del sistema no sobrescribirán tus cambios y es fácil deshacerlos borrando el fichero.

## 3.2 Perfiles en Windows

En Windows, el perfil de cada usuario se guarda en `C:\Users\usuario` y se crea **la primera vez que el usuario inicia sesión**, copiando el perfil plantilla `C:\Users\Default` (el equivalente a `/etc/skel`).

| Carpeta o fichero | Contenido |
| --- | --- |
| `Desktop`, `Documents`, `Downloads`, `Pictures`… | Carpetas personales (en el Explorador aparecen traducidas: *Escritorio*, *Documentos*…). |
| `AppData\Roaming` | Configuración de las aplicaciones que debe **acompañar al usuario** entre equipos (perfiles móviles). |
| `AppData\Local` | Datos y caché que solo tienen sentido en **este equipo**. |
| `AppData\LocalLow` | Igual que `Local`, para aplicaciones que se ejecutan con un nivel de integridad bajo (por ejemplo, navegadores en modo protegido). |
| `NTUSER.DAT` | Parte del **registro de Windows** del usuario. Al iniciar sesión se carga como la rama `HKEY_CURRENT_USER` (`HKCU`). |

La carpeta `AppData` está **oculta**. Para verla, activa en el Explorador *Ver > Mostrar > Elementos ocultos*, o escribe `%APPDATA%` en la barra de direcciones.

Además, `C:\Users\Public` (*Acceso público*) contiene carpetas compartidas por todos los usuarios del equipo.

### Variables de entorno del perfil

| CMD | PowerShell | Valor típico |
| --- | --- | --- |
| `%USERNAME%` | `$env:USERNAME` | `ana` |
| `%USERPROFILE%` | `$env:USERPROFILE` | `C:\Users\ana` |
| `%APPDATA%` | `$env:APPDATA` | `C:\Users\ana\AppData\Roaming` |
| `%LOCALAPPDATA%` | `$env:LOCALAPPDATA` | `C:\Users\ana\AppData\Local` |
| `%TEMP%` | `$env:TEMP` | `C:\Users\ana\AppData\Local\Temp` |
| `%PUBLIC%` | `$env:PUBLIC` | `C:\Users\Public` |

```powershell
Get-ChildItem Env:              # Todas las variables de entorno
explorer $env:APPDATA           # Abre la carpeta en el Explorador
```

### Tipos de perfiles

| Tipo | Descripción |
| --- | --- |
| **Local** | Se guarda en el disco del equipo. Es el tipo por defecto. |
| **Móvil** (*roaming*) | Se guarda en un servidor de la red y se copia al equipo al iniciar sesión. El usuario encuentra su entorno en cualquier equipo del dominio. |
| **Obligatorio** (*mandatory*) | Perfil móvil de solo lectura (el fichero se renombra a `NTUSER.MAN`): los cambios se pierden al cerrar sesión. Útil en aulas y quioscos. |
| **Temporal** | Windows lo crea cuando no puede cargar el perfil del usuario (por ejemplo, si está dañado). Se borra al cerrar sesión, así que **no se debe trabajar con él**. |

Los perfiles móviles y obligatorios necesitan un dominio y se configuran desde el servidor (Unidad 6).

> [!NOTE]
> Si inicias sesión con una cuenta Microsoft y activas la **copia de seguridad de carpetas** de OneDrive, las carpetas *Escritorio*, *Documentos* e *Imágenes* se trasladan a `C:\Users\usuario\OneDrive\`. Tenlo en cuenta cuando un script busque ficheros en `$env:USERPROFILE\Desktop`; la ruta fiable es `[Environment]::GetFolderPath('Desktop')`.

### Ver y eliminar perfiles

Los perfiles **no se borran** al eliminar la cuenta de usuario y siguen ocupando espacio. No se deben borrar eliminando la carpeta de `C:\Users`, porque quedaría una referencia en el registro y el sistema podría crear perfiles temporales. La forma correcta es:

- **Gráficamente**: `Win + R` > `sysdm.cpl` > pestaña **Opciones avanzadas** > **Perfiles de usuario** > **Configuración**. Selecciona el perfil y pulsa **Eliminar**.
- **Con PowerShell** (como administrador):

```powershell
# Lista los perfiles de usuarios reales (Special = $false excluye SYSTEM, LOCAL SERVICE…)
Get-CimInstance Win32_UserProfile |
    Where-Object { -not $_.Special } |
    Select-Object LocalPath, SID, LastUseTime, Loaded

# Elimina el perfil de una ruta concreta (el usuario no debe tener la sesión abierta: Loaded = False)
Get-CimInstance Win32_UserProfile |
    Where-Object LocalPath -eq 'C:\Users\prueba' |
    Remove-CimInstance
```

`Get-CimInstance` consulta la información de gestión de Windows (WMI) mediante el estándar CIM. Sustituye a las antiguas `Get-WmiObject` y `wmic`, que ya no se deben usar: `wmic` ha sido **eliminado** de las versiones actuales de Windows 11.

### El perfil de PowerShell

PowerShell también tiene su propio "`~/.bashrc`": un script que se ejecuta al abrir cada consola. Su ruta está en la variable `$PROFILE`.

```powershell
$PROFILE                                    # Ruta del perfil (puede no existir todavía)
if (-not (Test-Path $PROFILE)) { New-Item -Path $PROFILE -ItemType File -Force }
notepad $PROFILE
```

```powershell
# Contenido de ejemplo del perfil de PowerShell
Set-Alias -Name ll -Value Get-ChildItem          # Alias, como en Bash
function proyectos { Set-Location "$HOME\proyectos" }
```

## 3.3 Comparativa

| Concepto | Linux | Windows |
| --- | --- | --- |
| Ubicación | `/home/usuario` | `C:\Users\usuario` |
| Plantilla para perfiles nuevos | `/etc/skel` | `C:\Users\Default` |
| Configuración de aplicaciones | `~/.config`, ficheros ocultos | `AppData`, rama `HKCU` del registro |
| Configuración de la shell | `~/.bashrc`, `~/.profile` | `$PROFILE` de PowerShell |
| Configuración para todos | `/etc/profile.d/`, `/etc/environment` | Directivas de grupo, variables de entorno del sistema |
| Variables del perfil | `$HOME`, `$USER` | `%USERPROFILE%`, `%USERNAME%` |

## Ejercicios resueltos

### Ejercicio 3.1. Personalizar la plantilla de usuarios

Haz que todos los usuarios que se creen a partir de ahora en tu Linux tengan: un directorio `proyectos` vacío, un fichero `LEEME.txt` con las normas del aula y el alias `ll='ls -lah'`. Comprueba que un usuario nuevo los recibe y que uno existente no.

{{% details "Ver solución" %}}
```bash
sudo mkdir /etc/skel/proyectos
echo "Normas del aula: no compartas tu contraseña y guarda tu trabajo en ~/proyectos" |
    sudo tee /etc/skel/LEEME.txt > /dev/null
echo "alias ll='ls -lah'" | sudo tee -a /etc/skel/.bashrc > /dev/null

sudo useradd -m -s /bin/bash nuevo
sudo ls -la /home/nuevo        # Aparecen proyectos/ y LEEME.txt
ls ~/proyectos                 # En tu usuario (ya existente) no se ha creado
```

`sudo tee` se usa porque la redirección `>` la realiza la shell del usuario normal, que no tiene permiso de escritura en `/etc/skel`. `tee -a` añade al final del fichero en lugar de sobrescribirlo.
{{% /details %}}

### Ejercicio 3.2. Variable de entorno para todos los usuarios

Define la variable `AULA=B12` para todos los usuarios del sistema, actuales y futuros, sin modificar ficheros que puedan cambiar las actualizaciones.

{{% details "Ver solución" %}}
```bash
echo 'export AULA=B12' | sudo tee /etc/profile.d/aula.sh > /dev/null
```

Los ficheros de `/etc/profile.d/` se leen en los inicios de sesión. Para comprobarlo, abre una sesión de inicio nueva (`su - ana`) y ejecuta `echo "$AULA"`. En el escritorio gráfico hay que cerrar la sesión y volver a entrar.
{{% /details %}}

### Ejercicio 3.3. Perfiles huérfanos en Windows

Crea el usuario local `temporal`, inicia sesión con él una vez y elimínalo con `Remove-LocalUser`. Comprueba que su perfil sigue existiendo y bórralo correctamente.

{{% details "Ver solución" %}}
```powershell
# 1. Tras crear el usuario, iniciar sesión con él y cerrar la sesión:
Remove-LocalUser -Name temporal
Test-Path C:\Users\temporal           # True: la carpeta sigue existiendo

# 2. El perfil aparece con el SID de una cuenta que ya no existe
Get-CimInstance Win32_UserProfile | Where-Object LocalPath -like '*temporal*' |
    Select-Object LocalPath, SID

# 3. Borrado correcto (carpeta y entrada del registro)
Get-CimInstance Win32_UserProfile | Where-Object LocalPath -eq 'C:\Users\temporal' |
    Remove-CimInstance
Test-Path C:\Users\temporal           # False
```

En `sysdm.cpl`, el perfil huérfano aparece como *Cuenta desconocida*.
{{% /details %}}
