# 7. Compartición de recursos en red

Hasta ahora, los permisos protegían los ficheros de los usuarios **del mismo equipo**. En una organización es habitual que los ficheros y las impresoras estén en un equipo y se utilicen **desde otros equipos de la red**. A los ficheros, carpetas o impresoras que un equipo ofrece a la red se les llama **recursos compartidos**.

## 7.1 El protocolo SMB

Windows y Linux comparten ficheros e impresoras mediante el protocolo **SMB** (*Server Message Block*), también conocido por su antiguo nombre **CIFS**. Funciona según el modelo **cliente-servidor**:

- El **servidor** es el equipo que ofrece el recurso.
- El **cliente** es el equipo que accede a él.

| Característica | Detalle |
| --- | --- |
| Puerto | **445/TCP** (lo verás con detalle en la Unidad 5). |
| Versiones | SMB 1 (obsoleta, **insegura y deshabilitada** por defecto), SMB 2 y SMB 3 (actual, admite cifrado). |
| Ruta de acceso | Formato **UNC** (*Universal Naming Convention*): `\\servidor\recurso\carpeta\fichero` en Windows y `//servidor/recurso` en Linux. |
| Implementación en Linux | **Samba**, software libre que permite a Linux actuar como servidor y como cliente SMB. |

> [!NOTE]
> Entre sistemas Linux y Unix también se usa **NFS** (*Network File System*). En entornos mixtos con Windows, SMB es la opción más habitual, y es la que se estudia aquí.

### Novedades de seguridad en Windows 11

A partir de **Windows 11 24H2** y **Windows Server 2025**, Microsoft ha endurecido la configuración por defecto de SMB:

- La **firma SMB** es obligatoria en todas las conexiones. La firma garantiza que nadie ha manipulado los datos por el camino.
- En la edición **Pro**, el cliente ya **no permite el acceso como invitado** (sin usuario ni contraseña) a recursos de otros equipos.

En la práctica, esto significa que **para acceder a un recurso compartido hay que autenticarse siempre con un usuario y una contraseña** que existan en el servidor. Algunos dispositivos antiguos (NAS, routers con USB) que solo admiten acceso de invitado dejan de funcionar; la solución correcta es configurar en ellos un usuario, no rebajar la seguridad del cliente.

## 7.2 Compartir carpetas en Windows

### Requisitos previos

1. El perfil de la red debe ser **Privada** (*Configuración > Red e Internet > Ethernet o Wi-Fi > Tipo de perfil de red*). En una red **Pública**, Windows bloquea la compartición.
2. En **Configuración > Red e Internet > Configuración de red avanzada > Configuración de uso compartido avanzado**, activa **Detección de redes** y **Uso compartido de archivos e impresoras** para las redes privadas.

### Dos niveles de permisos

Un recurso compartido tiene **dos** capas de permisos, y el acceso desde la red debe superar **las dos**:

| Capa | Dónde se configura | Permisos disponibles | Se aplica a |
| --- | --- | --- | --- |
| **Permisos del recurso compartido** | *Propiedades > Compartir > Uso compartido avanzado > Permisos* | **Control total**, **Cambiar**, **Leer** | Solo a los accesos **por la red**. |
| **Permisos NTFS** | *Propiedades > Seguridad* (apartado 6) | Todos los vistos en el apartado 6 | A los accesos **por la red y locales**. |

```text
Permiso efectivo desde la red = el MÁS RESTRICTIVO entre (permiso de recurso compartido, permiso NTFS)
```

Por ejemplo, si `dam1` tiene *Control total* en el recurso compartido pero solo *Lectura* en NTFS, desde la red solo podrá leer.

> [!TIP]
> La práctica recomendada es dar un permiso amplio en el recurso compartido (por ejemplo, **Cambiar** o **Control total** a *Usuarios autentificados*) y controlar el acceso real con los **permisos NTFS**, que son más detallados y se aplican también a los accesos locales. Así solo hay que mantener un conjunto de permisos.

{{% steps %}}
1. ## Compartir la carpeta

   Clic derecho sobre la carpeta > **Propiedades** > pestaña **Compartir** > **Uso compartido avanzado**. Marca **Compartir esta carpeta** y escribe el **nombre del recurso** (es el nombre que se verá en la red; puede ser distinto del de la carpeta).

2. ## Permisos del recurso compartido

   Pulsa **Permisos**. Por defecto, *Todos* tiene solo *Leer*. Quita *Todos*, añade *Usuarios autentificados* (o el grupo que corresponda) y marca *Cambiar*.

3. ## Permisos NTFS

   En la pestaña **Seguridad**, ajusta los permisos NTFS para los grupos que deban acceder (apartado 6).

4. ## Comprobar desde otro equipo

   En el Explorador del cliente, escribe en la barra de direcciones `\\NOMBRE-SERVIDOR\recurso` (o `\\192.168.1.10\recurso`). Windows pedirá un usuario y una contraseña **del servidor**.
{{% /steps %}}

La consola **Carpetas compartidas** (`fsmgmt.msc`) muestra todos los recursos compartidos del equipo, las **sesiones** abiertas (qué usuarios están conectados) y los **archivos abiertos** desde la red.

### Recursos compartidos administrativos

Windows crea automáticamente recursos **ocultos**, cuyo nombre termina en `$` y que no aparecen al explorar la red: `C$` (la unidad C completa), `ADMIN$` (la carpeta `C:\Windows`) e `IPC$` (comunicación entre procesos). Solo los administradores pueden acceder a ellos. Tú también puedes crear un recurso oculto añadiendo `$` al final de su nombre.

### Desde la línea de comandos

```bat
:: CMD (como administrador)
net share                                                     :: Lista los recursos compartidos
net share Proyecto=C:\Proyecto /grant:"Usuarios autentificados",CHANGE /remark:"Proyecto DAM1"
net share Proyecto /delete                                    :: Deja de compartir (no borra la carpeta)
```

```powershell
# PowerShell (como administrador)
New-SmbShare -Name "Proyecto" -Path "C:\Proyecto" `
             -ChangeAccess "dam1" -ReadAccess "profesores" -FullAccess "Administradores" `
             -Description "Proyecto DAM1"

Get-SmbShare                                    # Recursos compartidos
Get-SmbShareAccess -Name "Proyecto"             # Sus permisos de recurso compartido
Grant-SmbShareAccess -Name "Proyecto" -AccountName "marta" -AccessRight Full -Force
Revoke-SmbShareAccess -Name "Proyecto" -AccountName "profesores" -Force
Get-SmbSession                                  # Quién está conectado
Get-SmbOpenFile                                 # Qué ficheros están abiertos desde la red
Remove-SmbShare -Name "Proyecto" -Force
```

### Acceder desde un cliente Windows

```bat
:: Conectar el recurso como unidad de red Z: (pide la contraseña y la recuerda tras reiniciar)
net use Z: \\SERVIDOR\Proyecto /user:SERVIDOR\ana /persistent:yes
net use                       :: Conexiones activas
net use Z: /delete            :: Desconectar
```

```powershell
# Equivalente en PowerShell. Get-Credential pide la contraseña y devuelve un objeto PSCredential.
$cred = Get-Credential -UserName "SERVIDOR\ana" -Message "Contraseña de ana en el servidor"
New-SmbMapping -LocalPath "Z:" -RemotePath "\\SERVIDOR\Proyecto" `
               -UserName $cred.UserName -Password $cred.GetNetworkCredential().Password `
               -Persistent $true
Get-SmbMapping
```

Gráficamente: en el Explorador, clic derecho sobre **Este equipo** > **Conectar a unidad de red**.

## 7.3 Compartir impresoras en Windows

{{% steps %}}
1. ## Compartir la impresora en el servidor

   **Configuración > Bluetooth y dispositivos > Impresoras y escáneres**, selecciona la impresora > **Propiedades de impresora** > pestaña **Compartir** > marca **Compartir esta impresora** y escribe un nombre de recurso.

2. ## Permisos de impresión

   En la pestaña **Seguridad** de las mismas propiedades hay tres permisos: **Imprimir**, **Administrar documentos** (pausar o cancelar trabajos de otros) y **Administrar esta impresora** (cambiar su configuración).

3. ## Conectar desde un cliente

   En el Explorador, abre `\\SERVIDOR`, haz doble clic sobre la impresora y Windows instalará su controlador automáticamente.
{{% /steps %}}

```powershell
# En el servidor
Get-Printer                                                   # Impresoras instaladas
Set-Printer -Name "HP LaserJet" -Shared $true -ShareName "Impresora-Aula"

# En el cliente
Add-Printer -ConnectionName "\\SERVIDOR\Impresora-Aula"
Get-Printer | Select-Object Name, Type, PortName
```

## 7.4 Servidor Samba en Linux

**Samba** permite que un equipo Linux comparta carpetas con clientes Windows, macOS y Linux. Es muy utilizado en servidores de ficheros y dispositivos NAS.

### Instalación

```bash
sudo apt update
sudo apt install samba
systemctl status smbd             # El servicio se llama smbd
sudo ufw allow samba              # Si el cortafuegos ufw está activo (Unidad 7)
```

### Configuración: `/etc/samba/smb.conf`

El fichero tiene formato **INI**: secciones entre corchetes y líneas `parámetro = valor`. La sección `[global]` contiene la configuración general y **cada recurso compartido es una sección** más.

```bash
sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.original    # Copia de seguridad
sudo nano /etc/samba/smb.conf
```

Añade al final:

```ini
# Recurso para el grupo de proyecto
[proyecto]
   comment = Proyecto DAM1
   path = /srv/proyecto
   # Solo pueden conectarse los miembros del grupo dam1 (@ indica grupo)
   valid users = @dam1
   # Permite escribir (por defecto los recursos son de solo lectura)
   read only = no
   # Permisos máximos de los ficheros y directorios que se creen desde la red
   create mask = 0660
   directory mask = 2770
   # Todo lo que se cree pertenecerá al grupo dam1
   force group = dam1
   # No aparece en la lista de recursos si el usuario no tiene acceso
   access based share enum = yes

# Recurso de solo lectura para documentación
[documentacion]
   path = /srv/documentacion
   valid users = @dam1 @profesores
   read only = yes
   # Excepción: los profesores sí pueden escribir
   write list = @profesores
```

| Parámetro | Significado |
| --- | --- |
| `path` | Directorio que se comparte. |
| `valid users` | Usuarios (o `@grupos`) que pueden conectarse. |
| `read only` / `writable` | Si se permite escribir (`read only = no` equivale a `writable = yes`). |
| `write list` | Usuarios o grupos que pueden escribir aunque el recurso sea de solo lectura. |
| `browseable` | Si el recurso aparece al explorar el servidor (`no` lo oculta). |
| `create mask` / `directory mask` | Permisos máximos de los ficheros y directorios nuevos. |
| `force group` / `force user` | Grupo o usuario propietario de lo que se cree. |
| `guest ok` | Permite el acceso sin contraseña. **No lo uses**: los clientes Windows actuales no lo admiten y es inseguro. |

Comprueba la sintaxis y aplica los cambios:

```bash
testparm                          # Revisa smb.conf y muestra la configuración efectiva
sudo systemctl restart smbd
```

### Usuarios de Samba

Samba usa **su propia base de contraseñas**, porque el formato de `/etc/shadow` no es compatible con la autenticación de SMB. Cada usuario de Samba **debe existir antes como usuario de Linux**:

```bash
sudo smbpasswd -a ana             # Añade ana a Samba y le asigna una contraseña SMB
sudo smbpasswd -a luis
sudo pdbedit -L                   # Lista los usuarios de Samba
sudo smbpasswd -d luis            # Deshabilita (-e para habilitar)
sudo smbpasswd -x luis            # Elimina de Samba (el usuario Linux sigue existiendo)
```

> [!IMPORTANT]
> Igual que en Windows, en Samba el acceso debe superar **dos capas**: la configuración del recurso en `smb.conf` (`valid users`, `read only`…) **y** los permisos del sistema de archivos de Linux (UGO y ACL, apartado 5). Si `smb.conf` permite escribir pero el directorio no tiene permiso de escritura para el usuario, no podrá escribir.

### Acceder desde un cliente

Desde **Windows**: `\\IP-DEL-SERVIDOR\proyecto` en el Explorador, con el usuario y la contraseña de Samba.

Desde **Linux** (gráficamente): en el gestor de archivos, *Otras ubicaciones* > *Conectar con el servidor* > `smb://IP-DEL-SERVIDOR/proyecto`.

Desde **Linux** (terminal), con el cliente `smbclient`:

```bash
sudo apt install smbclient cifs-utils
smbclient -L //192.168.1.20 -U ana          # Lista los recursos del servidor
smbclient //192.168.1.20/proyecto -U ana    # Sesión interactiva tipo FTP (ls, get, put, exit)
```

Para **montar** el recurso en el árbol de directorios, como si fuera un disco más, se usa `mount -t cifs` (paquete `cifs-utils`). Las credenciales se guardan en un fichero protegido:

```bash
# Fichero de credenciales, legible solo por root
sudo tee /root/.smb-ana > /dev/null <<'EOF'
username=ana
password=LaContraseñaDeAna
EOF
sudo chmod 600 /root/.smb-ana

sudo mkdir -p /mnt/proyecto
sudo mount -t cifs //192.168.1.20/proyecto /mnt/proyecto \
     -o credentials=/root/.smb-ana,uid=$(id -u),gid=$(id -g)
df -h /mnt/proyecto
```

Para que se monte automáticamente en cada arranque, se añade una línea a `/etc/fstab` (Unidad 3):

```text
//192.168.1.20/proyecto  /mnt/proyecto  cifs  credentials=/root/.smb-ana,uid=1000,gid=1000,_netdev,nofail  0  0
```

La opción `_netdev` indica que es un sistema de archivos de red (se monta cuando la red está disponible) y `nofail` evita que el arranque se detenga si el servidor no responde.

### Impresoras en Linux: CUPS

En Linux, la impresión la gestiona **CUPS** (*Common UNIX Printing System*). Se administra desde un navegador en `http://localhost:631` o desde la configuración del escritorio, y puede compartir impresoras con otros equipos Linux y macOS (mediante el protocolo IPP) y con Windows.

```bash
lpstat -p -d                      # Impresoras disponibles y la predeterminada
lp -d Impresora-Aula informe.pdf  # Imprime un fichero
lpstat -o                         # Cola de trabajos
cancel 12                         # Cancela el trabajo número 12
```

## 7.5 Comparativa

| Tarea | Windows | Linux (Samba) |
| --- | --- | --- |
| Compartir una carpeta | *Uso compartido avanzado*, `net share`, `New-SmbShare` | Sección en `smb.conf` |
| Permisos del recurso | *Control total / Cambiar / Leer* | `valid users`, `read only`, `write list` |
| Permisos del sistema de archivos | NTFS | UGO + ACL |
| Usuarios | Cuentas locales o de dominio | Usuarios Linux dados de alta con `smbpasswd -a` |
| Ver conexiones | `fsmgmt.msc`, `Get-SmbSession` | `sudo smbstatus` |
| Conectar como cliente | `net use`, `New-SmbMapping` | `smbclient`, `mount -t cifs` |

### Ejercicio 7.2. Recurso compartido en Windows con PowerShell

En una máquina Windows, crea la carpeta `C:\Compartida\dam1`, compártela como `DAM1` de forma que solo el grupo `dam1` pueda acceder desde la red, con permiso para crear y modificar ficheros. Conéctate desde otra máquina como la unidad `Z:`.

{{% details "Ver solución" %}}
En el **servidor**, en PowerShell como administrador:

```powershell
$ruta = "C:\Compartida\dam1"
New-Item -ItemType Directory -Path $ruta -Force | Out-Null

# Permisos NTFS: herencia deshabilitada, se quita Usuarios y Usuarios autentificados y se da Modificar a dam1
icacls $ruta /inheritance:d
icacls $ruta /remove *S-1-5-11 *S-1-5-32-545
icacls $ruta /grant "dam1:(OI)(CI)M"

# Recurso compartido: dam1 con Cambiar
New-SmbShare -Name "DAM1" -Path $ruta -ChangeAccess "dam1"
Get-SmbShareAccess -Name "DAM1"
```

En el **cliente**:

```bat
net use Z: \\SERVIDOR\DAM1 /user:SERVIDOR\ana
echo prueba > Z:\prueba.txt
dir Z:\
```

Si no conecta, comprueba que el perfil de red del servidor es *Privada* y que se resuelve el nombre del servidor (prueba con la IP: `\\192.168.1.10\DAM1`).
{{% /details %}}

### Ejercicio 7.3. Servidor Samba para el aula

En el servidor Linux:

1. Crea el recurso `[apuntes]` en `/srv/apuntes`: todos los miembros de `dam1` y `profesores` pueden leer, pero solo los de `profesores` pueden escribir.
2. Da de alta en Samba a `ana` (dam1) y `marta` (profesores).
3. Comprueba desde un cliente que `ana` solo puede leer y `marta` puede escribir.

{{% details "Ver solución" %}}
```bash
# Directorio con permisos Linux coherentes
sudo mkdir -p /srv/apuntes
sudo chown root:profesores /srv/apuntes
sudo chmod 2775 /srv/apuntes                       # profesores escribe; el resto, solo lee
sudo setfacl -m g:dam1:rx /srv/apuntes             # Garantiza la lectura para dam1

# Recurso en smb.conf
sudo tee -a /etc/samba/smb.conf > /dev/null <<'EOF'

[apuntes]
   comment = Apuntes del módulo
   path = /srv/apuntes
   valid users = @dam1 @profesores
   read only = yes
   write list = @profesores
   create mask = 0664
   directory mask = 2775
EOF

testparm -s                                        # -s: no espera a que pulses Intro
sudo systemctl restart smbd

# Usuarios Samba
sudo smbpasswd -a ana
sudo smbpasswd -a marta
```

Comprobación desde un cliente Linux:

```bash
smbclient //IP-SERVIDOR/apuntes -U marta -c 'put /etc/hostname prueba.txt; ls'   # Funciona
smbclient //IP-SERVIDOR/apuntes -U ana   -c 'ls'                                  # Funciona
smbclient //IP-SERVIDOR/apuntes -U ana   -c 'put /etc/hostname otra.txt'          # NT_STATUS_ACCESS_DENIED
```

La opción `-c` ejecuta las órdenes indicadas (separadas por `;`) y cierra la sesión. `<<'EOF' … EOF` es un *here document*: envía las líneas siguientes como entrada de la orden hasta encontrar `EOF`.
