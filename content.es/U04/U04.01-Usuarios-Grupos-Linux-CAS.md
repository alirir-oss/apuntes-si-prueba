# 1. Usuarios y grupos en Linux

GNU/Linux es un sistema **multiusuario**: varias personas (y varios programas) pueden usar el mismo equipo a la vez, cada una con su propia **cuenta**. Las cuentas sirven para dos cosas:

- **Autenticación**: comprobar *quién* eres (normalmente, con un nombre de usuario y una contraseña o una clave SSH).
- **Autorización**: decidir *qué* puedes hacer. Cada fichero y cada proceso pertenecen a un usuario y a un grupo, y los permisos (apartado 5) se calculan a partir de ellos.

## 1.1 Conceptos básicos

| Concepto | Descripción |
| --- | --- |
| **Usuario** | Cuenta que identifica a una persona o a un servicio. Tiene un nombre (*login*) y un número. |
| **UID** (*User ID*) | Número que identifica internamente al usuario. El sistema trabaja con el UID, no con el nombre. |
| **Grupo** | Conjunto de usuarios al que se le pueden asignar permisos de forma conjunta. |
| **GID** (*Group ID*) | Número que identifica internamente al grupo. |
| **Grupo primario** | Grupo principal del usuario. Es el grupo que se asigna a los ficheros que crea. Cada usuario tiene exactamente uno. |
| **Grupos secundarios** | Otros grupos a los que pertenece el usuario y cuyos permisos también obtiene. Puede tener varios o ninguno. |

### Tipos de cuentas

| Tipo | UID habitual | Ejemplos | Características |
| --- | --- | --- | --- |
| **Superusuario** | `0` | `root` | Administrador del sistema. No tiene ninguna restricción de permisos. |
| **Usuarios del sistema** | `1`–`999` | `www-data`, `systemd-network`, `mysql` | Los usan los servicios para ejecutarse sin privilegios de root. Normalmente no pueden iniciar sesión. |
| **Usuarios normales** | `1000` en adelante | `alumno`, `ana` | Personas que usan el equipo. |
| **`nobody`** | `65534` | `nobody` | Usuario sin privilegios para procesos que no deben tener acceso a nada. |

Los límites entre usuarios del sistema y normales se definen en el fichero `/etc/login.defs` (variables `SYS_UID_MAX`, `UID_MIN` y `UID_MAX`).

> [!NOTE]
> En Ubuntu la cuenta `root` existe, pero **no tiene contraseña** y no se puede iniciar sesión con ella directamente. En su lugar, el primer usuario que se crea en la instalación pertenece al grupo `sudo` y puede ejecutar órdenes como root con `sudo` (apartado 1.6).

Para saber quién eres y a qué grupos perteneces:

```bash
whoami          # Nombre del usuario actual
id              # uid=1000(alumno) gid=1000(alumno) grupos=1000(alumno),4(adm),27(sudo)...
id ana          # Lo mismo, para otro usuario
groups          # Solo los nombres de mis grupos
```

## 1.2 Los ficheros de cuentas

La información de usuarios y grupos se guarda en **ficheros de texto** dentro de `/etc`. Cada línea es una cuenta y los campos se separan con `:`.

### `/etc/passwd`: los usuarios

Lo puede leer cualquier usuario (los programas lo necesitan, por ejemplo, para mostrar el propietario de un fichero con `ls -l`).

```text
ana:x:1001:1001:Ana López,,,:/home/ana:/bin/bash
```

| Campo | Ejemplo | Significado |
| --- | --- | --- |
| 1. Nombre | `ana` | Nombre de inicio de sesión. |
| 2. Contraseña | `x` | Una `x` indica que la contraseña está en `/etc/shadow`. |
| 3. UID | `1001` | Identificador del usuario. |
| 4. GID | `1001` | Identificador del **grupo primario**. |
| 5. GECOS | `Ana López,,,` | Comentario: nombre completo, despacho, teléfonos… |
| 6. Directorio personal | `/home/ana` | Directorio *home* del usuario (`~`). |
| 7. Shell | `/bin/bash` | Programa que se ejecuta al iniciar sesión. `/usr/sbin/nologin` o `/bin/false` impiden el acceso interactivo. |

### `/etc/shadow`: las contraseñas

Solo lo puede leer **root**, porque contiene el *hash* de las contraseñas. Un ***hash*** es el resultado de aplicar una función matemática de un solo sentido a la contraseña: a partir del *hash* no se puede obtener la contraseña, pero sí se puede comprobar si una contraseña introducida coincide.

```text
ana:$y$j9T$Kw3...$Zx8...:20400:0:99999:7:::
```

| Campo | Ejemplo | Significado |
| --- | --- | --- |
| 1. Nombre | `ana` | Usuario al que pertenece la línea. |
| 2. *Hash* | `$y$j9T$...` | Contraseña cifrada. `$y$` indica el algoritmo *yescrypt*. Si empieza por `!` la cuenta está **bloqueada**; `*` o `!` solos indican que no tiene contraseña válida. |
| 3. Último cambio | `20400` | Día del último cambio de contraseña, contado en días desde el 1/1/1970. |
| 4. Mínimo | `0` | Días que deben pasar antes de poder cambiarla otra vez. |
| 5. Máximo | `99999` | Días de validez de la contraseña (`99999` = no caduca en la práctica). |
| 6. Aviso | `7` | Días de antelación con los que se avisa de que va a caducar. |
| 7. Inactividad | (vacío) | Días tras la caducidad en los que todavía se puede cambiar antes de que se desactive la cuenta. |
| 8. Expiración | (vacío) | Fecha en la que se desactiva la cuenta. |
| 9. Reservado | (vacío) | Sin uso. |

Los campos 3 a 8 forman la **política de caducidad** de la cuenta, que se gestiona con `chage` (apartado 4).

### `/etc/group` y `/etc/gshadow`: los grupos

```text
dam1:x:1010:ana,luis
```

| Campo | Significado |
| --- | --- |
| 1. Nombre | Nombre del grupo. |
| 2. Contraseña | `x`: la contraseña del grupo (raramente usada) está en `/etc/gshadow`. |
| 3. GID | Identificador del grupo. |
| 4. Miembros | Usuarios que tienen este grupo como **secundario**, separados por comas. Los usuarios cuyo grupo **primario** es este no aparecen aquí. |

> [!CAUTION]
> **No edites estos ficheros a mano** con un editor normal: un error de formato puede impedir que nadie inicie sesión. Usa siempre las órdenes de este apartado o, si necesitas editarlos, `sudo vipw` (para `passwd`) y `sudo vigr` (para `group`), que bloquean el fichero y comprueban la sintaxis.

Para consultar las cuentas es preferible `getent`, que muestra también los usuarios que vienen de otras fuentes (por ejemplo, un servidor LDAP o un dominio):

```bash
getent passwd ana        # Línea de ana en la base de datos de usuarios
getent group sudo        # Miembros del grupo sudo
getent passwd | awk -F: '$3 >= 1000 && $3 < 65534 {print $1}'   # Solo usuarios normales
```

## 1.3 Crear usuarios

Hay dos órdenes para crear usuarios y conviene conocer las dos:

| Orden | Disponibilidad | Características |
| --- | --- | --- |
| `useradd` | Todas las distribuciones | Orden de **bajo nivel**. No pregunta nada: hace exactamente lo que le indican las opciones. Es la adecuada para **scripts**. |
| `adduser` | Debian, Ubuntu y derivadas | Script **interactivo** y amigable: crea el directorio personal, pide la contraseña y los datos personales. Lee su configuración de `/etc/adduser.conf`. |

### `useradd`

```text
useradd [opciones] usuario
```

| Opción | Significado |
| --- | --- |
| `-m` | Crea el directorio personal (copiando el contenido de `/etc/skel`, apartado 3). **Sin esta opción no se crea.** |
| `-d ruta` | Directorio personal distinto de `/home/usuario`. |
| `-s shell` | Shell de inicio de sesión (por defecto puede ser `/bin/sh`; conviene indicar `/bin/bash`). |
| `-c "texto"` | Comentario (normalmente el nombre completo). |
| `-g grupo` | Grupo **primario** (debe existir). Si no se indica, se crea un grupo con el mismo nombre que el usuario. |
| `-G g1,g2` | Grupos **secundarios**, separados por comas y sin espacios. |
| `-u UID` | Fuerza un UID concreto. |
| `-e AAAA-MM-DD` | Fecha de expiración de la cuenta. |
| `-r` | Crea un **usuario del sistema** (UID bajo, sin caducidad de contraseña). |

```bash
# Usuario normal, con directorio personal, Bash, nombre completo y en el grupo secundario dam1
sudo useradd -m -s /bin/bash -c "Ana López" -G dam1 ana
sudo passwd ana                  # Asigna la contraseña (useradd NO la pide)
getent passwd ana                # Comprobación
ls -la /home/ana                 # Ficheros copiados de /etc/skel
```

Los valores por defecto de `useradd` se consultan con `useradd -D` y se guardan en `/etc/default/useradd`.

### `adduser` (Debian/Ubuntu)

```bash
sudo adduser luis                # Pregunta contraseña, nombre completo, teléfonos…
sudo adduser luis dam1           # Con DOS argumentos: añade un usuario existente a un grupo
sudo adduser --system --group --no-create-home miapp   # Usuario de sistema para un servicio
```

> [!NOTE]
> Desde las versiones recientes de Debian y Ubuntu, `adduser` crea los directorios personales con permisos restrictivos (otros usuarios no pueden entrar en el *home* de los demás). Puedes comprobarlo con `ls -ld /home/*`.

### Usuarios para servicios

Cuando despliegues una aplicación en un servidor, **nunca la ejecutes como root**. Lo correcto es crear un usuario del sistema dedicado, sin contraseña y sin posibilidad de iniciar sesión:

```bash
# -r: usuario del sistema, -s nologin: no puede abrir una shell, -d: directorio de la aplicación
sudo useradd -r -s /usr/sbin/nologin -d /opt/miapp -c "Servicio miapp" miapp
sudo mkdir -p /opt/miapp && sudo chown miapp:miapp /opt/miapp
```

En el apartado 8 verás cómo hacer que systemd arranque la aplicación con este usuario.

## 1.4 Modificar y eliminar usuarios

### `usermod`

| Opción | Significado |
| --- | --- |
| `-aG g1,g2` | **Añade** grupos secundarios (`-a` = *append*). |
| `-G g1,g2` | **Sustituye** la lista de grupos secundarios por la indicada. |
| `-g grupo` | Cambia el grupo primario. |
| `-s shell` | Cambia la shell. |
| `-c "texto"` | Cambia el comentario. |
| `-d ruta -m` | Cambia el directorio personal y **mueve** su contenido (`-m`). |
| `-l nuevo` | Cambia el nombre de inicio de sesión. |
| `-L` / `-U` | Bloquea / desbloquea la contraseña (añade o quita `!` en `/etc/shadow`). |
| `-e AAAA-MM-DD` | Fecha de expiración (`-e ""` la elimina). |

```bash
sudo usermod -aG docker,dialout ana    # Añade ana a dos grupos más
sudo usermod -s /usr/sbin/nologin luis # luis ya no puede abrir una shell
sudo usermod -L luis                   # Bloquea su contraseña
sudo usermod -c "Luis Pérez" -e 2027-06-30 luis
```

> [!CAUTION]
> `usermod -G grupo usuario` **sin** `-a` elimina al usuario de todos sus otros grupos secundarios. Si haces esto con tu propio usuario y el grupo `sudo`, perderás los privilegios de administración. Usa siempre `-aG` para añadir.

> [!IMPORTANT]
> Los cambios de grupo **no se aplican a las sesiones ya abiertas**. El usuario debe cerrar la sesión y volver a entrar (o ejecutar `newgrp grupo` en esa terminal) para que `id` muestre el grupo nuevo.

### `userdel`

```bash
sudo userdel luis        # Borra la cuenta, pero conserva /home/luis y sus ficheros
sudo userdel -r luis     # Borra también el directorio personal y el buzón de correo
```

Los ficheros que el usuario tuviera fuera de su directorio personal quedan con su antiguo UID como propietario (en `ls -l` aparecerá un número en lugar de un nombre). Puedes localizarlos antes de borrar la cuenta:

```bash
sudo find / -xdev -user luis 2>/dev/null     # Ficheros de luis en el sistema de archivos raíz
```

> [!TIP]
> En un entorno profesional, antes de borrar una cuenta se suele **bloquear** (`usermod -L` y `usermod -e 1`) durante un tiempo y hacer una copia de su directorio. Así se puede recuperar si alguien necesita algún fichero.

### Contraseñas y datos personales

```bash
passwd                   # Cambia MI contraseña (pide la actual)
sudo passwd ana          # root cambia la contraseña de ana sin conocer la anterior
sudo passwd -S ana       # Estado: P (tiene contraseña), L (bloqueada), NP (sin contraseña)
sudo chfn ana            # Cambia el campo GECOS (nombre completo, teléfonos…)
chsh -s /bin/zsh         # Cambia MI shell (debe estar en /etc/shells)
```

## 1.5 Gestionar grupos

| Orden | Función |
| --- | --- |
| `groupadd grupo` | Crea un grupo (`-g GID` para fijar el número, `-r` para un grupo del sistema). |
| `groupmod -n nuevo viejo` | Cambia el nombre de un grupo. |
| `groupdel grupo` | Borra un grupo (no se puede si es el grupo primario de algún usuario). |
| `gpasswd -a usuario grupo` | Añade un usuario a un grupo. |
| `gpasswd -d usuario grupo` | Quita un usuario de un grupo. |
| `gpasswd -M u1,u2 grupo` | Define la lista completa de miembros. |
| `gpasswd -A usuario grupo` | Nombra administrador del grupo a un usuario (podrá añadir y quitar miembros sin ser root). |

```bash
sudo groupadd dam1
sudo groupadd profesores
sudo gpasswd -a ana dam1
sudo gpasswd -M ana,luis,marta dam1   # Miembros exactos del grupo
sudo gpasswd -d luis dam1
getent group dam1                     # dam1:x:1010:ana,marta
```

En Debian/Ubuntu también existen `addgroup`, `delgroup` y `deluser usuario grupo`, que hacen lo mismo de forma interactiva.

### Grupos especiales de Ubuntu/Debian

Pertenecer a algunos grupos del sistema concede capacidades concretas. Conviene conocerlos porque los usarás como desarrollador:

| Grupo | Qué permite |
| --- | --- |
| `sudo` (Debian/Ubuntu) / `wheel` (Fedora, RHEL) | Ejecutar órdenes como root con `sudo`. |
| `adm` | Leer los registros de `/var/log` (apartado 10). |
| `systemd-journal` | Leer todo el *journal* de systemd. |
| `docker` | Usar Docker sin `sudo`. **Equivale a tener privilegios de root.** |
| `dialout` | Acceder a los puertos serie (Arduino, microcontroladores). |
| `plugdev` | Acceder a algunos dispositivos USB extraíbles. |
| `kvm` | Usar la virtualización por hardware (necesario para el emulador de Android en Linux). |

## 1.6 Cambiar de usuario: `su` y `sudo`

| Orden | Qué hace | Contraseña que pide |
| --- | --- | --- |
| `su usuario` | Abre una shell como otro usuario, conservando parte del entorno actual. | La del **usuario de destino**. |
| `su - usuario` | Igual, pero con un **inicio de sesión completo** (carga su entorno y va a su *home*). | La del usuario de destino. |
| `sudo orden` | Ejecuta **una orden** como root (o como otro usuario con `-u`). | La **tuya**. |
| `sudo -i` | Abre una shell de root con inicio de sesión completo. | La tuya. |
| `sudo -u ana orden` | Ejecuta una orden como el usuario `ana`. | La tuya. |

`sudo` es preferible a `su` porque:

- No hace falta compartir la contraseña de root.
- Se puede limitar **qué** órdenes puede ejecutar cada usuario.
- Queda **registrado** quién ejecutó cada orden (en `/var/log/auth.log` o en el *journal*).

```bash
sudo -l                   # ¿Qué puedo ejecutar con sudo?
sudo -u www-data id       # Ejecuta 'id' como el usuario www-data
sudo -k                   # Olvida la contraseña guardada: la próxima vez la volverá a pedir
```

### El fichero `sudoers`

La configuración de `sudo` está en `/etc/sudoers` y en los ficheros del directorio `/etc/sudoers.d/`. Una regla tiene este formato:

```text
quién   equipos=(como_quién:grupo)   órdenes
%sudo   ALL=(ALL:ALL)                ALL
```

Esta línea, incluida por defecto en Ubuntu, significa: "los miembros del grupo `sudo` (el `%` indica grupo) pueden ejecutar, en cualquier equipo, como cualquier usuario y grupo, cualquier orden".

Para dar permisos concretos, crea un fichero nuevo en `/etc/sudoers.d/` **siempre con `visudo`**, que comprueba la sintaxis antes de guardar:

```bash
sudo visudo -f /etc/sudoers.d/desarrollo
```

```text
# /etc/sudoers.d/desarrollo
# Los miembros de 'desarrollo' pueden reiniciar el servicio de la aplicación sin ser administradores
%desarrollo ALL=(root) /usr/bin/systemctl restart miapp.service, /usr/bin/systemctl is-active miapp.service

# ana puede ejecutar apt sin que se le pida contraseña (úsalo con mucha prudencia)
ana ALL=(root) NOPASSWD: /usr/bin/apt
```

Dos reglas importantes al escribir órdenes en `sudoers`:

- Si una orden se escribe **sin argumentos** (por ejemplo, `/usr/bin/systemctl`), el usuario podrá ejecutarla con **cualquier** argumento. Escribe siempre la orden completa que quieres permitir.
- No permitas órdenes que abran un **paginador o un editor** (`systemctl status`, `journalctl`, `less`, `vi`…): desde ellos se puede ejecutar una shell (por ejemplo, escribiendo `!sh` en `less`) que tendría privilegios de root.

> [!CAUTION]
> Un error de sintaxis en `sudoers` puede dejarte **sin acceso a `sudo`**. Por eso se usa `visudo` y se trabaja en un fichero aparte de `/etc/sudoers.d/`. Si aun así ocurre, puedes arreglarlo desde una sesión de root que tengas abierta o arrancando en modo de recuperación.

> [!NOTE]
> Desde **Ubuntu 25.10**, y por tanto en **Ubuntu 26.04 LTS**, la orden `sudo` la proporciona **sudo-rs**, una reimplementación escrita en el lenguaje Rust, más segura frente a errores de memoria. Para el usuario funciona igual; las diferencias visibles son que muestra asteriscos al escribir la contraseña y que no admite comodines dentro de los argumentos de las órdenes en `sudoers` (por eso, en el ejemplo anterior, las órdenes se escriben completas). La versión clásica sigue disponible como `sudo.ws`. Lo puedes comprobar con `sudo --version`.

## 1.7 ¿Quién está conectado?

```bash
who            # Usuarios con sesión abierta
w              # Lo mismo, con lo que está ejecutando cada uno y la carga del sistema
last           # Historial de inicios de sesión (lee /var/log/wtmp)
last -n 5 ana  # Los 5 últimos accesos de ana
sudo lastb     # Intentos de inicio de sesión FALLIDOS (lee /var/log/btmp)
```

## Ejercicios resueltos

### Ejercicio 1.1. Interpretar `/etc/passwd`

Dada la línea `www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin`, responde: ¿es un usuario normal o del sistema? ¿Cuál es su grupo primario? ¿Puede iniciar sesión?

{{% details "Ver solución" %}}
- UID `33` (menor que 1000): es un **usuario del sistema**. Lo utiliza el servidor web (Apache o Nginx).
- Su grupo primario tiene GID `33`; con `getent group 33` se comprueba que es el grupo `www-data`.
- Su shell es `/usr/sbin/nologin`, así que **no puede abrir una sesión interactiva**: si alguien lo intenta, recibe el mensaje *This account is currently not available*.
{{% /details %}}

### Ejercicio 1.2. Alta de un equipo de trabajo

Crea los grupos `dam1` y `profesores`. Después crea los usuarios `ana` y `luis` (grupo secundario `dam1`) y `marta` (grupo secundario `profesores`), todos con directorio personal, Bash y su nombre completo. Asigna contraseña a los tres y comprueba el resultado.

{{% details "Ver solución" %}}
```bash
sudo groupadd dam1
sudo groupadd profesores

sudo useradd -m -s /bin/bash -c "Ana López"   -G dam1       ana
sudo useradd -m -s /bin/bash -c "Luis Pérez"  -G dam1       luis
sudo useradd -m -s /bin/bash -c "Marta Ruiz"  -G profesores marta

# Asignar contraseñas sin interacción: chpasswd lee líneas "usuario:contraseña"
printf '%s\n' 'ana:Cambiar.2026' 'luis:Cambiar.2026' 'marta:Cambiar.2026' | sudo chpasswd

# Obligar a cambiarla en el primer inicio de sesión (caduca la contraseña)
sudo passwd -e ana; sudo passwd -e luis; sudo passwd -e marta

# Comprobaciones
id ana; id luis; id marta
getent group dam1 profesores
```

`chpasswd` es útil en scripts porque permite asignar muchas contraseñas a la vez. `passwd -e` marca la contraseña como caducada para que el usuario tenga que elegir una nueva al entrar.
{{% /details %}}

### Ejercicio 1.3. Error clásico con `usermod`

`ana` pertenece a `dam1` y a `sudo`. Un compañero ejecuta `sudo usermod -G docker ana`. ¿Qué ha ocurrido? ¿Cómo se arregla?

{{% details "Ver solución" %}}
Al usar `-G` sin `-a`, la lista de grupos secundarios de `ana` se ha **sustituido** por `docker`: ya no pertenece a `dam1` ni a `sudo`. Se arregla (desde otra cuenta con privilegios) añadiendo de nuevo los grupos:

```bash
sudo usermod -aG dam1,sudo ana
id ana
```

La forma correcta de la orden original era `sudo usermod -aG docker ana`.
{{% /details %}}

### Ejercicio 1.4. Permiso limitado con `sudo`

Crea el grupo `soporte` y añade a `luis`. Configura `sudo` para que los miembros de `soporte` puedan **solo** reiniciar el servicio de impresión `cups` y comprobar si está activo. Comprueba con `sudo -l` qué puede hacer `luis`.

{{% details "Ver solución" %}}
```bash
sudo groupadd soporte
sudo gpasswd -a luis soporte
sudo visudo -f /etc/sudoers.d/soporte
```

Contenido del fichero:

```text
%soporte ALL=(root) /usr/bin/systemctl restart cups.service, /usr/bin/systemctl is-active cups.service
```

Comprobación (desde una sesión de `luis`):

```bash
su - luis
sudo -l                                   # Muestra las dos órdenes permitidas
sudo systemctl restart cups.service       # Permitido
sudo systemctl is-active cups.service     # Permitido: responde "active"
sudo systemctl stop cups.service          # Denegado: los argumentos no coinciden con la regla
sudo apt update                           # Denegado: "luis is not allowed to run sudo..."
```

No se ha permitido `systemctl status` porque muestra la salida en un paginador (`less`) desde el que `luis` podría abrir una shell de root. Para consultar el estado detallado no necesita `sudo`: `systemctl status cups.service` funciona con un usuario normal.
{{% /details %}}

### Ejercicio 1.5. Baja segura de un usuario

`luis` deja el centro. Antes de eliminar su cuenta, haz una copia comprimida de su directorio personal en `/root/bajas/`, localiza los ficheros que tenga fuera de `/home/luis` y, por último, elimina la cuenta y su directorio.

{{% details "Ver solución" %}}
```bash
sudo usermod -L -e 1 luis                          # 1.º Bloquear la cuenta (contraseña y expiración)
sudo mkdir -p /root/bajas
sudo tar -czf /root/bajas/luis-$(date +%F).tar.gz -C /home luis   # 2.º Copia de seguridad
sudo find / -xdev -user luis -not -path '/home/luis/*' 2>/dev/null # 3.º Ficheros fuera de su home
sudo pkill -u luis                                 # 4.º Termina sus procesos, si los hay
sudo userdel -r luis                               # 5.º Elimina la cuenta y su directorio
```

`usermod -e 1` fija la fecha de expiración al 2 de enero de 1970, es decir, la cuenta queda caducada inmediatamente.
{{% /details %}}
