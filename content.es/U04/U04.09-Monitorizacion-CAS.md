# 9. Monitorización de recursos

**Monitorizar** un sistema es observar de forma continuada cómo usa sus recursos para detectar problemas **antes** de que afecten a los usuarios: un disco que se llena, un proceso que consume cada vez más memoria o un servidor que no da abasto con las peticiones. Como desarrolladores, también os servirá para saber si vuestra aplicación es eficiente o si tiene, por ejemplo, una **fuga de memoria** (*memory leak*): memoria que se reserva y nunca se libera.

## 9.1 Qué hay que vigilar

| Recurso | Indicadores | Señales de alarma |
| --- | --- | --- |
| **CPU** | % de uso, carga media, procesos que más consumen | Uso cercano al 100 % de forma sostenida. |
| **Memoria** | Memoria usada, disponible, *swap* | Poca memoria disponible y uso continuo de *swap*. |
| **Disco: espacio** | % ocupado por sistema de archivos | Más del 85–90 % ocupado. |
| **Disco: actividad** | Lecturas/escrituras por segundo, tiempo de respuesta | Disco al 100 % de actividad, procesos esperando E/S. |
| **Red** | Tráfico enviado/recibido, conexiones abiertas, puertos en escucha | Tráfico inesperado, puertos abiertos que no deberían estarlo. |

> [!NOTE]
> La **memoria de intercambio** (*swap* en Linux, *archivo de paginación* en Windows) es espacio en el disco que el sistema usa como ampliación de la RAM cuando esta se agota. Como el disco es mucho más lento que la RAM, si el sistema usa mucho la *swap* de forma continua, el rendimiento cae drásticamente.

## 9.2 Linux: visión general

### Carga del sistema: `uptime`

```bash
uptime
#  11:42:07 up 2:30,  2 users,  load average: 0,52, 0,78, 1,10
nproc        # Número de núcleos (CPU lógicas): 4
```

La **carga media** (*load average*) es el número medio de procesos que están ejecutándose o esperando para ejecutarse, en el último **1**, **5** y **15** minutos. Se interpreta en relación con el número de núcleos:

- Carga **menor** que el número de núcleos: el sistema tiene capacidad libre.
- Carga **igual**: está aprovechando la CPU al máximo.
- Carga **mayor**: hay procesos esperando turno.

En el ejemplo, con 4 núcleos y una carga de 0,52, el sistema está muy desocupado. Comparar los tres valores indica la tendencia: aquí la carga está **bajando** (1,10 hace 15 minutos, 0,52 ahora).

### `top`: monitor en tiempo real

`top` muestra un resumen del sistema y la lista de procesos, actualizada cada 3 segundos.

```text
top - 11:42:07 up  2:30,  2 users,  load average: 0,52, 0,78, 1,10
Tareas: 231 total,   1 ejecutar, 230 hibernar,   0 detener,   0 zombie
%Cpu(s):  3,1 us,  1,0 sy,  0,0 ni, 95,5 id,  0,3 wa,  0,0 hi,  0,1 si,  0,0 st
MiB Mem :   7940,2 total,   3120,4 libre,   2310,8 usado,   2509,0 búfer/caché
MiB Intercambio:   2048,0 total,   2048,0 libre,      0,0 usado.   5310,5 dispon Mem

    PID USUARIO   PR  NI    VIRT    RES    SHR S  %CPU  %MEM     HORA+ ORDEN
   1520 ana       20   0 3254012 312400 118000 S   2,3   3,8   1:02.31 code
```

| Campo de `%Cpu(s)` | Significado |
| --- | --- |
| `us` | Tiempo en procesos de usuario (programas normales). |
| `sy` | Tiempo en el núcleo (*system*). |
| `ni` | Procesos con prioridad modificada (*nice*). |
| `id` | CPU libre (*idle*). |
| `wa` | Esperando operaciones de E/S. Un valor alto indica un **disco lento o saturado**. |
| `st` | Tiempo "robado" por el hipervisor (solo en máquinas virtuales). |

| Tecla en `top` | Acción |
| --- | --- |
| `P` / `M` | Ordenar por CPU / por memoria. |
| `1` | Mostrar cada núcleo por separado. |
| `u` | Filtrar por usuario. |
| `k` | Enviar una señal a un proceso (pide el PID). |
| `r` | Cambiar el valor *nice* de un proceso. |
| `h` | Ayuda. |
| `q` | Salir. |

```bash
top -u ana          # Solo los procesos de ana
top -b -n 1 | head  # Modo no interactivo (batch): una sola vez, útil en scripts
```

### `htop` y `btop`

`htop` es una versión mejorada de `top`, con colores, barras de uso por núcleo, desplazamiento con el ratón, vista en árbol (`F5`), búsqueda (`F3`) y menú de acciones en la parte inferior. `btop` es otra alternativa más visual que incluye también gráficas de disco y red.

```bash
sudo apt install htop btop
htop
```

## 9.3 Linux: memoria, disco y red

### Memoria: `free`

```bash
free -h
#                total     usado     libre  compartido  búf/caché  disponible
# Mem:           7,8Gi     2,3Gi     3,0Gi       210Mi      2,5Gi       5,2Gi
# Inter.:        2,0Gi        0B     2,0Gi
```

> [!IMPORTANT]
> No te fijes en la columna **libre**, sino en **disponible**. Linux aprovecha la memoria que no usan los programas como **caché del disco** (`búf/caché`) para acelerar el sistema, y la libera en cuanto un programa la necesita. Que haya poca memoria "libre" es normal y deseable; lo preocupante es que haya poca **disponible**.

### Visión global: `vmstat`

```bash
vmstat 2 5          # Una línea cada 2 segundos, 5 veces
# procs -----------memoria---------- --swap-- ---io--- -sistema-- ------cpu-----
#  r  b   swpd   libre   búfer  caché  si  so  bi  bo   in   cs us sy id wa st
#  1  0      0 3120400  98000 2410000   0   0  12  40  310  620  3  1 96  0  0
```

Las columnas `si` y `so` indican memoria que entra y sale de la *swap*: si son distintas de 0 de forma continua, falta RAM. La columna `wa` indica espera de disco, como en `top`.

### Espacio en disco: `df` y `du`

```bash
df -h                       # Espacio de cada sistema de archivos montado
df -h /                     # Solo el de la raíz
df -i                       # Uso de inodos: un disco puede "llenarse" por número de ficheros
du -sh ~/Descargas          # Tamaño total de un directorio
du -h --max-depth=1 /var 2>/dev/null | sort -h    # Qué subdirectorios de /var ocupan más
```

Para analizar el espacio de forma interactiva, `ncdu` (apartado 11) permite navegar por los directorios ordenados por tamaño.

### Actividad del disco: `iostat`

```bash
sudo apt install sysstat
iostat -xz 2 3              # Estadísticas extendidas de cada disco, cada 2 s, 3 veces
```

La columna **`%util`** indica el porcentaje de tiempo que el disco ha estado ocupado. Valores cercanos al 100 % de forma sostenida indican que el disco es el cuello de botella.

### Red: `ss` e `ip`

```bash
ss -tulpn                   # Puertos TCP (t) y UDP (u) en escucha (l), con el proceso (p) y en número (n)
ss -tn state established    # Conexiones TCP establecidas
ip -s link                  # Estadísticas de tráfico de cada interfaz
```

Revisar con `ss -tulpn` qué puertos tiene abiertos un servidor es una tarea básica de seguridad: cada puerto en escucha es una posible vía de entrada. En la Unidad 5 se estudian los puertos en detalle.

### Información del hardware

```bash
lscpu                       # Procesador: modelo, núcleos, hilos, virtualización
lsblk                       # Discos y particiones
cat /proc/meminfo | head    # Detalle de la memoria
sudo dmidecode -t memory    # Módulos de RAM instalados
```

### La herramienta gráfica

En el escritorio GNOME, la aplicación **Monitor del sistema** (*gnome-system-monitor*) muestra los procesos, las gráficas de uso de CPU, memoria y red, y el espacio de los sistemas de archivos.

## 9.4 Windows: herramientas gráficas

### Administrador de tareas: pestaña Rendimiento

Muestra gráficas en tiempo real de la **CPU** (con su velocidad, número de núcleos, procesos e hilos, tiempo activo y si la **virtualización** está habilitada), la **memoria** (en uso, disponible, comprometida, velocidad y ranuras usadas), cada **disco** (tiempo activo y velocidad), la **red** y la **GPU**.

### Monitor de recursos: `resmon`

El **Monitor de recursos** (`resmon.exe`, o desde el enlace al pie de la pestaña *Rendimiento*) ofrece mucho más detalle que el Administrador de tareas:

| Pestaña | Información útil |
| --- | --- |
| **CPU** | Uso por proceso y por servicio. En **Identificadores asociados** puedes buscar qué proceso tiene abierto un fichero (muy útil cuando Windows dice que "el archivo está en uso"). |
| **Memoria** | Uso por proceso y un gráfico de cómo se reparte la memoria física. |
| **Disco** | Qué ficheros está leyendo o escribiendo cada proceso y el tiempo de respuesta. |
| **Red** | Conexiones TCP de cada proceso y **puertos de escucha** con su proceso. |

### Monitor de rendimiento: `perfmon`

El **Monitor de rendimiento** (`perfmon.msc`) es la herramienta profesional de Windows. Trabaja con **contadores de rendimiento**: medidas de cientos de aspectos del sistema (`% de tiempo de procesador`, `Bytes disponibles` de memoria, `Longitud media de la cola de disco`…).

{{% steps %}}
1. ## Ver contadores en tiempo real

   En **Herramientas de supervisión > Monitor de rendimiento**, pulsa el botón **+** (Agregar). Elige un objeto (por ejemplo, *Memoria*), un contador (*MBytes disponibles*) y pulsa **Agregar** y **Aceptar**.

2. ## Registrar datos durante un tiempo

   En **Conjuntos de recopiladores de datos > Definidos por el usuario**, crea un conjunto nuevo con los contadores que te interesen y un intervalo de muestreo. Al iniciarlo, guarda los datos en un fichero que podrás analizar después. Es la forma de estudiar un problema que solo ocurre a determinadas horas.

3. ## Generar un informe del sistema

   Ejecuta `perfmon /report` en una consola de administrador. Durante 60 segundos recopila datos y genera un **diagnóstico del sistema** con advertencias sobre problemas de hardware, configuración y rendimiento.
{{% /steps %}}

### Monitor de confiabilidad

`perfmon /rel` abre el **Monitor de confiabilidad**: un historial diario con un índice de estabilidad de 1 a 10 y la lista de errores de aplicaciones, errores de Windows, actualizaciones e instalaciones. Es muy útil para responder a la pregunta "¿desde cuándo falla esto y qué cambió ese día?".

## 9.5 Windows: línea de comandos

```bat
:: CMD
systeminfo                         :: Resumen: versión, memoria total y disponible, actualizaciones
tasklist /fi "memusage gt 200000"  :: Procesos que usan más de 200 000 KB
netstat -ano                       :: Conexiones y puertos con el PID del proceso
```

```powershell
# Memoria total y libre (los valores de Win32_OperatingSystem están en KB)
$so = Get-CimInstance Win32_OperatingSystem
"{0:N1} GB libres de {1:N1} GB" -f ($so.FreePhysicalMemory / 1MB), ($so.TotalVisibleMemorySize / 1MB)

# Carga de la CPU (media de todos los núcleos)
(Get-CimInstance Win32_Processor | Measure-Object -Property LoadPercentage -Average).Average

# Espacio libre de cada volumen
Get-Volume | Where-Object DriveLetter |
    Select-Object DriveLetter, FileSystemLabel,
        @{n='TamañoGB'; e={[math]::Round($_.Size / 1GB, 1)}},
        @{n='LibreGB';  e={[math]::Round($_.SizeRemaining / 1GB, 1)}}

# Puertos TCP en escucha y el proceso que los usa
Get-NetTCPConnection -State Listen |
    Select-Object LocalAddress, LocalPort, OwningProcess,
        @{n='Proceso'; e={(Get-Process -Id $_.OwningProcess).ProcessName}} |
    Sort-Object LocalPort
```

### Contadores de rendimiento con `Get-Counter`

```powershell
Get-Counter -ListSet * | Select-Object CounterSetName     # Conjuntos de contadores disponibles
Get-Counter '\Procesador(_Total)\% de tiempo de procesador' -SampleInterval 2 -MaxSamples 5
```

> [!WARNING]
> Los nombres de los contadores **están traducidos al idioma de Windows**: en un sistema en español el contador se llama `\Procesador(_Total)\% de tiempo de procesador` y en uno en inglés, `\Processor(_Total)\% Processor Time`. Un script con los nombres en un idioma falla en un equipo con otro idioma. Para scripts portables, es preferible usar las clases CIM, como en los ejemplos anteriores, cuyos nombres no se traducen.

## 9.6 Comparativa

| Necesidad | Linux | Windows |
| --- | --- | --- |
| Monitor en tiempo real | `top`, `htop`, `btop` | Administrador de tareas, `resmon` |
| Carga de la CPU | `uptime`, `top` | Administrador de tareas, `Win32_Processor` |
| Memoria | `free -h`, `vmstat` | Pestaña *Rendimiento*, `Win32_OperatingSystem` |
| Espacio en disco | `df -h`, `du -sh` | Explorador, `Get-Volume` |
| Actividad del disco | `iostat -x` | `resmon` (pestaña *Disco*) |
| Puertos en escucha | `ss -tulpn` | `Get-NetTCPConnection -State Listen`, `netstat -ano` |
| Registro histórico de rendimiento | `sar` (paquete `sysstat`) | `perfmon` (recopiladores de datos) |
| Diagnóstico general | `journalctl`, `dmesg` | `perfmon /report`, `perfmon /rel` |

## Ejercicios resueltos

### Ejercicio 9.1. Interpretar la carga

Un servidor con 2 núcleos muestra `load average: 3,90, 3,10, 1,20`. ¿Qué está ocurriendo?

{{% details "Ver solución" %}}
Con 2 núcleos, una carga de 3,90 significa que de media hay casi 4 procesos queriendo usar la CPU cuando solo pueden ejecutarse 2 a la vez: hay procesos **esperando** y el sistema está **sobrecargado**. Además, la tendencia es **creciente**: hace 15 minutos la carga era 1,20, hace 5 minutos 3,10 y ahora 3,90. Habría que buscar con `top` (ordenando por CPU con `P`) qué proceso ha empezado a consumir recursos, y comprobar con la columna `wa` si el problema es la CPU o la espera de disco.
{{% /details %}}

### Ejercicio 9.2. Provocar y observar carga

En una máquina virtual Linux, abre `htop` en una terminal. En otra terminal genera carga en la CPU y en la memoria y observa los cambios. Termina después los procesos generados.

{{% details "Ver solución" %}}
```bash
# Terminal 1
htop

# Terminal 2: un bucle infinito por cada núcleo (consume CPU)
for i in $(seq "$(nproc)"); do (while :; do :; done) & done

# Terminal 2: reservar unos 500 MB de memoria durante 60 segundos con Python
python3 -c "import time; datos = bytearray(500 * 1024 * 1024); time.sleep(60)" &

# Para terminar los bucles de la terminal 2:
kill $(jobs -p)
```

En `htop` verás todas las barras de los núcleos al 100 %, la carga media subiendo poco a poco y la barra de memoria creciendo unos 500 MB. `jobs -p` muestra los PID de los trabajos en segundo plano de la terminal actual, así que `kill $(jobs -p)` los termina todos.
{{% /details %}}

### Ejercicio 9.3. ¿Quién usa este puerto?

Al arrancar tu aplicación aparece el error *Address already in use* en el puerto 8080. Averigua qué proceso lo está usando en Linux y en Windows.

{{% details "Ver solución" %}}
Linux:

```bash
sudo ss -tlpn 'sport = :8080'
# LISTEN 0 5 0.0.0.0:8080 0.0.0.0:* users:(("python3",pid=6120,fd=3))
ps -o pid,user,cmd -p 6120
```

Windows (PowerShell):

```powershell
$con = Get-NetTCPConnection -LocalPort 8080 -State Listen
Get-Process -Id $con.OwningProcess | Select-Object Id, ProcessName, Path
```

O, en CMD: `netstat -ano | findstr :8080` y después `tasklist /fi "pid eq 6120"`.
{{% /details %}}

### Ejercicio 9.4. Informe de estado

Escribe un script de PowerShell `estado.ps1` que muestre: el nombre del equipo, el tiempo que lleva encendido, el % de uso de la CPU, la memoria libre y el espacio libre de la unidad `C:`, y que avise si la memoria libre baja del 15 % o el disco del 10 %.

{{% details "Ver solución" %}}
```powershell
# estado.ps1 - Resumen del estado del sistema
$so    = Get-CimInstance Win32_OperatingSystem
$cpu   = (Get-CimInstance Win32_Processor | Measure-Object LoadPercentage -Average).Average
$disco = Get-Volume -DriveLetter C

$memLibrePct   = [math]::Round($so.FreePhysicalMemory / $so.TotalVisibleMemorySize * 100)
$discoLibrePct = [math]::Round($disco.SizeRemaining / $disco.Size * 100)
$encendido     = (Get-Date) - $so.LastBootUpTime        # Restar fechas da un TimeSpan

Write-Output "Equipo:       $env:COMPUTERNAME"
Write-Output ("Encendido:    {0} días, {1} h, {2} min" -f $encendido.Days, $encendido.Hours, $encendido.Minutes)
Write-Output "CPU:          $cpu %"
Write-Output "Memoria libre: $memLibrePct %"
Write-Output "Disco C libre: $discoLibrePct %"

if ($memLibrePct -lt 15)   { Write-Warning "Queda poca memoria libre" }
if ($discoLibrePct -lt 10) { Write-Warning "Queda poco espacio en C:" }
```

`LastBootUpTime` es la fecha del último arranque; al restarla de la fecha actual se obtiene un objeto `TimeSpan` con propiedades como `Days`, `Hours` y `Minutes`.
{{% /details %}}
