# 4. Directivas de cuenta y de contraseñas

Crear cuentas no basta: hay que **asegurar el acceso** al sistema. Si las contraseñas son cortas, nunca se revisan o se pueden probar sin límite, un atacante acabará adivinándolas. Las **directivas** (o políticas) **de cuenta** son las reglas que el sistema impone a todas las cuentas para evitarlo.

## 4.1 Qué se puede controlar

| Directiva | Qué controla | Ataque que dificulta |
| --- | --- | --- |
| **Longitud mínima** | Número mínimo de caracteres. | Fuerza bruta: probar todas las combinaciones posibles. |
| **Complejidad** | Obligar a mezclar tipos de caracteres (mayúsculas, minúsculas, dígitos, símbolos). | Ataques de diccionario. |
| **Historial** | Impedir reutilizar las últimas *N* contraseñas. | Volver siempre a la misma contraseña. |
| **Vigencia máxima** (caducidad) | Días que dura una contraseña antes de tener que cambiarla. | Uso prolongado de una contraseña robada. |
| **Vigencia mínima** | Días que deben pasar antes de poder cambiarla otra vez. | Saltarse el historial cambiándola varias veces seguidas. |
| **Umbral de bloqueo** | Intentos fallidos permitidos antes de bloquear la cuenta. | Fuerza bruta en línea (probar contraseñas contra el sistema). |
| **Duración del bloqueo** | Tiempo que la cuenta permanece bloqueada. | Ídem. |
| **Expiración de la cuenta** | Fecha a partir de la cual la cuenta deja de funcionar. | Cuentas olvidadas de personas que ya no están en la organización. |

> [!NOTE]
> Las recomendaciones actuales de seguridad, como las directrices del NIST estadounidense (publicación SP 800-63B), han cambiado algunas prácticas tradicionales: dan más importancia a la **longitud** que a la complejidad (una frase larga es mejor que una palabra corta con símbolos), desaconsejan **obligar a cambiar la contraseña periódicamente** si no hay indicios de que se haya visto comprometida, y recomiendan comprobar las contraseñas nuevas contra **listas de contraseñas filtradas** y usar la **autenticación multifactor**. En esta unidad aprenderás a configurar todas las directivas, pero al elegir sus valores ten en cuenta este criterio.

## 4.2 Linux: caducidad de contraseñas

### Valores por defecto: `/etc/login.defs`

Este fichero define los valores que se aplican a las **cuentas que se creen a partir de ahora**:

```text
# Vigencia máxima (99999 = sin caducidad en la práctica)
PASS_MAX_DAYS   99999
# Vigencia mínima
PASS_MIN_DAYS   0
# Días de aviso antes de caducar
PASS_WARN_AGE   7
# Máscara de permisos por defecto (apartado 5)
UMASK           022
```

> [!IMPORTANT]
> Modificar `/etc/login.defs` **no cambia las cuentas que ya existen**. Para ellas se usa `chage`.

### `chage`: caducidad de una cuenta

`chage` (*change age*) modifica los campos de caducidad de `/etc/shadow` (apartado 1.2).

| Opción | Significado |
| --- | --- |
| `-l usuario` | Muestra la política de caducidad de la cuenta. |
| `-M días` | Vigencia máxima de la contraseña. |
| `-m días` | Vigencia mínima. |
| `-W días` | Días de aviso previo. |
| `-I días` | Días de inactividad tras caducar la contraseña antes de desactivar la cuenta. |
| `-E AAAA-MM-DD` | Fecha de expiración de la cuenta (`-E -1` la elimina). |
| `-d 0` | Pone a 0 la fecha del último cambio: **obliga a cambiar la contraseña** en el próximo inicio de sesión. |

```bash
sudo chage -l ana
# Last password change                         : nov 08, 2026
# Password expires                             : never
# ...

sudo chage -M 180 -m 1 -W 14 ana     # Caduca a los 180 días, aviso 14 días antes
sudo chage -E 2027-06-30 ana         # La cuenta deja de funcionar al terminar el curso
sudo chage -d 0 ana                  # Debe cambiar la contraseña al entrar
```

Sin opciones, `sudo chage ana` pregunta los valores uno por uno de forma interactiva.

### Bloquear y desbloquear cuentas manualmente

```bash
sudo passwd -l ana       # Bloquea la contraseña (añade '!' al hash en /etc/shadow)
sudo passwd -u ana       # La desbloquea
sudo passwd -S ana       # Estado: ana L ... (L = bloqueada, P = contraseña válida)
```

> [!WARNING]
> `passwd -l` solo impide autenticarse **con contraseña**. Si el usuario tiene una clave SSH configurada, podrá seguir entrando por SSH. Para deshabilitar la cuenta por completo, caduca también la cuenta (`sudo chage -E 0 ana` o `sudo usermod -e 1 ana`).

## 4.3 Linux: PAM

En Linux, la autenticación no la hace cada programa por su cuenta: `login`, `sudo`, `su`, el gestor gráfico de inicio de sesión o el servidor SSH delegan en **PAM** (*Pluggable Authentication Modules*, módulos de autenticación conectables).

PAM es un sistema de **módulos** que se encadenan. Cada programa tiene su fichero de configuración en `/etc/pam.d/`, y en Debian/Ubuntu todos incluyen unos ficheros comunes:

| Fichero | Para qué |
| --- | --- |
| `/etc/pam.d/common-auth` | Comprobar la identidad (pedir y verificar la contraseña). |
| `/etc/pam.d/common-account` | Comprobar si la cuenta puede usarse (caducada, bloqueada…). |
| `/etc/pam.d/common-password` | Reglas para **cambiar** la contraseña. |
| `/etc/pam.d/common-session` | Acciones al abrir y cerrar sesión. |

Gracias a PAM, añadiendo un módulo se puede, por ejemplo, exigir contraseñas robustas o bloquear cuentas tras varios fallos, y el cambio se aplica a todos los programas a la vez.

> [!CAUTION]
> Un error en los ficheros de `/etc/pam.d/` puede impedir que **nadie** inicie sesión, ni siquiera root mediante `sudo`. Antes de modificarlos: trabaja en una máquina virtual con una **instantánea**, abre una **segunda terminal con `sudo -i`** y no la cierres hasta comprobar en otra terminal que puedes iniciar sesión.

### Calidad de las contraseñas: `pam_pwquality`

El módulo `pam_pwquality` comprueba la contraseña nueva cuando el usuario la cambia con `passwd`.

```bash
sudo apt install libpam-pwquality    # Instala el módulo y lo añade a common-password
grep pwquality /etc/pam.d/common-password
# password  requisite  pam_pwquality.so retry=3
```

Las reglas se configuran en `/etc/security/pwquality.conf` (descomenta y ajusta las líneas que necesites):

```ini
# /etc/security/pwquality.conf
# Longitud mínima
minlen = 12
# Tipos de caracteres distintos (minúsculas, mayúsculas, dígitos, otros)
minclass = 3
# Máximo de caracteres iguales seguidos
maxrepeat = 3
# Rechaza palabras de diccionario
dictcheck = 1
# Rechaza contraseñas que contengan el nombre del usuario
usercheck = 1
# Caracteres que deben cambiar respecto a la contraseña anterior
difok = 5
# Aplica las reglas también cuando root cambia contraseñas
enforce_for_root
```

```bash
passwd               # Prueba: una contraseña corta mostrará "BAD PASSWORD: The password is shorter than 12 characters"
```

Para el **historial** de contraseñas se usa el módulo `pam_pwhistory`, añadiendo en `/etc/pam.d/common-password`, justo antes de la línea de `pam_unix.so`:

```text
password  required  pam_pwhistory.so remember=5 use_authtok
```

### Bloqueo tras intentos fallidos: `pam_faillock`

El módulo `pam_faillock` cuenta los intentos fallidos y bloquea la cuenta temporalmente. Se configura en `/etc/security/faillock.conf`:

```ini
# /etc/security/faillock.conf
# Bloquear tras 5 fallos…
deny = 5
# …producidos en 15 minutos (900 s)
fail_interval = 900
# Desbloquear automáticamente a los 10 minutos
unlock_time = 600
```

En Ubuntu el módulo viene instalado pero **no activado**. Para activarlo hay que modificar `/etc/pam.d/common-auth` para que quede así (las líneas de `pam_faillock` rodean a la de `pam_unix`):

```text
auth    requisite                       pam_faillock.so preauth
auth    [success=1 default=ignore]      pam_unix.so nullok
auth    [default=die]                   pam_faillock.so authfail
auth    sufficient                      pam_faillock.so authsucc
auth    requisite                       pam_deny.so
auth    required                        pam_permit.so
```

Y añadir al final de `/etc/pam.d/common-account`:

```text
account required                        pam_faillock.so
```

Gestión de los bloqueos:

```bash
sudo faillock --user ana            # Muestra los intentos fallidos de ana
sudo faillock --user ana --reset    # Desbloquea la cuenta inmediatamente
```

> [!NOTE]
> El contenido exacto de `common-auth` puede variar según la versión y los paquetes instalados (por ejemplo, si el equipo usa huella dactilar o un dominio). Compara siempre con tu fichero antes de modificarlo y guarda una copia: `sudo cp /etc/pam.d/common-auth /root/common-auth.bak`.

## 4.4 Windows: directiva de seguridad local

En Windows, las directivas de cuenta se configuran en la **Directiva de seguridad local** (`secpol.msc`, no disponible en Windows Home), dentro de **Configuración de seguridad > Directivas de cuenta**.

### Directiva de contraseñas

| Directiva | Valores | Comentario |
| --- | --- | --- |
| **Exigir historial de contraseñas** | 0–24 contraseñas recordadas | |
| **Vigencia máxima de la contraseña** | 0–999 días (0 = no caduca) | Por defecto, 42 días. |
| **Vigencia mínima de la contraseña** | 0–998 días | |
| **Longitud mínima de la contraseña** | 0–14 caracteres | |
| **La contraseña debe cumplir los requisitos de complejidad** | Habilitada / Deshabilitada | Exige al menos 6 caracteres de 3 de estas 4 categorías: mayúsculas, minúsculas, dígitos y símbolos, y que no contenga el nombre de la cuenta. |
| **Almacenar contraseñas con cifrado reversible** | Habilitada / Deshabilitada | **Debe estar siempre deshabilitada**: equivale a guardar las contraseñas casi en texto plano. |

### Directiva de bloqueo de cuenta

| Directiva | Significado |
| --- | --- |
| **Umbral de bloqueo de cuenta** | Intentos fallidos que provocan el bloqueo (0 = nunca se bloquea). |
| **Duración del bloqueo de cuenta** | Minutos que permanece bloqueada (0 = hasta que un administrador la desbloquee). |
| **Restablecer el contador de bloqueos de cuenta tras** | Minutos tras los cuales el contador de fallos vuelve a 0. |
| **Permitir bloqueo de cuenta de administrador** | Si se aplica también a la cuenta Administrador integrada. |

> [!NOTE]
> En las versiones actuales de Windows 11, el bloqueo de cuentas viene **activado por defecto** con un umbral de 10 intentos y una duración de 10 minutos. Compruébalo en tu equipo con `net accounts`.

{{% steps %}}
1. ## Abrir la consola

   `Win + R` > `secpol.msc`. Despliega **Directivas de cuenta > Directiva de contraseñas**.

2. ## Modificar una directiva

   Haz doble clic sobre la directiva (por ejemplo, *Longitud mínima de la contraseña*), escribe el valor y pulsa **Aceptar**. Los cambios se aplican inmediatamente, pero solo se comprueban la **próxima vez** que cada usuario cambie su contraseña.

3. ## Forzar la actualización

   Si el cambio no parece aplicarse, ejecuta `gpupdate /force` en una consola de administrador.
{{% /steps %}}

Las mismas opciones, y muchas más, están en el **Editor de directivas de grupo local** (`gpedit.msc`), en *Configuración del equipo > Configuración de Windows > Configuración de seguridad*. En un dominio se configuran de forma centralizada con **directivas de grupo** (GPO), como verás en la Unidad 6.

## 4.5 Windows: directivas desde la línea de comandos

### `net accounts`

Muestra y modifica las directivas de contraseña y bloqueo. Funciona en **todas las ediciones**, incluida Home.

| Opción | Directiva |
| --- | --- |
| `/minpwlen:N` | Longitud mínima. |
| `/maxpwage:N` | Vigencia máxima en días (`UNLIMITED` para que no caduque). |
| `/minpwage:N` | Vigencia mínima en días. |
| `/uniquepw:N` | Historial: contraseñas recordadas. |
| `/lockoutthreshold:N` | Umbral de bloqueo. |
| `/lockoutduration:N` | Duración del bloqueo en minutos. |
| `/lockoutwindow:N` | Minutos para restablecer el contador de fallos. |

```bat
net accounts
net accounts /minpwlen:12 /maxpwage:180 /minpwage:1 /uniquepw:5
net accounts /lockoutthreshold:5 /lockoutduration:15 /lockoutwindow:15
```

### `secedit`: la directiva de complejidad

`net accounts` no permite activar la **complejidad**. Para ello, se exporta la configuración de seguridad a un fichero de texto, se modifica y se vuelve a importar con `secedit`:

```powershell
# Ejecutar en PowerShell como administrador
New-Item -ItemType Directory -Path C:\Temp -Force | Out-Null      # Crea C:\Temp si no existe
secedit /export /cfg C:\Temp\seguridad.inf /areas SECURITYPOLICY

# Cambia la línea "PasswordComplexity = 0" por "PasswordComplexity = 1"
(Get-Content C:\Temp\seguridad.inf) -replace 'PasswordComplexity = 0', 'PasswordComplexity = 1' |
    Set-Content C:\Temp\seguridad.inf

secedit /configure /db C:\Windows\security\database\secedit.sdb /cfg C:\Temp\seguridad.inf /areas SECURITYPOLICY
net accounts            # Comprobación (la complejidad no aparece aquí: revísala en secpol.msc)
```

### Directivas de una cuenta concreta

Algunas opciones no son globales, sino de cada usuario:

```powershell
# El usuario debe cambiar la contraseña al iniciar sesión
net user ana /logonpasswordchg:yes

# La contraseña de ana SÍ caduca según la directiva global
Set-LocalUser -Name ana -PasswordNeverExpires $false

# La cuenta expira al final del curso
Set-LocalUser -Name ana -AccountExpires (Get-Date "2027-06-30")

# Horario de inicio de sesión: solo de lunes a viernes de 8:00 a 15:00
# (las abreviaturas de los días dependen del idioma del sistema; consúltalas con: net help user)
net user ana /times:L-V,08:00-15:00

# Desbloquear una cuenta bloqueada por intentos fallidos
net user ana /active:yes
```

Una cuenta bloqueada también se puede desbloquear en `lusrmgr.msc`: en las propiedades del usuario, desmarca la casilla **La cuenta está bloqueada**.

> [!TIP]
> En la pantalla **Configuración > Cuentas > Opciones de inicio de sesión** se configura **Windows Hello** (PIN, huella o reconocimiento facial). El PIN de Windows Hello está ligado al dispositivo: aunque alguien lo descubra, no le sirve para acceder desde otro equipo, a diferencia de la contraseña.

## 4.6 Comparativa

| Directiva | Linux | Windows |
| --- | --- | --- |
| Valores por defecto | `/etc/login.defs` | `secpol.msc`, `net accounts` |
| Caducidad de una cuenta concreta | `chage -M`, `chage -E` | `Set-LocalUser -AccountExpires`, `net user /expires` |
| Forzar cambio en el siguiente acceso | `chage -d 0`, `passwd -e` | `net user /logonpasswordchg:yes` |
| Longitud y complejidad | `pam_pwquality` (`pwquality.conf`) | Directiva de contraseñas |
| Historial | `pam_pwhistory` | *Exigir historial de contraseñas*, `/uniquepw` |
| Bloqueo tras fallos | `pam_faillock` (`faillock.conf`) | Directiva de bloqueo, `/lockoutthreshold` |
| Desbloquear | `faillock --reset`, `passwd -u` | `net user /active:yes` |

## Ejercicios resueltos

### Ejercicio 4.1. Leer `chage -l`

`sudo chage -l luis` muestra *Password expires: dic 01, 2026* y *Password inactive: dic 08, 2026*. ¿Qué ocurre si `luis` intenta iniciar sesión el 3 de diciembre? ¿Y el 10?

{{% details "Ver solución" %}}
- El **3 de diciembre** la contraseña ya ha caducado, pero está dentro del periodo de inactividad: `luis` puede entrar, pero el sistema le **obligará a cambiar la contraseña** antes de continuar.
- El **10 de diciembre** ha terminado el periodo de inactividad: la cuenta queda **desactivada** y `luis` no puede entrar. Un administrador debe asignarle una contraseña nueva (`sudo passwd luis`).
{{% /details %}}

### Ejercicio 4.2. Política del aula en Linux

Configura tu Linux para que:

1. Las cuentas nuevas tengan contraseñas con una vigencia máxima de 180 días y aviso a los 14.
2. La cuenta existente `ana` tenga esa misma política y expire el 30 de junio de 2027.
3. Las contraseñas tengan al menos 12 caracteres de 3 tipos distintos.

{{% details "Ver solución" %}}
```bash
# 1. Cuentas futuras: editar /etc/login.defs
sudo sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS   180/; s/^PASS_WARN_AGE.*/PASS_WARN_AGE   14/' /etc/login.defs
grep ^PASS_ /etc/login.defs

# 2. Cuenta existente
sudo chage -M 180 -W 14 -E 2027-06-30 ana
sudo chage -l ana

# 3. Calidad de contraseñas
sudo apt install libpam-pwquality
sudo sed -i 's/^# *minlen.*/minlen = 12/; s/^# *minclass.*/minclass = 3/' /etc/security/pwquality.conf
grep -E '^(minlen|minclass)' /etc/security/pwquality.conf
```

`sed -i 's/patrón/sustitución/'` modifica el fichero en el propio sitio (Unidad 3). El patrón `^# *minlen.*` encuentra la línea comentada, con o sin espacio tras `#`.
{{% /details %}}

### Ejercicio 4.3. Política del aula en Windows

Configura Windows con: longitud mínima de 12, historial de 5 contraseñas, complejidad activada y bloqueo tras 5 intentos durante 15 minutos. Después, comprueba el bloqueo.

{{% details "Ver solución" %}}
```bat
net accounts /minpwlen:12 /uniquepw:5 /lockoutthreshold:5 /lockoutduration:15 /lockoutwindow:15
```

La complejidad se activa en `secpol.msc` (*La contraseña debe cumplir los requisitos de complejidad* > *Habilitada*) o con `secedit`, como en el apartado 4.5.

**Comprobación**: cierra la sesión e intenta entrar 5 veces con una contraseña incorrecta en una cuenta de prueba (nunca con la única cuenta de administrador). En el sexto intento aparecerá el mensaje *La cuenta a la que se hace referencia está bloqueada*. Desde otra cuenta de administrador:

```bat
net user prueba          :: "Cuenta activa: Bloqueada"
net user prueba /active:yes
```

En el apartado 10 verás que cada bloqueo queda registrado en el Visor de eventos con el identificador **4740**.
{{% /details %}}

### Ejercicio 4.4. Análisis crítico

Una empresa obliga a cambiar la contraseña cada 30 días, exige 8 caracteres con complejidad y no tiene bloqueo de cuentas. Los empleados usan contraseñas como `Enero2026!`, `Febrero2026!`… Identifica los problemas y propone una política mejor.

{{% details "Ver solución" %}}
Problemas:

- **Cambio cada 30 días**: provoca que los usuarios usen patrones predecibles (el mes y el año). Si un atacante conoce una contraseña, deduce las siguientes.
- **8 caracteres**: es una longitud corta. La complejidad se cumple con patrones muy previsibles (mayúscula al principio, símbolo al final).
- **Sin bloqueo**: un atacante puede probar contraseñas sin límite.

Propuesta razonada:

- Longitud mínima de 12 a 15 caracteres, animando a usar **frases de contraseña** (por ejemplo, cuatro palabras al azar).
- Sin caducidad periódica, pero **cambio obligatorio** si hay sospecha de que la contraseña se ha filtrado.
- **Bloqueo** tras 5–10 intentos durante 10–15 minutos.
- **Historial** de al menos 5 contraseñas.
- **Autenticación multifactor** para los accesos remotos y las cuentas de administrador.
- Uso de un **gestor de contraseñas** para no tener que memorizar contraseñas distintas.
{{% /details %}}
