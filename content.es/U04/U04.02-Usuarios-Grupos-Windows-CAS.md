# 2. Usuarios y grupos en Windows

Windows también es un sistema multiusuario y sigue la misma idea que Linux: cada persona tiene su **cuenta**, las cuentas se agrupan en **grupos** y los permisos se asignan preferentemente a los grupos. Lo que cambia es la forma de identificarlos y las herramientas para gestionarlos.

## 2.1 Tipos de cuentas

Según **dónde** se guarda la cuenta y quién la autentica:

| Tipo | Dónde se guarda | Uso típico |
| --- | --- | --- |
| **Cuenta local** | En el propio equipo, en la base de datos **SAM** (*Security Account Manager*). | Equipos individuales, aulas, máquinas virtuales. Funciona sin conexión a Internet. |
| **Cuenta Microsoft** | En los servidores de Microsoft (`usuario@outlook.com`…). | Equipos domésticos. Sincroniza configuración, OneDrive y la Tienda entre dispositivos. |
| **Cuenta de dominio** | En un **controlador de dominio** con *Active Directory* (o en la nube con *Microsoft Entra ID*). | Empresas y centros educativos: un mismo usuario puede iniciar sesión en cualquier equipo de la organización. Se estudia en la Unidad 6. |

Según los **privilegios** que tiene:

| Tipo | Qué puede hacer |
| --- | --- |
| **Administrador** | Instalar programas y controladores, cambiar la configuración del sistema, gestionar otras cuentas. |
| **Usuario estándar** | Usar los programas instalados y modificar sus propios ficheros y su configuración personal. Para tareas de administración necesita las credenciales de un administrador. |

> [!TIP]
> Igual que en Linux no se trabaja como root, en Windows la buena práctica es usar a diario una **cuenta estándar** y reservar la cuenta de administrador para cuando haga falta. Si un programa malicioso se ejecuta desde una cuenta estándar, el daño que puede causar es mucho menor.

### Cuentas integradas

Windows crea algunas cuentas automáticamente durante la instalación:

| Cuenta | Descripción |
| --- | --- |
| **Administrador** (*Administrator*) | Administrador integrado. Está **deshabilitada** por defecto en las versiones de escritorio. |
| **Invitado** (*Guest*) | Acceso muy limitado y sin contraseña. **Deshabilitada** por defecto; no se recomienda activarla. |
| **DefaultAccount** | Cuenta interna que usa el sistema. Deshabilitada. |
| **SYSTEM**, **LOCAL SERVICE**, **NETWORK SERVICE** | Cuentas de servicio con las que se ejecutan los procesos y servicios del sistema (apartado 8). No aparecen en la lista de usuarios. `SYSTEM` tiene más privilegios que cualquier administrador. |

## 2.2 Identificadores de seguridad (SID)

Internamente, Windows no identifica las cuentas por su nombre sino por su **SID** (*Security Identifier*), un identificador único con este aspecto:

```text
S-1-5-21-3623811015-3361044348-30300820-1001
└┬┘ │ │  └──────────── identificador del equipo ───┘ └┬─┘
 │  │ └ autoridad (5 = NT Authority)                   RID: número relativo de la cuenta
 │  └ versión
 └ prefijo
```

El último número, el **RID**, distingue cada cuenta dentro del equipo. Algunos RID son fijos: `500` es el Administrador integrado y `501` el Invitado. Las cuentas que creas tú empiezan en `1000`. Los grupos integrados tienen SID fijos y conocidos, iguales en todos los equipos, por ejemplo `S-1-5-32-544` (Administradores) o `S-1-5-32-545` (Usuarios).

Como los permisos se guardan asociados al SID, si borras una cuenta y creas otra con el mismo nombre, la nueva **no** recupera los permisos de la anterior: tiene otro SID.

```powershell
whoami            # equipo\usuario
whoami /user      # Nombre y SID del usuario actual
whoami /groups    # Grupos a los que pertenezco, con sus SID
```

## 2.3 Grupos locales integrados

| Grupo (nombre en español) | SID | Qué permite |
| --- | --- | --- |
| **Administradores** | `S-1-5-32-544` | Control total del equipo. |
| **Usuarios** | `S-1-5-32-545` | Uso normal del equipo. Todas las cuentas nuevas se añaden a este grupo. |
| **Invitados** | `S-1-5-32-546` | Acceso mínimo y temporal. |
| **Usuarios de escritorio remoto** | `S-1-5-32-555` | Iniciar sesión mediante Escritorio remoto (RDP). |
| **Operadores de copia de seguridad** | `S-1-5-32-551` | Hacer y restaurar copias de seguridad aunque no tengan permisos sobre los ficheros. |
| **Usuarios del monitor de sistema** | `S-1-5-32-558` | Consultar los contadores de rendimiento (apartado 9). |
| **Lectores del registro de eventos** | `S-1-5-32-573` | Leer los registros de eventos (apartado 10). |

Además existen **identidades especiales** cuyos miembros los decide el sistema automáticamente: **Todos** (*Everyone*, `S-1-1-0`), **Usuarios autentificados** (`S-1-5-11`), **INTERACTIVE** (usuarios con sesión local), **CREATOR OWNER**…

> [!WARNING]
> Los **nombres** de los grupos integrados dependen del **idioma** de Windows: en un Windows en español el grupo se llama `Administradores` y en uno en inglés, `Administrators`. Los **SID**, en cambio, son siempre los mismos. Por eso, en los scripts que deban funcionar en cualquier equipo, es mejor referirse a los grupos integrados por su SID.

## 2.4 Control de cuentas de usuario (UAC)

Cuando un administrador inicia sesión, Windows le asigna **dos testigos de acceso** (*access tokens*): uno con privilegios de usuario estándar y otro con privilegios completos. Por defecto, todos los programas se ejecutan con el testigo **estándar**. Cuando un programa necesita privilegios, el **UAC** (*User Account Control*) muestra un aviso:

- Si eres administrador, solo tienes que **confirmar** (botón *Sí*).
- Si eres usuario estándar, debes escribir las **credenciales de un administrador**.

Este mecanismo es similar a `sudo`: aunque seas administrador, los privilegios solo se usan cuando se confirman explícitamente. Para abrir una consola con privilegios, haz clic derecho sobre *Terminal* o *PowerShell* y elige **Ejecutar como administrador**. El título de la ventana indicará *Administrador*.

```powershell
# ¿Esta consola se ejecuta con privilegios de administrador? (True / False)
([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole(
    [Security.Principal.WindowsBuiltInRole]::Administrator)
```

## 2.5 Herramientas gráficas

| Herramienta | Cómo se abre | Para qué |
| --- | --- | --- |
| **Configuración > Cuentas** | `Win + I` | Gestión básica: añadir usuarios, cambiar el tipo de cuenta (estándar/administrador), opciones de inicio de sesión. Disponible en todas las ediciones. |
| **Usuarios y grupos locales** | `lusrmgr.msc` | Gestión completa de usuarios y grupos locales. **No disponible en Windows Home.** |
| **Administración de equipos** | `compmgmt.msc` | Consola que incluye *Usuarios y grupos locales*, *Carpetas compartidas*, *Servicios*, *Visor de eventos*… |
| **Cuentas de usuario avanzadas** | `netplwiz` | Lista de usuarios y sus grupos, inicio de sesión automático. |

{{% steps %}}
1. ## Crear un usuario local desde Configuración

   Abre **Configuración > Cuentas > Otros usuarios** y pulsa **Agregar cuenta**. En el asistente elige *No tengo los datos de inicio de sesión de esta persona* y después *Agregar un usuario sin cuenta Microsoft*. Escribe el nombre, la contraseña y las preguntas de seguridad.

2. ## Cambiar el tipo de cuenta

   En la misma pantalla, despliega el usuario, pulsa **Cambiar el tipo de cuenta** y elige *Usuario estándar* o *Administrador*.

3. ## Gestión avanzada con `lusrmgr.msc`

   Pulsa `Win + R`, escribe `lusrmgr.msc` y acepta. En la carpeta **Usuarios**, con el botón derecho > *Usuario nuevo…*, puedes indicar además opciones como *El usuario debe cambiar la contraseña en el siguiente inicio de sesión* o *La cuenta está deshabilitada*. En **Grupos**, haz doble clic sobre un grupo para añadir o quitar miembros.
{{% /steps %}}

> [!NOTE]
> Los nombres exactos de los menús de *Configuración* pueden variar ligeramente entre versiones de Windows 11, porque Microsoft los modifica con las actualizaciones. Si no encuentras una opción, usa el buscador de *Configuración*.

## 2.6 Gestión desde CMD: `net user` y `net localgroup`

Las órdenes `net` existen desde hace décadas y siguen funcionando en todas las versiones y ediciones de Windows. Requieren una consola **ejecutada como administrador** para hacer cambios.

| Orden | Función |
| --- | --- |
| `net user` | Lista las cuentas locales. |
| `net user ana` | Muestra la información de la cuenta `ana` (grupos, último inicio de sesión, caducidad…). |
| `net user ana * /add` | Crea `ana` y pide la contraseña sin mostrarla (`*`). |
| `net user ana /fullname:"Ana López" /comment:"DAM1"` | Cambia datos de la cuenta. |
| `net user ana /active:no` | Deshabilita la cuenta (`yes` para habilitarla). |
| `net user ana /expires:30/06/2027` | Fecha de caducidad de la cuenta (formato de fecha según el idioma del sistema). |
| `net user ana /logonpasswordchg:yes` | Obliga a cambiar la contraseña en el siguiente inicio de sesión. |
| `net user ana /delete` | Elimina la cuenta. |
| `net localgroup` | Lista los grupos locales. |
| `net localgroup dam1 /add` | Crea el grupo `dam1`. |
| `net localgroup dam1 ana /add` | Añade `ana` al grupo `dam1` (`/delete` para quitarla). |

```bat
:: Crear un usuario estándar y hacerlo miembro del grupo dam1
net localgroup dam1 /add
net user ana * /add /fullname:"Ana López"
net localgroup dam1 ana /add
net user ana
```

> [!CAUTION]
> Evita escribir la contraseña directamente en la orden (`net user ana Clave123 /add`): queda visible en pantalla y en el historial de la consola. Usa `*` para que la pida de forma oculta.

## 2.7 Gestión desde PowerShell

El módulo `Microsoft.PowerShell.LocalAccounts` incluye *cmdlets* para gestionar usuarios y grupos locales. Todos siguen el patrón **verbo-sustantivo** que viste en la Unidad 3.

| Cmdlet | Función |
| --- | --- |
| `Get-LocalUser` | Lista los usuarios locales (o uno concreto con `-Name`). |
| `New-LocalUser` | Crea un usuario. |
| `Set-LocalUser` | Modifica propiedades (nombre completo, descripción, caducidad…). |
| `Enable-LocalUser` / `Disable-LocalUser` | Habilita / deshabilita una cuenta. |
| `Rename-LocalUser` | Cambia el nombre (el SID se mantiene). |
| `Remove-LocalUser` | Elimina un usuario. |
| `Get-LocalGroup` / `New-LocalGroup` / `Remove-LocalGroup` | Consulta, crea y elimina grupos. |
| `Get-LocalGroupMember` | Lista los miembros de un grupo. |
| `Add-LocalGroupMember` / `Remove-LocalGroupMember` | Añade / quita miembros de un grupo. |

```powershell
# Pide la contraseña de forma segura: Read-Host -AsSecureString devuelve un objeto SecureString,
# que guarda el texto cifrado en memoria en lugar de como texto plano.
$clave = Read-Host "Contraseña para ana" -AsSecureString

# Crea el usuario. Los parámetros se pueden partir en varias líneas con el acento grave (`)
New-LocalUser -Name "ana" -Password $clave `
              -FullName "Ana López" -Description "Alumna de DAM1"

New-LocalGroup -Name "dam1" -Description "Alumnado de 1.º de DAM"
Add-LocalGroupMember -Group "dam1" -Member "ana"

# Añadir a un grupo integrado usando su SID, para que funcione en cualquier idioma
Add-LocalGroupMember -SID "S-1-5-32-555" -Member "ana"     # Usuarios de escritorio remoto

# Consultas
Get-LocalUser -Name ana | Format-List *          # Todas las propiedades de la cuenta
Get-LocalGroupMember -Group "dam1"
Get-LocalUser | Where-Object Enabled | Select-Object Name, LastLogon

# Modificaciones y baja
Set-LocalUser -Name ana -AccountExpires (Get-Date "2027-06-30")
Disable-LocalUser -Name ana
Remove-LocalUser -Name ana
```

> [!IMPORTANT]
> El módulo `Microsoft.PowerShell.LocalAccounts` pertenece a **Windows PowerShell 5.1**, que viene instalado en todos los Windows. **PowerShell 7** no lo incluye y lo carga mediante su función de compatibilidad, lo que en algunas versiones produce errores. Si un *cmdlet* `*-LocalUser` falla en PowerShell 7, ejecútalo en *Windows PowerShell* o importa antes el módulo con:
>
> ```powershell
> Import-Module Microsoft.PowerShell.LocalAccounts -UseWindowsPowerShell
> ```

### Ejecutar como otro usuario

```bat
runas /user:ana cmd               :: Abre una consola como ana (pide su contraseña)
```

Desde el Explorador, con `Mayús + clic derecho` sobre un programa aparece la opción **Ejecutar como otro usuario**.

## 2.8 Comparativa Linux / Windows

| Concepto | Linux | Windows |
| --- | --- | --- |
| Identificador interno | UID / GID | SID |
| Base de datos local | `/etc/passwd`, `/etc/shadow`, `/etc/group` | SAM (en el registro, no editable directamente) |
| Superusuario | `root` (UID 0) | Grupo *Administradores*; cuenta `SYSTEM` para el sistema |
| Elevar privilegios | `sudo` | UAC, *Ejecutar como administrador*, `runas` |
| Crear usuario | `useradd -m usuario` | `net user usuario * /add`, `New-LocalUser` |
| Añadir a grupo | `usermod -aG grupo usuario` | `net localgroup grupo usuario /add`, `Add-LocalGroupMember` |
| Ver mis grupos | `id` | `whoami /groups` |
| Gestión centralizada | LDAP, FreeIPA | Active Directory, Microsoft Entra ID |

## Ejercicios resueltos

### Ejercicio 2.1. Usuarios del aula con `net`

Desde una consola de administrador, crea el grupo `dam1` y los usuarios estándar `john` y `doe`, ambos miembros de `dam1`. `doe` debe ser además administrador. Ambos deben cambiar la contraseña en su primer inicio de sesión.

{{% details "Ver solución" %}}
```bat
net localgroup dam1 /add
net user john * /add
net user doe * /add
net localgroup dam1 john /add
net localgroup dam1 doe /add
net localgroup Administradores doe /add
net user john /logonpasswordchg:yes
net user doe /logonpasswordchg:yes
net localgroup dam1
net user doe
```

En la salida de `net user doe` deben aparecer, en *Miembros del grupo local*, `*Administradores`, `*dam1` y `*Usuarios`. Si el Windows está en inglés, el grupo se llama `Administrators`.

> No uses contraseñas como `admin` o `john123`, aunque sea en prácticas: acostúmbrate desde el principio a usar contraseñas robustas (apartado 4).
{{% /details %}}

### Ejercicio 2.2. El mismo alta con PowerShell

Repite el ejercicio anterior con PowerShell, de forma que el script funcione aunque Windows esté en inglés.

{{% details "Ver solución" %}}
```powershell
# Ejecutar en Windows PowerShell 5.1 como administrador
New-LocalGroup -Name "dam1" -ErrorAction SilentlyContinue   # Si ya existe, no muestra error

foreach ($nombre in "john", "doe") {
    $clave = Read-Host "Contraseña inicial para $nombre" -AsSecureString
    New-LocalUser -Name $nombre -Password $clave | Out-Null
    Add-LocalGroupMember -Group "dam1" -Member $nombre
    net user $nombre /logonpasswordchg:yes | Out-Null      # PowerShell también ejecuta órdenes de CMD
}

Add-LocalGroupMember -SID "S-1-5-32-544" -Member "doe"     # Administradores, en cualquier idioma

Get-LocalGroupMember -Group "dam1"
Get-LocalGroupMember -SID "S-1-5-32-544"
```
{{% /details %}}

### Ejercicio 2.3. Auditoría de cuentas

Escribe un script de PowerShell que muestre las cuentas **habilitadas**, indicando para cada una si es administrador, la fecha de su último inicio de sesión y si su contraseña caduca.

{{% details "Ver solución" %}}
```powershell
# Obtenemos una vez los nombres de los miembros del grupo Administradores.
# Get-LocalGroupMember devuelve nombres del tipo "EQUIPO\usuario"; nos quedamos con la parte final.
$admins = Get-LocalGroupMember -SID "S-1-5-32-544" |
          ForEach-Object { $_.Name.Split('\')[-1] }

Get-LocalUser | Where-Object Enabled | ForEach-Object {
    [PSCustomObject]@{                       # Crea un objeto con las columnas que queremos mostrar
        Usuario       = $_.Name
        Administrador = $admins -contains $_.Name
        UltimoAcceso  = $_.LastLogon
        ClaveCaduca   = $null -ne $_.PasswordExpires
    }
} | Format-Table -AutoSize
```

`[PSCustomObject]@{...}` construye un objeto a partir de una tabla de pares *clave = valor*; es la forma habitual en PowerShell de generar informes con columnas personalizadas.
{{% /details %}}

### Ejercicio 2.4. Nombre frente a SID

Crea el usuario `prueba`, añádelo al grupo *Usuarios de escritorio remoto*, comprueba su SID y bórralo. Vuelve a crear un usuario llamado `prueba`. ¿Sigue perteneciendo al grupo? ¿Tiene el mismo SID? Explica por qué.

{{% details "Ver solución" %}}
```powershell
$c = Read-Host -AsSecureString
New-LocalUser prueba -Password $c | Out-Null
Add-LocalGroupMember -SID "S-1-5-32-555" -Member prueba
(Get-LocalUser prueba).SID.Value          # p. ej. S-1-5-21-...-1005
Remove-LocalUser prueba

New-LocalUser prueba -Password $c | Out-Null
(Get-LocalUser prueba).SID.Value          # p. ej. S-1-5-21-...-1006  (RID distinto)
Get-LocalGroupMember -SID "S-1-5-32-555"  # prueba ya NO aparece
```

La nueva cuenta recibe un **RID distinto**, así que su SID es otro. Como la pertenencia a grupos y los permisos se guardan por SID, la cuenta nueva no hereda nada de la antigua aunque se llame igual.
{{% /details %}}
