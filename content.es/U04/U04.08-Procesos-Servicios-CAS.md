# 8. Procesos y servicios

Un administrador debe saber en todo momento **qué se está ejecutando** en el sistema, poder **detener** lo que no debe estar en marcha y **arrancar** lo que se necesita. En este apartado se estudian los dos elementos que se ejecutan en un sistema operativo: los **procesos** y los **servicios**.

## 8.1 Conceptos

| Concepto | Descripción |
| --- | --- |
| **Programa** | Fichero ejecutable guardado en el disco (por ejemplo, `/usr/bin/python3` o `notepad.exe`). Es algo estático. |
| **Proceso** | Un programa **en ejecución**, con su memoria, sus ficheros abiertos y su estado. Un mismo programa puede dar lugar a varios procesos a la vez. |
| **PID** (*Process ID*) | Número que identifica a cada proceso mientras existe. |
| **PPID** (*Parent PID*) | PID del proceso **padre**, el que lo creó. Los procesos forman un árbol. |
| **Hilo** (*thread*) | Línea de ejecución dentro de un proceso. Un proceso puede tener varios hilos que comparten su memoria. |
| **Servicio** o **demonio** (*daemon*) | Proceso que se ejecuta en **segundo plano**, sin interfaz, normalmente desde el arranque y aunque no haya ningún usuario conectado: servidor web, base de datos, SSH, impresión… En Linux sus nombres suelen terminar en `d` (`sshd`, `smbd`). |

Cada proceso se ejecuta con la identidad de un **usuario** y solo puede acceder a lo que ese usuario tenga permitido. Por eso es tan importante que los servicios se ejecuten con usuarios sin privilegios (apartado 1.3).

### Estados de un proceso en Linux

| Estado | Letra en `ps` | Significado |
| --- | --- | --- |
| En ejecución | `R` | Usando la CPU o esperando turno para usarla. |
| Dormido | `S` | Esperando un evento (una tecla, datos de la red…). Es el estado más habitual. |
| Espera ininterrumpible | `D` | Esperando una operación de E/S del disco. Muchos procesos en `D` indican un problema de disco. |
| Detenido | `T` | Pausado (por ejemplo, con `Ctrl+Z`). |
| Zombi | `Z` | Ha terminado, pero su padre todavía no ha recogido su código de salida. No consume recursos, salvo su entrada en la tabla de procesos. |

## 8.2 Procesos en Linux

### Listar procesos

| Orden | Función |
| --- | --- |
| `ps` | Procesos de la terminal actual. |
| `ps aux` | **Todos** los procesos, con usuario, % de CPU y de memoria (sintaxis BSD). |
| `ps -ef` | Todos los procesos, con PPID (sintaxis System V). |
| `ps -u ana` | Procesos del usuario `ana`. |
| `ps -o pid,ppid,user,%cpu,%mem,cmd` | Columnas personalizadas. |
| `ps aux --sort=-%cpu` | Ordenados de mayor a menor uso de CPU. |
| `pstree -p` | Árbol de procesos con sus PID. |
| `pgrep -a nombre` | PID y orden de los procesos cuyo nombre coincide. |
| `pidof programa` | PID de un programa concreto. |

```bash
ps aux | head -n 5
# USER   PID %CPU %MEM    VSZ   RSS TTY  STAT START   TIME COMMAND
# root     1  0.0  0.3  23440 13600 ?    Ss   09:12   0:02 /sbin/init splash
# root     2  0.0  0.0      0     0 ?    S    09:12   0:00 [kthreadd]
```

| Columna | Significado |
| --- | --- |
| `USER` | Usuario con el que se ejecuta. |
| `PID` | Identificador del proceso. |
| `%CPU` / `%MEM` | Porcentaje de CPU y de memoria física que usa. |
| `VSZ` / `RSS` | Memoria virtual reservada / memoria física realmente ocupada (en KiB). |
| `TTY` | Terminal asociada (`?` = ninguna, típico de los servicios). |
| `STAT` | Estado (ver tabla anterior). |
| `COMMAND` | Orden que lanzó el proceso. Entre corchetes, los hilos del núcleo. |

El proceso con **PID 1** es el primero que arranca el núcleo y el antecesor de todos los demás. En las distribuciones actuales es **systemd**.

```bash
ps -o pid,ppid,user,%mem,cmd --sort=-%mem | head -n 6   # Los 5 procesos que más memoria usan
pgrep -a ssh                                           # Procesos relacionados con SSH
pstree -p $$                                           # $$ = PID de la shell actual
```

### Señales: terminar procesos

Para comunicarse con un proceso se le envían **señales**. Las más importantes:

| Señal | Número | Significado | Se puede ignorar |
| --- | --- | --- | --- |
| `SIGTERM` | 15 | Pide al proceso que **termine ordenadamente** (guardando datos y cerrando ficheros). Es la señal por defecto. | Sí |
| `SIGKILL` | 9 | **Mata** el proceso inmediatamente. Puede perder datos. | **No** |
| `SIGINT` | 2 | Interrupción, la que envía `Ctrl+C`. | Sí |
| `SIGHUP` | 1 | "Se ha colgado la terminal". Muchos servicios la usan para **releer su configuración**. | Sí |
| `SIGSTOP` | 19 | Pausa el proceso. | **No** |
| `SIGTSTP` | 20 | Pausa desde el teclado (`Ctrl+Z`). | Sí |
| `SIGCONT` | 18 | Reanuda un proceso pausado. | — |

| Orden | Función |
| --- | --- |
| `kill PID` | Envía `SIGTERM` al proceso. |
| `kill -9 PID` o `kill -KILL PID` | Envía `SIGKILL`. |
| `kill -l` | Lista todas las señales. |
| `pkill nombre` | Envía la señal a todos los procesos cuyo nombre coincide. |
| `pkill -u ana` | A todos los procesos de `ana`. |
| `killall nombre` | Por nombre exacto del programa. |

```bash
sleep 600 &              # Lanza un proceso de prueba en segundo plano
pgrep -a sleep           # 4321 sleep 600
kill 4321                # Le pide que termine
kill -9 4321             # Solo si no ha respondido a SIGTERM
```

> [!TIP]
> Usa siempre primero `kill` (SIGTERM) y espera unos segundos. Recurre a `kill -9` solo si el proceso no responde, porque no le da oportunidad de guardar datos ni de liberar recursos (ficheros temporales, bloqueos…).

Un usuario normal solo puede enviar señales a **sus propios** procesos; root puede enviarlas a cualquiera.

### Primer y segundo plano

| Acción | Cómo |
| --- | --- |
| Lanzar en segundo plano | Añadir `&` al final: `orden &` |
| Pausar el proceso en primer plano | `Ctrl+Z` |
| Ver los trabajos de esta terminal | `jobs` |
| Continuar en segundo plano | `bg %1` |
| Traer a primer plano | `fg %1` |
| Que no termine al cerrar la terminal | `nohup orden &` (la salida va a `nohup.out`) |

```bash
python3 -m http.server 8000      # Servidor web de prueba en primer plano
# Ctrl+Z                         -> [1]+ Detenido  python3 -m http.server 8000
bg %1                            # Sigue funcionando en segundo plano
jobs                             # [1]+ Ejecutando  python3 -m http.server 8000 &
fg %1                            # Vuelve a primer plano; Ctrl+C para terminarlo
```

### Prioridad: `nice` y `renice`

El planificador del sistema reparte la CPU entre los procesos según su **prioridad**. En Linux se controla con el valor ***nice***, entre **-20** (máxima prioridad) y **19** (mínima). Por defecto es 0. Se llama así porque un proceso con un valor alto es más "amable" (*nice*) con los demás.

```bash
nice -n 15 tar -czf copia.tar.gz ~/proyectos   # Compresión con baja prioridad
renice -n 10 -p 4321                           # Cambia la prioridad de un proceso en marcha
sudo renice -n -5 -p 4321                      # Solo root puede SUBIR la prioridad (valores negativos)
ps -o pid,ni,cmd -p 4321                       # Columna NI: valor nice
```

## 8.3 Servicios en Linux: systemd

**systemd** es el sistema de inicio y el gestor de servicios de casi todas las distribuciones actuales. Organiza todo lo que gestiona en **unidades** (*units*), cada una descrita por un fichero de texto:

| Tipo de unidad | Extensión | Qué representa |
| --- | --- | --- |
| Servicio | `.service` | Un servicio o demonio. |
| *Socket* | `.socket` | Un punto de conexión que arranca un servicio cuando alguien se conecta. |
| *Timer* | `.timer` | Una tarea programada (alternativa a `cron`, Unidad 3). |
| Montaje | `.mount` | Un sistema de archivos montado. |
| Objetivo | `.target` | Un grupo de unidades que definen un estado del sistema. |

Los ficheros de las unidades están en `/usr/lib/systemd/system/` (los instalan los paquetes) y en `/etc/systemd/system/` (los del administrador, que tienen prioridad).

### `systemctl`: gestionar servicios

Hay que distinguir dos ideas:

- **Arrancar/detener** (`start`/`stop`): afecta **ahora**, pero no al próximo arranque.
- **Habilitar/deshabilitar** (`enable`/`disable`): decide si se arranca **automáticamente al iniciar el sistema**, pero no lo arranca ni lo para ahora.

| Orden | Función |
| --- | --- |
| `systemctl status ssh` | Estado, PID, memoria y últimas líneas de su registro. |
| `sudo systemctl start ssh` | Arranca el servicio. |
| `sudo systemctl stop ssh` | Lo detiene. |
| `sudo systemctl restart ssh` | Lo detiene y lo vuelve a arrancar. |
| `sudo systemctl reload ssh` | Relee la configuración sin detenerlo (si el servicio lo admite). |
| `sudo systemctl enable ssh` | Lo arrancará automáticamente en cada inicio. |
| `sudo systemctl disable ssh` | Ya no se arrancará en el inicio. |
| `sudo systemctl enable --now ssh` | Habilita **y** arranca a la vez (`disable --now` para lo contrario). |
| `systemctl is-active ssh` / `is-enabled ssh` | Responde con una palabra; útil en scripts. |
| `sudo systemctl mask ssh` | Impide que se pueda arrancar de ninguna forma, ni manualmente (`unmask` para deshacerlo). |
| `systemctl list-units --type=service --state=running` | Servicios en ejecución. |
| `systemctl list-unit-files --type=service` | Todos los servicios instalados y su estado de habilitación. |
| `systemctl --failed` | Unidades que han fallado. |
| `sudo systemctl daemon-reload` | Relee los ficheros de unidad tras modificarlos. |

```bash
systemctl status cron
# ● cron.service - Regular background program processing daemon
#      Loaded: loaded (/usr/lib/systemd/system/cron.service; enabled; preset: enabled)
#      Active: active (running) since Sun 2026-11-08 09:12:31 CET; 2h ago
#    Main PID: 812 (cron)
#       Tasks: 1 (limit: 4558)
#      Memory: 1.2M
```

En la línea `Loaded`, `enabled` indica que arranca con el sistema. En la línea `Active`, `active (running)` indica que está en marcha ahora. Los estados de habilitación más habituales en `list-unit-files` son:

| Estado | Significado |
| --- | --- |
| `enabled` | Se arranca automáticamente en el inicio. |
| `disabled` | No se arranca en el inicio, pero se puede arrancar manualmente. |
| `static` | No se puede habilitar por sí mismo; lo arranca otra unidad que depende de él. |
| `masked` | Bloqueado: no se puede arrancar de ninguna forma. |
| `alias` | Es otro nombre de una unidad. |

> [!NOTE]
> En algunas distribuciones el mismo servicio tiene nombres distintos: el servidor SSH se llama `ssh` en Debian/Ubuntu y `sshd` en Fedora/RHEL; el servidor web Apache, `apache2` en Debian/Ubuntu y `httpd` en Fedora/RHEL.

### Objetivos (*targets*)

Un **objetivo** agrupa las unidades necesarias para un estado del sistema. Sustituyen a los antiguos *runlevels*:

| Objetivo | Estado del sistema |
| --- | --- |
| `graphical.target` | Multiusuario, con red y entorno gráfico (escritorio). |
| `multi-user.target` | Multiusuario, con red y **sin** entorno gráfico (servidores). |
| `rescue.target` | Modo de rescate: un único usuario (root), sin red. |
| `emergency.target` | Mínimo posible: shell de root con el sistema de archivos en solo lectura. |
| `poweroff.target` / `reboot.target` | Apagar / reiniciar. |

```bash
systemctl get-default                          # Objetivo con el que arranca el sistema
sudo systemctl set-default multi-user.target   # Arrancar en modo texto a partir de ahora
sudo systemctl isolate multi-user.target       # Cambiar ahora (cierra el entorno gráfico)
```

### Crear un servicio para tu aplicación

Como desarrollador, querrás que tu aplicación arranque sola con el servidor y se reinicie si falla. Para ello basta con escribir un fichero de unidad. Ejemplo para una aplicación web en Python situada en `/opt/miapp`, que se ejecuta con el usuario de servicio `miapp` creado en el apartado 1.3:

```ini
# /etc/systemd/system/miapp.service
[Unit]
Description=Aplicación web de ejemplo (DAM)
# Arrancar después de que la red esté disponible
After=network-online.target
Wants=network-online.target

[Service]
# Usuario y grupo sin privilegios con los que se ejecuta
User=miapp
Group=miapp
WorkingDirectory=/opt/miapp
# Orden que se ejecuta (ruta absoluta obligatoria)
ExecStart=/usr/bin/python3 -m http.server 8080
# Si el proceso termina con error, reiniciarlo a los 5 segundos
Restart=on-failure
RestartSec=5
# Variables de entorno para la aplicación
Environment=ENTORNO=produccion

[Install]
# Habilitar el servicio lo incluye en el arranque normal en modo multiusuario
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload            # systemd lee el fichero nuevo
sudo systemctl enable --now miapp       # Habilitar y arrancar
systemctl status miapp
curl -I http://localhost:8080           # Comprobar que responde
journalctl -u miapp -f                  # Seguir su registro (apartado 10)
```

## 8.4 Procesos en Windows

### Administrador de tareas

Se abre con **`Ctrl + Mayús + Esc`** (o con `Ctrl + Alt + Supr`). Sus secciones principales son:

| Sección | Uso |
| --- | --- |
| **Procesos** | Aplicaciones y procesos en segundo plano agrupados, con su uso de CPU, memoria, disco y red. Botón **Finalizar tarea**. |
| **Rendimiento** | Gráficas de uso de los recursos (apartado 9). |
| **Historial de aplicaciones** | Consumo acumulado de las aplicaciones de la Tienda. |
| **Aplicaciones de arranque** | Programas que se inician con la sesión; se pueden deshabilitar (apartado 11). |
| **Usuarios** | Usuarios con sesión iniciada y sus procesos. |
| **Detalles** | Lista completa de procesos con **PID**, usuario y estado. Desde el menú contextual se puede **establecer la prioridad**, **finalizar el árbol de procesos** o **abrir la ubicación del archivo**. |
| **Servicios** | Lista de servicios con su estado; permite iniciarlos y detenerlos. |

### Desde la línea de comandos

```bat
:: CMD
tasklist                                   :: Lista de procesos con su PID y memoria
tasklist /svc                              :: Qué servicios hay dentro de cada proceso
tasklist /fi "imagename eq notepad.exe"    :: Filtrar por nombre
taskkill /im notepad.exe                   :: Pide cerrar todos los notepad.exe
taskkill /pid 4520 /f                      :: Fuerza la terminación de un PID
taskkill /im chrome.exe /t /f              :: /t: también los procesos hijos (el árbol)
```

```powershell
# PowerShell
Get-Process                                          # Todos los procesos (alias: ps, gps)
Get-Process -Name notepad                            # Por nombre (sin .exe)
Get-Process -Id 4520 | Format-List *                 # Todas las propiedades de un proceso
Get-Process | Sort-Object WorkingSet -Descending |
    Select-Object -First 5 Name, Id, @{n='MemoriaMB'; e={[math]::Round($_.WorkingSet / 1MB)}}
Get-Process -IncludeUserName                         # Con el usuario (requiere administrador)

Start-Process notepad                                # Lanza un programa
Start-Process pwsh -Verb RunAs                       # Lo lanza como administrador (aviso de UAC)
Stop-Process -Name notepad                           # Termina por nombre
Stop-Process -Id 4520 -Force                         # Termina a la fuerza
(Get-Process -Name notepad).PriorityClass = 'BelowNormal'   # Cambia la prioridad
```

`@{n='MemoriaMB'; e={...}}` es una **propiedad calculada**: crea una columna nueva (`n`, *name*) cuyo valor se obtiene ejecutando la expresión (`e`, *expression*) para cada objeto. `$_` representa el objeto actual de la tubería.

| Prioridad en Windows | Equivalencia aproximada en Linux |
| --- | --- |
| Tiempo real (*RealTime*) | `nice -20` y planificación de tiempo real. No usar: puede bloquear el sistema. |
| Alta (*High*) | `nice -10` |
| Por encima de lo normal (*AboveNormal*) | `nice -5` |
| Normal | `nice 0` |
| Por debajo de lo normal (*BelowNormal*) | `nice 5` |
| Baja (*Idle*) | `nice 19` |

## 8.5 Servicios en Windows

### La consola Servicios

Se abre con `services.msc`. Para cada servicio muestra su **nombre para mostrar**, su descripción, su **estado** y su **tipo de inicio**. En las propiedades de un servicio (doble clic) se puede:

- **Iniciar**, **Detener**, **Pausar** o **Reanudar** el servicio.
- Cambiar el **tipo de inicio**:

| Tipo de inicio | Significado |
| --- | --- |
| **Automático** | Se inicia al arrancar el sistema. |
| **Automático (inicio retrasado)** | Se inicia poco después del arranque, para que este sea más rápido. |
| **Manual** | Se inicia cuando alguien o algo lo solicita. |
| **Deshabilitado** | No se puede iniciar. |

- Ver el **nombre del servicio** (distinto del nombre para mostrar; por ejemplo, el *Administrador de trabajos de impresión* se llama `Spooler`) y la **ruta del ejecutable**.
- En la pestaña **Iniciar sesión**, elegir la cuenta con la que se ejecuta (*Sistema local*, *Servicio local*, *Servicio de red* u otra cuenta).
- En la pestaña **Recuperación**, indicar qué hacer si el servicio falla (reiniciarlo, ejecutar un programa o reiniciar el equipo).
- En la pestaña **Dependencias**, ver qué servicios necesita y cuáles dependen de él.

### Desde la línea de comandos

```powershell
# PowerShell (para modificar, como administrador)
Get-Service                                            # Todos los servicios
Get-Service -Name Spooler                              # Por nombre del servicio
Get-Service -DisplayName "*impres*"                    # Por nombre para mostrar, con comodines
Get-Service | Where-Object Status -eq 'Running'        # Solo los que están en ejecución

Stop-Service -Name Spooler
Start-Service -Name Spooler
Restart-Service -Name Spooler
Set-Service -Name Spooler -StartupType Manual          # Automatic, AutomaticDelayedStart, Manual, Disabled

Get-Service -Name Spooler -DependentServices           # Servicios que dependen de él

# Get-Service no muestra la ruta ni la cuenta: se obtienen con CIM
Get-CimInstance Win32_Service -Filter "Name='Spooler'" |
    Select-Object Name, State, StartMode, StartName, PathName
```

```bat
:: CMD: la orden sc.exe
sc query Spooler                     :: Estado
sc qc Spooler                        :: Configuración (tipo de inicio, ruta, cuenta)
sc stop Spooler
sc start Spooler
sc config Spooler start= demand      :: auto | delayed-auto | demand (manual) | disabled
net stop Spooler                     :: Alternativa clásica
net start                            :: Servicios iniciados
```

> [!WARNING]
> En **PowerShell**, `sc` es un alias de `Set-Content` (escribir en un fichero), no de la herramienta de servicios. Para usarla desde PowerShell escribe siempre **`sc.exe`**. Fíjate también en que `sc config` exige un **espacio después del `=`** (`start= demand`).

> [!CAUTION]
> No detengas ni deshabilites servicios del sistema sin saber qué hacen. Antes de tocar un servicio, lee su descripción y comprueba sus dependencias. Muchas "guías de optimización" de Internet recomiendan deshabilitar servicios que en realidad son necesarios para las actualizaciones, la red o la seguridad.

## 8.6 Comparativa

| Tarea | Linux | Windows (PowerShell) | Windows (CMD) |
| --- | --- | --- | --- |
| Listar procesos | `ps aux` | `Get-Process` | `tasklist` |
| Buscar un proceso | `pgrep -a nombre` | `Get-Process -Name nombre` | `tasklist /fi "imagename eq ..."` |
| Terminar un proceso | `kill PID` | `Stop-Process -Id PID` | `taskkill /pid PID` |
| Forzar la terminación | `kill -9 PID` | `Stop-Process -Id PID -Force` | `taskkill /pid PID /f` |
| Cambiar la prioridad | `renice` | `.PriorityClass = ...` | — |
| Listar servicios | `systemctl list-units --type=service` | `Get-Service` | `sc query`, `net start` |
| Estado de un servicio | `systemctl status servicio` | `Get-Service servicio` | `sc query servicio` |
| Arrancar / detener | `systemctl start` / `stop` | `Start-Service` / `Stop-Service` | `net start` / `net stop` |
| Inicio automático | `systemctl enable` | `Set-Service -StartupType Automatic` | `sc config ... start= auto` |
| Herramienta gráfica | Monitor del sistema, `htop` | Administrador de tareas, `services.msc` | |

## Ejercicios resueltos

### Ejercicio 8.1. Investigar un proceso

Lanza `sleep 900 &` y responde usando órdenes: ¿cuál es su PID? ¿Y el de su padre? ¿Qué proceso es su padre? ¿En qué estado está? Termínalo de forma ordenada.

{{% details "Ver solución" %}}
```bash
sleep 900 &
pgrep -a sleep                            # 5120 sleep 900
ps -o pid,ppid,stat,cmd -p 5120           # PPID 4987, STAT S (dormido)
ps -o pid,cmd -p 4987                     # El padre es la shell: bash
kill 5120                                 # SIGTERM
pgrep sleep || echo "Ya no existe"
```

Está en estado `S` porque `sleep` no hace nada salvo esperar. Su padre es la shell desde la que se lanzó.
{{% /details %}}

### Ejercicio 8.2. Servicio en Linux

Instala el servidor SSH (`openssh-server`). Comprueba si está activo y habilitado. Desactívalo para que no arranque al iniciar el sistema, pero déjalo en marcha ahora. Reinicia el equipo y verifica el resultado. Finalmente, déjalo habilitado y en marcha.

{{% details "Ver solución" %}}
```bash
sudo apt install openssh-server
systemctl is-active ssh; systemctl is-enabled ssh    # active / enabled
sudo systemctl disable ssh                           # Ya no arrancará en el inicio…
systemctl is-active ssh                              # …pero sigue "active" ahora
sudo reboot
# Tras reiniciar:
systemctl is-active ssh                              # inactive
sudo systemctl enable --now ssh
systemctl status ssh
```

> En Ubuntu, el servicio SSH puede arrancarse mediante **activación por *socket*** (`ssh.socket`): systemd escucha en el puerto 22 y arranca `ssh.service` cuando llega una conexión. Si al deshabilitar `ssh` sigue aceptando conexiones, deshabilita también el socket: `sudo systemctl disable --now ssh.socket`.
{{% /details %}}

### Ejercicio 8.3. Investigar un servicio de Windows

Averigua, con PowerShell, el nombre del servicio cuyo nombre para mostrar es *Cola de impresión* (o *Administrador de trabajos de impresión*), su tipo de inicio, la cuenta con la que se ejecuta y la ruta del ejecutable. Detenlo, comprueba qué ocurre al intentar imprimir y vuelve a iniciarlo.

{{% details "Ver solución" %}}
```powershell
Get-Service -DisplayName "*impresi*"                  # Name: Spooler
Get-CimInstance Win32_Service -Filter "Name='Spooler'" |
    Select-Object Name, StartMode, StartName, PathName
# Spooler  Auto  LocalSystem  C:\Windows\System32\spoolsv.exe

Stop-Service Spooler
Get-Printer          # Error: el servicio de cola de impresión no se está ejecutando
Start-Service Spooler
Get-Service Spooler  # Status: Running
```

Sin el servicio *Spooler* no se puede imprimir ni consultar las impresoras. El ejecutable es `spoolsv.exe`, que puedes ver con `Get-Process spoolsv`.
{{% /details %}}

### Ejercicio 8.4. Script de vigilancia de un servicio

Escribe un script de Bash que compruebe si un servicio (recibido como parámetro) está activo y, si no lo está, intente arrancarlo y registre el suceso con `logger`. Prográmalo con `cron` cada 5 minutos (Unidad 3).

{{% details "Ver solución" %}}
```bash
#!/usr/bin/env bash
# vigila_servicio.sh - Arranca un servicio si está detenido
# Uso: sudo ./vigila_servicio.sh nombre_servicio
set -u

servicio="${1:?Uso: $0 servicio}"     # Si falta el parámetro, muestra el mensaje y termina

if systemctl is-active --quiet "$servicio"; then   # --quiet: solo el código de salida
    exit 0
fi

logger -t vigilante "El servicio $servicio estaba detenido; se intenta arrancar"
if systemctl start "$servicio"; then
    logger -t vigilante "Servicio $servicio arrancado correctamente"
else
    logger -t vigilante -p user.err "No se ha podido arrancar $servicio"
    exit 1
fi
```

```bash
sudo install -m 755 vigila_servicio.sh /usr/local/sbin/
sudo crontab -e
# */5 * * * * /usr/local/sbin/vigila_servicio.sh cups
```
