# 11. Automatización y programación de tareas

Un script ahorra tiempo cuando lo ejecutamos nosotros, pero su verdadero valor aparece cuando el sistema lo ejecuta **automáticamente**: copias de seguridad nocturnas, limpieza de temporales, comprobaciones periódicas de espacio en disco… En este apartado veremos las principales herramientas para programar tareas en Linux y en Windows.

| Herramienta | Tipo de tarea | Ejemplo |
| --- | --- | --- |
| `cron` | **Periódica** (cada día, cada hora, los lunes…). | Copia de seguridad diaria a las 2:00. |
| `at` | **Una sola vez**, en un momento concreto. | Reiniciar un servicio esta noche a las 23:30. |
| *Timers* de systemd | Periódica o diferida, integrada con los servicios y registros de systemd. | Alternativa moderna a `cron`. |
| **Programador de tareas** | Periódica o puntual en **Windows**, con interfaz gráfica o desde PowerShell. | Ejecutar un script de PowerShell cada noche. |

## 11.1 `cron`: tareas periódicas

`cron` es un servicio que se ejecuta permanentemente y, cada minuto, comprueba si hay alguna tarea que lanzar. Cada usuario tiene su propia tabla de tareas, llamada **crontab**.

| Orden | Función |
| --- | --- |
| `crontab -e` | Edita tu crontab (la primera vez pregunta qué editor usar). |
| `crontab -l` | Muestra tu crontab. |
| `crontab -r` | **Borra** tu crontab completa (¡cuidado, no pide confirmación!). |
| `sudo crontab -u ana -l` | Muestra la crontab de otro usuario. |

### Formato de una línea

Cada línea de la crontab define una tarea con **cinco campos de tiempo** seguidos de la orden:

```text
┌───────────── minuto (0-59)
│ ┌─────────── hora (0-23)
│ │ ┌───────── día del mes (1-31)
│ │ │ ┌─────── mes (1-12)
│ │ │ │ ┌───── día de la semana (0-7; 0 y 7 son domingo, 1 lunes…)
│ │ │ │ │
* * * * *  orden a ejecutar
```

| Símbolo | Significado | Ejemplo |
| --- | --- | --- |
| `*` | Cualquier valor. | `*` en la hora = todas las horas. |
| `,` | Lista de valores. | `1,15` en el día = días 1 y 15. |
| `-` | Rango. | `1-5` en el día de la semana = de lunes a viernes. |
| `/` | Intervalo. | `*/10` en el minuto = cada 10 minutos. |

| Línea de crontab | Cuándo se ejecuta |
| --- | --- |
| `30 2 * * * /home/alumno/bin/backup.sh` | Todos los días a las 2:30. |
| `0 * * * * /home/alumno/bin/comprobar.sh` | Al principio de cada hora. |
| `*/15 * * * * /home/alumno/bin/ping.sh` | Cada 15 minutos. |
| `0 8 * * 1-5 /home/alumno/bin/informe.sh` | De lunes a viernes a las 8:00. |
| `0 0 1 * * /home/alumno/bin/mensual.sh` | El día 1 de cada mes a medianoche. |
| `@reboot /home/alumno/bin/al_arrancar.sh` | Cada vez que se inicia el sistema. |
| `@daily`, `@weekly`, `@monthly` | Una vez al día, a la semana, al mes. |

> [!TIP]
> La web <https://crontab.guru> traduce a lenguaje natural cualquier expresión de cron. Es muy útil para comprobar que la programación es la que queremos.

### El entorno de cron: errores típicos

Las tareas de cron **no** se ejecutan en una terminal con tu sesión, sino en un entorno mínimo. Esto provoca los errores más frecuentes:

1. **El `PATH` es muy reducido** (normalmente `/usr/bin:/bin`). Usa **rutas absolutas** para los scripts y los programas, o define el `PATH` al principio de la crontab.
2. **El directorio de trabajo es el personal**, no el del script. Dentro del script, usa rutas absolutas o haz `cd` al directorio adecuado.
3. **No hay pantalla**: lo que la tarea escriba se pierde (o se envía por correo local, si está configurado). **Redirige la salida a un fichero de registro.**
4. El script debe tener **permiso de ejecución** y un *shebang* correcto.
5. En una crontab, el carácter `%` es especial (equivale a un salto de línea): hay que escribirlo como `\%`, por ejemplo en `date +\%F`.

Una crontab bien escrita tiene este aspecto:

```text
# Variables para todas las tareas
PATH=/usr/local/bin:/usr/bin:/bin
MAILTO=""

# m  h  dom mes dow  orden
30   2  *   *   *    /home/alumno/bin/backup.sh >> /home/alumno/logs/backup.log 2>&1
*/10 *  *   *   *    /home/alumno/bin/espacio.sh >> /home/alumno/logs/espacio.log 2>&1
```

### Tareas del sistema

Además de las crontabs de cada usuario, el administrador puede programar tareas del sistema:

| Ubicación | Uso |
| --- | --- |
| `/etc/crontab` y `/etc/cron.d/` | Tareas del sistema. Tienen un **sexto campo** con el usuario que ejecuta la orden. |
| `/etc/cron.hourly/`, `cron.daily/`, `cron.weekly/`, `cron.monthly/` | Basta con copiar un script ejecutable (sin extensión `.sh`) en el directorio para que se ejecute con esa periodicidad. |

```text
# /etc/cron.d/limpieza  (fíjate en el campo de usuario "root")
0 3 * * 0  root  find /tmp -type f -mtime +7 -delete
```

## 11.2 `at`: tareas de una sola vez

`at` ejecuta una orden **una sola vez** en el momento indicado. Puede que haya que instalarlo (`sudo apt install at`).

```bash
at 23:30                          # Abre un prompt: escribe las órdenes y pulsa Ctrl+D
at now + 10 minutes <<< "/home/alumno/bin/aviso.sh"
echo "systemctl restart nginx" | sudo at 03:00 tomorrow
at -f tarea.sh 08:00 2026-12-01   # Ejecuta las órdenes del fichero tarea.sh
atq                               # Lista las tareas pendientes (con su número)
atrm 3                            # Cancela la tarea número 3
```

## 11.3 *Timers* de systemd (ampliación)

En los sistemas con systemd, los ***timers*** son la alternativa moderna a `cron`. Requieren dos ficheros: un **servicio** (qué se ejecuta) y un ***timer*** (cuándo). A cambio, ofrecen ventajas: el registro queda en `journalctl`, se pueden recuperar las ejecuciones perdidas si el equipo estaba apagado (`Persistent=true`) y se gestionan con `systemctl` como cualquier servicio.

```ini
# /etc/systemd/system/backup.service
[Unit]
Description=Copia de seguridad de /home

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh
```

```ini
# /etc/systemd/system/backup.timer
[Unit]
Description=Copia de seguridad diaria a las 2:30

[Timer]
OnCalendar=*-*-* 02:30:00
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl daemon-reload              # Relee los ficheros de unidades
sudo systemctl enable --now backup.timer  # Activa el timer
systemctl list-timers                     # Muestra los timers y su próxima ejecución
journalctl -u backup.service              # Registro de las ejecuciones
systemd-analyze calendar "Mon..Fri 08:00" # Comprueba una expresión OnCalendar
```

## 11.4 El Programador de tareas de Windows

En Windows, el equivalente de `cron` es el **Programador de tareas** (*Task Scheduler*). Cada tarea se compone de:

| Elemento | Significado | Ejemplo |
| --- | --- | --- |
| **Desencadenador** (*trigger*) | Cuándo se ejecuta. | Diariamente a las 2:30, al iniciar sesión, al arrancar el equipo… |
| **Acción** (*action*) | Qué se ejecuta. | El programa `pwsh.exe` con el script como argumento. |
| **Entidad de seguridad** (*principal*) | Con qué usuario y privilegios se ejecuta. | El usuario actual o la cuenta `SYSTEM`, con privilegios elevados. |
| **Configuración** (*settings*) | Comportamiento ante incidencias. | Reintentar si falla, ejecutar si se perdió una ejecución… |

### Desde la interfaz gráfica

{{% steps %}}
1. ## Abrir el Programador

   Pulsa `Win+R` y escribe `taskschd.msc`, o búscalo en el menú Inicio.

2. ## Crear la tarea

   En el panel derecho, elige **Crear tarea básica…**, escribe un nombre y una descripción.

3. ## Elegir el desencadenador

   Selecciona la periodicidad (diaria, semanal, al iniciar el equipo…) y la hora.

4. ## Indicar la acción

   Elige **Iniciar un programa**. En *Programa o script* escribe `pwsh.exe` (o `powershell.exe` en Windows PowerShell 5.1) y en *Agregar argumentos* `-NoProfile -ExecutionPolicy Bypass -File "C:\Scripts\backup.ps1"`.

5. ## Revisar y comprobar

   Al terminar, la tarea aparece en la **Biblioteca del Programador de tareas**. Con el botón derecho → **Ejecutar** se prueba al momento; la columna *Resultado de la última ejecución* muestra `0x0` si terminó correctamente.
{{% /steps %}}

### Desde PowerShell

El módulo `ScheduledTasks` permite crear las tareas desde un script, lo que facilita automatizar también su instalación:

| Cmdlet | Función |
| --- | --- |
| `New-ScheduledTaskAction` | Define la acción (programa y argumentos). |
| `New-ScheduledTaskTrigger` | Define el desencadenador (`-Daily`, `-Weekly`, `-AtStartup`, `-AtLogOn`, `-Once`). |
| `New-ScheduledTaskPrincipal` | Define el usuario y el nivel de privilegios. |
| `Register-ScheduledTask` | Registra (crea) la tarea. |
| `Get-ScheduledTask` / `Get-ScheduledTaskInfo` | Consulta las tareas y su última ejecución. |
| `Start-ScheduledTask` | Ejecuta la tarea en ese momento. |
| `Disable-ScheduledTask` / `Unregister-ScheduledTask` | Desactiva / elimina la tarea. |

```powershell
# Requiere una consola de PowerShell abierta como administrador
$accion   = New-ScheduledTaskAction -Execute "pwsh.exe" `
              -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\Scripts\backup.ps1"'
$disparo  = New-ScheduledTaskTrigger -Daily -At "02:30"
$usuario  = New-ScheduledTaskPrincipal -UserId "SYSTEM" -RunLevel Highest

Register-ScheduledTask -TaskName "Copia diaria" -Description "Copia de Documentos" `
    -Action $accion -Trigger $disparo -Principal $usuario

Get-ScheduledTaskInfo -TaskName "Copia diaria"   # LastRunTime, LastTaskResult, NextRunTime
```

También existe la orden clásica `schtasks`, que funciona en CMD y PowerShell:

```powershell
schtasks /Create /TN "Copia diaria" /SC DAILY /ST 02:30 /RU SYSTEM `
    /TR "pwsh.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\backup.ps1"
schtasks /Query /TN "Copia diaria"
schtasks /Delete /TN "Copia diaria" /F
```

> [!NOTE]
> `-ExecutionPolicy Bypass` permite ejecutar ese script concreto sin cambiar la política de ejecución del equipo (apartado 13). Igual que en `cron`, usa **rutas absolutas** dentro del script y registra lo que hace en un fichero, porque la tarea se ejecuta sin ventana.

## 11.5 Registrar lo que hacen los scripts automáticos

Como nadie ve la pantalla de una tarea programada, es imprescindible que el script **deje constancia** de lo que hace:

- Redirigir la salida a un fichero de registro (`>> fichero.log 2>&1`), con fecha y hora en cada línea.
- Usar `logger`, que envía mensajes al registro del sistema y permite consultarlos con `journalctl`:

```bash
logger -t backup "Copia terminada correctamente"    # -t: etiqueta
journalctl -t backup                                # Consulta los mensajes con esa etiqueta
```

- Terminar con un **código de salida** correcto (0 si todo ha ido bien).

### Ejercicio 11.2. Copia de seguridad con rotación

Escribe un script `backup.sh` que:

1. Cree en `/var/backups/home` (o en el directorio pasado como segundo parámetro) un fichero `.tar.gz` con el contenido del directorio pasado como primer parámetro, cuyo nombre incluya la fecha y la hora.
2. Conserve solo las **7 copias más recientes**, borrando las más antiguas.
3. Registre el resultado con `logger` y en un fichero de registro.
4. Termine con código 0 si todo va bien y distinto de 0 si algo falla.

Después, prográmalo para que se ejecute cada día a las 2:30.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
#==============================================================
# backup.sh - Copia de seguridad comprimida con rotación
# Uso: backup.sh <directorio_origen> [directorio_destino]
#==============================================================
set -uo pipefail

readonly MAX_COPIAS=7
readonly ORIGEN=${1:?"Uso: $0 <directorio_origen> [directorio_destino]"}
readonly DESTINO=${2:-/var/backups/home}
readonly LOG="$DESTINO/backup.log"
readonly FECHA=$(date +%Y-%m-%d_%H%M)
readonly NOMBRE="backup_$(basename "$ORIGEN")_$FECHA.tar.gz"

log() {
    echo "$(date '+%F %T') $*" >> "$LOG"
    logger -t backup "$*"
}

# 1. Comprobaciones previas
if [[ ! -d $ORIGEN ]]; then
    echo "Error: el origen '$ORIGEN' no existe" >&2
    exit 1
fi
mkdir -p "$DESTINO" || { echo "No se puede crear '$DESTINO'" >&2; exit 2; }

# 2. Crear la copia
if tar -czf "$DESTINO/$NOMBRE" -C "$(dirname "$ORIGEN")" "$(basename "$ORIGEN")"; then
    log "OK: creada $NOMBRE ($(du -h "$DESTINO/$NOMBRE" | cut -f1))"
else
    log "ERROR: fallo al crear $NOMBRE"
    rm -f "$DESTINO/$NOMBRE"          # No dejamos copias a medias
    exit 3
fi

# 3. Rotación: listamos las copias de la más reciente a la más antigua (ls -t)
#    y borramos a partir de la octava (tail -n +8)
ls -1t "$DESTINO"/backup_"$(basename "$ORIGEN")"_*.tar.gz 2>/dev/null \
    | tail -n +$(( MAX_COPIAS + 1 )) \
    | while IFS= read -r antigua; do
        rm -f -- "$antigua"
        log "Rotación: borrada $(basename "$antigua")"
      done

exit 0
```

**Instalación y programación:**

```bash
sudo cp backup.sh /usr/local/bin/backup.sh
sudo chmod 755 /usr/local/bin/backup.sh
sudo /usr/local/bin/backup.sh /home      # Prueba manual
ls -lh /var/backups/home
sudo crontab -e                          # Crontab de root, porque necesita leer todo /home
```

```text
30 2 * * * /usr/local/bin/backup.sh /home >> /var/log/backup_cron.log 2>&1
```

**Restauración** de una copia (siempre en un directorio de prueba primero):

```bash
mkdir /tmp/restaurar
sudo tar -xzf /var/backups/home/backup_home_2026-11-08_0230.tar.gz -C /tmp/restaurar
```

> [!NOTE]
> Una copia de seguridad guardada en el mismo disco que los datos no protege frente a una avería del disco. En un entorno real, las copias se envían también a otro equipo o a la nube (por ejemplo con `rsync` o `rclone`), siguiendo la regla **3-2-1**: 3 copias, en 2 soportes distintos, 1 de ellas fuera del lugar de trabajo.
{{% /details %}}

### Ejercicio 11.3. Vigilante de espacio en disco

Escribe un script que compruebe el porcentaje de uso de todos los sistemas de ficheros montados y, si alguno supera un umbral (por defecto, 80 %), escriba un aviso en el registro del sistema. Prográmalo cada 10 minutos.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# espacio.sh - Avisa si algún sistema de ficheros supera el umbral de uso
# Uso: espacio.sh [umbral]
umbral=${1:-80}
alertas=0

# --output=pcent,target: solo el % de uso y el punto de montaje (una línea por sistema)
# -x tmpfs -x devtmpfs: excluye los sistemas de ficheros en memoria
# tail -n +2: elimina la línea de cabecera
while read -r uso punto; do
    uso=${uso%\%}                      # Quita el símbolo % del final
    if (( uso >= umbral )); then
        logger -t espacio -p user.warning "ATENCIÓN: $punto al $uso% (umbral $umbral%)"
        echo "$(date '+%F %T') AVISO $punto al $uso%"
        alertas=$(( alertas + 1 ))
    fi
done < <(df --output=pcent,target -x tmpfs -x devtmpfs | tail -n +2)

(( alertas == 0 )) && echo "$(date '+%F %T') OK: ningún sistema de ficheros supera el $umbral%"
exit 0
```

```text
*/10 * * * * /home/alumno/bin/espacio.sh 80 >> /home/alumno/logs/espacio.log 2>&1
```

Para comprobar que funciona sin llenar el disco, ejecútalo con un umbral bajo: `./espacio.sh 5` y consulta `journalctl -t espacio`.
{{% /details %}}

### Ejercicio 11.4. Programar una copia en Windows

Programa el script `backup.ps1` del apartado 13 (guardado en `C:\Scripts`) para que se ejecute de lunes a viernes a las 18:00 con tu usuario. Después, ejecútalo manualmente para probarlo, comprueba el resultado y elimina la tarea.

{{% details "Ver solución" %}}
```powershell
$accion  = New-ScheduledTaskAction -Execute "pwsh.exe" `
             -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\Scripts\backup.ps1"'
$disparo = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Monday,Tuesday,Wednesday,Thursday,Friday -At "18:00"

Register-ScheduledTask -TaskName "Backup laborables" -Action $accion -Trigger $disparo

Start-ScheduledTask -TaskName "Backup laborables"            # Prueba inmediata
Get-ScheduledTaskInfo -TaskName "Backup laborables" |
    Select-Object LastRunTime, LastTaskResult, NextRunTime   # LastTaskResult = 0 → correcto

Unregister-ScheduledTask -TaskName "Backup laborables" -Confirm:$false
```

Sin `-Principal`, la tarea se registra con el usuario actual y solo se ejecuta mientras tiene la sesión iniciada. Para que se ejecute aunque no haya nadie conectado hay que usar una cuenta de servicio (como `SYSTEM`) o indicar la contraseña del usuario.
{{% /details %}}
