# 6. Variables, parámetros, entrada y salida

## 6.1 Variables

Una **variable** es un nombre que guarda un valor para poder usarlo más tarde. En Bash:

- **No es obligatorio declararlas** y, por defecto, no tienen tipo: todo valor es, en principio, una **cadena de texto**.
- Se **asignan** con `nombre=valor`, **sin espacios** alrededor del `=`.
- Se **consultan** anteponiendo `$`: `$nombre` o, de forma más explícita, `${nombre}`.
- Consultar una variable que no existe no da error: se sustituye por una cadena vacía (salvo con `set -u`).

```bash
#!/bin/bash
ciclo="DAM"
curso=1
modulo="Sistemas Informáticos"

echo "Estudio $curso.º de $ciclo, módulo $modulo"
echo "Fichero de notas: ${ciclo}_notas.txt"   # Las llaves delimitan el nombre
echo "Fichero de notas: $ciclo_notas.txt"     # ¡Error! Busca la variable "ciclo_notas"
```

**Reglas para los nombres**: letras, cifras y guion bajo; no pueden empezar por cifra; distinguen mayúsculas. Por convenio, las variables de **entorno** y las constantes se escriben en MAYÚSCULAS (`PATH`, `HOME`, `MAX_INTENTOS`) y las variables propias del script en minúsculas (`fichero`, `contador`), para no sobrescribir por error una variable del sistema.

```bash
readonly IVA=21        # Constante: no se puede modificar
unset curso            # Elimina la variable
```

### Tipos de datos: `declare`

Aunque Bash guarda todo como texto, la orden interna `declare` permite indicar el **tipo** o un **atributo** de una variable. Es lo más parecido a declarar tipos que ofrece Bash:

| Declaración | Tipo / atributo | Ejemplo |
| --- | --- | --- |
| *(ninguna)* | Cadena de texto (tipo por defecto). | `nombre="Ana"` |
| `declare -i` | **Entero**: las asignaciones se evalúan como expresiones aritméticas. | `declare -i total=2+3` → `5` |
| `declare -a` | *Array* indexado (lista). | `declare -a notas=(7 5 9)` |
| `declare -A` | *Array* asociativo (diccionario). | `declare -A capital` |
| `declare -r` | Constante (solo lectura); equivale a `readonly`. | `declare -r PI=3` |
| `declare -x` | Variable de entorno; equivale a `export`. | `declare -x EDITOR=nano` |
| `declare -l` / `-u` | Convierte el valor a minúsculas / mayúsculas al asignarlo. | `declare -u siglas=dam` → `DAM` |

```bash
declare -i contador=10
contador=contador+5        # Al ser entero, se calcula: 15
echo "$contador"           # 15
contador="hola"            # Un texto no numérico vale 0 en un entero
echo "$contador"           # 0

declare -p contador        # Muestra cómo está declarada: declare -i contador="0"
```

Los *arrays* se estudian en el apartado 10. Bash **no** tiene tipo decimal ni booleano: los decimales se calculan con herramientas externas (apartado 6.5) y los valores lógicos se representan con códigos de salida (apartado 7).

## 6.2 Comillas

Las comillas son una de las fuentes de errores más habituales en Bash. Conviene tener claras las diferencias:

| Escritura | Comportamiento | Ejemplo | Resultado |
| --- | --- | --- | --- |
| `"…"` (dobles) | Agrupan en **un solo argumento** y **sí** sustituyen `$variables` y `$(órdenes)`. | `echo "Hola $USER"` | `Hola alumno` |
| `'…'` (simples) | Agrupan y **no** sustituyen nada: texto literal. | `echo 'Hola $USER'` | `Hola $USER` |
| `\` (barra invertida) | Escapa (quita el significado especial de) el carácter siguiente. | `echo "Precio: \$5"` | `Precio: $5` |
| Sin comillas | La shell **divide** el valor por los espacios y **expande** los comodines. | `echo $var` | Imprevisible |

¿Por qué es tan importante entrecomillar las variables? Observa este ejemplo:

```bash
fichero="mis notas.txt"
touch "$fichero"     # Crea UN fichero llamado "mis notas.txt"
rm $fichero          # ¡Intenta borrar DOS ficheros: "mis" y "notas.txt"!
rm "$fichero"        # Correcto
```

> [!IMPORTANT]
> Regla de oro: **entrecomilla siempre las variables con comillas dobles** (`"$var"`), salvo que sepas exactamente por qué no hacerlo.

## 6.3 Variables de entorno

Las **variables de entorno** las define el sistema o el usuario y las heredan todos los programas que se ejecutan desde la shell.

| Variable | Contenido |
| --- | --- |
| `HOME` | Directorio personal del usuario. |
| `USER` | Nombre del usuario. |
| `PWD` | Directorio actual. |
| `PATH` | Directorios donde se buscan las órdenes, separados por `:`. |
| `SHELL` | Shell por defecto del usuario. |
| `HOSTNAME` | Nombre del equipo. |
| `LANG` | Idioma y configuración regional. |
| `RANDOM` | Un número aleatorio entre 0 y 32767 cada vez que se consulta. |

```bash
env                          # Lista las variables de entorno
echo "$PATH"
export EDITOR=nano           # Crea una variable de entorno (la heredarán los procesos hijos)
export PATH="$PATH:$HOME/herramientas"   # Añade un directorio al PATH
```

Una variable creada sin `export` solo existe en la shell actual; los scripts y programas que lancemos no la verán. Para que una variable o un `alias` se definan en todas las sesiones, se añaden al fichero `~/.bashrc`.

## 6.4 Sustitución de órdenes

`$(orden)` ejecuta la orden y se sustituye por **lo que esta escribe en la salida estándar**. Así podemos guardar el resultado de cualquier orden en una variable:

```bash
hoy=$(date +%F)
num_usuarios=$(wc -l < /etc/passwd)
kernel=$(uname -r)
echo "El $hoy hay $num_usuarios usuarios y el kernel es $kernel"
```

> [!NOTE]
> Encontrarás en scripts antiguos la forma con acentos graves: `` hoy=`date +%F` ``. Funciona igual, pero `$(…)` es más legible y se puede anidar sin problemas: `$(basename "$(pwd)")`. Usa siempre `$(…)`.

## 6.5 Aritmética

Como las variables son texto, Bash necesita una sintaxis especial para hacer cálculos. La forma recomendada es la **expansión aritmética** `$(( ))`:

```bash
a=17
b=5
echo "Suma: $(( a + b ))"            # 22  (dentro de (( )) no hace falta el $)
echo "Resta: $(( a - b ))"           # 12
echo "Producto: $(( a * b ))"        # 85
echo "Cociente: $(( a / b ))"        # 3   -> ¡división ENTERA!
echo "Resto: $(( a % b ))"           # 2
echo "Potencia: $(( 2 ** 10 ))"      # 1024

total=$(( (a + b) * 2 ))             # Paréntesis para la precedencia
(( contador = 0 ))                   # (( )) evalúa sin devolver el valor
(( contador++ ))                     # Incremento: contador vale 1
(( contador += 5 ))                  # contador vale 6
let "contador = contador * 2"        # let es equivalente a (( ))
```

| Operador | Significado | | Operador | Significado |
| --- | --- | --- | --- | --- |
| `+ - * /` | Suma, resta, producto, cociente entero | | `++ --` | Incremento, decremento |
| `%` | Resto de la división | | `+= -= *= /=` | Operación y asignación |
| `**` | Potencia | | `< > <= >= == !=` | Comparaciones (devuelven 1 o 0) |

> [!NOTE]
> `(( ))` también devuelve un código de salida: `0` (verdadero) si el resultado es distinto de cero y `1` (falso) si es cero. Por eso `(( contador++ ))` con `contador=0` "falla" y, con `set -e`, detendría el script. Si usas el modo estricto, incrementa con `contador=$(( contador + 1 ))`.

Bash **solo trabaja con enteros**. Para decimales hay que recurrir a otra herramienta, como `awk` o `bc` (este último puede requerir `sudo apt install bc`):

```bash
awk "BEGIN { printf \"%.2f\n\", 17 / 5 }"   # 3.40
echo "scale=2; 17 / 5" | bc                 # 3.40
```

> [!WARNING]
> En apuntes antiguos aparecen `expr 3 + 2` y `$[ 3 + 2 ]`. `expr` es un programa externo, lento e incómodo (exige espacios y escapar el `*`: `expr 3 \* 2`), y `$[ ]` es una sintaxis **obsoleta** que puede desaparecer. Utiliza siempre `$(( ))`.

## 6.6 Parámetros de un script

Igual que `ls -l /etc` recibe una opción y un argumento, nuestros scripts pueden recibir **parámetros** desde la línea de órdenes. Dentro del script se consultan con estas **variables especiales**:

| Variable | Contenido |
| --- | --- |
| `$0` | Nombre con el que se ha invocado el script. |
| `$1`, `$2`, … `$9` | Primer, segundo… noveno parámetro. A partir del décimo: `${10}`, `${11}`… |
| `$#` | **Número** de parámetros recibidos. |
| `"$@"` | Todos los parámetros, **cada uno como un elemento independiente**. Es la forma correcta de recorrerlos. |
| `"$*"` | Todos los parámetros unidos en **una sola cadena**. |
| `$?` | Código de salida de la última orden. |
| `$$` | PID del propio script. |
| `$!` | PID del último proceso lanzado en segundo plano. |

```bash
#!/bin/bash
# parametros.sh - Muestra los parámetros recibidos
echo "Script:        $0"
echo "Nº parámetros: $#"
echo "Primero:       $1"
echo "Segundo:       $2"
echo "Todos:         $*"
```

```text
$ ./parametros.sh hola "buenos días" 42
Script:        ./parametros.sh
Nº parámetros: 3
Primero:       hola
Segundo:       buenos días
Todos:         hola buenos días 42
```

Fíjate en que `"buenos días"` llega como **un único** parámetro gracias a las comillas.

### Desplazar parámetros: `shift`

`shift` descarta `$1` y desplaza el resto una posición: `$2` pasa a ser `$1`, `$3` pasa a ser `$2`, y `$#` disminuye en uno. Es útil para procesar los parámetros de uno en uno:

```bash
#!/bin/bash
echo "Primero: $1 (hay $#)"
shift
echo "Ahora el primero es: $1 (quedan $#)"
```

### Valores por defecto

```bash
destino=${1:-/tmp}       # Si no se pasa $1 (o está vacío), se usa /tmp
nombre=${2:-"invitado"}
fichero=${1:?"Falta el nombre del fichero"}   # Si falta $1, muestra el error y termina
```

## 6.7 Entrada de datos: `read`

`read` detiene el script hasta que el usuario escribe una línea y pulsa Intro, y guarda lo escrito en una o varias variables.

| Opción | Efecto |
| --- | --- |
| `-p "texto"` | Muestra un mensaje (*prompt*) antes de leer. |
| `-r` | No interpreta las barras invertidas `\` (recomendado **siempre**). |
| `-s` | No muestra lo que se escribe (contraseñas). |
| `-n N` | Termina tras leer N caracteres, sin esperar a Intro. |
| `-t N` | Espera como máximo N segundos. |
| `-a array` | Guarda cada palabra en un elemento de un *array* (apartado 10). |

```bash
#!/bin/bash
read -rp "¿Cómo te llamas? " nombre
read -rp "¿Cuántos años tienes? " edad
echo "Hola, $nombre. Dentro de 10 años tendrás $(( edad + 10 ))."

read -rsp "Contraseña: " clave
echo                                  # Salto de línea (con -s no se muestra el Intro)
echo "La contraseña tiene ${#clave} caracteres."   # ${#var} = longitud

read -rp "Nombre y apellido: " nom ape   # La primera palabra va a nom, el resto a ape
read -rn 1 -p "¿Continuar? (s/n) " resp
echo
```

## 6.8 Salida de datos: `echo` y `printf`

`echo` es suficiente para mensajes sencillos:

```bash
echo "Texto con salto de línea al final"
echo -n "Sin salto de línea: "
echo -e "Tabulador:\tfin\nNueva línea"   # -e interpreta \t, \n…
```

`printf` permite controlar el **formato** (anchura de columnas, decimales…) de forma precisa y se comporta igual en todos los sistemas. Recibe una cadena de formato y los valores:

| Formato | Significado |
| --- | --- |
| `%s` | Cadena. |
| `%d` | Número entero. |
| `%f` / `%.2f` | Número decimal / con dos decimales. |
| `%10s` / `%-10s` | Cadena alineada a la derecha / izquierda en 10 caracteres. |
| `%05d` | Entero de 5 cifras rellenado con ceros. |
| `\n`, `\t` | Salto de línea, tabulador (`printf` **no** añade el salto final automáticamente). |

```bash
printf "%-10s %5s\n" "Alumno" "Nota"
printf "%-10s %5.1f\n" "Ana" 8.75 "Luis" 6.5   # El formato se reutiliza para cada pareja
printf "Fichero_%03d.txt\n" 7                   # Fichero_007.txt
```

```text
Alumno      Nota
Ana          8.8
Luis         6.5
Fichero_007.txt
```

### Ejercicio 6.1. Calculadora de dos números

Script que reciba dos números enteros **como parámetros** y muestre su suma, resta, producto, cociente y resto. Si no recibe exactamente dos parámetros, debe mostrar cómo se usa y terminar con código 1.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# calculadora.sh - Operaciones básicas con dos enteros
# Uso: ./calculadora.sh <num1> <num2>

if [[ $# -ne 2 ]]; then              # Las condiciones se explican en el apartado 7
    echo "Uso: $0 <num1> <num2>" >&2
    exit 1
fi

a=$1
b=$2

echo "$a + $b = $(( a + b ))"
echo "$a - $b = $(( a - b ))"
echo "$a * $b = $(( a * b ))"
echo "$a / $b = $(( a / b ))   (división entera)"
echo "$a % $b = $(( a % b ))"
```

```text
$ ./calculadora.sh 17 5
17 + 5 = 22
17 - 5 = 12
17 * 5 = 85
17 / 5 = 3   (división entera)
17 % 5 = 2
```

¿Qué ocurre si el segundo número es 0 o si se pasa una letra? En el apartado 7 aprenderemos a validar la entrada; la versión completa está en los [ejercicios resueltos]({{< relref "/U03/U03.12-Ejercicios-Resueltos-CAS.md" >}}).

### Ejercicio 6.2. Conversor de unidades

Script interactivo que pida una cantidad de **segundos** y la muestre en horas, minutos y segundos. Por ejemplo, `3725` → `1 h 2 min 5 s`.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# segundos.sh - Convierte segundos a h/min/s

read -rp "Introduce un número de segundos: " total

horas=$(( total / 3600 ))
minutos=$(( (total % 3600) / 60 ))
segundos=$(( total % 60 ))

echo "$total segundos = $horas h $minutos min $segundos s"
printf "Formato reloj: %02d:%02d:%02d\n" "$horas" "$minutos" "$segundos"
```

```text
Introduce un número de segundos: 3725
3725 segundos = 1 h 2 min 5 s
Formato reloj: 01:02:05
```

### Ejercicio 6.3. Generador de ficheros de proyecto

Script que reciba el nombre de un proyecto (por defecto, `proyecto`) y cree en el directorio actual una carpeta con ese nombre, los subdirectorios `src`, `docs` y `tests`, y un `README.md` con el título del proyecto, el autor (el usuario actual) y la fecha.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# nuevo_proyecto.sh - Crea el esqueleto de un proyecto
# Uso: ./nuevo_proyecto.sh [nombre]

nombre=${1:-proyecto}

mkdir -p "$nombre"/{src,docs,tests}

cat > "$nombre/README.md" <<EOF
# $nombre

- Autor: $USER
- Fecha de creación: $(date +%F)

## Descripción

Escribe aquí la descripción del proyecto.
EOF

echo "Proyecto '$nombre' creado:"
ls -R "$nombre"
```

### Ejercicio 6.4. `"$@"` frente a `"$*"`

Ejecuta este script como `./comillas.sh uno "dos tres" cuatro` y explica la diferencia entre los dos bucles (el bucle `for` se explica en el apartado 8: repite la orden `echo` para cada elemento).

```bash
#!/bin/bash
echo 'Con "$@":'
for p in "$@"; do echo "  [$p]"; done
echo 'Con "$*":'
for p in "$*"; do echo "  [$p]"; done
```

{{% details "Ver solución" %}}
```text
Con "$@":
  [uno]
  [dos tres]
  [cuatro]
Con "$*":
  [uno dos tres cuatro]
```

`"$@"` mantiene **cada parámetro por separado**, respetando que `"dos tres"` es uno solo. `"$*"` los **une** todos en una única cadena. Por eso, para recorrer o reenviar los parámetros a otra orden, se usa siempre `"$@"`.
{{% /details %}}
