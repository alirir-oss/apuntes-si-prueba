# 1. Introducción a la shell

## 1.1 Terminal, consola y shell

Estos tres términos se usan a menudo como sinónimos, pero no significan lo mismo:

| Concepto | Qué es | Ejemplos |
| --- | --- | --- |
| **Terminal** (emulador de terminal) | Programa con una ventana donde se escribe texto y se ve la respuesta. | GNOME Terminal, Konsole, Windows Terminal, el terminal integrado de VS Code. |
| **Consola** | Terminal "física" del sistema, sin entorno gráfico (la que aparece con `Ctrl+Alt+F3`). | `tty1`, `tty2`… |
| **Shell** (intérprete de comandos) | Programa que **lee** lo que escribimos, lo **interpreta** y pide al sistema operativo que lo **ejecute**. | `bash`, `zsh`, `sh`/`dash`, `fish`, PowerShell. |

Es decir: el terminal es la "ventana" y la shell es el "cerebro" que hay detrás. En esta unidad usaremos **Bash** (*Bourne Again SHell*), la shell por defecto en la mayoría de distribuciones GNU/Linux y la más utilizada en servidores, contenedores Docker y *pipelines* de CI/CD.

```bash
echo "$SHELL"      # Muestra la shell configurada para tu usuario
cat /etc/shells    # Lista las shells instaladas en el sistema
bash --version     # Muestra la versión de Bash
```

> [!NOTE]
> macOS utiliza **zsh** por defecto desde 2019. La mayoría de lo que se explica aquí funciona igual en zsh, pero los scripts de esta unidad se ejecutarán siempre con Bash.

## 1.2 El *prompt*

Cuando abrimos un terminal, la shell muestra el ***prompt*** (indicador), que nos avisa de que está esperando una orden:

```text
alumno@dam-pc:~/proyectos$
```

| Parte | Significado |
| --- | --- |
| `alumno` | Usuario con el que hemos iniciado sesión. |
| `dam-pc` | Nombre del equipo (*hostname*). |
| `~/proyectos` | Directorio actual. `~` representa el directorio personal del usuario (`/home/alumno`). |
| `$` | Usuario normal. Si aparece `#`, estamos trabajando como **root** (administrador). |

> [!WARNING]
> En la documentación, el símbolo `$` o `#` del *prompt* **no se escribe**: solo indica quién ejecuta la orden. En esta unidad omitiremos el *prompt* en los bloques de código, salvo cuando queramos mostrar también la salida.

## 1.3 Sintaxis de un comando

Todos los comandos siguen la misma estructura general:

```text
comando [opciones] [argumentos]
```

- **Comando**: nombre del programa u orden que se ejecuta (`ls`, `cp`, `grep`…).
- **Opciones** (también llamadas *flags* o modificadores): cambian el comportamiento del comando. Pueden ser:
  - **Cortas**: un guion y una letra (`-l`, `-a`). Se pueden agrupar: `-la` equivale a `-l -a`.
  - **Largas**: dos guiones y una palabra (`--all`, `--human-readable`). Son más legibles y se recomiendan en los scripts.
- **Argumentos**: los datos sobre los que actúa el comando (ficheros, directorios, textos…).

Los elementos se separan con **espacios**, y Bash **distingue mayúsculas de minúsculas** (`ls` no es lo mismo que `LS`).

```bash
ls -l -h /etc          # comando: ls | opciones: -l -h | argumento: /etc
ls -lh /etc            # lo mismo, con las opciones cortas agrupadas
ls --format=long --human-readable /etc   # lo mismo, con opciones largas
```

Algunas opciones necesitan a su vez un valor, por ejemplo `head -n 5 fichero` (muestra 5 líneas). El doble guion `--` indica "fin de las opciones": todo lo que va detrás se trata como argumento, aunque empiece por guion (`rm -- -fichero-raro`).

### Tipos de comandos

No todos los comandos son programas independientes. El comando `type` nos dice qué tipo de comando es cada uno:

```bash
type cd       # cd is a shell builtin       -> comando interno de Bash
type ls       # ls is aliased to 'ls --color=auto' -> alias
type grep     # grep is /usr/bin/grep       -> programa externo
command -v python3   # Muestra la ruta del ejecutable (o nada si no existe)
```

| Tipo | Descripción |
| --- | --- |
| **Interno** (*builtin*) | Forma parte de la propia shell: `cd`, `echo`, `read`, `exit`, `export`… |
| **Externo** | Programa guardado en un directorio del sistema (`/usr/bin/ls`). La shell lo busca en los directorios de la variable `PATH`. |
| **Alias** | Atajo definido por el usuario: `alias ll='ls -l'`. |
| **Función** | Bloque de código con nombre definido en la shell (lo veremos en el apartado 9). |

## 1.4 Cómo obtener ayuda

Nadie memoriza todas las opciones de todos los comandos. Lo importante es **saber consultarlas**:

| Orden | Para qué sirve |
| --- | --- |
| `man comando` | Abre la página del manual. Se navega con las flechas, `/texto` busca, `n` va al siguiente resultado y `q` sale. |
| `comando --help` | Resumen breve de uso y opciones (casi todos los programas externos lo tienen). |
| `help comando` | Ayuda de los comandos **internos** de Bash (`help cd`, `help read`). |
| `man -k palabra` | Busca comandos relacionados con una palabra clave (equivale a `apropos`). |
| `whatis comando` | Descripción de una línea. |

```bash
man ls              # Manual completo de ls
ls --help | less    # Ayuda resumida, paginada con less
help read           # Ayuda del comando interno read
man -k password     # ¿Qué comandos tienen que ver con contraseñas?
```

> [!TIP]
> El manual se divide en **secciones** numeradas. Las más usadas son la **1** (comandos de usuario), la **5** (formatos de ficheros de configuración) y la **8** (comandos de administración). Por ejemplo, `man 5 passwd` explica el fichero `/etc/passwd`, mientras que `man 1 passwd` explica el comando `passwd`.

## 1.5 El sistema de ficheros

### Un único árbol

A diferencia de Windows (con unidades `C:`, `D:`…), en Linux todo cuelga de **un único árbol de directorios** cuya raíz es `/`. Los discos, memorias USB o particiones se "enganchan" (**montan**) en algún directorio de ese árbol.

La organización de los directorios sigue el estándar **FHS** (*Filesystem Hierarchy Standard*):

| Directorio | Contenido |
| --- | --- |
| `/` | Raíz del sistema de ficheros. |
| `/bin`, `/usr/bin` | Programas (comandos) disponibles para todos los usuarios. |
| `/sbin`, `/usr/sbin` | Programas de administración del sistema. |
| `/etc` | Ficheros de **configuración** del sistema (texto plano). |
| `/home` | Directorios personales de los usuarios (`/home/alumno`). |
| `/root` | Directorio personal del administrador. |
| `/var` | Datos variables: registros (`/var/log`), colas, cachés, bases de datos. |
| `/tmp` | Ficheros temporales (se suelen borrar al reiniciar). |
| `/dev` | Ficheros especiales que representan dispositivos (`/dev/sda`). |
| `/proc`, `/sys` | Sistemas de ficheros virtuales con información del núcleo y los procesos. |
| `/mnt`, `/media` | Puntos de montaje de discos y dispositivos extraíbles. |
| `/opt` | Software adicional instalado fuera del gestor de paquetes. |

> [!NOTE]
> En las distribuciones actuales, `/bin` y `/sbin` son enlaces a `/usr/bin` y `/usr/sbin` (esquema conocido como *usrmerge*). Por eso es indiferente escribir `/bin/bash` o `/usr/bin/bash`.

### Rutas absolutas y relativas

Una **ruta** indica dónde está un fichero o directorio dentro del árbol:

- **Ruta absoluta**: empieza por `/` y describe el camino completo desde la raíz. Funciona igual desde cualquier directorio. Ejemplo: `/home/alumno/proyectos/web/index.html`.
- **Ruta relativa**: **no** empieza por `/` y se interpreta a partir del **directorio actual**. Ejemplo: si estamos en `/home/alumno`, la ruta `proyectos/web/index.html` apunta al mismo fichero.

Hay varios nombres especiales:

| Símbolo | Significado |
| --- | --- |
| `.` | El directorio actual. |
| `..` | El directorio padre (el que está un nivel por encima). |
| `~` | El directorio personal del usuario actual. |
| `~ana` | El directorio personal del usuario `ana`. |
| `-` | (Solo con `cd`) el directorio en el que estábamos antes. |

```bash
pwd                 # /home/alumno            -> ¿dónde estoy?
cd proyectos/web    # ruta relativa
cd ../..            # subo dos niveles        -> /home/alumno
cd /var/log         # ruta absoluta
cd -                # vuelvo al directorio anterior
cd                  # sin argumentos: vuelvo a mi directorio personal
```

> [!IMPORTANT]
> Los ficheros y directorios cuyo nombre empieza por punto (`.bashrc`, `.git`, `.config`) son **ocultos**: `ls` no los muestra salvo que usemos `ls -a`. Los nombres de fichero distinguen mayúsculas (`Datos.txt` y `datos.txt` son dos ficheros distintos) y conviene evitar los espacios y las tildes en ellos.

## 1.6 Comodines (*globbing*)

Los **comodines** permiten referirse a varios ficheros a la vez mediante un patrón. Es la **shell** quien los expande, sustituyendo el patrón por la lista de nombres que coinciden **antes** de ejecutar el comando.

| Comodín | Coincide con | Ejemplo | Resultado |
| --- | --- | --- | --- |
| `*` | Cualquier secuencia de caracteres (incluso vacía). | `*.txt` | Todos los ficheros acabados en `.txt`. |
| `?` | Exactamente un carácter. | `foto?.png` | `foto1.png`, `fotoA.png`, pero no `foto10.png`. |
| `[abc]` | Un carácter de la lista. | `[Dd]atos.csv` | `Datos.csv` y `datos.csv`. |
| `[a-z]` | Un carácter del rango. | `tema[1-3].md` | `tema1.md`, `tema2.md`, `tema3.md`. |
| `[!abc]` | Un carácter que **no** esté en la lista. | `[!0-9]*` | Ficheros que no empiezan por cifra. |

```bash
ls *.sh            # Todos los scripts del directorio actual
ls /etc/*.conf     # Ficheros .conf de /etc
cp informe?.pdf /tmp/   # Copia informe1.pdf, informe2.pdf…
echo *             # Truco: echo muestra en qué se expande el patrón
```

### Expansión de llaves

Las **llaves** no buscan ficheros existentes: **generan** cadenas. Son muy útiles para crear estructuras de directorios o series de ficheros:

```bash
echo {lunes,martes,miercoles}   # lunes martes miercoles
echo fichero{1..5}.txt          # fichero1.txt fichero2.txt … fichero5.txt
mkdir -p proyecto/{src,docs,tests}   # Crea tres subdirectorios de golpe
cp config.yml{,.bak}            # Equivale a: cp config.yml config.yml.bak
```

## 1.7 Trabajar más rápido en la terminal

| Atajo / orden | Efecto |
| --- | --- |
| `Tab` | **Autocompleta** comandos, rutas y nombres de fichero. Pulsado dos veces muestra las opciones posibles. |
| `↑` / `↓` | Recorre el historial de órdenes. |
| `Ctrl+R` | Búsqueda inversa en el historial (escribe parte de una orden anterior). |
| `history` | Muestra el historial numerado. `!42` repite la orden número 42 y `!!` repite la última. |
| `Ctrl+C` | Interrumpe (termina) el comando en ejecución. |
| `Ctrl+D` | Fin de entrada. En un *prompt* vacío, cierra la shell. |
| `Ctrl+L` o `clear` | Limpia la pantalla. |
| `Ctrl+A` / `Ctrl+E` | Va al principio / final de la línea. |
| `Ctrl+U` / `Ctrl+K` | Borra desde el cursor hasta el principio / final de la línea. |
| `Ctrl+Z` | Suspende el proceso actual (lo veremos en la Unidad 4). |

> [!TIP]
> `sudo !!` repite la última orden anteponiendo `sudo`. Es muy útil cuando olvidamos que una orden necesitaba permisos de administrador.

## 1.8 Comandos de información general

| Comando | Qué muestra |
| --- | --- |
| `whoami` | El nombre del usuario actual. |
| `id` | El usuario, su identificador (UID) y los grupos a los que pertenece. |
| `hostname` | El nombre del equipo. |
| `uname -a` | Información del núcleo (*kernel*): versión, arquitectura… |
| `cat /etc/os-release` | Nombre y versión de la distribución. |
| `date` | Fecha y hora. Admite formatos: `date +%F` → `2026-11-08`, `date +%H:%M` → `17:30`. |
| `uptime` | Hora, tiempo encendido, usuarios conectados y carga media del sistema. |
| `who` / `w` | Usuarios conectados (con `w`, además, qué están haciendo). |
| `echo texto` | Muestra un texto o el valor de una variable (`echo "$HOME"`). |

```bash
date "+Hoy es %A, %d de %B de %Y"   # Formato personalizado
uname -r                            # Solo la versión del kernel
```

## 1.9 Ejecutar órdenes como administrador: `sudo`

**root** es el administrador del sistema y no tiene ninguna restricción de permisos. Trabajar siempre como root es peligroso (un error puede dañar el sistema), por eso lo habitual es usar una cuenta normal y elevar privilegios **solo** para las órdenes que lo necesitan, anteponiendo `sudo`:

```bash
sudo apt update          # Ejecuta una orden como root (pide TU contraseña)
sudo -i                  # Abre una shell de root (se sale con exit)
```

Para usar `sudo`, el usuario debe pertenecer al grupo `sudo` (Debian/Ubuntu) o `wheel` (Fedora/RHEL). La gestión de usuarios, grupos y privilegios se estudia en la Unidad 4.

### Ejercicio 1.2. Rutas absolutas y relativas

Estás en `/home/alumno/dam/sistemas`. Escribe la ruta **relativa** y la ruta **absoluta** para llegar a:

1. `/home/alumno/dam/programacion`
2. `/home/alumno`
3. `/etc/ssh`

{{% details "Ver solución" %}}
| Destino | Ruta relativa | Ruta absoluta |
| --- | --- | --- |
| `programacion` | `../programacion` | `/home/alumno/dam/programacion` |
| directorio personal | `../..` (o simplemente `~`) | `/home/alumno` |
| `/etc/ssh` | `../../../../etc/ssh` | `/etc/ssh` |

En el tercer caso la ruta relativa es correcta pero poco práctica: cuando el destino está "lejos", la ruta absoluta es más clara.

### Ejercicio 1.3. Comodines

En un directorio hay estos ficheros: `tema1.md`, `tema2.md`, `tema10.md`, `Tema3.md`, `notas.txt`, `notas.bak`. ¿Qué ficheros muestra cada orden?

1. `ls tema?.md`
2. `ls [tT]ema*`
3. `ls notas.*`
4. `ls *[0-9].md`

{{% details "Ver solución" %}}
1. `tema1.md tema2.md` (`?` es exactamente un carácter, por eso no aparece `tema10.md`; y `Tema3.md` empieza por mayúscula).
2. `tema1.md`, `tema10.md`, `tema2.md` y `Tema3.md` (todos los que empiezan por `tema` o `Tema`).
3. `notas.bak notas.txt`.
4. `tema1.md`, `tema10.md`, `tema2.md` y `Tema3.md` (acaban en una cifra seguida de `.md`).

`ls` muestra los resultados ordenados alfabéticamente; el orden exacto entre mayúsculas y minúsculas depende de la configuración regional del sistema.

Puedes comprobarlo creando los ficheros con `touch tema1.md tema2.md tema10.md Tema3.md notas.txt notas.bak`.

### Ejercicio 1.4. Estructura de un proyecto

Con **una sola orden**, crea en tu directorio personal esta estructura:

```text
app/
├── src/
├── tests/
└── docs/
```

{{% details "Ver solución" %}}
```bash
mkdir -p ~/app/{src,tests,docs}
```

La opción `-p` (*parents*) crea también los directorios intermedios (`app`) si no existen y no da error si ya existen. Las llaves generan las tres rutas `~/app/src`, `~/app/tests` y `~/app/docs`.
