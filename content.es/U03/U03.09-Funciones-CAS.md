# 9. Funciones

## 9.1 ¿Para qué sirven?

Una **función** es un bloque de órdenes con nombre que se puede ejecutar (**llamar**) tantas veces como se quiera. Las funciones permiten:

- **No repetir código**: si una tarea se hace en varios sitios, se escribe una vez.
- **Dividir** un script largo en piezas pequeñas, cada una con una responsabilidad clara.
- **Dar nombre** a las operaciones, lo que hace que el programa principal se lea casi como un texto: `comprobar_argumentos`, `crear_copia`, `enviar_informe`.

## 9.2 Definir y llamar a una función

```bash
nombre_funcion() {
    órdenes
}
```

Existe también la forma `function nombre_funcion { … }`, propia de Bash. Ambas son equivalentes; la primera es la estándar y la que usaremos.

Para **llamar** a la función se escribe su nombre como si fuera una orden más. La función debe estar **definida antes** de llamarla, por eso las funciones se colocan al principio del script.

```bash
#!/bin/bash
separador() {
    echo "----------------------------------------"
}

separador
echo "Informe del sistema"
separador
```

## 9.3 Parámetros

Las funciones reciben parámetros **igual que un script**: dentro de la función, `$1`, `$2`, `$#` y `"$@"` se refieren a los argumentos de la **llamada**, no a los del script.

```bash
#!/bin/bash
saludar() {
    echo "Hola, $1. Tienes $2 años."
}

saludar "Ana" 19        # Hola, Ana. Tienes 19 años.
saludar "Luis" 22       # Hola, Luis. Tienes 22 años.
```

Si la función necesita los parámetros del script, hay que pasárselos explícitamente: `procesar "$@"`.

## 9.4 Ámbito de las variables: `local`

Por defecto, **todas las variables son globales**: una variable creada o modificada dentro de una función es visible (y modificable) en todo el script. Esto puede provocar errores difíciles de encontrar:

```bash
#!/bin/bash
contar_hasta_3() {
    for i in 1 2 3; do echo -n "$i "; done
    echo
}

i=1
while (( i <= 3 )); do
    echo "Vuelta $i del bucle principal"
    contar_hasta_3      # Al terminar, la i global vale 3…
    i=$(( i + 1 ))      # …pasa a 4 y el bucle principal termina tras UNA sola vuelta
done
```

```text
Vuelta 1 del bucle principal
1 2 3
```

La solución es declarar las variables internas de la función con `local`, que hace que solo existan dentro de ella:

```bash
contar_hasta_3() {
    local i
    for i in 1 2 3; do echo -n "$i "; done
    echo
}
```

> [!TIP]
> Declara como `local` **todas** las variables de tus funciones, salvo que quieras modificar a propósito una variable global. Es buena práctica copiar los parámetros en variables locales con nombres descriptivos: `local fichero=$1 destino=$2`.

## 9.5 Devolver resultados

Una función de Bash no "devuelve" valores como en Java. Hay dos mecanismos, con usos distintos:

### 1. Devolver un estado con `return`

`return N` termina la función con un **código de salida** entre 0 y 255 (igual que `exit` en un script, pero sin terminar el script). Se usa para funciones que responden **sí o no**, y permite usarlas directamente como condición:

```bash
es_entero() {
    [[ $1 =~ ^-?[0-9]+$ ]]      # El código de salida de la última orden es el de la función
}

es_par() {
    if (( $1 % 2 == 0 )); then
        return 0                 # Verdadero
    else
        return 1                 # Falso
    fi
}

if es_entero "$1" && es_par "$1"; then
    echo "$1 es un entero par"
fi
```

### 2. Devolver un dato con `echo`

Para devolver un **dato** (un texto, un número grande, una lista…), la función lo escribe en la salida estándar y quien la llama lo captura con `$( )`:

```bash
area_rectangulo() {
    local base=$1 altura=$2
    echo $(( base * altura ))
}

extension() {
    echo "${1##*.}"
}

area=$(area_rectangulo 4 5)
echo "El área es $area"                       # El área es 20
echo "Extensión: $(extension informe.pdf)"    # Extensión: pdf
```

> [!WARNING]
> Si usas este mecanismo, la función no debe escribir **nada más** en la salida estándar, porque también se capturaría. Los mensajes informativos o de error de la función deben ir a la salida de errores: `echo "Calculando…" >&2`.

| Necesito… | Mecanismo | Ejemplo de llamada |
| --- | --- | --- |
| Saber si algo es verdadero/falso o si ha habido error | `return 0` / `return 1` | `if existe_usuario "$u"; then …` |
| Obtener un dato calculado | `echo dato` | `total=$(sumar 3 4)` |

## 9.6 Bibliotecas de funciones: `source`

Las funciones que se reutilizan en varios scripts pueden guardarse en un fichero aparte (una **biblioteca**) y cargarse con `source` (o su abreviatura `.`):

```bash
# lib/utilidades.sh - Funciones comunes (no necesita shebang ni permiso de ejecución)
error() {
    echo "ERROR: $*" >&2
    exit 1
}

info() {
    echo "[$(date +%T)] $*"
}

confirmar() {
    local resp
    read -rp "$1 (s/n) " resp
    [[ $resp == [sS] ]]
}
```

```bash
#!/bin/bash
# limpiar.sh - Usa la biblioteca de utilidades
# Carga la biblioteca usando la ruta del propio script, para que funcione
# se ejecute desde donde se ejecute
source "$(dirname "$0")/lib/utilidades.sh"

[[ -d $1 ]] || error "'$1' no es un directorio"

if confirmar "¿Borrar los ficheros .tmp de $1?"; then
    find "$1" -name '*.tmp' -delete
    info "Limpieza terminada"
fi
```

## 9.7 Estructura recomendada: la función `main`

En scripts de cierto tamaño es habitual meter el programa principal en una función `main`, que se llama en la última línea. Así el script se lee de arriba abajo, empezando por lo general:

```bash
#!/bin/bash
# plantilla con main

uso() {
    echo "Uso: $0 <directorio>" >&2
    exit 1
}

contar_ficheros() {
    local dir=$1
    find "$dir" -type f | wc -l
}

main() {
    [[ $# -eq 1 ]] || uso
    [[ -d $1 ]] || { echo "No existe el directorio '$1'" >&2; exit 2; }
    echo "El directorio $1 contiene $(contar_ficheros "$1") ficheros"
}

main "$@"
```

## Ejercicios resueltos

### Ejercicio 9.1. Funciones de validación

Escribe las funciones `es_entero`, `es_positivo` y `en_rango` (que recibe un número, un mínimo y un máximo) y úsalas en un script que pida una nota del 0 al 10 hasta que el valor sea correcto.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# pedir_nota.sh - Validación con funciones

es_entero() {
    [[ $1 =~ ^-?[0-9]+$ ]]
}

es_positivo() {
    es_entero "$1" && (( $1 >= 0 ))
}

en_rango() {
    local n=$1 min=$2 max=$3
    es_entero "$n" && (( n >= min && n <= max ))
}

read -rp "Nota (0-10): " nota
until en_rango "$nota" 0 10; do
    echo "La nota debe ser un entero entre 0 y 10."
    read -rp "Nota (0-10): " nota
done

echo "Nota registrada: $nota"
```

Fíjate en que cada función es una sola condición: su código de salida es el de la última orden, así que no hace falta `return`. Además, `es_positivo` y `en_rango` reutilizan `es_entero`.
{{% /details %}}

### Ejercicio 9.2. Usuarios reales del sistema

Usando funciones, escribe un script que liste los usuarios del sistema que corresponden a **personas** (UID ≥ 1000 y distinto de 65534, que es el usuario especial `nobody`), mostrando su nombre, su directorio personal y si este existe.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# usuarios_reales.sh - Lista las cuentas de personas

readonly UID_MIN=1000
readonly UID_NOBODY=65534

# Devuelve verdadero si el UID corresponde a una persona
es_persona() {
    local uid=$1
    (( uid >= UID_MIN && uid != UID_NOBODY ))
}

# Muestra una línea con la información del usuario
mostrar_usuario() {
    local nombre=$1 home=$2 estado
    if [[ -d $home ]]; then
        estado="existe"
    else
        estado="NO existe"
    fi
    printf "%-15s %-25s %s\n" "$nombre" "$home" "$estado"
}

main() {
    printf "%-15s %-25s %s\n" "USUARIO" "DIRECTORIO" "ESTADO"
    local nombre uid home
    while IFS=: read -r nombre _ uid _ _ home _; do
        if es_persona "$uid"; then
            mostrar_usuario "$nombre" "$home"
        fi
    done < /etc/passwd
}

main
```

Cada función tiene una única responsabilidad y recibe por parámetro todo lo que necesita: no depende de variables globales con un nombre concreto. Esto se llama **bajo acoplamiento** y hace que las funciones sean fáciles de probar y de reutilizar.
{{% /details %}}

### Ejercicio 9.3. Registro de mensajes

Crea una función `log` que reciba un nivel (`INFO`, `AVISO`, `ERROR`) y un mensaje, y escriba una línea con la fecha y hora, el nivel y el mensaje, tanto en pantalla como en el fichero indicado por la variable `LOG`. Los mensajes de nivel `ERROR` deben mostrarse por la salida de errores. Pruébala en un script que compruebe si existen varios directorios.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# comprobar_dirs.sh - Ejemplo de función de registro

LOG="/tmp/comprobar_dirs.log"

log() {
    local nivel=$1
    shift                               # Quitamos el nivel; el resto es el mensaje
    local linea
    linea="$(date '+%F %T') [$nivel] $*"
    echo "$linea" >> "$LOG"
    if [[ $nivel == "ERROR" ]]; then
        echo "$linea" >&2
    else
        echo "$linea"
    fi
}

log INFO "Inicio de la comprobación"
for dir in /etc /var/log /noexiste "$HOME"; do
    if [[ -d $dir ]]; then
        log INFO "El directorio $dir existe"
    else
        log ERROR "No existe el directorio $dir"
    fi
done
log INFO "Fin. Registro guardado en $LOG"
```

`shift` dentro de una función desplaza los parámetros **de la función**, no los del script.
