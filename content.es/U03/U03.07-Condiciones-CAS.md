# 7. Condiciones: tomar decisiones

## 7.1 Verdadero y falso en Bash

En la mayoría de lenguajes, una condición es una expresión que vale `true` o `false`. En Bash, en cambio, **una condición es una orden**, y lo que se evalúa es su **código de salida**:

- Código `0` (la orden ha tenido éxito) → **verdadero**.
- Código distinto de `0` (la orden ha fallado) → **falso**.

> [!IMPORTANT]
> Es justo al revés que en C o Java, donde `0` significa falso. En Bash, `0` = éxito = verdadero.

Por eso podemos usar directamente cualquier orden como condición:

```bash
if grep -q "^ana:" /etc/passwd; then
    echo "El usuario ana existe"
fi
```

Para comparar valores o comprobar ficheros existe una orden especial: `test`, que se escribe normalmente con corchetes.

## 7.2 `test`, `[ ]` y `[[ ]]`

```bash
test 5 -gt 3      # Orden test clásica
[ 5 -gt 3 ]       # Equivalente: [ es otro nombre de test (necesita el ] final)
[[ 5 -gt 3 ]]     # Versión mejorada, propia de Bash
echo $?           # 0 -> verdadero
```

> [!WARNING]
> Los corchetes **necesitan espacios** a ambos lados: `[ "$a" = "$b" ]`. Escribir `["$a" = "$b"]` provoca el error `[hola: command not found`, porque `[` es una orden y tiene que ir separada de sus argumentos.

| | `[ ]` (`test`) | `[[ ]]` |
| --- | --- | --- |
| Disponibilidad | Todas las shells POSIX (`sh`, `dash`…). | Bash, zsh, ksh. |
| Variables sin comillas | Fallan si están vacías o tienen espacios. | Funcionan (aunque entrecomillar sigue siendo buena práctica). |
| Operadores lógicos | `!`, y entre corchetes: `[ … ] && [ … ]`. | `!`, `&&`, `\|\|` y paréntesis dentro. |
| Patrones y regex | No. | `==` con comodines y `=~` con expresiones regulares. |

En los scripts de Bash de esta unidad usaremos **`[[ ]]`** para cadenas y ficheros, y **`(( ))`** para comparaciones numéricas.

## 7.3 Operadores de comprobación

### Ficheros

| Operador | Verdadero si… |
| --- | --- |
| `-e ruta` | Existe (sea del tipo que sea). |
| `-f ruta` | Existe y es un fichero normal. |
| `-d ruta` | Existe y es un directorio. |
| `-L ruta` | Es un enlace simbólico. |
| `-s ruta` | Existe y su tamaño es mayor que 0. |
| `-r` / `-w` / `-x ruta` | El usuario actual puede leerlo / escribirlo / ejecutarlo. |
| `f1 -nt f2` | `f1` es más reciente (*newer than*) que `f2`. |

### Cadenas

| Operador | Verdadero si… |
| --- | --- |
| `-z "$s"` | La cadena está vacía (longitud cero). |
| `-n "$s"` | La cadena **no** está vacía. |
| `"$a" == "$b"` | Son iguales (en `[ ]` se usa `=`). |
| `"$a" != "$b"` | Son distintas. |
| `"$s" == patrón` | (Solo `[[ ]]`) la cadena encaja con un patrón con comodines, p. ej. `[[ $f == *.txt ]]`. |
| `"$s" =~ regex` | (Solo `[[ ]]`) la cadena cumple la expresión regular. |

### Números

| En `[ ]` / `[[ ]]` | En `(( ))` | Significado |
| --- | --- | --- |
| `-eq` | `==` | Igual. |
| `-ne` | `!=` | Distinto. |
| `-lt` | `<` | Menor que (*less than*). |
| `-le` | `<=` | Menor o igual. |
| `-gt` | `>` | Mayor que (*greater than*). |
| `-ge` | `>=` | Mayor o igual. |

```bash
edad=20
[[ $edad -ge 18 ]] && echo "Mayor de edad"
(( edad >= 18 )) && echo "Mayor de edad"     # Más legible para los números
```

> [!CAUTION]
> Dentro de `[[ ]]`, los operadores `<` y `>` comparan **cadenas** alfabéticamente, no números: `[[ 10 < 9 ]]` es **verdadero** porque el carácter `1` va antes que `9`. Para números usa `-lt`/`-gt` o, mejor, `(( ))`.

### Operadores lógicos

| Operador | Significado | Ejemplo |
| --- | --- | --- |
| `!` | NO | `[[ ! -f "$f" ]]` |
| `&&` | Y | `[[ -f "$f" && -r "$f" ]]` |
| `\|\|` | O | `[[ $resp == "s" \|\| $resp == "S" ]]` |

## 7.4 La estructura `if`

```bash
if condición; then
    órdenes si es verdadera
elif otra_condición; then
    órdenes si la primera es falsa y esta verdadera
else
    órdenes si ninguna es verdadera
fi
```

- `then` puede ir en la línea siguiente; si va en la misma línea que la condición, hay que separarlos con `;`.
- Las partes `elif` y `else` son opcionales y puede haber tantos `elif` como se necesite.
- La estructura se cierra con `fi` (`if` al revés).

```bash
#!/bin/bash
# nota.sh - Calificación a partir de una nota numérica
read -rp "Introduce la nota (0-10): " nota

if (( nota < 0 || nota > 10 )); then
    echo "Nota no válida" >&2
    exit 1
elif (( nota < 5 )); then
    echo "Insuficiente"
elif (( nota < 7 )); then
    echo "Aprobado"
elif (( nota < 9 )); then
    echo "Notable"
else
    echo "Sobresaliente"
fi
```

### Validar la entrada

Antes de operar con un dato hay que comprobar que es correcto. Las **expresiones regulares** con `=~` son perfectas para ello:

```bash
if [[ ! $nota =~ ^[0-9]+$ ]]; then
    echo "Error: '$nota' no es un número entero positivo" >&2
    exit 1
fi
```

| Expresión regular | Acepta |
| --- | --- |
| `^[0-9]+$` | Enteros positivos: `0`, `42`. |
| `^-?[0-9]+$` | Enteros con signo opcional: `-7`, `15`. |
| `^[a-zA-Z_]+$` | Solo letras y guion bajo. |
| `^[a-z0-9._-]+@[a-z0-9.-]+\.[a-z]{2,}$` | Un correo electrónico (simplificado). |

> [!TIP]
> No escribas la expresión regular entre comillas en `=~`: `[[ $x =~ "^[0-9]+$" ]]` compara con el texto literal. Si la expresión es compleja, guárdala en una variable: `re='^[0-9]+$'; [[ $x =~ $re ]]`.

### Comprobar ficheros y argumentos

```bash
#!/bin/bash
# info_fichero.sh - Informa sobre la ruta recibida
# Uso: ./info_fichero.sh <ruta>

if [[ $# -ne 1 ]]; then
    echo "Uso: $0 <ruta>" >&2
    exit 1
fi

ruta=$1

if [[ ! -e $ruta ]]; then
    echo "'$ruta' no existe" >&2
    exit 2
elif [[ -d $ruta ]]; then
    echo "'$ruta' es un directorio con $(ls -A "$ruta" | wc -l) elementos"
elif [[ -f $ruta ]]; then
    echo "'$ruta' es un fichero de $(stat -c %s "$ruta") bytes"
    if [[ -x $ruta ]]; then
        echo "Además, tienes permiso para ejecutarlo"
    fi
else
    echo "'$ruta' es un fichero especial"
fi
```

> [!NOTE]
> ¿Por qué no se ha escrito `[[ -x $ruta ]] && echo "…"` en una sola línea? Porque, si el fichero no es ejecutable, la condición es falsa y esa línea, la última del script, devuelve un código distinto de 0: el script terminaría indicando un error sin haberlo. Con `if` no ocurre, porque un `if` cuya condición es falsa y no tiene `else` devuelve 0.

## 7.5 La estructura `case`

Cuando hay que comparar **una misma variable** con muchos valores posibles, `case` es más claro que una cadena de `elif`:

```bash
case "$variable" in
    patrón1)
        órdenes
        ;;
    patrón2 | patrón3)
        órdenes
        ;;
    *)
        órdenes por defecto
        ;;
esac
```

- Cada opción termina con `;;`.
- Los patrones admiten comodines: `*`, `?`, `[ ]`, y `|` para indicar varias alternativas.
- `*)` captura cualquier valor no contemplado (equivale a `else` o al `default` de Java).
- Se cierra con `esac` (`case` al revés).

```bash
#!/bin/bash
# servicio.sh - Gestiona un servicio de ejemplo
# Uso: ./servicio.sh start|stop|restart|status

case "$1" in
    start)
        echo "Arrancando el servicio…"
        ;;
    stop)
        echo "Deteniendo el servicio…"
        ;;
    restart | reload)
        echo "Reiniciando el servicio…"
        ;;
    status)
        echo "El servicio está en ejecución"
        ;;
    *)
        echo "Uso: $0 {start|stop|restart|status}" >&2
        exit 1
        ;;
esac
```

```bash
#!/bin/bash
# tipo_tecla.sh - Clasifica el carácter introducido
read -rn 1 -p "Pulsa una tecla: " tecla
echo
case "$tecla" in
    [aeiouAEIOU])  echo "Es una vocal" ;;
    [a-zA-Z])      echo "Es una consonante" ;;
    [0-9])         echo "Es una cifra" ;;
    *)             echo "Es otro carácter" ;;
esac
```

Este patrón es muy habitual para analizar respuestas del tipo sí/no:

```bash
read -rp "¿Deseas continuar? (s/n) " resp
case "$resp" in
    [sS] | [sS][iíIÍ]) echo "Continuamos" ;;
    *)                 echo "Operación cancelada"; exit 0 ;;
esac
```

## 7.6 Condiciones cortas con `&&` y `||`

Para condiciones con una sola orden, los operadores `&&` y `||` ofrecen una forma compacta:

```bash
[[ -d copias ]] || mkdir copias           # Si no existe el directorio, créalo
[[ $# -eq 0 ]] && { echo "Faltan argumentos" >&2; exit 1; }   # { } agrupa varias órdenes
cd "$destino" || exit 1                   # Si no se puede entrar, termina
```

> [!WARNING]
> `cond && A || B` **no** equivale exactamente a un `if/else`: si `cond` es verdadera pero `A` falla, también se ejecuta `B`. Úsalo solo cuando `A` no pueda fallar (como un `echo`); en caso contrario, escribe un `if` completo.

### Ejercicio 7.1. Par o impar

Script que reciba un número entero como parámetro, compruebe que realmente es un entero (puede ser negativo) e indique si es par o impar.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# par_impar.sh - Indica si un número es par o impar
# Uso: ./par_impar.sh <entero>

if [[ $# -ne 1 ]]; then
    echo "Uso: $0 <entero>" >&2
    exit 1
fi

if [[ ! $1 =~ ^-?[0-9]+$ ]]; then
    echo "Error: '$1' no es un número entero" >&2
    exit 2
fi

if (( $1 % 2 == 0 )); then
    echo "$1 es par"
else
    echo "$1 es impar"
fi
```

### Ejercicio 7.2. El mayor de tres números

Script que pida tres números enteros por teclado y muestre el mayor. Si hay empate en el valor máximo, debe indicarlo.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# mayor.sh - Muestra el mayor de tres números

read -rp "Primer número: " a
read -rp "Segundo número: " b
read -rp "Tercer número: " c

# Validamos los tres valores de una vez
for n in "$a" "$b" "$c"; do
    if [[ ! $n =~ ^-?[0-9]+$ ]]; then
        echo "Error: '$n' no es un entero" >&2
        exit 1
    fi
done

mayor=$a
(( b > mayor )) && mayor=$b
(( c > mayor )) && mayor=$c

# Contamos cuántos valores coinciden con el máximo
veces=0
for n in "$a" "$b" "$c"; do
    (( n == mayor )) && veces=$(( veces + 1 ))
done

if (( veces > 1 )); then
    echo "El mayor es $mayor (aparece $veces veces)"
else
    echo "El mayor es $mayor"
fi
```

La idea es suponer que el mayor es el primero y actualizarlo si encontramos uno más grande, una técnica que utilizaréis constantemente en Programación.
{{% /details %}}

### Ejercicio 7.3. Copia de seguridad segura de un fichero

Script que reciba la ruta de un fichero y cree una copia con el sufijo `.bak`. Debe comprobar que: se ha pasado un argumento, el fichero existe y es un fichero normal, se puede leer y, si la copia ya existe, preguntar antes de sobrescribirla.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# bak.sh - Crea una copia .bak de un fichero
# Uso: ./bak.sh <fichero>

[[ $# -eq 1 ]] || { echo "Uso: $0 <fichero>" >&2; exit 1; }

origen=$1
copia="$origen.bak"

if [[ ! -f $origen ]]; then
    echo "Error: '$origen' no existe o no es un fichero normal" >&2
    exit 2
fi

if [[ ! -r $origen ]]; then
    echo "Error: no tienes permiso de lectura sobre '$origen'" >&2
    exit 3
fi

if [[ -e $copia ]]; then
    read -rp "'$copia' ya existe. ¿Sobrescribir? (s/n) " resp
    case "$resp" in
        [sS]) ;;                                    # Opción vacía: seguimos
        *)    echo "No se ha hecho la copia"; exit 0 ;;
    esac
fi

if cp -- "$origen" "$copia"; then
    echo "Copia creada: $copia"
else
    echo "Error al copiar" >&2
    exit 4
fi
```

Cada error tiene un código de salida distinto, lo que permite a quien use el script saber qué ha fallado.

### Ejercicio 7.4. Clasificador de ficheros por extensión

Script que reciba el nombre de un fichero e indique su categoría según la extensión: imagen (`jpg`, `jpeg`, `png`, `gif`), documento (`pdf`, `odt`, `docx`, `txt`), código (`java`, `py`, `sh`, `kt`) o comprimido (`zip`, `tar`, `gz`). La comparación no debe distinguir mayúsculas.

{{% details "Ver solución" %}}
```bash
#!/bin/bash
# categoria.sh - Clasifica un fichero por su extensión
# Uso: ./categoria.sh <fichero>

[[ $# -eq 1 ]] || { echo "Uso: $0 <fichero>" >&2; exit 1; }

# ${1##*.} elimina todo hasta el último punto (apartado 10); ,, pasa a minúsculas
extension=${1##*.}
extension=${extension,,}

case "$extension" in
    jpg | jpeg | png | gif)   categoria="imagen" ;;
    pdf | odt | docx | txt)   categoria="documento" ;;
    java | py | sh | kt)      categoria="código fuente" ;;
    zip | tar | gz)           categoria="fichero comprimido" ;;
    *)                        categoria="desconocida" ;;
esac

echo "$1 → $categoria"
```

```text
$ ./categoria.sh Foto.JPG
Foto.JPG → imagen
$ ./categoria.sh Main.kt
Main.kt → código fuente
```
