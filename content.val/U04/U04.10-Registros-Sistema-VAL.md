# 10. Registres del sistema

Els **registres** (*logs*) són fitxers o bases de dades on el sistema operatiu, els serveis i les aplicacions anoten, per ordre cronològic, tot el que ocorre: arrancades i apagades, inicis de sessió, errors dels programes, instal·lació de paquets, connexions rebutjades… Quan alguna cosa falla, els registres són **la primera font d'informació** per a esbrinar què ha passat.

Com a desenvolupadors, també escriureu registres des de les vostres aplicacions. Conéixer com funcionen els del sistema vos ajudarà a fer-ho bé.

## 10.1 Nivells de gravetat

Cada missatge de registre porta un **nivell de gravetat**. L'estàndard *syslog*, utilitzat en Linux, en definix huit:

| Nivell | Nom | Significat | Equivalent en Windows |
| --- | --- | --- | --- |
| 0 | `emerg` | El sistema no es pot utilitzar. | Crític |
| 1 | `alert` | Cal actuar immediatament. | Crític |
| 2 | `crit` | Condició crítica. | Crític |
| 3 | `err` | Error. | Error |
| 4 | `warning` | Advertiment. | Advertiment |
| 5 | `notice` | Situació normal però significativa. | Informació |
| 6 | `info` | Missatge informatiu. | Informació |
| 7 | `debug` | Informació de depuració. | Detallat |

Els mateixos nivells s'utilitzen en les biblioteques de registre dels llenguatges de programació (per exemple, `logging` en Python o SLF4J en Java).

## 10.2 Linux: dos sistemes de registre

En les distribucions actuals conviuen dos sistemes:

| Sistema | Format | On guarda | Com es consulta |
| --- | --- | --- | --- |
| **systemd-journald** (el *journal*) | Binari, estructurat (cada missatge porta camps: servei, PID, usuari, prioritat…) | `/var/log/journal/` (o en memòria, en `/run/log/journal/`, si no és persistent) | `journalctl` |
| **rsyslog** | Text pla | Fitxers en `/var/log/` | `less`, `tail`, `grep` |

El *journal* arreplega **tots** els missatges i, si rsyslog està instal·lat, els hi reenvia perquè els escriga també en els fitxers de text.

> [!NOTE]
> Algunes distribucions ja no instal·len rsyslog per defecte (per exemple, Debian des de la versió 12). En aquestes no existixen fitxers com `/var/log/syslog` o `/var/log/auth.log` i tota la informació es consulta amb `journalctl`. Comprova-ho en el teu sistema amb `systemctl status rsyslog`. Si necessites els fitxers de text, s'instal·la amb `sudo apt install rsyslog`.

### Fitxers de `/var/log`

| Fitxer | Contingut |
| --- | --- |
| `/var/log/syslog` | Missatges generals del sistema (en Fedora/RHEL: `/var/log/messages`). |
| `/var/log/auth.log` | **Autenticació**: inicis de sessió, ús de `sudo`, connexions SSH (en Fedora/RHEL: `/var/log/secure`). |
| `/var/log/kern.log` | Missatges del nucli. |
| `/var/log/dpkg.log` | Paquets instal·lats, actualitzats i eliminats. |
| `/var/log/apt/history.log` | Historial d'ordres `apt` (què es va instal·lar, quan i qui). |
| `/var/log/boot.log` | Missatges de l'arrancada. |
| `/var/log/wtmp`, `/var/log/btmp` | Inicis de sessió correctes i fallits. Són binaris: es lligen amb `last` i `lastb` (apartat 1.7). |
| `/var/log/apache2/`, `/var/log/samba/`… | Registres propis de cada servei. |

```bash
sudo tail -n 20 /var/log/auth.log             # Últims 20 missatges d'autenticació
sudo tail -f /var/log/syslog                  # Seguir en temps real (Ctrl+C per a eixir)
sudo grep -i "failed password" /var/log/auth.log    # Intents d'accés SSH fallits
zgrep "install " /var/log/dpkg.log*           # Busca també en els fitxers antics comprimits (.gz)
```

Per a llegir els registres sense `sudo`, l'usuari ha de pertànyer al grup **`adm`** (fitxers de `/var/log`) o **`systemd-journal`** (*journal* complet). En Ubuntu, el primer usuari ja pertany a `adm`.

### `journalctl`

| Opció | Funció |
| --- | --- |
| (sense opcions) | Tot el *journal*, del més antic al més recent, en un paginador. |
| `-r` | En ordre invers (el més recent primer). |
| `-n 50` | Només els 50 últims missatges. |
| `-f` | Seguir en temps real. |
| `-b` | Només des de l'última arrancada. `-b -1`: l'arrancada anterior. |
| `--list-boots` | Llista d'arrancades registrades. |
| `-u servei` | Missatges d'una unitat de systemd. |
| `-p err` | Només els de prioritat `err` o més greu. S'admet un rang: `-p warning..err`. |
| `-k` | Només els missatges del nucli (equival a `dmesg`). |
| `-t etiqueta` | Per identificador (per exemple, els missatges enviats amb `logger -t`). |
| `--since` / `--until` | Interval de temps: `"2026-11-08 09:00"`, `"1 hour ago"`, `today`, `yesterday`. |
| `_UID=1001` | Missatges dels processos d'un usuari (filtre per camp). |
| `-o verbose` / `-o json-pretty` | Mostra tots els camps de cada missatge. |
| `--no-pager` | Sense paginador (per a utilitzar en scripts i canonades). |

```bash
journalctl -b -p err                        # Errors des de l'última arrancada
journalctl -u ssh --since today             # Missatges de SSH de hui
journalctl -u miapp -f                      # Seguir el registre de la teua aplicació (apartat 8.3)
journalctl --since "1 hour ago" -p warning  # Advertiments i errors de l'última hora
journalctl _COMM=sudo --since yesterday     # Ús de sudo des d'ahir (_COMM: nom del programa)
journalctl -k -b -1                         # Missatges del nucli de l'arrancada anterior (per si es va penjar)
```

### Gestió de l'espai del *journal*

```bash
journalctl --disk-usage                     # Espai que ocupa
sudo journalctl --vacuum-time=4weeks        # Esborra els missatges de fa més de 4 setmanes
sudo journalctl --vacuum-size=500M          # Reduïx el journal a 500 MB com a màxim
```

La grandària màxima permanent es configura amb `SystemMaxUse=` en `/etc/systemd/journald.conf`. Perquè el *journal* es guarde en el disc i no es perda en reiniciar, ha d'existir el directori `/var/log/journal` (en Ubuntu existix per defecte).

### Missatges del nucli: `dmesg`

```bash
sudo dmesg -T | tail -n 20       # -T: dates llegibles
sudo dmesg -T --level=err,warn   # Només errors i advertiments
sudo dmesg -w                    # Seguir en temps real (útil en connectar un dispositiu USB)
```

### Escriure en el registre: `logger`

Els teus scripts poden enviar missatges al registre del sistema, que després es consulten amb les mateixes eines:

```bash
logger "Còpia de seguretat acabada"
logger -t backup -p user.err "No queda espai en la destinació"
journalctl -t backup
```

### Rotació de registres: `logrotate`

Si els registres creixeren indefinidament, acabarien omplint el disc. **`logrotate`** s'executa diàriament (mitjançant un *timer* de systemd) i, segons la seua configuració, **fa rotar** els fitxers: reanomena l'actual (`syslog` → `syslog.1`), comprimix els antics (`syslog.2.gz`…), esborra els que superen el nombre màxim i comença un fitxer nou.

La configuració general està en `/etc/logrotate.conf` i la de cada servei en `/etc/logrotate.d/`. Exemple per als registres de la teua aplicació:

```text
# /etc/logrotate.d/miapp
/var/log/miapp/*.log {
    # Rotar cada setmana (també: daily, monthly)
    weekly
    # Conservar 8 fitxers antics
    rotate 8
    # Comprimir els antics amb gzip…
    compress
    # …excepte el més recent (per si l'aplicació encara hi escriu)
    delaycompress
    # No donar error si no existix el fitxer ni fer-lo rotar si està buit
    missingok
    notifempty
    # Permisos, propietari i grup del fitxer nou
    create 0640 miapp adm
}
```

> [!WARNING]
> En els fitxers de `logrotate` els comentaris han d'anar en **línies pròpies** que comencen per `#`. Un comentari al final d'una directiva (`weekly # cada setmana`) provoca un error.

```bash
sudo logrotate -d /etc/logrotate.d/miapp     # Simulació (debug): mostra què faria sense fer-ho
sudo logrotate -f /etc/logrotate.d/miapp     # Força una rotació ara
```

## 10.3 Windows: el Visor d'esdeveniments

En Windows, els registres s'anomenen **registres d'esdeveniments** i es consulten amb el **Visor d'esdeveniments** (`eventvwr.msc`).

### Registres principals

| Registre | Contingut |
| --- | --- |
| **Aplicació** | Esdeveniments dels programes (errors d'aplicacions, missatges d'instal·ladors…). |
| **Seguretat** | Esdeveniments d'**auditoria**: inicis de sessió, canvis en comptes, accessos a fitxers auditats. Només els administradors el poden llegir. |
| **Instal·lació** | Instal·lació d'actualitzacions i característiques de Windows. |
| **Sistema** | Esdeveniments dels components de Windows: serveis, controladors, arrancada i apagada. |
| **Registres d'aplicacions i serveis** | Registres específics de cada component (PowerShell, Windows Defender, Programador de tasques…). |

### Informació d'un esdeveniment

| Camp | Descripció |
| --- | --- |
| **Nivell** | Crític, Error, Advertiment, Informació, Detallat. En el registre *Seguretat*: Auditoria correcta o Auditoria errònia. |
| **Data i hora** | Quan va ocórrer. |
| **Origen** | Component o programa que el va generar. |
| **Id. de l'esdeveniment** | Número que identifica el **tipus** d'esdeveniment. Juntament amb l'origen, permet buscar-ne informació. |
| **Usuari** | Compte relacionat amb l'esdeveniment. |
| **Descripció** | Text explicatiu (pestanya *General*) i dades completes en XML (pestanya *Detalls*). |

### Identificadors d'esdeveniment importants

| Registre | Id. | Significat |
| --- | --- | --- |
| Seguretat | **4624** | Inici de sessió correcte. |
| Seguretat | **4625** | Inici de sessió **fallit**. |
| Seguretat | **4634** / **4647** | Tancament de sessió. |
| Seguretat | **4720** | S'ha creat un compte d'usuari. |
| Seguretat | **4726** | S'ha eliminat un compte d'usuari. |
| Seguretat | **4732** | S'ha afegit un membre a un grup local. |
| Seguretat | **4740** | Un compte s'ha **bloquejat** (apartat 4). |
| Sistema | **6005** / **6006** | El servei de registre d'esdeveniments s'ha iniciat / aturat (indica arrancada / apagada). |
| Sistema | **1074** | Un usuari o un procés ha iniciat l'apagada o el reinici. |
| Sistema | **41** (origen *Kernel-Power*) | El sistema es va reiniciar sense apagar-se correctament (tall de llum, penjada). |
| Sistema | **7036** | Un servei ha canviat d'estat (iniciat, aturat). |

> [!NOTE]
> Els esdeveniments del registre *Seguretat* depenen de la **directiva d'auditoria**: només es registra el que està configurat per a auditar-se. Els inicis de sessió i la gestió de comptes s'auditen per defecte en Windows 11, però altres esdeveniments, com els accessos a fitxers, cal activar-los (en `secpol.msc` > *Directives locals > Directiva d'auditoria*, o amb `auditpol`). Pots veure la configuració actual amb `auditpol /get /category:*` en una consola d'administrador.

### Treballar amb el Visor d'esdeveniments

- **Filtrar el registre actual** (tauler dret): mostrar només certs nivells, orígens, identificadors o un interval de temps.
- **Crear una visualització personalitzada**: guardar un filtre, fins i tot combinant diversos registres. La visualització predefinida *Esdeveniments administratius* reunix els errors i advertiments de tots els registres.
- **Adjuntar una tasca a aquest esdeveniment**: executar un programa o script automàticament quan es produïsca un esdeveniment concret (crea una tasca en el Programador de tasques).
- **Desar tots els esdeveniments com a…**: exportar el registre a un fitxer `.evtx` per a analitzar-lo en un altre equip.
- **Propietats del registre**: grandària màxima i què fer quan s'ompli (sobreescriure els esdeveniments antics, arxivar…). És l'equivalent a la rotació de Linux.

## 10.4 Windows: registres des de la línia d'ordres

### PowerShell: `Get-WinEvent`

```powershell
Get-WinEvent -ListLog * | Where-Object RecordCount -gt 0 |
    Sort-Object RecordCount -Descending | Select-Object -First 10 LogName, RecordCount

Get-WinEvent -LogName System -MaxEvents 20            # Els 20 esdeveniments més recents de Sistema

# -FilterHashtable filtra en el mateix servei de registre, molt més ràpid que Where-Object
Get-WinEvent -FilterHashtable @{
    LogName   = 'System'
    Level     = 2                                     # 1 Crític, 2 Error, 3 Advertiment, 4 Informació
    StartTime = (Get-Date).AddDays(-1)                # Últimes 24 hores
}

# Inicis de sessió fallits de l'última setmana (com a administrador)
Get-WinEvent -FilterHashtable @{ LogName = 'Security'; Id = 4625; StartTime = (Get-Date).AddDays(-7) } |
    Select-Object TimeCreated, Id, Message | Format-List
```

> [!NOTE]
> L'antic *cmdlet* `Get-EventLog` només existix en Windows PowerShell 5.1 i **no està disponible en PowerShell 7**. Utilitza sempre `Get-WinEvent`.

### CMD: `wevtutil` i `eventcreate`

```bat
wevtutil el                                  :: Llista tots els registres
wevtutil qe System /c:5 /rd:true /f:text     :: Els 5 esdeveniments més recents de Sistema, en text
wevtutil epl System C:\Temp\sistema.evtx     :: Exporta el registre a un fitxer
wevtutil gl Application                      :: Configuració del registre (grandària màxima…)

:: Escriure un esdeveniment propi en el registre Aplicació (equival a logger en Linux)
eventcreate /T WARNING /ID 100 /L APPLICATION /SO ElMeuScript /D "No queda espai en la destinació"
```

## 10.5 Comparativa

| Tasca | Linux | Windows |
| --- | --- | --- |
| Eina principal | `journalctl`, fitxers de `/var/log` | Visor d'esdeveniments (`eventvwr.msc`), `Get-WinEvent` |
| Missatges generals | `/var/log/syslog`, `journalctl` | Registre *Sistema* |
| Autenticació | `/var/log/auth.log`, `journalctl _COMM=sshd` | Registre *Seguretat* (4624, 4625…) |
| Des de l'última arrancada | `journalctl -b` | Filtrar des de l'esdeveniment 6005 |
| Només errors | `journalctl -p err` | Filtre per nivell *Error*, `Level = 2` |
| Seguir en temps real | `journalctl -f`, `tail -f` | (Visualització actualitzada manualment o `Get-WinEvent` en bucle) |
| Escriure un missatge propi | `logger` | `eventcreate`, `Write-EventLog` (només PowerShell 5.1) |
| Limitar la grandària | `logrotate`, `journald.conf` | Propietats del registre |

## Exercicis resolts

### Exercici 10.1. Investigar un accés amb `sudo`

Esbrina qui ha utilitzat `sudo` hui en el teu Linux i quines ordres ha executat.

{{% details "Veure solució" %}}
```bash
journalctl _COMM=sudo --since today --no-pager
# nov 08 10:15:02 equip sudo[4120]:   alumne : TTY=pts/0 ; PWD=/home/alumne ; USER=root ; COMMAND=/usr/bin/apt update
```

Si rsyslog està instal·lat, també: `sudo grep sudo /var/log/auth.log`. Cada línia indica l'usuari, el terminal, el directori, l'usuari de destinació i l'ordre executada. Per això `sudo` és preferible a compartir la contrasenya de root: queda constància de qui va fer què.
{{% /details %}}

### Exercici 10.2. Detectar un atac de força bruta per SSH

Des d'una altra màquina, intenta connectar-te diverses vegades per SSH al teu servidor amb una contrasenya incorrecta. Després, en el servidor, compta els intents fallits i obtín les adreces IP d'origen.

{{% details "Veure solució" %}}
```bash
# Des del client (diverses vegades, amb contrasenya errònia)
ssh usuari_inexistent@IP-SERVIDOR

# En el servidor
journalctl -u ssh --since today | grep -i "failed password\|invalid user"
journalctl -u ssh --since today --no-pager |
    grep -oE 'from [0-9.]+' | sort | uniq -c | sort -rn
#      6 from 192.168.1.35
```

`grep -o` mostra només la part que coincidix amb el patró; `sort | uniq -c` compta les repeticions i `sort -rn` les ordena de més a menys (Unitat 3). En un servidor exposat a Internet veuràs centenars d'intents al dia: per això es recomana desactivar l'accés per contrasenya en SSH i utilitzar claus (Unitat 6), a més d'eines com *fail2ban*.
{{% /details %}}

### Exercici 10.3. Inicis de sessió fallits en Windows

Provoca dos inicis de sessió fallits amb un compte de prova en Windows. Després, amb PowerShell, obtín la data, el nom del compte i el motiu dels esdeveniments 4625 de l'última hora.

{{% details "Veure solució" %}}
```powershell
# Executar com a administrador
Get-WinEvent -FilterHashtable @{ LogName = 'Security'; Id = 4625; StartTime = (Get-Date).AddHours(-1) } |
    ForEach-Object {
        $xml = [xml]$_.ToXml()                       # Convertix l'esdeveniment a XML per a llegir-ne els camps
        $dades = @{}
        foreach ($d in $xml.Event.EventData.Data) { $dades[$d.Name] = $d.'#text' }
        [PSCustomObject]@{
            Data    = $_.TimeCreated
            Compte  = $dades['TargetUserName']
            Estat   = $dades['SubStatus']            # 0xC000006A = contrasenya incorrecta
            Origen  = $dades['IpAddress']
        }
    } | Format-Table -AutoSize
```

El codi `SubStatus` indica el motiu: `0xC000006A` contrasenya incorrecta, `0xC0000064` l'usuari no existix, `0xC0000234` compte bloquejat. Convertir l'esdeveniment a XML és la manera fiable d'obtindre'n els camps, perquè el text del missatge (`Message`) depén de l'idioma.
{{% /details %}}

### Exercici 10.4. Rotació per a una aplicació pròpia

La teua aplicació escriu en `/var/log/miapp/app.log`. Configura `logrotate` per a fer-lo rotar diàriament, conservar 14 dies comprimits i crear el fitxer nou amb propietari `miapp`. Comprova la configuració sense aplicar-la.

{{% details "Veure solució" %}}
```bash
sudo mkdir -p /var/log/miapp
sudo chown miapp:adm /var/log/miapp
sudo tee /etc/logrotate.d/miapp > /dev/null <<'EOF'
/var/log/miapp/app.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    create 0640 miapp adm
}
EOF
sudo logrotate -d /etc/logrotate.d/miapp
```

L'eixida de `-d` mostra quins fitxers es considerarien i quines accions es farien, sense modificar res.
{{% /details %}}
