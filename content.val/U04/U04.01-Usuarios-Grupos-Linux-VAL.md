# 1. Usuaris i grups en Linux

GNU/Linux és un sistema **multiusuari**: diverses persones (i diversos programes) poden utilitzar el mateix equip alhora, cadascuna amb el seu propi **compte**. Els comptes servixen per a dues coses:

- **Autenticació**: comprovar *qui* eres (normalment, amb un nom d'usuari i una contrasenya o una clau SSH).
- **Autorització**: decidir *què* pots fer. Cada fitxer i cada procés pertanyen a un usuari i a un grup, i els permisos (apartat 5) es calculen a partir d'ells.

## 1.1 Conceptes bàsics

| Concepte | Descripció |
| --- | --- |
| **Usuari** | Compte que identifica una persona o un servei. Té un nom (*login*) i un número. |
| **UID** (*User ID*) | Número que identifica internament l'usuari. El sistema treballa amb l'UID, no amb el nom. |
| **Grup** | Conjunt d'usuaris al qual es poden assignar permisos de manera conjunta. |
| **GID** (*Group ID*) | Número que identifica internament el grup. |
| **Grup primari** | Grup principal de l'usuari. És el grup que s'assigna als fitxers que crea. Cada usuari en té exactament un. |
| **Grups secundaris** | Altres grups als quals pertany l'usuari i dels quals també obté els permisos. En pot tindre diversos o cap. |

### Tipus de comptes

| Tipus | UID habitual | Exemples | Característiques |
| --- | --- | --- | --- |
| **Superusuari** | `0` | `root` | Administrador del sistema. No té cap restricció de permisos. |
| **Usuaris del sistema** | `1`–`999` | `www-data`, `systemd-network`, `mysql` | Els utilitzen els serveis per a executar-se sense privilegis de root. Normalment no poden iniciar sessió. |
| **Usuaris normals** | `1000` en avant | `alumne`, `ana` | Persones que utilitzen l'equip. |
| **`nobody`** | `65534` | `nobody` | Usuari sense privilegis per a processos que no han de tindre accés a res. |

Els límits entre usuaris del sistema i normals es definixen en el fitxer `/etc/login.defs` (variables `SYS_UID_MAX`, `UID_MIN` i `UID_MAX`).

> [!NOTE]
> En Ubuntu el compte `root` existix, però **no té contrasenya** i no s'hi pot iniciar sessió directament. En el seu lloc, el primer usuari que es crea en la instal·lació pertany al grup `sudo` i pot executar ordres com a root amb `sudo` (apartat 1.6).

Per a saber qui eres i a quins grups pertanys:

```bash
whoami          # Nom de l'usuari actual
id              # uid=1000(alumne) gid=1000(alumne) grups=1000(alumne),4(adm),27(sudo)...
id ana          # El mateix, per a un altre usuari
groups          # Només els noms dels meus grups
```

## 1.2 Els fitxers de comptes

La informació d'usuaris i grups es guarda en **fitxers de text** dins de `/etc`. Cada línia és un compte i els camps se separen amb `:`.

### `/etc/passwd`: els usuaris

El pot llegir qualsevol usuari (els programes el necessiten, per exemple, per a mostrar el propietari d'un fitxer amb `ls -l`).

```text
ana:x:1001:1001:Ana López,,,:/home/ana:/bin/bash
```

| Camp | Exemple | Significat |
| --- | --- | --- |
| 1. Nom | `ana` | Nom d'inici de sessió. |
| 2. Contrasenya | `x` | Una `x` indica que la contrasenya està en `/etc/shadow`. |
| 3. UID | `1001` | Identificador de l'usuari. |
| 4. GID | `1001` | Identificador del **grup primari**. |
| 5. GECOS | `Ana López,,,` | Comentari: nom complet, despatx, telèfons… |
| 6. Directori personal | `/home/ana` | Directori *home* de l'usuari (`~`). |
| 7. Shell | `/bin/bash` | Programa que s'executa en iniciar sessió. `/usr/sbin/nologin` o `/bin/false` impedixen l'accés interactiu. |

### `/etc/shadow`: les contrasenyes

Només el pot llegir **root**, perquè conté el *hash* de les contrasenyes. Un ***hash*** és el resultat d'aplicar una funció matemàtica d'un sol sentit a la contrasenya: a partir del *hash* no es pot obtindre la contrasenya, però sí que es pot comprovar si una contrasenya introduïda hi coincidix.

```text
ana:$y$j9T$Kw3...$Zx8...:20400:0:99999:7:::
```

| Camp | Exemple | Significat |
| --- | --- | --- |
| 1. Nom | `ana` | Usuari al qual pertany la línia. |
| 2. *Hash* | `$y$j9T$...` | Contrasenya xifrada. `$y$` indica l'algorisme *yescrypt*. Si comença per `!` el compte està **bloquejat**; `*` o `!` sols indiquen que no té contrasenya vàlida. |
| 3. Últim canvi | `20400` | Dia de l'últim canvi de contrasenya, comptat en dies des de l'1/1/1970. |
| 4. Mínim | `0` | Dies que han de passar abans de poder canviar-la una altra vegada. |
| 5. Màxim | `99999` | Dies de validesa de la contrasenya (`99999` = en la pràctica no caduca). |
| 6. Avís | `7` | Dies d'antelació amb què s'avisa que caducarà. |
| 7. Inactivitat | (buit) | Dies després de la caducitat en què encara es pot canviar abans que es desactive el compte. |
| 8. Expiració | (buit) | Data en què es desactiva el compte. |
| 9. Reservat | (buit) | Sense ús. |

Els camps 3 a 8 formen la **política de caducitat** del compte, que es gestiona amb `chage` (apartat 4).

### `/etc/group` i `/etc/gshadow`: els grups

```text
dam1:x:1010:ana,luis
```

| Camp | Significat |
| --- | --- |
| 1. Nom | Nom del grup. |
| 2. Contrasenya | `x`: la contrasenya del grup (rarament utilitzada) està en `/etc/gshadow`. |
| 3. GID | Identificador del grup. |
| 4. Membres | Usuaris que tenen aquest grup com a **secundari**, separats per comes. Els usuaris el grup **primari** dels quals és aquest no hi apareixen. |

> [!CAUTION]
> **No edites aquests fitxers a mà** amb un editor normal: un error de format pot impedir que ningú inicie sessió. Utilitza sempre les ordres d'aquest apartat o, si necessites editar-los, `sudo vipw` (per a `passwd`) i `sudo vigr` (per a `group`), que bloquegen el fitxer i comproven la sintaxi.

Per a consultar els comptes és preferible `getent`, que mostra també els usuaris que vénen d'altres fonts (per exemple, un servidor LDAP o un domini):

```bash
getent passwd ana        # Línia d'ana en la base de dades d'usuaris
getent group sudo        # Membres del grup sudo
getent passwd | awk -F: '$3 >= 1000 && $3 < 65534 {print $1}'   # Només usuaris normals
```

## 1.3 Crear usuaris

Hi ha dues ordres per a crear usuaris i convé conéixer-les totes dues:

| Ordre | Disponibilitat | Característiques |
| --- | --- | --- |
| `useradd` | Totes les distribucions | Ordre de **baix nivell**. No pregunta res: fa exactament el que li indiquen les opcions. És l'adequada per a **scripts**. |
| `adduser` | Debian, Ubuntu i derivades | Script **interactiu** i amigable: crea el directori personal, demana la contrasenya i les dades personals. Llig la seua configuració de `/etc/adduser.conf`. |

### `useradd`

```text
useradd [opcions] usuari
```

| Opció | Significat |
| --- | --- |
| `-m` | Crea el directori personal (copiant el contingut de `/etc/skel`, apartat 3). **Sense aquesta opció no es crea.** |
| `-d ruta` | Directori personal diferent de `/home/usuari`. |
| `-s shell` | Shell d'inici de sessió (per defecte pot ser `/bin/sh`; convé indicar `/bin/bash`). |
| `-c "text"` | Comentari (normalment el nom complet). |
| `-g grup` | Grup **primari** (ha d'existir). Si no s'indica, es crea un grup amb el mateix nom que l'usuari. |
| `-G g1,g2` | Grups **secundaris**, separats per comes i sense espais. |
| `-u UID` | Força un UID concret. |
| `-e AAAA-MM-DD` | Data d'expiració del compte. |
| `-r` | Crea un **usuari del sistema** (UID baix, sense caducitat de contrasenya). |

```bash
# Usuari normal, amb directori personal, Bash, nom complet i en el grup secundari dam1
sudo useradd -m -s /bin/bash -c "Ana López" -G dam1 ana
sudo passwd ana                  # Assigna la contrasenya (useradd NO la demana)
getent passwd ana                # Comprovació
ls -la /home/ana                 # Fitxers copiats de /etc/skel
```

Els valors per defecte de `useradd` es consulten amb `useradd -D` i es guarden en `/etc/default/useradd`.

### `adduser` (Debian/Ubuntu)

```bash
sudo adduser luis                # Pregunta contrasenya, nom complet, telèfons…
sudo adduser luis dam1           # Amb DOS arguments: afig un usuari existent a un grup
sudo adduser --system --group --no-create-home miapp   # Usuari de sistema per a un servei
```

> [!NOTE]
> Des de les versions recents de Debian i Ubuntu, `adduser` crea els directoris personals amb permisos restrictius (els altres usuaris no poden entrar en el *home* dels altres). Pots comprovar-ho amb `ls -ld /home/*`.

### Usuaris per a serveis

Quan desplegues una aplicació en un servidor, **no l'executes mai com a root**. El correcte és crear un usuari del sistema dedicat, sense contrasenya i sense possibilitat d'iniciar sessió:

```bash
# -r: usuari del sistema, -s nologin: no pot obrir una shell, -d: directori de l'aplicació
sudo useradd -r -s /usr/sbin/nologin -d /opt/miapp -c "Servei miapp" miapp
sudo mkdir -p /opt/miapp && sudo chown miapp:miapp /opt/miapp
```

En l'apartat 8 voràs com fer que systemd arranque l'aplicació amb aquest usuari.

## 1.4 Modificar i eliminar usuaris

### `usermod`

| Opció | Significat |
| --- | --- |
| `-aG g1,g2` | **Afig** grups secundaris (`-a` = *append*). |
| `-G g1,g2` | **Substituïx** la llista de grups secundaris per la indicada. |
| `-g grup` | Canvia el grup primari. |
| `-s shell` | Canvia la shell. |
| `-c "text"` | Canvia el comentari. |
| `-d ruta -m` | Canvia el directori personal i **mou** el seu contingut (`-m`). |
| `-l nou` | Canvia el nom d'inici de sessió. |
| `-L` / `-U` | Bloqueja / desbloqueja la contrasenya (afig o lleva `!` en `/etc/shadow`). |
| `-e AAAA-MM-DD` | Data d'expiració (`-e ""` l'elimina). |

```bash
sudo usermod -aG docker,dialout ana    # Afig ana a dos grups més
sudo usermod -s /usr/sbin/nologin luis # luis ja no pot obrir una shell
sudo usermod -L luis                   # Bloqueja la seua contrasenya
sudo usermod -c "Luis Pérez" -e 2027-06-30 luis
```

> [!CAUTION]
> `usermod -G grup usuari` **sense** `-a` elimina l'usuari de tots els seus altres grups secundaris. Si fas això amb el teu propi usuari i el grup `sudo`, perdràs els privilegis d'administració. Utilitza sempre `-aG` per a afegir.

> [!IMPORTANT]
> Els canvis de grup **no s'apliquen a les sessions ja obertes**. L'usuari ha de tancar la sessió i tornar a entrar (o executar `newgrp grup` en aquell terminal) perquè `id` mostre el grup nou.

### `userdel`

```bash
sudo userdel luis        # Esborra el compte, però conserva /home/luis i els seus fitxers
sudo userdel -r luis     # Esborra també el directori personal i la bústia de correu
```

Els fitxers que l'usuari tinguera fora del seu directori personal queden amb el seu antic UID com a propietari (en `ls -l` apareixerà un número en lloc d'un nom). Pots localitzar-los abans d'esborrar el compte:

```bash
sudo find / -xdev -user luis 2>/dev/null     # Fitxers de luis en el sistema d'arxius arrel
```

> [!TIP]
> En un entorn professional, abans d'esborrar un compte se sol **bloquejar** (`usermod -L` i `usermod -e 1`) durant un temps i fer una còpia del seu directori. Així es pot recuperar si algú necessita algun fitxer.

### Contrasenyes i dades personals

```bash
passwd                   # Canvia LA MEUA contrasenya (demana l'actual)
sudo passwd ana          # root canvia la contrasenya d'ana sense conéixer l'anterior
sudo passwd -S ana       # Estat: P (té contrasenya), L (bloquejada), NP (sense contrasenya)
sudo chfn ana            # Canvia el camp GECOS (nom complet, telèfons…)
chsh -s /bin/zsh         # Canvia LA MEUA shell (ha d'estar en /etc/shells)
```

## 1.5 Gestionar grups

| Ordre | Funció |
| --- | --- |
| `groupadd grup` | Crea un grup (`-g GID` per a fixar el número, `-r` per a un grup del sistema). |
| `groupmod -n nou vell` | Canvia el nom d'un grup. |
| `groupdel grup` | Esborra un grup (no es pot si és el grup primari d'algun usuari). |
| `gpasswd -a usuari grup` | Afig un usuari a un grup. |
| `gpasswd -d usuari grup` | Lleva un usuari d'un grup. |
| `gpasswd -M u1,u2 grup` | Definix la llista completa de membres. |
| `gpasswd -A usuari grup` | Nomena administrador del grup un usuari (podrà afegir i llevar membres sense ser root). |

```bash
sudo groupadd dam1
sudo groupadd professors
sudo gpasswd -a ana dam1
sudo gpasswd -M ana,luis,marta dam1   # Membres exactes del grup
sudo gpasswd -d luis dam1
getent group dam1                     # dam1:x:1010:ana,marta
```

En Debian/Ubuntu també existixen `addgroup`, `delgroup` i `deluser usuari grup`, que fan el mateix de manera interactiva.

### Grups especials d'Ubuntu/Debian

Pertànyer a alguns grups del sistema concedix capacitats concretes. Convé conéixer-los perquè els utilitzaràs com a desenvolupador:

| Grup | Què permet |
| --- | --- |
| `sudo` (Debian/Ubuntu) / `wheel` (Fedora, RHEL) | Executar ordres com a root amb `sudo`. |
| `adm` | Llegir els registres de `/var/log` (apartat 10). |
| `systemd-journal` | Llegir tot el *journal* de systemd. |
| `docker` | Utilitzar Docker sense `sudo`. **Equival a tindre privilegis de root.** |
| `dialout` | Accedir als ports sèrie (Arduino, microcontroladors). |
| `plugdev` | Accedir a alguns dispositius USB extraïbles. |
| `kvm` | Utilitzar la virtualització per maquinari (necessari per a l'emulador d'Android en Linux). |

## 1.6 Canviar d'usuari: `su` i `sudo`

| Ordre | Què fa | Contrasenya que demana |
| --- | --- | --- |
| `su usuari` | Obri una shell com un altre usuari, conservant part de l'entorn actual. | La de l'**usuari de destinació**. |
| `su - usuari` | Igual, però amb un **inici de sessió complet** (carrega el seu entorn i va al seu *home*). | La de l'usuari de destinació. |
| `sudo ordre` | Executa **una ordre** com a root (o com un altre usuari amb `-u`). | La **teua**. |
| `sudo -i` | Obri una shell de root amb inici de sessió complet. | La teua. |
| `sudo -u ana ordre` | Executa una ordre com l'usuari `ana`. | La teua. |

`sudo` és preferible a `su` perquè:

- No cal compartir la contrasenya de root.
- Es pot limitar **quines** ordres pot executar cada usuari.
- Queda **registrat** qui va executar cada ordre (en `/var/log/auth.log` o en el *journal*).

```bash
sudo -l                   # Què puc executar amb sudo?
sudo -u www-data id       # Executa 'id' com l'usuari www-data
sudo -k                   # Oblida la contrasenya guardada: la pròxima vegada la tornarà a demanar
```

### El fitxer `sudoers`

La configuració de `sudo` està en `/etc/sudoers` i en els fitxers del directori `/etc/sudoers.d/`. Una regla té aquest format:

```text
qui     equips=(com_a_qui:grup)       ordres
%sudo   ALL=(ALL:ALL)                 ALL
```

Aquesta línia, inclosa per defecte en Ubuntu, significa: "els membres del grup `sudo` (el `%` indica grup) poden executar, en qualsevol equip, com qualsevol usuari i grup, qualsevol ordre".

Per a donar permisos concrets, crea un fitxer nou en `/etc/sudoers.d/` **sempre amb `visudo`**, que comprova la sintaxi abans de guardar:

```bash
sudo visudo -f /etc/sudoers.d/desenvolupament
```

```text
# /etc/sudoers.d/desenvolupament
# Els membres de 'desenvolupament' poden reiniciar el servei de l'aplicació sense ser administradors
%desenvolupament ALL=(root) /usr/bin/systemctl restart miapp.service, /usr/bin/systemctl is-active miapp.service

# ana pot executar apt sense que se li demane contrasenya (utilitza-ho amb molta prudència)
ana ALL=(root) NOPASSWD: /usr/bin/apt
```

Dues regles importants en escriure ordres en `sudoers`:

- Si una ordre s'escriu **sense arguments** (per exemple, `/usr/bin/systemctl`), l'usuari podrà executar-la amb **qualsevol** argument. Escriu sempre l'ordre completa que vols permetre.
- No permetes ordres que obrin un **paginador o un editor** (`systemctl status`, `journalctl`, `less`, `vi`…): des d'aquests es pot executar una shell (per exemple, escrivint `!sh` en `less`) que tindria privilegis de root.

> [!CAUTION]
> Un error de sintaxi en `sudoers` et pot deixar **sense accés a `sudo`**. Per això s'utilitza `visudo` i es treballa en un fitxer a banda de `/etc/sudoers.d/`. Si tot i això ocorre, pots arreglar-ho des d'una sessió de root que tingues oberta o arrancant en mode de recuperació.

> [!NOTE]
> Des d'**Ubuntu 25.10**, i per tant en **Ubuntu 26.04 LTS**, l'ordre `sudo` la proporciona **sudo-rs**, una reimplementació escrita en el llenguatge Rust, més segura davant d'errors de memòria. Per a l'usuari funciona igual; les diferències visibles són que mostra asteriscos en escriure la contrasenya i que no admet comodins dins dels arguments de les ordres en `sudoers` (per això, en l'exemple anterior, les ordres s'escriuen completes). La versió clàssica continua disponible com a `sudo.ws`. Ho pots comprovar amb `sudo --version`.


## Exercicis resolts

### Exercici 1.1. Interpretar `/etc/passwd`

Donada la línia `www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin`, respon: és un usuari normal o del sistema? Quin és el seu grup primari? Pot iniciar sessió?

{{% details "Veure solució" %}}
- UID `33` (menor que 1000): és un **usuari del sistema**. L'utilitza el servidor web (Apache o Nginx).
- El seu grup primari té GID `33`; amb `getent group 33` es comprova que és el grup `www-data`.
- La seua shell és `/usr/sbin/nologin`, així que **no pot obrir una sessió interactiva**: si algú ho intenta, rep el missatge *This account is currently not available*.
{{% /details %}}

### Exercici 1.2. Alta d'un equip de treball

Crea els grups `dam1` i `professors`. Després crea els usuaris `ana` i `luis` (grup secundari `dam1`) i `marta` (grup secundari `professors`), tots amb directori personal, Bash i el seu nom complet. Assigna contrasenya als tres i comprova el resultat.

{{% details "Veure solució" %}}
```bash
sudo groupadd dam1
sudo groupadd professors

sudo useradd -m -s /bin/bash -c "Ana López"   -G dam1       ana
sudo useradd -m -s /bin/bash -c "Luis Pérez"  -G dam1       luis
sudo useradd -m -s /bin/bash -c "Marta Ruiz"  -G professors marta

# Assignar contrasenyes sense interacció: chpasswd llig línies "usuari:contrasenya"
printf '%s\n' 'ana:Canviar.2026' 'luis:Canviar.2026' 'marta:Canviar.2026' | sudo chpasswd

# Obligar a canviar-la en el primer inici de sessió (fa caducar la contrasenya)
sudo passwd -e ana; sudo passwd -e luis; sudo passwd -e marta

# Comprovacions
id ana; id luis; id marta
getent group dam1 professors
```

`chpasswd` és útil en scripts perquè permet assignar moltes contrasenyes alhora. `passwd -e` marca la contrasenya com a caducada perquè l'usuari haja de triar-ne una de nova en entrar.
{{% /details %}}

### Exercici 1.3. Error clàssic amb `usermod`

`ana` pertany a `dam1` i a `sudo`. Un company executa `sudo usermod -G docker ana`. Què ha passat? Com s'arregla?

{{% details "Veure solució" %}}
En utilitzar `-G` sense `-a`, la llista de grups secundaris d'`ana` s'ha **substituït** per `docker`: ja no pertany a `dam1` ni a `sudo`. S'arregla (des d'un altre compte amb privilegis) afegint de nou els grups:

```bash
sudo usermod -aG dam1,sudo ana
id ana
```

La forma correcta de l'ordre original era `sudo usermod -aG docker ana`.
{{% /details %}}

### Exercici 1.4. Permís limitat amb `sudo`

Crea el grup `suport` i afig-hi `luis`. Configura `sudo` perquè els membres de `suport` puguen **només** reiniciar el servei d'impressió `cups` i comprovar si està actiu. Comprova amb `sudo -l` què pot fer `luis`.

{{% details "Veure solució" %}}
```bash
sudo groupadd suport
sudo gpasswd -a luis suport
sudo visudo -f /etc/sudoers.d/suport
```

Contingut del fitxer:

```text
%suport ALL=(root) /usr/bin/systemctl restart cups.service, /usr/bin/systemctl is-active cups.service
```

Comprovació (des d'una sessió de `luis`):

```bash
su - luis
sudo -l                                   # Mostra les dues ordres permeses
sudo systemctl restart cups.service       # Permés
sudo systemctl is-active cups.service     # Permés: respon "active"
sudo systemctl stop cups.service          # Denegat: els arguments no coincidixen amb la regla
sudo apt update                           # Denegat: "luis is not allowed to run sudo..."
```

No s'ha permés `systemctl status` perquè mostra l'eixida en un paginador (`less`) des del qual `luis` podria obrir una shell de root. Per a consultar l'estat detallat no necessita `sudo`: `systemctl status cups.service` funciona amb un usuari normal.
{{% /details %}}

### Exercici 1.5. Baixa segura d'un usuari

`luis` deixa el centre. Abans d'eliminar el seu compte, fes una còpia comprimida del seu directori personal en `/root/baixes/`, localitza els fitxers que tinga fora de `/home/luis` i, finalment, elimina el compte i el seu directori.

{{% details "Veure solució" %}}
```bash
sudo usermod -L -e 1 luis                          # 1r Bloquejar el compte (contrasenya i expiració)
sudo mkdir -p /root/baixes
```
