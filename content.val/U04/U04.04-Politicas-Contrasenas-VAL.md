# 4. Directives de compte i de contrasenyes

Crear comptes no és suficient: cal **assegurar l'accés** al sistema. Si les contrasenyes són curtes, no es revisen mai o es poden provar sense límit, un atacant acabarà endevinant-les. Les **directives** (o polítiques) **de compte** són les regles que el sistema imposa a tots els comptes per a evitar-ho.

## 4.1 Què es pot controlar

| Directiva | Què controla | Atac que dificulta |
| --- | --- | --- |
| **Longitud mínima** | Nombre mínim de caràcters. | Força bruta: provar totes les combinacions possibles. |
| **Complexitat** | Obligar a mesclar tipus de caràcters (majúscules, minúscules, dígits, símbols). | Atacs de diccionari. |
| **Historial** | Impedir reutilitzar les últimes *N* contrasenyes. | Tornar sempre a la mateixa contrasenya. |
| **Vigència màxima** (caducitat) | Dies que dura una contrasenya abans d'haver de canviar-la. | Ús prolongat d'una contrasenya robada. |
| **Vigència mínima** | Dies que han de passar abans de poder canviar-la una altra vegada. | Saltar-se l'historial canviant-la diverses vegades seguides. |
| **Llindar de bloqueig** | Intents fallits permesos abans de bloquejar el compte. | Força bruta en línia (provar contrasenyes contra el sistema). |
| **Duració del bloqueig** | Temps que el compte roman bloquejat. | Ídem. |
| **Expiració del compte** | Data a partir de la qual el compte deixa de funcionar. | Comptes oblidats de persones que ja no són en l'organització. |

> [!NOTE]
> Les recomanacions actuals de seguretat, com les directrius del NIST nord-americà (publicació SP 800-63B), han canviat algunes pràctiques tradicionals: donen més importància a la **longitud** que a la complexitat (una frase llarga és millor que una paraula curta amb símbols), desaconsellen **obligar a canviar la contrasenya periòdicament** si no hi ha indicis que s'haja vist compromesa, i recomanen comprovar les contrasenyes noves contra **llistes de contrasenyes filtrades** i utilitzar l'**autenticació multifactor**. En aquesta unitat aprendràs a configurar totes les directives, però en triar-ne els valors tin en compte aquest criteri.

## 4.2 Linux: caducitat de contrasenyes

### Valors per defecte: `/etc/login.defs`

Aquest fitxer definix els valors que s'apliquen als **comptes que es creen a partir d'ara**:

```text
# Vigència màxima (99999 = sense caducitat en la pràctica)
PASS_MAX_DAYS   99999
# Vigència mínima
PASS_MIN_DAYS   0
# Dies d'avís abans de caducar
PASS_WARN_AGE   7
# Màscara de permisos per defecte (apartat 5)
UMASK           022
```

> [!IMPORTANT]
> Modificar `/etc/login.defs` **no canvia els comptes que ja existixen**. Per a aquests s'utilitza `chage`.

### `chage`: caducitat d'un compte

`chage` (*change age*) modifica els camps de caducitat de `/etc/shadow` (apartat 1.2).

| Opció | Significat |
| --- | --- |
| `-l usuari` | Mostra la política de caducitat del compte. |
| `-M dies` | Vigència màxima de la contrasenya. |
| `-m dies` | Vigència mínima. |
| `-W dies` | Dies d'avís previ. |
| `-I dies` | Dies d'inactivitat després de caducar la contrasenya abans de desactivar el compte. |
| `-E AAAA-MM-DD` | Data d'expiració del compte (`-E -1` l'elimina). |
| `-d 0` | Posa a 0 la data de l'últim canvi: **obliga a canviar la contrasenya** en el pròxim inici de sessió. |

```bash
sudo chage -l ana
# Last password change                         : nov 08, 2026
# Password expires                             : never
# ...

sudo chage -M 180 -m 1 -W 14 ana     # Caduca als 180 dies, avís 14 dies abans
sudo chage -E 2027-06-30 ana         # El compte deixa de funcionar en acabar el curs
sudo chage -d 0 ana                  # Ha de canviar la contrasenya en entrar
```

Sense opcions, `sudo chage ana` pregunta els valors un per un de manera interactiva.

### Bloquejar i desbloquejar comptes manualment

```bash
sudo passwd -l ana       # Bloqueja la contrasenya (afig '!' al hash en /etc/shadow)
sudo passwd -u ana       # La desbloqueja
sudo passwd -S ana       # Estat: ana L ... (L = bloquejada, P = contrasenya vàlida)
```

> [!WARNING]
> `passwd -l` només impedix autenticar-se **amb contrasenya**. Si l'usuari té una clau SSH configurada, podrà continuar entrant per SSH. Per a deshabilitar el compte completament, fes caducar també el compte (`sudo chage -E 0 ana` o `sudo usermod -e 1 ana`).

## 4.3 Linux: PAM

En Linux, l'autenticació no la fa cada programa pel seu compte: `login`, `sudo`, `su`, el gestor gràfic d'inici de sessió o el servidor SSH deleguen en **PAM** (*Pluggable Authentication Modules*, mòduls d'autenticació connectables).

PAM és un sistema de **mòduls** que s'encadenen. Cada programa té el seu fitxer de configuració en `/etc/pam.d/`, i en Debian/Ubuntu tots inclouen uns fitxers comuns:

| Fitxer | Per a què |
| --- | --- |
| `/etc/pam.d/common-auth` | Comprovar la identitat (demanar i verificar la contrasenya). |
| `/etc/pam.d/common-account` | Comprovar si el compte es pot utilitzar (caducat, bloquejat…). |
| `/etc/pam.d/common-password` | Regles per a **canviar** la contrasenya. |
| `/etc/pam.d/common-session` | Accions en obrir i tancar sessió. |

Gràcies a PAM, afegint un mòdul es pot, per exemple, exigir contrasenyes robustes o bloquejar comptes després de diverses fallades, i el canvi s'aplica a tots els programes alhora.

> [!CAUTION]
> Un error en els fitxers de `/etc/pam.d/` pot impedir que **ningú** inicie sessió, ni tan sols root mitjançant `sudo`. Abans de modificar-los: treballa en una màquina virtual amb una **instantània**, obri un **segon terminal amb `sudo -i`** i no el tanques fins a comprovar en un altre terminal que pots iniciar sessió.

### Qualitat de les contrasenyes: `pam_pwquality`

El mòdul `pam_pwquality` comprova la contrasenya nova quan l'usuari la canvia amb `passwd`.

```bash
sudo apt install libpam-pwquality    # Instal·la el mòdul i l'afig a common-password
grep pwquality /etc/pam.d/common-password
# password  requisite  pam_pwquality.so retry=3
```

Les regles es configuren en `/etc/security/pwquality.conf` (descomenta i ajusta les línies que necessites):

```ini
# /etc/security/pwquality.conf
# Longitud mínima
minlen = 12
# Tipus de caràcters diferents (minúscules, majúscules, dígits, altres)
minclass = 3
# Màxim de caràcters iguals seguits
maxrepeat = 3
# Rebutja paraules de diccionari
dictcheck = 1
# Rebutja contrasenyes que continguen el nom de l'usuari
usercheck = 1
# Caràcters que han de canviar respecte a la contrasenya anterior
difok = 5
# Aplica les regles també quan root canvia contrasenyes
enforce_for_root
```

```bash
passwd               # Prova: una contrasenya curta mostrarà "BAD PASSWORD: The password is shorter than 12 characters"
```

Per a l'**historial** de contrasenyes s'utilitza el mòdul `pam_pwhistory`, afegint en `/etc/pam.d/common-password`, just abans de la línia de `pam_unix.so`:

```text
password  required  pam_pwhistory.so remember=5 use_authtok
```

### Bloqueig després d'intents fallits: `pam_faillock`

El mòdul `pam_faillock` compta els intents fallits i bloqueja el compte temporalment. Es configura en `/etc/security/faillock.conf`:

```ini
# /etc/security/faillock.conf
# Bloquejar després de 5 fallades…
deny = 5
# …produïdes en 15 minuts (900 s)
fail_interval = 900
# Desbloquejar automàticament als 10 minuts
unlock_time = 600
```

En Ubuntu el mòdul ve instal·lat però **no activat**. Per a activar-lo cal modificar `/etc/pam.d/common-auth` perquè quede així (les línies de `pam_faillock` envolten la de `pam_unix`):

```text
auth    requisite                       pam_faillock.so preauth
auth    [success=1 default=ignore]      pam_unix.so nullok
auth    [default=die]                   pam_faillock.so authfail
auth    sufficient                      pam_faillock.so authsucc
auth    requisite                       pam_deny.so
auth    required                        pam_permit.so
```

I afegir al final de `/etc/pam.d/common-account`:

```text
account required                        pam_faillock.so
```

Gestió dels bloquejos:

```bash
sudo faillock --user ana            # Mostra els intents fallits d'ana
sudo faillock --user ana --reset    # Desbloqueja el compte immediatament
```

> [!NOTE]
> El contingut exacte de `common-auth` pot variar segons la versió i els paquets instal·lats (per exemple, si l'equip utilitza empremta digital o un domini). Compara sempre amb el teu fitxer abans de modificar-lo i guarda'n una còpia: `sudo cp /etc/pam.d/common-auth /root/common-auth.bak`.

## 4.4 Windows: directiva de seguretat local

En Windows, les directives de compte es configuren en la **Directiva de seguretat local** (`secpol.msc`, no disponible en Windows Home), dins de **Configuració de seguretat > Directives de compte**.

### Directiva de contrasenyes

| Directiva | Valors | Comentari |
| --- | --- | --- |
| **Exigir historial de contrasenyes** | 0–24 contrasenyes recordades | |
| **Vigència màxima de la contrasenya** | 0–999 dies (0 = no caduca) | Per defecte, 42 dies. |
| **Vigència mínima de la contrasenya** | 0–998 dies | |
| **Longitud mínima de la contrasenya** | 0–14 caràcters | |
| **La contrasenya ha de complir els requisits de complexitat** | Habilitada / Deshabilitada | Exigix almenys 6 caràcters de 3 d'aquestes 4 categories: majúscules, minúscules, dígits i símbols, i que no continga el nom del compte. |
| **Emmagatzemar contrasenyes amb xifratge reversible** | Habilitada / Deshabilitada | **Ha d'estar sempre deshabilitada**: equival a guardar les contrasenyes quasi en text pla. |

### Directiva de bloqueig de compte

| Directiva | Significat |
| --- | --- |
| **Llindar de bloqueig del compte** | Intents fallits que provoquen el bloqueig (0 = no es bloqueja mai). |
| **Duració del bloqueig del compte** | Minuts que roman bloquejat (0 = fins que un administrador el desbloquege). |
| **Restablir el comptador de bloquejos del compte després de** | Minuts després dels quals el comptador de fallades torna a 0. |
| **Permetre el bloqueig del compte d'administrador** | Si s'aplica també al compte Administrador integrat. |

> [!NOTE]
> En les versions actuals de Windows 11, el bloqueig de comptes ve **activat per defecte** amb un llindar de 10 intents i una duració de 10 minuts. Comprova-ho en el teu equip amb `net accounts`.

{{% steps %}}
1. ## Obrir la consola

   `Win + R` > `secpol.msc`. Desplega **Directives de compte > Directiva de contrasenyes**.

2. ## Modificar una directiva

   Fes doble clic sobre la directiva (per exemple, *Longitud mínima de la contrasenya*), escriu el valor i prem **D'acord**. Els canvis s'apliquen immediatament, però només es comproven la **pròxima vegada** que cada usuari canvie la seua contrasenya.

3. ## Forçar l'actualització

   Si el canvi no sembla aplicar-se, executa `gpupdate /force` en una consola d'administrador.
{{% /steps %}}

Les mateixes opcions, i moltes més, estan en l'**Editor de directives de grup local** (`gpedit.msc`), en *Configuració de l'equip > Configuració de Windows > Configuració de seguretat*. En un domini es configuren de manera centralitzada amb **directives de grup** (GPO), com voràs en la Unitat 6.

## 4.5 Windows: directives des de la línia d'ordres

### `net accounts`

Mostra i modifica les directives de contrasenya i bloqueig. Funciona en **totes les edicions**, inclosa Home.

| Opció | Directiva |
| --- | --- |
| `/minpwlen:N` | Longitud mínima. |
| `/maxpwage:N` | Vigència màxima en dies (`UNLIMITED` perquè no caduque). |
| `/minpwage:N` | Vigència mínima en dies. |
| `/uniquepw:N` | Historial: contrasenyes recordades. |
| `/lockoutthreshold:N` | Llindar de bloqueig. |
| `/lockoutduration:N` | Duració del bloqueig en minuts. |
| `/lockoutwindow:N` | Minuts per a restablir el comptador de fallades. |

```bat
net accounts
net accounts /minpwlen:12 /maxpwage:180 /minpwage:1 /uniquepw:5
net accounts /lockoutthreshold:5 /lockoutduration:15 /lockoutwindow:15
```

### `secedit`: la directiva de complexitat

`net accounts` no permet activar la **complexitat**. Per a això, s'exporta la configuració de seguretat a un fitxer de text, es modifica i es torna a importar amb `secedit`:

```powershell
# Executar en PowerShell com a administrador
New-Item -ItemType Directory -Path C:\Temp -Force | Out-Null      # Crea C:\Temp si no existix
secedit /export /cfg C:\Temp\seguretat.inf /areas SECURITYPOLICY

# Canvia la línia "PasswordComplexity = 0" per "PasswordComplexity = 1"
(Get-Content C:\Temp\seguretat.inf) -replace 'PasswordComplexity = 0', 'PasswordComplexity = 1' |
    Set-Content C:\Temp\seguretat.inf

secedit /configure /db C:\Windows\security\database\secedit.sdb /cfg C:\Temp\seguretat.inf /areas SECURITYPOLICY
net accounts            # Comprovació (la complexitat no apareix ací: revisa-la en secpol.msc)
```

### Directives d'un compte concret

Algunes opcions no són globals, sinó de cada usuari:

```powershell
# L'usuari ha de canviar la contrasenya en iniciar sessió
net user ana /logonpasswordchg:yes

# La contrasenya d'ana SÍ que caduca segons la directiva global
Set-LocalUser -Name ana -PasswordNeverExpires $false

# El compte expira al final del curs
Set-LocalUser -Name ana -AccountExpires (Get-Date "2027-06-30")

# Horari d'inici de sessió: només de dilluns a divendres de 8:00 a 15:00
# (les abreviatures dels dies depenen de l'idioma del sistema; consulta-les amb: net help user)
net user ana /times:L-V,08:00-15:00

# Desbloquejar un compte bloquejat per intents fallits
net user ana /active:yes
```

Un compte bloquejat també es pot desbloquejar en `lusrmgr.msc`: en les propietats de l'usuari, desmarca la casella **El compte està bloquejat**.

> [!TIP]
> En la pantalla **Configuració > Comptes > Opcions d'inici de sessió** es configura **Windows Hello** (PIN, empremta o reconeixement facial). El PIN de Windows Hello està lligat al dispositiu: encara que algú el descobrisca, no li servix per a accedir des d'un altre equip, a diferència de la contrasenya.

## 4.6 Comparativa

| Directiva | Linux | Windows |
| --- | --- | --- |
| Valors per defecte | `/etc/login.defs` | `secpol.msc`, `net accounts` |
| Caducitat d'un compte concret | `chage -M`, `chage -E` | `Set-LocalUser -AccountExpires`, `net user /expires` |
| Forçar canvi en el següent accés | `chage -d 0`, `passwd -e` | `net user /logonpasswordchg:yes` |
| Longitud i complexitat | `pam_pwquality` (`pwquality.conf`) | Directiva de contrasenyes |
| Historial | `pam_pwhistory` | *Exigir historial de contrasenyes*, `/uniquepw` |
| Bloqueig després de fallades | `pam_faillock` (`faillock.conf`) | Directiva de bloqueig, `/lockoutthreshold` |
| Desbloquejar | `faillock --reset`, `passwd -u` | `net user /active:yes` |

## Exercicis resolts

### Exercici 4.1. Llegir `chage -l`

`sudo chage -l luis` mostra *Password expires: dic 01, 2026* i *Password inactive: dic 08, 2026*. Què ocorre si `luis` intenta iniciar sessió el 3 de desembre? I el 10?

{{% details "Veure solució" %}}
- El **3 de desembre** la contrasenya ja ha caducat, però està dins del període d'inactivitat: `luis` pot entrar, però el sistema l'**obligarà a canviar la contrasenya** abans de continuar.
- El **10 de desembre** ha acabat el període d'inactivitat: el compte queda **desactivat** i `luis` no pot entrar. Un administrador li ha d'assignar una contrasenya nova (`sudo passwd luis`).
{{% /details %}}

### Exercici 4.2. Política de l'aula en Linux

Configura el teu Linux perquè:

1. Els comptes nous tinguen contrasenyes amb una vigència màxima de 180 dies i avís als 14.
2. El compte existent `ana` tinga aquesta mateixa política i expire el 30 de juny de 2027.
3. Les contrasenyes tinguen almenys 12 caràcters de 3 tipus diferents.

{{% details "Veure solució" %}}
```bash
# 1. Comptes futurs: editar /etc/login.defs
sudo sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS   180/; s/^PASS_WARN_AGE.*/PASS_WARN_AGE   14/' /etc/login.defs
grep ^PASS_ /etc/login.defs

# 2. Compte existent
sudo chage -M 180 -W 14 -E 2027-06-30 ana
sudo chage -l ana

# 3. Qualitat de contrasenyes
sudo apt install libpam-pwquality
sudo sed -i 's/^# *minlen.*/minlen = 12/; s/^# *minclass.*/minclass = 3/' /etc/security/pwquality.conf
grep -E '^(minlen|minclass)' /etc/security/pwquality.conf
```

`sed -i 's/patró/substitució/'` modifica el fitxer en el mateix lloc (Unitat 3). El patró `^# *minlen.*` troba la línia comentada, amb espai o sense després de `#`.
{{% /details %}}

### Exercici 4.3. Política de l'aula en Windows

Configura Windows amb: longitud mínima de 12, historial de 5 contrasenyes, complexitat activada i bloqueig després de 5 intents durant 15 minuts. Després, comprova el bloqueig.

{{% details "Veure solució" %}}
```bat
net accounts /minpwlen:12 /uniquepw:5 /lockoutthreshold:5 /lockoutduration:15 /lockoutwindow:15
```

La complexitat s'activa en `secpol.msc` (*La contrasenya ha de complir els requisits de complexitat* > *Habilitada*) o amb `secedit`, com en l'apartat 4.5.

**Comprovació**: tanca la sessió i intenta entrar 5 vegades amb una contrasenya incorrecta en un compte de prova (mai amb l'únic compte d'administrador). En el sisé intent apareixerà el missatge que el compte està bloquejat. Des d'un altre compte d'administrador:

```bat
net user prova           :: "Cuenta activa: Bloqueada"
net user prova /active:yes
```

En l'apartat 10 voràs que cada bloqueig queda registrat en el Visor d'esdeveniments amb l'identificador **4740**.
{{% /details %}}

### Exercici 4.4. Anàlisi crítica

Una empresa obliga a canviar la contrasenya cada 30 dies, exigix 8 caràcters amb complexitat i no té bloqueig de comptes. Els empleats utilitzen contrasenyes com `Gener2026!`, `Febrer2026!`… Identifica els problemes i proposa una política millor.

{{% details "Veure solució" %}}
Problemes:

- **Canvi cada 30 dies**: provoca que els usuaris utilitzen patrons previsibles (el mes i l'any). Si un atacant coneix una contrasenya, deduïx les següents.
- **8 caràcters**: és una longitud curta. La complexitat es complix amb patrons molt previsibles (majúscula al principi, símbol al final).
- **Sense bloqueig**: un atacant pot provar contrasenyes sense límit.

Proposta raonada:

- Longitud mínima de 12 a 15 caràcters, animant a utilitzar **frases de contrasenya** (per exemple, quatre paraules a l'atzar).
- Sense caducitat periòdica, però **canvi obligatori** si hi ha sospita que la contrasenya s'ha filtrat.
- **Bloqueig** després de 5–10 intents durant 10–15 minuts.
- **Historial** d'almenys 5 contrasenyes.
- **Autenticació multifactor** per als accessos remots i els comptes d'administrador.
- Ús d'un **gestor de contrasenyes** per a no haver de memoritzar contrasenyes diferents.
{{% /details %}}
