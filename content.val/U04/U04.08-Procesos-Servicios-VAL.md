# 8. Processos i serveis

Un administrador ha de saber en tot moment **què s'està executant** en el sistema, poder **aturar** el que no ha d'estar en marxa i **arrancar** el que es necessita. En aquest apartat s'estudien els dos elements que s'executen en un sistema operatiu: els **processos** i els **serveis**.

## 8.1 Conceptes

| Concepte | Descripció |
| --- | --- |
| **Programa** | Fitxer executable guardat en el disc (per exemple, `/usr/bin/python3` o `notepad.exe`). És una cosa estàtica. |
| **Procés** | Un programa **en execució**, amb la seua memòria, els seus fitxers oberts i el seu estat. Un mateix programa pot donar lloc a diversos processos alhora. |
| **PID** (*Process ID*) | Número que identifica cada procés mentre existix. |
| **PPID** (*Parent PID*) | PID del procés **pare**, el que el va crear. Els processos formen un arbre. |
| **Fil** (*thread*) | Línia d'execució dins d'un procés. Un procés pot tindre diversos fils que compartixen la seua memòria. |
| **Servei** o **dimoni** (*daemon*) | Procés que s'executa en **segon pla**, sense interfície, normalment des de l'arrancada i encara que no hi haja cap usuari connectat: servidor web, base de dades, SSH, impressió… En Linux els seus noms solen acabar en `d` (`sshd`, `smbd`). |

Cada procés s'executa amb la identitat d'un **usuari** i només pot accedir al que aquest usuari tinga permés. Per això és tan important que els serveis s'executen amb usuaris sense privilegis (apartat 1.3).

### Estats d'un procés en Linux

| Estat | Lletra en `ps` | Significat |
| --- | --- | --- |
| En execució | `R` | Utilitzant la CPU o esperant torn per a utilitzar-la. |
| Adormit | `S` | Esperant un esdeveniment (una tecla, dades de la xarxa…). És l'estat més habitual. |
| Espera ininterrompible | `D` | Esperant una operació d'E/S del disc. Molts processos en `D` indiquen un problema de disc. |
| Aturat | `T` | Pausat (per exemple, amb `Ctrl+Z`). |
| Zombi | `Z` | Ha acabat, però el seu pare encara no ha recollit el seu codi d'eixida. No consumix recursos, excepte la seua entrada en la taula de processos. |

## 8.2 Processos en Linux

### Llistar processos

| Ordre | Funció |
| --- | --- |
| `ps` | Processos del terminal actual. |
| `ps aux` | **Tots** els processos, amb usuari, % de CPU i de memòria (sintaxi BSD). |
| `ps -ef` | Tots els processos, amb PPID (sintaxi System V). |
| `ps -u ana` | Processos de l'usuari `ana`. |
| `ps -o pid,ppid,user,%cpu,%mem,cmd` | Columnes personalitzades. |
| `ps aux --sort=-%cpu` | Ordenats de més a menys ús de CPU. |
| `pstree -p` | Arbre de processos amb els seus PID. |
| `pgrep -a nom` | PID i ordre dels processos el nom dels quals coincidix. |
| `pidof programa` | PID d'un programa concret. |

```bash
ps aux | head -n 5
# USER   PID %CPU %MEM    VSZ   RSS TTY  STAT START   TIME COMMAND
# root     1  0.0  0.3  23440 13600 ?    Ss   09:12   0:02 /sbin/init splash
# root     2  0.0  0.0      0     0 ?    S    09:12   0:00 [kthreadd]
```

| Columna | Significat |
| --- | --- |
| `USER` | Usuari amb què s'executa. |
| `PID` | Identificador del procés. |
| `%CPU` / `%MEM` | Percentatge de CPU i de memòria física que utilitza. |
| `VSZ` / `RSS` | Memòria virtual reservada / memòria física realment ocupada (en KiB). |
| `TTY` | Terminal associat (`?` = cap, típic dels serveis). |
| `STAT` | Estat (vegeu la taula anterior). |
| `COMMAND` | Ordre que va llançar el procés. Entre claudàtors, els fils del nucli. |

El procés amb **PID 1** és el primer que arranca el nucli i l'avantpassat de tots els altres. En les distribucions actuals és **systemd**.

```bash
ps -o pid,ppid,user,%mem,cmd --sort=-%mem | head -n 6   # Els 5 processos que més memòria utilitzen
pgrep -a ssh                                           # Processos relacionats amb SSH
pstree -p $$                                           # $$ = PID de la shell actual
```

### Senyals: finalitzar processos

Per a comunicar-se amb un procés se li envien **senyals**. Els més importants:

| Senyal | Número | Significat | Es pot ignorar |
| --- | --- | --- | --- |
| `SIGTERM` | 15 | Demana al procés que **acabe ordenadament** (guardant dades i tancant fitxers). És el senyal per defecte. | Sí |
| `SIGKILL` | 9 | **Mata** el procés immediatament. Pot perdre dades. | **No** |
| `SIGINT` | 2 | Interrupció, el que envia `Ctrl+C`. | Sí |
| `SIGHUP` | 1 | "S'ha penjat el terminal". Molts serveis l'utilitzen per a **rellegir la seua configuració**. | Sí |
| `SIGSTOP` | 19 | Pausa el procés. | **No** |
| `SIGTSTP` | 20 | Pausa des del teclat (`Ctrl+Z`). | Sí |
| `SIGCONT` | 18 | Reprén un procés pausat. | — |

| Ordre | Funció |
| --- | --- |
| `kill PID` | Envia `SIGTERM` al procés. |
| `kill -9 PID` o `kill -KILL PID` | Envia `SIGKILL`. |
| `kill -l` | Llista tots els senyals. |
| `pkill nom` | Envia el senyal a tots els processos el nom dels quals coincidix. |
| `pkill -u ana` | A tots els processos d'`ana`. |
| `killall nom` | Pel nom exacte del programa. |

```bash
sleep 600 &              # Llança un procés de prova en segon pla
pgrep -a sleep           # 4321 sleep 600
kill 4321                # Li demana que acabe
kill -9 4321             # Només si no ha respost a SIGTERM
```

> [!TIP]
> Utilitza sempre primer `kill` (SIGTERM) i espera uns segons. Recorre a `kill -9` només si el procés no respon, perquè no li dona oportunitat de guardar dades ni d'alliberar recursos (fitxers temporals, bloquejos…).

Un usuari normal només pot enviar senyals als **seus propis** processos; root els pot enviar a qualsevol.

### Primer i segon pla

| Acció | Com |
| --- | --- |
| Llançar en segon pla | Afegir `&` al final: `ordre &` |
| Pausar el procés en primer pla | `Ctrl+Z` |
| Veure els treballs d'aquest terminal | `jobs` |
| Continuar en segon pla | `bg %1` |
| Portar a primer pla | `fg %1` |
| Que no acabe en tancar el terminal | `nohup ordre &` (l'eixida va a `nohup.out`) |

```bash
python3 -m http.server 8000      # Servidor web de prova en primer pla
# Ctrl+Z                         -> [1]+ Detingut  python3 -m http.server 8000
bg %1                            # Continua funcionant en segon pla
jobs                             # [1]+ Executant  python3 -m http.server 8000 &
fg %1                            # Torna a primer pla; Ctrl+C per a acabar-lo
```

### Prioritat: `nice` i `renice`

El planificador del sistema repartix la CPU entre els processos segons la seua **prioritat**. En Linux es controla amb el valor ***nice***, entre **-20** (màxima prioritat) i **19** (mínima). Per defecte és 0. S'anomena així perquè un procés amb un valor alt és més "amable" (*nice*) amb els altres.

```bash
nice -n 15 tar -czf copia.tar.gz ~/projectes   # Compressió amb baixa prioritat
renice -n 10 -p 4321                           # Canvia la prioritat d'un procés en marxa
sudo renice -n -5 -p 4321                      # Només root pot PUJAR la prioritat (valors negatius)
ps -o pid,ni,cmd -p 4321                       # Columna NI: valor nice
```

## 8.3 Serveis en Linux: systemd

**systemd** és el sistema d'inici i el gestor de serveis de quasi totes les distribucions actuals. Organitza tot el que gestiona en **unitats** (*units*), cadascuna descrita per un fitxer de text:

| Tipus d'unitat | Extensió | Què representa |
| --- | --- | --- |
| Servei | `.service` | Un servei o dimoni. |
| *Socket* | `.socket` | Un punt de connexió que arranca un servei quan algú s'hi connecta. |
| *Timer* | `.timer` | Una tasca programada (alternativa a `cron`, Unitat 3). |
| Muntatge | `.mount` | Un sistema d'arxius muntat. |
| Objectiu | `.target` | Un grup d'unitats que definixen un estat del sistema. |

Els fitxers de les unitats estan en `/usr/lib/systemd/system/` (els instal·len els paquets) i en `/etc/systemd/system/` (els de l'administrador, que tenen prioritat).

### `systemctl`: gestionar serveis

Cal distingir dues idees:

- **Arrancar/aturar** (`start`/`stop`): afecta **ara**, però no a la pròxima arrancada.
- **Habilitar/deshabilitar** (`enable`/`disable`): decidix si s'arranca **automàticament en iniciar el sistema**, però no l'arranca ni l'atura ara.

| Ordre | Funció |
| --- | --- |
| `systemctl status ssh` | Estat, PID, memòria i últimes línies del seu registre. |
| `sudo systemctl start ssh` | Arranca el servei. |
| `sudo systemctl stop ssh` | L'atura. |
| `sudo systemctl restart ssh` | L'atura i el torna a arrancar. |
| `sudo systemctl reload ssh` | Rellig la configuració sense aturar-lo (si el servei ho admet). |
| `sudo systemctl enable ssh` | L'arrancarà automàticament en cada inici. |
| `sudo systemctl disable ssh` | Ja no s'arrancarà en l'inici. |
| `sudo systemctl enable --now ssh` | Habilita **i** arranca alhora (`disable --now` per al contrari). |
| `systemctl is-active ssh` / `is-enabled ssh` | Respon amb una paraula; útil en scripts. |
| `sudo systemctl mask ssh` | Impedix que es puga arrancar de cap manera, ni manualment (`unmask` per a desfer-ho). |
| `systemctl list-units --type=service --state=running` | Serveis en execució. |
| `systemctl list-unit-files --type=service` | Tots els serveis instal·lats i el seu estat d'habilitació. |
| `systemctl --failed` | Unitats que han fallat. |
| `sudo systemctl daemon-reload` | Rellig els fitxers d'unitat després de modificar-los. |

```bash
systemctl status cron
# ● cron.service - Regular background program processing daemon
#      Loaded: loaded (/usr/lib/systemd/system/cron.service; enabled; preset: enabled)
#      Active: active (running) since Sun 2026-11-08 09:12:31 CET; 2h ago
#    Main PID: 812 (cron)
#       Tasks: 1 (limit: 4558)
#      Memory: 1.2M
```

En la línia `Loaded`, `enabled` indica que arranca amb el sistema. En la línia `Active`, `active (running)` indica que està en marxa ara. Els estats d'habilitació més habituals en `list-unit-files` són:

| Estat | Significat |
| --- | --- |
| `enabled` | S'arranca automàticament en l'inici. |
| `disabled` | No s'arranca en l'inici, però es pot arrancar manualment. |
| `static` | No es pot habilitar per si mateix; l'arranca una altra unitat que en depén. |
| `masked` | Bloquejat: no es pot arrancar de cap manera. |
| `alias` | És un altre nom d'una unitat. |

> [!NOTE]
> En algunes distribucions el mateix servei té noms diferents: el servidor SSH s'anomena `ssh` en Debian/Ubuntu i `sshd` en Fedora/RHEL; el servidor web Apache, `apache2` en Debian/Ubuntu i `httpd` en Fedora/RHEL.

### Objectius (*targets*)

Un **objectiu** agrupa les unitats necessàries per a un estat del sistema. Substituïxen els antics *runlevels*:

| Objectiu | Estat del sistema |
| --- | --- |
| `graphical.target` | Multiusuari, amb xarxa i entorn gràfic (escriptori). |
| `multi-user.target` | Multiusuari, amb xarxa i **sense** entorn gràfic (servidors). |
| `rescue.target` | Mode de rescat: un únic usuari (root), sense xarxa. |
| `emergency.target` | Mínim possible: shell de root amb el sistema d'arxius en només lectura. |
| `poweroff.target` / `reboot.target` | Apagar / reiniciar. |

```bash
systemctl get-default                          # Objectiu amb què arranca el sistema
sudo systemctl set-default multi-user.target   # Arrancar en mode text a partir d'ara
sudo systemctl isolate multi-user.target       # Canviar ara (tanca l'entorn gràfic)
```

### Crear un servei per a la teua aplicació

Com a desenvolupador, voldràs que la teua aplicació arranque sola amb el servidor i es reinicie si falla. Per a això n'hi ha prou d'escriure un fitxer d'unitat. Exemple per a una aplicació web en Python situada en `/opt/miapp`, que s'executa amb l'usuari de servei `miapp` creat en l'apartat 1.3:

```ini
# /etc/systemd/system/miapp.service
[Unit]
Description=Aplicació web d'exemple (DAM)
# Arrancar després que la xarxa estiga disponible
After=network-online.target
Wants=network-online.target

[Service]
# Usuari i grup sense privilegis amb què s'executa
User=miapp
Group=miapp
WorkingDirectory=/opt/miapp
# Ordre que s'executa (ruta absoluta obligatòria)
ExecStart=/usr/bin/python3 -m http.server 8080
# Si el procés acaba amb error, reiniciar-lo als 5 segons
Restart=on-failure
RestartSec=5
# Variables d'entorn per a l'aplicació
Environment=ENTORN=produccio

[Install]
# Habilitar el servei l'inclou en l'arrancada normal en mode multiusuari
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload            # systemd llig el fitxer nou
sudo systemctl enable --now miapp       # Habilitar i arrancar
systemctl status miapp
curl -I http://localhost:8080           # Comprovar que respon
journalctl -u miapp -f                  # Seguir el seu registre (apartat 10)
```

## 8.4 Processos en Windows

### Administrador de tasques

S'obri amb **`Ctrl + Maj + Esc`** (o amb `Ctrl + Alt + Supr`). Les seues seccions principals són:

| Secció | Ús |
| --- | --- |
| **Processos** | Aplicacions i processos en segon pla agrupats, amb el seu ús de CPU, memòria, disc i xarxa. Botó **Finalitza la tasca**. |
| **Rendiment** | Gràfiques d'ús dels recursos (apartat 9). |
| **Historial d'aplicacions** | Consum acumulat de les aplicacions de la Botiga. |
| **Aplicacions d'inici** | Programes que s'inicien amb la sessió; es poden deshabilitar (apartat 11). |
| **Usuaris** | Usuaris amb sessió iniciada i els seus processos. |
| **Detalls** | Llista completa de processos amb **PID**, usuari i estat. Des del menú contextual es pot **establir la prioritat**, **finalitzar l'arbre de processos** o **obrir la ubicació del fitxer**. |
| **Serveis** | Llista de serveis amb el seu estat; permet iniciar-los i aturar-los. |

### Des de la línia d'ordres

```bat
:: CMD
tasklist                                   :: Llista de processos amb el seu PID i memòria
tasklist /svc                              :: Quins serveis hi ha dins de cada procés
tasklist /fi "imagename eq notepad.exe"    :: Filtrar per nom
taskkill /im notepad.exe                   :: Demana tancar tots els notepad.exe
taskkill /pid 4520 /f                      :: Força la finalització d'un PID
taskkill /im chrome.exe /t /f              :: /t: també els processos fills (l'arbre)
```

```powershell
# PowerShell
Get-Process                                          # Tots els processos (àlies: ps, gps)
Get-Process -Name notepad                            # Per nom (sense .exe)
Get-Process -Id 4520 | Format-List *                 # Totes les propietats d'un procés
Get-Process | Sort-Object WorkingSet -Descending |
    Select-Object -First 5 Name, Id, @{n='MemoriaMB'; e={[math]::Round($_.WorkingSet / 1MB)}}
Get-Process -IncludeUserName                         # Amb l'usuari (requerix administrador)

Start-Process notepad                                # Llança un programa
Start-Process pwsh -Verb RunAs                       # El llança com a administrador (avís d'UAC)
Stop-Process -Name notepad                           # Finalitza per nom
Stop-Process -Id 4520 -Force                         # Finalitza per la força
(Get-Process -Name notepad).PriorityClass = 'BelowNormal'   # Canvia la prioritat
```

`@{n='MemoriaMB'; e={...}}` és una **propietat calculada**: crea una columna nova (`n`, *name*) el valor de la qual s'obté executant l'expressió (`e`, *expression*) per a cada objecte. `$_` representa l'objecte actual de la canonada.

| Prioritat en Windows | Equivalència aproximada en Linux |
| --- | --- |
| Temps real (*RealTime*) | `nice -20` i planificació de temps real. No s'ha d'utilitzar: pot bloquejar el sistema. |
| Alta (*High*) | `nice -10` |
| Per damunt del normal (*AboveNormal*) | `nice -5` |
| Normal | `nice 0` |
| Per davall del normal (*BelowNormal*) | `nice 5` |
| Baixa (*Idle*) | `nice 19` |

## 8.5 Serveis en Windows

### La consola Serveis

S'obri amb `services.msc`. Per a cada servei mostra el seu **nom per a mostrar**, la seua descripció, el seu **estat** i el seu **tipus d'inici**. En les propietats d'un servei (doble clic) es pot:

- **Iniciar**, **Aturar**, **Pausar** o **Reprendre** el servei.
- Canviar el **tipus d'inici**:

| Tipus d'inici | Significat |
| --- | --- |
| **Automàtic** | S'inicia en arrancar el sistema. |
| **Automàtic (inici retardat)** | S'inicia poc després de l'arrancada, perquè aquesta siga més ràpida. |
| **Manual** | S'inicia quan algú o alguna cosa ho sol·licita. |
| **Deshabilitat** | No es pot iniciar. |

- Veure el **nom del servei** (diferent del nom per a mostrar; per exemple, la *Cua d'impressió* s'anomena `Spooler`) i la **ruta de l'executable**.
- En la pestanya **Inici de sessió**, triar el compte amb què s'executa (*Sistema local*, *Servei local*, *Servei de xarxa* o un altre compte).
- En la pestanya **Recuperació**, indicar què fer si el servei falla (reiniciar-lo, executar un programa o reiniciar l'equip).
- En la pestanya **Dependències**, veure quins serveis necessita i quins en depenen.

### Des de la línia d'ordres

```powershell
# PowerShell (per a modificar, com a administrador)
Get-Service                                            # Tots els serveis
Get-Service -Name Spooler                              # Pel nom del servei
Get-Service -DisplayName "*impres*"                    # Pel nom per a mostrar, amb comodins
Get-Service | Where-Object Status -eq 'Running'        # Només els que estan en execució

Stop-Service -Name Spooler
Start-Service -Name Spooler
Restart-Service -Name Spooler
Set-Service -Name Spooler -StartupType Manual          # Automatic, AutomaticDelayedStart, Manual, Disabled

Get-Service -Name Spooler -DependentServices           # Serveis que en depenen

# Get-Service no mostra la ruta ni el compte: s'obtenen amb CIM
Get-CimInstance Win32_Service -Filter "Name='Spooler'" |
    Select-Object Name, State, StartMode, StartName, PathName
```

```bat
:: CMD: l'ordre sc.exe
sc query Spooler                     :: Estat
sc qc Spooler                        :: Configuració (tipus d'inici, ruta, compte)
sc stop Spooler
sc start Spooler
sc config Spooler start= demand      :: auto | delayed-auto | demand (manual) | disabled
net stop Spooler                     :: Alternativa clàssica
net start                            :: Serveis iniciats
```

> [!WARNING]
> En **PowerShell**, `sc` és un àlies de `Set-Content` (escriure en un fitxer), no de l'eina de serveis. Per a utilitzar-la des de PowerShell escriu sempre **`sc.exe`**. Fixa't també que `sc config` exigix un **espai després de l'`=`** (`start= demand`).

> [!CAUTION]
> No atures ni deshabilites serveis del sistema sense saber què fan. Abans de tocar un servei, llig-ne la descripció i comprova'n les dependències. Moltes "guies d'optimització" d'Internet recomanen deshabilitar serveis que en realitat són necessaris per a les actualitzacions, la xarxa o la seguretat.

## 8.6 Comparativa

| Tasca | Linux | Windows (PowerShell) | Windows (CMD) |
| --- | --- | --- | --- |
| Llistar processos | `ps aux` | `Get-Process` | `tasklist` |
| Buscar un procés | `pgrep -a nom` | `Get-Process -Name nom` | `tasklist /fi "imagename eq ..."` |
| Finalitzar un procés | `kill PID` | `Stop-Process -Id PID` | `taskkill /pid PID` |
| Forçar la finalització | `kill -9 PID` | `Stop-Process -Id PID -Force` | `taskkill /pid PID /f` |
| Canviar la prioritat | `renice` | `.PriorityClass = ...` | — |
| Llistar serveis | `systemctl list-units --type=service` | `Get-Service` | `sc query`, `net start` |
| Estat d'un servei | `systemctl status servei` | `Get-Service servei` | `sc query servei` |
| Arrancar / aturar | `systemctl start` / `stop` | `Start-Service` / `Stop-Service` | `net start` / `net stop` |
| Inici automàtic | `systemctl enable` | `Set-Service -StartupType Automatic` | `sc config ... start= auto` |
| Eina gràfica | Monitor del sistema, `htop` | Administrador de tasques, `services.msc` | |

## Exercicis resolts

### Exercici 8.1. Investigar un procés

Llança `sleep 900 &` i respon utilitzant ordres: quin és el seu PID? I el del seu pare? Quin procés és el seu pare? En quin estat està? Finalitza'l de manera ordenada.

{{% details "Veure solució" %}}
```bash
sleep 900 &
pgrep -a sleep                            # 5120 sleep 900
ps -o pid,ppid,stat,cmd -p 5120           # PPID 4987, STAT S (adormit)
ps -o pid,cmd -p 4987                     # El pare és la shell: bash
kill 5120                                 # SIGTERM
pgrep sleep || echo "Ja no existix"
```

Està en estat `S` perquè `sleep` no fa res excepte esperar. El seu pare és la shell des de la qual es va llançar.
{{% /details %}}

### Exercici 8.2. Servei en Linux

Instal·la el servidor SSH (`openssh-server`). Comprova si està actiu i habilitat. Desactiva'l perquè no arranque en iniciar el sistema, però deixa'l en marxa ara. Reinicia l'equip i verifica el resultat. Finalment, deixa'l habilitat i en marxa.

{{% details "Veure solució" %}}
```bash
sudo apt install openssh-server
systemctl is-active ssh; systemctl is-enabled ssh    # active / enabled
sudo systemctl disable ssh                           # Ja no arrancarà en l'inici…
systemctl is-active ssh                              # …però continua "active" ara
sudo reboot
# Després de reiniciar:
systemctl is-active ssh                              # inactive
sudo systemctl enable --now ssh
systemctl status ssh
```

> En Ubuntu, el servei SSH es pot arrancar mitjançant **activació per *socket*** (`ssh.socket`): systemd escolta en el port 22 i arranca `ssh.service` quan arriba una connexió. Si en deshabilitar `ssh` continua acceptant connexions, deshabilita també el socket: `sudo systemctl disable --now ssh.socket`.
{{% /details %}}

### Exercici 8.3. Investigar un servei de Windows

Esbrina, amb PowerShell, el nom del servei el nom per a mostrar del qual és *Cola de impresión* (en un Windows en espanyol), el seu tipus d'inici, el compte amb què s'executa i la ruta de l'executable. Atura'l, comprova què ocorre en intentar imprimir i torna a iniciar-lo.

{{% details "Veure solució" %}}
```powershell
Get-Service -DisplayName "*impresi*"                  # Name: Spooler
Get-CimInstance Win32_Service -Filter "Name='Spooler'" |
    Select-Object Name, StartMode, StartName, PathName
# Spooler  Auto  LocalSystem  C:\Windows\System32\spoolsv.exe

Stop-Service Spooler
Get-Printer          # Error: el servei de cua d'impressió no s'està executant
Start-Service Spooler
Get-Service Spooler  # Status: Running
```

Sense el servei *Spooler* no es pot imprimir ni consultar les impressores. L'executable és `spoolsv.exe`, que pots veure amb `Get-Process spoolsv`.

### Exercici 8.4. Script de vigilància d'un servei

Escriu un script de Bash que comprove si un servei (rebut com a paràmetre) està actiu i, si no ho està, intente arrancar-lo i registre el succés amb `logger`. Programa'l amb `cron` cada 5 minuts (Unitat 3).

{{% details "Veure solució" %}}
```bash
#!/usr/bin/env bash
# vigila_servei.sh - Arranca un servei si està aturat
# Ús: sudo ./vigila_servei.sh nom_servei
set -u

servei="${1:?Ús: $0 servei}"          # Si falta el paràmetre, mostra el missatge i acaba

if systemctl is-active --quiet "$servei"; then     # --quiet: només el codi d'eixida
    exit 0
fi

logger -t vigilant "El servei $servei estava aturat; s'intenta arrancar"
if systemctl start "$servei"; then
    logger -t vigilant "Servei $servei arrancat correctament"
else
    logger -t vigilant -p user.err "No s'ha pogut arrancar $servei"
    exit 1
fi
```

```bash
sudo install -m 755 vigila_servei.sh /usr/local/sbin/
sudo crontab -e
# */5 * * * * /usr/local/sbin/vigila_servei.sh cups
journalctl -t vigilant           # Consulta els missatges registrats
```

Per a serveis propis, l'opció `Restart=on-failure` de systemd (apartat 8.3) és una solució més senzilla i robusta; aquest script és útil per a serveis que no controles o per a practicar.
