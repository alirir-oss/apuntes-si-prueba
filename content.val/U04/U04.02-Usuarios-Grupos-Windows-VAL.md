# 2. Usuaris i grups en Windows

Windows també és un sistema multiusuari i seguix la mateixa idea que Linux: cada persona té el seu **compte**, els comptes s'agrupen en **grups** i els permisos s'assignen preferentment als grups. El que canvia és la manera d'identificar-los i les eines per a gestionar-los.

## 2.1 Tipus de comptes

Segons **on** es guarda el compte i qui l'autentica:

| Tipus | On es guarda | Ús típic |
| --- | --- | --- |
| **Compte local** | En el mateix equip, en la base de dades **SAM** (*Security Account Manager*). | Equips individuals, aules, màquines virtuals. Funciona sense connexió a Internet. |
| **Compte Microsoft** | En els servidors de Microsoft (`usuari@outlook.com`…). | Equips domèstics. Sincronitza configuració, OneDrive i la Botiga entre dispositius. |
| **Compte de domini** | En un **controlador de domini** amb *Active Directory* (o en el núvol amb *Microsoft Entra ID*). | Empreses i centres educatius: un mateix usuari pot iniciar sessió en qualsevol equip de l'organització. S'estudia en la Unitat 6. |

Segons els **privilegis** que té:

| Tipus | Què pot fer |
| --- | --- |
| **Administrador** | Instal·lar programes i controladors, canviar la configuració del sistema, gestionar altres comptes. |
| **Usuari estàndard** | Utilitzar els programes instal·lats i modificar els seus propis fitxers i la seua configuració personal. Per a tasques d'administració necessita les credencials d'un administrador. |

> [!TIP]
> Igual que en Linux no es treballa com a root, en Windows la bona pràctica és utilitzar diàriament un **compte estàndard** i reservar el compte d'administrador per a quan faça falta. Si un programa maliciós s'executa des d'un compte estàndard, el dany que pot causar és molt menor.

### Comptes integrats

Windows crea alguns comptes automàticament durant la instal·lació:

| Compte | Descripció |
| --- | --- |
| **Administrador** (*Administrator*) | Administrador integrat. Està **deshabilitat** per defecte en les versions d'escriptori. |
| **Convidat** (*Guest*) | Accés molt limitat i sense contrasenya. **Deshabilitat** per defecte; no es recomana activar-lo. |
| **DefaultAccount** | Compte intern que utilitza el sistema. Deshabilitat. |
| **SYSTEM**, **LOCAL SERVICE**, **NETWORK SERVICE** | Comptes de servei amb què s'executen els processos i serveis del sistema (apartat 8). No apareixen en la llista d'usuaris. `SYSTEM` té més privilegis que qualsevol administrador. |

## 2.2 Identificadors de seguretat (SID)

Internament, Windows no identifica els comptes pel seu nom sinó pel seu **SID** (*Security Identifier*), un identificador únic amb aquest aspecte:

```text
S-1-5-21-3623811015-3361044348-30300820-1001
└┬┘ │ │  └──────────── identificador de l'equip ──┘ └┬─┘
 │  │ └ autoritat (5 = NT Authority)                   RID: número relatiu del compte
 │  └ versió
 └ prefix
```

L'últim número, el **RID**, distingix cada compte dins de l'equip. Alguns RID són fixos: `500` és l'Administrador integrat i `501` el Convidat. Els comptes que crees tu comencen en `1000`. Els grups integrats tenen SID fixos i coneguts, iguals en tots els equips, per exemple `S-1-5-32-544` (Administradors) o `S-1-5-32-545` (Usuaris).

Com que els permisos es guarden associats al SID, si esborres un compte i en crees un altre amb el mateix nom, el nou **no** recupera els permisos de l'anterior: té un altre SID.

```powershell
whoami            # equip\usuari
whoami /user      # Nom i SID de l'usuari actual
whoami /groups    # Grups als quals pertanyc, amb els seus SID
```

## 2.3 Grups locals integrats

| Grup (nom en Windows en espanyol) | SID | Què permet |
| --- | --- | --- |
| **Administradores** | `S-1-5-32-544` | Control total de l'equip. |
| **Usuarios** | `S-1-5-32-545` | Ús normal de l'equip. Tots els comptes nous s'afigen a aquest grup. |
| **Invitados** | `S-1-5-32-546` | Accés mínim i temporal. |
| **Usuarios de escritorio remoto** | `S-1-5-32-555` | Iniciar sessió mitjançant Escriptori remot (RDP). |
| **Operadores de copia de seguridad** | `S-1-5-32-551` | Fer i restaurar còpies de seguretat encara que no tinguen permisos sobre els fitxers. |
| **Usuarios del monitor de sistema** | `S-1-5-32-558` | Consultar els comptadors de rendiment (apartat 9). |
| **Lectores del registro de eventos** | `S-1-5-32-573` | Llegir els registres d'esdeveniments (apartat 10). |

A més, existixen **identitats especials** els membres de les quals els decidix el sistema automàticament: **Todos** (*Everyone*, `S-1-1-0`), **Usuarios autentificados** (`S-1-5-11`), **INTERACTIVE** (usuaris amb sessió local), **CREATOR OWNER**…

> [!WARNING]
> Els **noms** dels grups integrats depenen de l'**idioma** de Windows: en un Windows en espanyol el grup es diu `Administradores`, en un en anglés, `Administrators`, i en un en valencià/català, `Administradors`. Els **SID**, en canvi, són sempre els mateixos. Per això, en els scripts que hagen de funcionar en qualsevol equip, és millor referir-se als grups integrats pel seu SID. En els exemples d'aquesta unitat s'utilitzen els noms d'un Windows en espanyol, que és l'habitual a l'aula.

## 2.4 Control de comptes d'usuari (UAC)

Quan un administrador inicia sessió, Windows li assigna **dos testimonis d'accés** (*access tokens*): un amb privilegis d'usuari estàndard i un altre amb privilegis complets. Per defecte, tots els programes s'executen amb el testimoni **estàndard**. Quan un programa necessita privilegis, l'**UAC** (*User Account Control*) mostra un avís:

- Si eres administrador, només has de **confirmar** (botó *Sí*).
- Si eres usuari estàndard, has d'escriure les **credencials d'un administrador**.

Aquest mecanisme és semblant a `sudo`: encara que sigues administrador, els privilegis només s'utilitzen quan es confirmen explícitament. Per a obrir una consola amb privilegis, fes clic dret sobre *Terminal* o *PowerShell* i tria **Executa com a administrador**. El títol de la finestra indicarà *Administrador*.

```powershell
# Aquesta consola s'executa amb privilegis d'administrador? (True / False)
([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole(
    [Security.Principal.WindowsBuiltInRole]::Administrator)
```

## 2.5 Eines gràfiques

| Eina | Com s'obri | Per a què |
| --- | --- | --- |
| **Configuració > Comptes** | `Win + I` | Gestió bàsica: afegir usuaris, canviar el tipus de compte (estàndard/administrador), opcions d'inici de sessió. Disponible en totes les edicions. |
| **Usuaris i grups locals** | `lusrmgr.msc` | Gestió completa d'usuaris i grups locals. **No disponible en Windows Home.** |
| **Administració d'equips** | `compmgmt.msc` | Consola que inclou *Usuaris i grups locals*, *Carpetes compartides*, *Serveis*, *Visor d'esdeveniments*… |
| **Comptes d'usuari avançats** | `netplwiz` | Llista d'usuaris i els seus grups, inici de sessió automàtic. |

{{% steps %}}
1. ## Crear un usuari local des de Configuració

   Obri **Configuració > Comptes > Altres usuaris** i prem **Afig un compte**. En l'assistent tria *No tinc les dades d'inici de sessió d'aquesta persona* i després *Afig un usuari sense compte Microsoft*. Escriu el nom, la contrasenya i les preguntes de seguretat.

2. ## Canviar el tipus de compte

   En la mateixa pantalla, desplega l'usuari, prem **Canvia el tipus de compte** i tria *Usuari estàndard* o *Administrador*.

3. ## Gestió avançada amb `lusrmgr.msc`

   Prem `Win + R`, escriu `lusrmgr.msc` i accepta. En la carpeta **Usuaris**, amb el botó dret > *Usuari nou…*, pots indicar a més opcions com *L'usuari ha de canviar la contrasenya en el següent inici de sessió* o *El compte està deshabilitat*. En **Grups**, fes doble clic sobre un grup per a afegir-hi o llevar-ne membres.
{{% /steps %}}

> [!NOTE]
> Els noms exactes dels menús de *Configuració* poden variar lleugerament entre versions de Windows 11 i segons l'idioma del sistema, perquè Microsoft els modifica amb les actualitzacions. Si no trobes una opció, utilitza el cercador de *Configuració*.

## 2.6 Gestió des de CMD: `net user` i `net localgroup`

Les ordres `net` existixen des de fa dècades i continuen funcionant en totes les versions i edicions de Windows. Requerixen una consola **executada com a administrador** per a fer canvis.

| Ordre | Funció |
| --- | --- |
| `net user` | Llista els comptes locals. |
| `net user ana` | Mostra la informació del compte `ana` (grups, últim inici de sessió, caducitat…). |
| `net user ana * /add` | Crea `ana` i demana la contrasenya sense mostrar-la (`*`). |
| `net user ana /fullname:"Ana López" /comment:"DAM1"` | Canvia dades del compte. |
| `net user ana /active:no` | Deshabilita el compte (`yes` per a habilitar-lo). |
| `net user ana /expires:30/06/2027` | Data de caducitat del compte (format de data segons l'idioma del sistema). |
| `net user ana /logonpasswordchg:yes` | Obliga a canviar la contrasenya en el següent inici de sessió. |
| `net user ana /delete` | Elimina el compte. |
| `net localgroup` | Llista els grups locals. |
| `net localgroup dam1 /add` | Crea el grup `dam1`. |
| `net localgroup dam1 ana /add` | Afig `ana` al grup `dam1` (`/delete` per a llevar-la). |

```bat
:: Crear un usuari estàndard i fer-lo membre del grup dam1
net localgroup dam1 /add
net user ana * /add /fullname:"Ana López"
net localgroup dam1 ana /add
net user ana
```

> [!CAUTION]
> Evita escriure la contrasenya directament en l'ordre (`net user ana Clau123 /add`): queda visible en pantalla i en l'historial de la consola. Utilitza `*` perquè la demane de manera oculta.

## 2.7 Gestió des de PowerShell

El mòdul `Microsoft.PowerShell.LocalAccounts` inclou *cmdlets* per a gestionar usuaris i grups locals. Tots seguixen el patró **verb-substantiu** que vas veure en la Unitat 3.

| Cmdlet | Funció |
| --- | --- |
| `Get-LocalUser` | Llista els usuaris locals (o un de concret amb `-Name`). |
| `New-LocalUser` | Crea un usuari. |
| `Set-LocalUser` | Modifica propietats (nom complet, descripció, caducitat…). |
| `Enable-LocalUser` / `Disable-LocalUser` | Habilita / deshabilita un compte. |
| `Rename-LocalUser` | Canvia el nom (el SID es manté). |
| `Remove-LocalUser` | Elimina un usuari. |
| `Get-LocalGroup` / `New-LocalGroup` / `Remove-LocalGroup` | Consulta, crea i elimina grups. |
| `Get-LocalGroupMember` | Llista els membres d'un grup. |
| `Add-LocalGroupMember` / `Remove-LocalGroupMember` | Afig / lleva membres d'un grup. |

```powershell
# Demana la contrasenya de manera segura: Read-Host -AsSecureString retorna un objecte SecureString,
# que guarda el text xifrat en memòria en lloc de com a text pla.
$clau = Read-Host "Contrasenya per a ana" -AsSecureString

# Crea l'usuari. Els paràmetres es poden partir en diverses línies amb l'accent greu (`)
New-LocalUser -Name "ana" -Password $clau `
              -FullName "Ana López" -Description "Alumna de DAM1"

New-LocalGroup -Name "dam1" -Description "Alumnat de 1r de DAM"
Add-LocalGroupMember -Group "dam1" -Member "ana"

# Afegir a un grup integrat utilitzant el seu SID, perquè funcione en qualsevol idioma
Add-LocalGroupMember -SID "S-1-5-32-555" -Member "ana"     # Usuaris d'escriptori remot

# Consultes
Get-LocalUser -Name ana | Format-List *          # Totes les propietats del compte
Get-LocalGroupMember -Group "dam1"
Get-LocalUser | Where-Object Enabled | Select-Object Name, LastLogon

# Modificacions i baixa
Set-LocalUser -Name ana -AccountExpires (Get-Date "2027-06-30")
Disable-LocalUser -Name ana
Remove-LocalUser -Name ana
```

> [!IMPORTANT]
> El mòdul `Microsoft.PowerShell.LocalAccounts` pertany a **Windows PowerShell 5.1**, que ve instal·lat en tots els Windows. **PowerShell 7** no l'inclou i el carrega mitjançant la seua funció de compatibilitat, cosa que en algunes versions produïx errors. Si un *cmdlet* `*-LocalUser` falla en PowerShell 7, executa'l en *Windows PowerShell* o importa abans el mòdul amb:
>
> ```powershell
> Import-Module Microsoft.PowerShell.LocalAccounts -UseWindowsPowerShell
> ```

### Executar com un altre usuari

```bat
runas /user:ana cmd               :: Obri una consola com ana (demana la seua contrasenya)
```

Des de l'Explorador, amb `Maj + clic dret` sobre un programa apareix l'opció **Executa com un altre usuari**.

## 2.8 Comparativa Linux / Windows

| Concepte | Linux | Windows |
| --- | --- | --- |
| Identificador intern | UID / GID | SID |
| Base de dades local | `/etc/passwd`, `/etc/shadow`, `/etc/group` | SAM (en el registre, no editable directament) |
| Superusuari | `root` (UID 0) | Grup *Administradors*; compte `SYSTEM` per al sistema |
| Elevar privilegis | `sudo` | UAC, *Executa com a administrador*, `runas` |
| Crear usuari | `useradd -m usuari` | `net user usuari * /add`, `New-LocalUser` |
| Afegir a grup | `usermod -aG grup usuari` | `net localgroup grup usuari /add`, `Add-LocalGroupMember` |
| Veure els meus grups | `id` | `whoami /groups` |
| Gestió centralitzada | LDAP, FreeIPA | Active Directory, Microsoft Entra ID |

## Exercicis resolts

### Exercici 2.1. Usuaris de l'aula amb `net`

Des d'una consola d'administrador, crea el grup `dam1` i els usuaris estàndard `john` i `doe`, tots dos membres de `dam1`. `doe` ha de ser, a més, administrador. Tots dos han de canviar la contrasenya en el seu primer inici de sessió.

{{% details "Veure solució" %}}
```bat
net localgroup dam1 /add
net user john * /add
net user doe * /add
net localgroup dam1 john /add
net localgroup dam1 doe /add
net localgroup Administradores doe /add
net user john /logonpasswordchg:yes
net user doe /logonpasswordchg:yes
net localgroup dam1
net user doe
```

En l'eixida de `net user doe` han d'aparéixer, en *Miembros del grupo local*, `*Administradores`, `*dam1` i `*Usuarios`. Si el Windows està en anglés, el grup es diu `Administrators`.

> No utilitzes contrasenyes com `admin` o `john123`, encara que siga en pràctiques: acostuma't des del principi a utilitzar contrasenyes robustes (apartat 4).
{{% /details %}}

### Exercici 2.2. La mateixa alta amb PowerShell

Repetix l'exercici anterior amb PowerShell, de manera que l'script funcione encara que Windows estiga en anglés.

{{% details "Veure solució" %}}
```powershell
# Executar en Windows PowerShell 5.1 com a administrador
New-LocalGroup -Name "dam1" -ErrorAction SilentlyContinue   # Si ja existix, no mostra error

foreach ($nom in "john", "doe") {
    $clau = Read-Host "Contrasenya inicial per a $nom" -AsSecureString
    New-LocalUser -Name $nom -Password $clau | Out-Null
    Add-LocalGroupMember -Group "dam1" -Member $nom
    net user $nom /logonpasswordchg:yes | Out-Null         # PowerShell també executa ordres de CMD
}

Add-LocalGroupMember -SID "S-1-5-32-544" -Member "doe"     # Administradors, en qualsevol idioma

Get-LocalGroupMember -Group "dam1"
Get-LocalGroupMember -SID "S-1-5-32-544"
```
{{% /details %}}

### Exercici 2.3. Auditoria de comptes

Escriu un script de PowerShell que mostre els comptes **habilitats**, indicant per a cadascun si és administrador, la data del seu últim inici de sessió i si la seua contrasenya caduca.

{{% details "Veure solució" %}}
```powershell
# Obtenim una vegada els noms dels membres del grup Administradors.
# Get-LocalGroupMember retorna noms del tipus "EQUIP\usuari"; ens quedem amb la part final.
$admins = Get-LocalGroupMember -SID "S-1-5-32-544" |
          ForEach-Object { $_.Name.Split('\')[-1] }

Get-LocalUser | Where-Object Enabled | ForEach-Object {
    [PSCustomObject]@{                       # Crea un objecte amb les columnes que volem mostrar
        Usuari        = $_.Name
        Administrador = $admins -contains $_.Name
        UltimAcces    = $_.LastLogon
        ClauCaduca    = $null -ne $_.PasswordExpires
    }
} | Format-Table -AutoSize
```

`[PSCustomObject]@{...}` construïx un objecte a partir d'una taula de parells *clau = valor*; és la manera habitual en PowerShell de generar informes amb columnes personalitzades.
{{% /details %}}

### Exercici 2.4. Nom enfront de SID

Crea l'usuari `prova`, afig-lo al grup *Usuaris d'escriptori remot*, comprova el seu SID i esborra'l. Torna a crear un usuari anomenat `prova`. Continua pertanyent al grup? Té el mateix SID? Explica per què.

{{% details "Veure solució" %}}
```powershell
$c = Read-Host -AsSecureString
New-LocalUser prova -Password $c | Out-Null
Add-LocalGroupMember -SID "S-1-5-32-555" -Member prova
(Get-LocalUser prova).SID.Value           # p. ex. S-1-5-21-...-1005
Remove-LocalUser prova

New-LocalUser prova -Password $c | Out-Null
(Get-LocalUser prova).SID.Value           # p. ex. S-1-5-21-...-1006  (RID diferent)
Get-LocalGroupMember -SID "S-1-5-32-555"  # prova ja NO hi apareix
```

El compte nou rep un **RID diferent**, així que el seu SID és un altre. Com que la pertinença a grups i els permisos es guarden per SID, el compte nou no hereta res de l'antic encara que es diga igual.
{{% /details %}}
