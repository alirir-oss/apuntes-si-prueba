# 12. El sistema al servei del desenvolupament

En aquest últim apartat s'aplica tot l'anterior al vostre futur treball: **avaluar què necessita un equip** per a desenvolupar un tipus d'aplicació concret, **preparar-lo** correctament i **desplegar** una aplicació en un servidor seguint bones pràctiques d'administració. Acaba amb un **cas pràctic integrador** i un **resum d'ordres** de tota la unitat.

## 12.1 Avaluar les necessitats segons el tipus de desenvolupament

No tots els desenvolupaments necessiten el mateix equip. La taula següent és **orientativa**: els requisits reals depenen de la grandària dels projectes i canvien amb cada versió de les eines, per la qual cosa sempre cal **consultar els requisits oficials** de cadascuna.

| Tipus de desenvolupament | Eines típiques | Recursos més exigits | Necessitats del sistema |
| --- | --- | --- | --- |
| **Web (*frontend* i *backend*)** | VS Code, Node.js, Python, Java, bases de dades | RAM moderada, disc SSD | Servidors locals, ports lliures, contenidors. |
| **Mòbil Android** | Android Studio, emulador, Gradle | **Molta RAM**, CPU amb diversos nuclis, SSD | **Virtualització per maquinari** activa per a l'emulador; espai per als SDK i imatges. |
| **Multiplataforma d'escriptori** | IntelliJ IDEA, .NET, Qt, Flutter | RAM, CPU | Diversos SDK; de vegades, màquines virtuals amb altres sistemes per a provar. |
| **Contenidors i microserveis** | Docker, Kubernetes local | RAM (cada contenidor consumix), disc | Virtualització (Docker Desktop i WSL 2 en Windows), xarxes virtuals. |
| **Dades i intel·ligència artificial** | Python, Jupyter, biblioteques de càlcul | RAM, **GPU** compatible | Controladors de la GPU, molt d'espai per als conjunts de dades. |
| **Videojocs** | Unity, Unreal Engine, Godot | GPU, CPU, RAM | Controladors gràfics actualitzats, molt d'espai. |

### Com mesurar si l'equip és suficient

Les eines de l'apartat 9 servixen per a prendre la decisió amb dades i no "a ull". Amb l'entorn de treball obert (IDE, emulador, contenidors…) i durant una sessió normal de treball, observa:

- **Memòria disponible**: si baixa de manera habitual per davall del 10–15 % i augmenta l'ús de *swap* o del fitxer de paginació, falta RAM.
- **CPU**: si les compilacions mantenen tots els nuclis al 100 % durant molt de temps, una CPU amb més nuclis reduiria els temps d'espera.
- **Disc**: si el temps actiu del disc està sovint al 100 % o s'utilitza un disc mecànic, un SSD és la millora més notable.
- **Espai**: els SDK, les imatges dels emuladors, les imatges de Docker i les dependències dels projectes ocupen desenes de gigabytes.

### Comprovar la virtualització per maquinari

L'emulador d'Android, Docker Desktop, WSL 2 i les màquines virtuals necessiten que la CPU tinga activada la **virtualització per maquinari** (Intel VT-x o AMD-V) en la configuració del firmware (UEFI).

```bash
# Linux
lscpu | grep -i virtualiz                    # Virtualization: VT-x  (o AMD-V)
grep -cE 'vmx|svm' /proc/cpuinfo             # Major que 0: la CPU l'admet
ls -l /dev/kvm                               # Existix si KVM està disponible
```

```powershell
# Windows: també en Administrador de tasques > Rendiment > CPU > "Virtualització: Habilitada"
(Get-CimInstance Win32_Processor).VirtualizationFirmwareEnabled
```

> [!NOTE]
> Si Windows ja utilitza l'hipervisor (perquè estan activats Hyper-V, WSL 2 o la seguretat basada en virtualització), `VirtualizationFirmwareEnabled` pot retornar `False` encara que la virtualització funcione. En aquest cas, comprova en l'Administrador de tasques si apareix *S'ha detectat un hipervisor* o *Virtualització: Habilitada*.

## 12.2 Preparar l'equip de desenvolupament

### Un compte sense privilegis

Treballa diàriament amb un compte **estàndard** o, en Linux, amb el teu usuari normal utilitzant `sudo` només quan faça falta. Afig el teu usuari únicament als grups que realment necessites (apartat 1.5):

```bash
sudo usermod -aG dialout "$USER"   # Programar plaques de desenvolupament pel port sèrie
sudo usermod -aG kvm "$USER"       # Acceleració de l'emulador d'Android en Linux
```

> [!CAUTION]
> Pertànyer al grup `docker` permet, per exemple, arrancar un contenidor que munte `/` de l'amfitrió amb permisos de root: **és equivalent a ser administrador**. Afig a aquest grup només el teu usuari, en el teu propi equip, i mai usuaris de servei ni comptes compartits.

### Variables d'entorn

Moltes eines es localitzen mitjançant variables d'entorn, com `PATH` (directoris on es busquen els programes) o `JAVA_HOME` (instal·lació de Java).

```bash
# Linux: per al teu usuari, en ~/.profile (apartat 3)
export JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64
export PATH="$JAVA_HOME/bin:$HOME/.local/bin:$PATH"
```

```powershell
# Windows: variable d'usuari permanent (s'aplica en les consoles que s'obrin després)
[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Java\jdk-25", "User")

# Afegir un directori al PATH de l'usuari sense perdre el que ja té
$actual = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$actual;$env:USERPROFILE\eines\bin", "User")
```

Gràficament: `Win + R` > `sysdm.cpl` > *Opcions avançades* > **Variables d'entorn**. La part superior conté les variables de l'**usuari** i la inferior les del **sistema** (per a tots els usuaris; requerix administrador).

> [!WARNING]
> Evita l'ordre `setx` per a modificar el `PATH`: **trunca** els valors de més de 1024 caràcters, i un `PATH` llarg pot quedar danyat sense avís. Utilitza el mètode de .NET anterior o la finestra de variables d'entorn.

### Ajustos de Windows útils per a desenvolupar

| Ajust | On | Per a què |
| --- | --- | --- |
| **Mode de desenvolupador** | *Configuració > Sistema > Per a desenvolupadors* | Permet crear enllaços simbòlics sense ser administrador, instal·lar aplicacions sense signar de la Botiga i dona accés a altres opcions per a desenvolupadors. |
| **Directiva d'execució de PowerShell** | `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser` | Permet executar els teus propis scripts; els descarregats han d'estar signats (Unitat 3). |
| **Rutes llargues** | Valor `LongPathsEnabled` del registre (vegeu més avall) i `git config --global core.longpaths true` | Evita errors amb rutes de més de 260 caràcters (molt habituals en `node_modules`). |
| **Dev Drive** | *Configuració > Sistema > Emmagatzematge > Configuració avançada d'emmagatzematge > Discos i volums* | Volum amb el sistema d'arxius ReFS optimitzat per a codi font i compilacions, amb l'antivirus en mode de rendiment. |
| **WSL** | `wsl --install` (Unitat 2) | Disposar d'un Linux complet per a les eines que ho requerixen. |

```powershell
# Habilitar les rutes llargues en tot el sistema (com a administrador; requerix reiniciar)
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
                 -Name LongPathsEnabled -Value 1 -PropertyType DWord -Force
```

## 12.3 Desplegar una aplicació en un servidor: bones pràctiques

Quan la teua aplicació passe a un servidor Linux, aplica el que has aprés en la unitat:

| Pràctica | Com | Apartat |
| --- | --- | --- |
| **Usuari propi sense privilegis** | `useradd -r -s /usr/sbin/nologin miapp` | 1.3 |
| **Permisos mínims** | El codi, de només lectura per a l'usuari de l'aplicació; només els directoris de dades i registres, amb escriptura. | 5 |
| **Secrets protegits** | Contrasenyes i claus en un fitxer `640` (propietari root, grup de l'aplicació) o en variables d'entorn del servei, mai dins del codi. | 5 |
| **Gestionada com a servei** | Unitat de systemd amb `User=`, `Restart=on-failure` i `enable`. | 8.3 |
| **Ports no privilegiats** | En Linux, només root pot obrir ports per davall del 1024. L'aplicació escolta en un port alt (8080) i, si cal, un servidor web (Unitat 6) la publica en el 80/443. | 9.3 |
| **Registres controlats** | Missatges al *journal* o a un fitxer amb rotació. | 10 |
| **Manteniment** | Actualitzacions automàtiques de seguretat i vigilància de l'espai en disc. | 11 |
| **Permisos de desplegament limitats** | L'equip de desenvolupament pot reiniciar el servei amb `sudo`, però no té accés complet de root. | 1.6 |

## 12.4 Cas pràctic integrador

Una xicoteta empresa de desenvolupament t'encarrega preparar un **servidor Linux** per a l'equip del projecte *Agenda*, format per les desenvolupadores `ana` i `luis`, i la cap de projecte `marta`. Requisits:

1. Grups `agenda` (ana, luis i marta) i `caps` (marta).
2. Contrasenyes d'almenys 12 caràcters; els comptes d'ana i luis caduquen el 30 de juny de 2027.
3. Directori `/srv/agenda` on tot el grup puga crear i modificar fitxers, que pertanyen sempre al grup `agenda`, i on ningú no puga esborrar el d'un altre. Els altres usuaris del servidor no hi han de poder entrar.
4. Directori `/srv/agenda/informes` on només `marta` puga escriure, però tot el grup puga llegir.
5. L'aplicació (de moment, un servidor web de prova en Python en el port 8080) s'ha d'executar com a servei amb l'usuari `agenda-app`, arrancar sola i reiniciar-se si falla.
6. Els membres d'`agenda` poden **reiniciar** el servei, però no tenen més privilegis.
7. Comprovacions: el servei respon, se'n poden consultar els registres i se sap quins ports té oberts el servidor.

{{% details "Veure solució" %}}
**1. Grups i usuaris**

```bash
sudo groupadd agenda
sudo groupadd caps
for u in ana luis marta; do
    sudo useradd -m -s /bin/bash -G agenda "$u"
done
sudo usermod -aG caps marta
id marta                      # ... grups=...(marta),...(agenda),...(caps)
```

**2. Contrasenyes i caducitat**

```bash
sudo apt install libpam-pwquality
sudo sed -i 's/^# *minlen.*/minlen = 12/' /etc/security/pwquality.conf
for u in ana luis marta; do sudo passwd "$u"; done     # Ha de rebutjar contrasenyes curtes
sudo chage -E 2027-06-30 ana
sudo chage -E 2027-06-30 luis
sudo chage -l ana | grep -i "account expires"
```

**3. Directori del projecte**

```bash
sudo mkdir -p /srv/agenda
sudo chown root:agenda /srv/agenda
sudo chmod 3770 /srv/agenda                        # SGID + sticky, rwx per al grup, res per a la resta
sudo setfacl -d -m g:agenda:rwX /srv/agenda        # El que siga nou serà modificable pel grup
ls -ld /srv/agenda                                 # drwxrws--T+ root agenda
```

**4. Directori d'informes**

```bash
sudo mkdir /srv/agenda/informes
sudo chown marta:agenda /srv/agenda/informes
sudo setfacl -b -k /srv/agenda/informes                     # Lleva les ACL heretades de /srv/agenda
sudo chmod 2750 /srv/agenda/informes                        # marta rwx, grup agenda r-x, resta res
sudo setfacl -d -m u::rwx,g::rx,o::--- /srv/agenda/informes # El que siga nou: el grup només podrà llegir
getfacl /srv/agenda/informes
```

En crear-se dins de `/srv/agenda`, el directori `informes` **hereta** la seua ACL per defecte, que dona `rwx` al grup. Per això primer s'eliminen amb `setfacl -b` (entrades d'accés) i `-k` (ACL per defecte), després es fixen els permisos amb `chmod` i, finalment, es definix una ACL per defecte pròpia perquè els fitxers que cree `marta` siguen de només lectura per al grup, independentment de la seua `umask`.

**5. Servei de l'aplicació**

```bash
sudo useradd -r -s /usr/sbin/nologin -d /opt/agenda agenda-app
sudo mkdir -p /opt/agenda
echo "<h1>Agenda funcionant</h1>" | sudo tee /opt/agenda/index.html > /dev/null
sudo chown -R root:agenda-app /opt/agenda
sudo chmod -R 750 /opt/agenda                      # L'aplicació llig, però no pot modificar el seu codi

sudo tee /etc/systemd/system/agenda.service > /dev/null <<'EOF'
[Unit]
Description=Aplicació Agenda
After=network-online.target
Wants=network-online.target

[Service]
User=agenda-app
Group=agenda-app
WorkingDirectory=/opt/agenda
ExecStart=/usr/bin/python3 -m http.server 8080
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now agenda
```

**6. Reinici delegat amb `sudo`**

```bash
sudo visudo -f /etc/sudoers.d/agenda
```

```text
%agenda ALL=(root) /usr/bin/systemctl restart agenda.service
```

```bash
sudo -l -U ana                         # Mostra el que ana pot executar amb sudo
```

**7. Comprovacions**

```bash
systemctl status agenda                # active (running), usuari agenda-app
curl -s http://localhost:8080          # <h1>Agenda funcionant</h1>
ps -o user,pid,cmd -C python3          # S'executa com agenda-app, no com a root
sudo kill -9 "$(systemctl show -p MainPID --value agenda)"   # Simular una fallada…
sleep 6; systemctl is-active agenda    # …systemd l'ha reiniciat: active
journalctl -u agenda -n 20             # Registres del servei
sudo ss -tlpn                          # Ports en escolta: apareix 8080 amb python3
```

Verifica també els permisos amb diferents usuaris: `sudo -u luis touch /srv/agenda/prova` (ha de funcionar), `sudo -u luis touch /srv/agenda/informes/x` (ha de fallar) i `sudo -u luis rm /srv/agenda/<fitxer d'ana>` (ha de fallar pel *sticky bit*).
{{% /details %}}

> [!TIP]
> Com a ampliació, fes el **mateix cas en Windows**: grups amb `New-LocalGroup`, directives amb `net accounts`, carpeta amb `icacls`, i per a l'aplicació un servei o una tasca programada que s'execute en iniciar el sistema amb un compte sense privilegis.

## 12.5 Resum d'ordres d'administració

| Tasca | Bash (Linux) | CMD (Windows) | PowerShell (Windows) |
| --- | --- | --- | --- |
| Usuari actual i els seus grups | `id` | `whoami /groups` | `whoami /groups` |
| Llistar usuaris | `getent passwd` | `net user` | `Get-LocalUser` |
| Crear usuari | `useradd -m -s /bin/bash u` | `net user u * /add` | `New-LocalUser u` |
| Canviar contrasenya | `passwd u` | `net user u *` | `Set-LocalUser u -Password ...` |
| Deshabilitar compte | `usermod -L -e 1 u` | `net user u /active:no` | `Disable-LocalUser u` |
| Eliminar usuari | `userdel -r u` | `net user u /delete` | `Remove-LocalUser u` |
| Crear grup | `groupadd g` | `net localgroup g /add` | `New-LocalGroup g` |
| Afegir a grup | `usermod -aG g u` | `net localgroup g u /add` | `Add-LocalGroupMember g -Member u` |
| Directives de contrasenya | `chage`, `pwquality.conf` | `net accounts` | `secedit` |
| Veure permisos | `ls -l`, `getfacl` | `icacls f` | `Get-Acl f` |
| Canviar permisos | `chmod`, `setfacl` | `icacls f /grant ...` | `Set-Acl` |
| Canviar propietari | `chown u f` | `icacls f /setowner u` | `Set-Acl` (amb `SetOwner`) |
| Compartir carpeta | `smb.conf` + `smbpasswd` | `net share` | `New-SmbShare` |
| Connectar recurs de xarxa | `mount -t cifs` | `net use Z: \\srv\r` | `New-SmbMapping` |
| Llistar processos | `ps aux` | `tasklist` | `Get-Process` |
| Finalitzar procés | `kill PID` | `taskkill /pid PID` | `Stop-Process -Id PID` |
| Estat d'un servei | `systemctl status s` | `sc query s` | `Get-Service s` |
| Arrancar / aturar servei | `systemctl start` / `stop s` | `net start` / `net stop s` | `Start-Service` / `Stop-Service s` |
| Inici automàtic | `systemctl enable s` | `sc config s start= auto` | `Set-Service s -StartupType Automatic` |
| Memòria | `free -h` | `systeminfo` | `Get-CimInstance Win32_OperatingSystem` |
| Espai en disc | `df -h` | `fsutil volume diskfree C:` | `Get-Volume` |
| Ports en escolta | `ss -tulpn` | `netstat -ano` | `Get-NetTCPConnection -State Listen` |
| Registres | `journalctl` | `wevtutil qe System` | `Get-WinEvent` |
| Actualitzar el sistema | `apt update && apt upgrade` | — | `winget upgrade --all` |
