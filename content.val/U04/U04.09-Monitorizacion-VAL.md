# 9. Monitoratge de recursos

**Monitorar** un sistema és observar de manera continuada com utilitza els seus recursos per a detectar problemes **abans** que afecten els usuaris: un disc que s'ompli, un procés que consumix cada vegada més memòria o un servidor que no dona l'abast amb les peticions. Com a desenvolupadors, també vos servirà per a saber si la vostra aplicació és eficient o si té, per exemple, una **fuita de memòria** (*memory leak*): memòria que es reserva i mai no s'allibera.

## 9.1 Què cal vigilar

| Recurs | Indicadors | Senyals d'alarma |
| --- | --- | --- |
| **CPU** | % d'ús, càrrega mitjana, processos que més consumixen | Ús pròxim al 100 % de manera sostinguda. |
| **Memòria** | Memòria utilitzada, disponible, *swap* | Poca memòria disponible i ús continu de *swap*. |
| **Disc: espai** | % ocupat per sistema d'arxius | Més del 85–90 % ocupat. |
| **Disc: activitat** | Lectures/escriptures per segon, temps de resposta | Disc al 100 % d'activitat, processos esperant E/S. |
| **Xarxa** | Trànsit enviat/rebut, connexions obertes, ports en escolta | Trànsit inesperat, ports oberts que no haurien d'estar-ho. |

> [!NOTE]
> La **memòria d'intercanvi** (*swap* en Linux, *fitxer de paginació* en Windows) és espai en el disc que el sistema utilitza com a ampliació de la RAM quan aquesta s'esgota. Com que el disc és molt més lent que la RAM, si el sistema utilitza molt la *swap* de manera contínua, el rendiment cau dràsticament.

## 9.2 Linux: visió general

### Càrrega del sistema: `uptime`

```bash
uptime
#  11:42:07 up 2:30,  2 users,  load average: 0,52, 0,78, 1,10
nproc        # Nombre de nuclis (CPU lògiques): 4
```

La **càrrega mitjana** (*load average*) és el nombre mitjà de processos que s'estan executant o esperant per a executar-se, en l'últim **1**, **5** i **15** minuts. S'interpreta en relació amb el nombre de nuclis:

- Càrrega **menor** que el nombre de nuclis: el sistema té capacitat lliure.
- Càrrega **igual**: està aprofitant la CPU al màxim.
- Càrrega **major**: hi ha processos esperant torn.

En l'exemple, amb 4 nuclis i una càrrega de 0,52, el sistema està molt desocupat. Comparar els tres valors indica la tendència: ací la càrrega està **baixant** (1,10 fa 15 minuts, 0,52 ara).

### `top`: monitor en temps real

`top` mostra un resum del sistema i la llista de processos, actualitzada cada 3 segons.

```text
top - 11:42:07 up  2:30,  2 users,  load average: 0,52, 0,78, 1,10
Tasks: 231 total,   1 running, 230 sleeping,   0 stopped,   0 zombie
%Cpu(s):  3,1 us,  1,0 sy,  0,0 ni, 95,5 id,  0,3 wa,  0,0 hi,  0,1 si,  0,0 st
MiB Mem :   7940,2 total,   3120,4 free,   2310,8 used,   2509,0 buff/cache
MiB Swap:   2048,0 total,   2048,0 free,      0,0 used.   5310,5 avail Mem

    PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
   1520 ana       20   0 3254012 312400 118000 S   2,3   3,8   1:02.31 code
```

| Camp de `%Cpu(s)` | Significat |
| --- | --- |
| `us` | Temps en processos d'usuari (programes normals). |
| `sy` | Temps en el nucli (*system*). |
| `ni` | Processos amb prioritat modificada (*nice*). |
| `id` | CPU lliure (*idle*). |
| `wa` | Esperant operacions d'E/S. Un valor alt indica un **disc lent o saturat**. |
| `st` | Temps "robat" per l'hipervisor (només en màquines virtuals). |

| Tecla en `top` | Acció |
| --- | --- |
| `P` / `M` | Ordenar per CPU / per memòria. |
| `1` | Mostrar cada nucli per separat. |
| `u` | Filtrar per usuari. |
| `k` | Enviar un senyal a un procés (demana el PID). |
| `r` | Canviar el valor *nice* d'un procés. |
| `h` | Ajuda. |
| `q` | Eixir. |

```bash
top -u ana          # Només els processos d'ana
top -b -n 1 | head  # Mode no interactiu (batch): una sola vegada, útil en scripts
```

### `htop` i `btop`

`htop` és una versió millorada de `top`, amb colors, barres d'ús per nucli, desplaçament amb el ratolí, vista en arbre (`F5`), cerca (`F3`) i menú d'accions en la part inferior. `btop` és una altra alternativa més visual que inclou també gràfiques de disc i xarxa.

```bash
sudo apt install htop btop
htop
```

## 9.3 Linux: memòria, disc i xarxa

### Memòria: `free`

```bash
free -h
#                total     usado     libre  compartido  búf/caché  disponible
# Mem:           7,8Gi     2,3Gi     3,0Gi       210Mi      2,5Gi       5,2Gi
# Inter.:        2,0Gi        0B     2,0Gi
```

> [!IMPORTANT]
> No et fixes en la columna **lliure** (*libre*), sinó en **disponible**. Linux aprofita la memòria que no utilitzen els programes com a **memòria cau del disc** (`búf/caché`) per a accelerar el sistema, i l'allibera tan prompte com un programa la necessita. Que hi haja poca memòria "lliure" és normal i desitjable; el que és preocupant és que n'hi haja poca **disponible**.

### Visió global: `vmstat`

```bash
vmstat 2 5          # Una línia cada 2 segons, 5 vegades
# procs -----------memoria---------- --swap-- ---io--- -sistema-- ------cpu-----
#  r  b   swpd   libre   búfer  caché  si  so  bi  bo   in   cs us sy id wa st
#  1  0      0 3120400  98000 2410000   0   0  12  40  310  620  3  1 96  0  0
```

Les columnes `si` i `so` indiquen memòria que entra i ix de la *swap*: si són diferents de 0 de manera contínua, falta RAM. La columna `wa` indica espera de disc, com en `top`.

### Espai en disc: `df` i `du`

```bash
df -h                       # Espai de cada sistema d'arxius muntat
df -h /                     # Només el de l'arrel
df -i                       # Ús d'inodes: un disc es pot "omplir" per nombre de fitxers
du -sh ~/Baixades           # Grandària total d'un directori
du -h --max-depth=1 /var 2>/dev/null | sort -h    # Quins subdirectoris de /var ocupen més
```

Per a analitzar l'espai de manera interactiva, `ncdu` (apartat 11) permet navegar pels directoris ordenats per grandària.

### Activitat del disc: `iostat`

```bash
sudo apt install sysstat
iostat -xz 2 3              # Estadístiques esteses de cada disc, cada 2 s, 3 vegades
```

La columna **`%util`** indica el percentatge de temps que el disc ha estat ocupat. Valors pròxims al 100 % de manera sostinguda indiquen que el disc és el coll de botella.

### Xarxa: `ss` i `ip`

```bash
ss -tulpn                   # Ports TCP (t) i UDP (u) en escolta (l), amb el procés (p) i en número (n)
ss -tn state established    # Connexions TCP establides
ip -s link                  # Estadístiques de trànsit de cada interfície
```

Revisar amb `ss -tulpn` quins ports té oberts un servidor és una tasca bàsica de seguretat: cada port en escolta és una possible via d'entrada. En la Unitat 5 s'estudien els ports en detall.

### Informació del maquinari

```bash
lscpu                       # Processador: model, nuclis, fils, virtualització
lsblk                       # Discos i particions
cat /proc/meminfo | head    # Detall de la memòria
sudo dmidecode -t memory    # Mòduls de RAM instal·lats
```

### L'eina gràfica

En l'escriptori GNOME, l'aplicació **Monitor del sistema** (*gnome-system-monitor*) mostra els processos, les gràfiques d'ús de CPU, memòria i xarxa, i l'espai dels sistemes d'arxius.

## 9.4 Windows: eines gràfiques

### Administrador de tasques: pestanya Rendiment

Mostra gràfiques en temps real de la **CPU** (amb la seua velocitat, nombre de nuclis, processos i fils, temps actiu i si la **virtualització** està habilitada), la **memòria** (en ús, disponible, compromesa, velocitat i ranures utilitzades), cada **disc** (temps actiu i velocitat), la **xarxa** i la **GPU**.

### Monitor de recursos: `resmon`

El **Monitor de recursos** (`resmon.exe`, o des de l'enllaç al peu de la pestanya *Rendiment*) oferix molt més detall que l'Administrador de tasques:

| Pestanya | Informació útil |
| --- | --- |
| **CPU** | Ús per procés i per servei. En **Identificadors associats** pots buscar quin procés té obert un fitxer (molt útil quan Windows diu que "el fitxer està en ús"). |
| **Memòria** | Ús per procés i un gràfic de com es repartix la memòria física. |
| **Disc** | Quins fitxers està llegint o escrivint cada procés i el temps de resposta. |
| **Xarxa** | Connexions TCP de cada procés i **ports d'escolta** amb el seu procés. |

### Monitor de rendiment: `perfmon`

El **Monitor de rendiment** (`perfmon.msc`) és l'eina professional de Windows. Treballa amb **comptadors de rendiment**: mesures de centenars d'aspectes del sistema (`% de temps de processador`, `Bytes disponibles` de memòria, `Longitud mitjana de la cua de disc`…).

{{% steps %}}
1. ## Veure comptadors en temps real

   En **Eines de supervisió > Monitor de rendiment**, prem el botó **+** (Afig). Tria un objecte (per exemple, *Memòria*), un comptador (*MBytes disponibles*) i prem **Afig** i **D'acord**.

2. ## Registrar dades durant un temps

   En **Conjunts de recopiladors de dades > Definits per l'usuari**, crea un conjunt nou amb els comptadors que t'interessen i un interval de mostreig. En iniciar-lo, guarda les dades en un fitxer que podràs analitzar després. És la manera d'estudiar un problema que només ocorre a determinades hores.

3. ## Generar un informe del sistema

   Executa `perfmon /report` en una consola d'administrador. Durant 60 segons recopila dades i genera un **diagnòstic del sistema** amb advertiments sobre problemes de maquinari, configuració i rendiment.
{{% /steps %}}

### Monitor de fiabilitat

`perfmon /rel` obri el **Monitor de fiabilitat**: un historial diari amb un índex d'estabilitat d'1 a 10 i la llista d'errors d'aplicacions, errors de Windows, actualitzacions i instal·lacions. És molt útil per a respondre a la pregunta "des de quan falla això i què va canviar aquell dia?".

## 9.5 Windows: línia d'ordres

```bat
:: CMD
systeminfo                         :: Resum: versió, memòria total i disponible, actualitzacions
tasklist /fi "memusage gt 200000"  :: Processos que utilitzen més de 200 000 KB
netstat -ano                       :: Connexions i ports amb el PID del procés
```

```powershell
# Memòria total i lliure (els valors de Win32_OperatingSystem estan en KB)
$so = Get-CimInstance Win32_OperatingSystem
"{0:N1} GB lliures de {1:N1} GB" -f ($so.FreePhysicalMemory / 1MB), ($so.TotalVisibleMemorySize / 1MB)

# Càrrega de la CPU (mitjana de tots els nuclis)
(Get-CimInstance Win32_Processor | Measure-Object -Property LoadPercentage -Average).Average

# Espai lliure de cada volum
Get-Volume | Where-Object DriveLetter |
    Select-Object DriveLetter, FileSystemLabel,
        @{n='GrandariaGB'; e={[math]::Round($_.Size / 1GB, 1)}},
        @{n='LliureGB';    e={[math]::Round($_.SizeRemaining / 1GB, 1)}}

# Ports TCP en escolta i el procés que els utilitza
Get-NetTCPConnection -State Listen |
    Select-Object LocalAddress, LocalPort, OwningProcess,
        @{n='Proces'; e={(Get-Process -Id $_.OwningProcess).ProcessName}} |
    Sort-Object LocalPort
```

### Comptadors de rendiment amb `Get-Counter`

```powershell
Get-Counter -ListSet * | Select-Object CounterSetName     # Conjunts de comptadors disponibles
Get-Counter '\Procesador(_Total)\% de tiempo de procesador' -SampleInterval 2 -MaxSamples 5
```

> [!WARNING]
> Els noms dels comptadors **estan traduïts a l'idioma de Windows**: en un sistema en espanyol el comptador s'anomena `\Procesador(_Total)\% de tiempo de procesador` i en un en anglés, `\Processor(_Total)\% Processor Time`. Un script amb els noms en un idioma falla en un equip amb un altre idioma. Per a scripts portables, és preferible utilitzar les classes CIM, com en els exemples anteriors, els noms de les quals no es tradueixen.

## 9.6 Comparativa

| Necessitat | Linux | Windows |
| --- | --- | --- |
| Monitor en temps real | `top`, `htop`, `btop` | Administrador de tasques, `resmon` |
| Càrrega de la CPU | `uptime`, `top` | Administrador de tasques, `Win32_Processor` |
| Memòria | `free -h`, `vmstat` | Pestanya *Rendiment*, `Win32_OperatingSystem` |
| Espai en disc | `df -h`, `du -sh` | Explorador, `Get-Volume` |
| Activitat del disc | `iostat -x` | `resmon` (pestanya *Disc*) |
| Ports en escolta | `ss -tulpn` | `Get-NetTCPConnection -State Listen`, `netstat -ano` |
| Registre històric de rendiment | `sar` (paquet `sysstat`) | `perfmon` (recopiladors de dades) |
| Diagnòstic general | `journalctl`, `dmesg` | `perfmon /report`, `perfmon /rel` |

## Exercicis resolts

### Exercici 9.1. Interpretar la càrrega

Un servidor amb 2 nuclis mostra `load average: 3,90, 3,10, 1,20`. Què està passant?

{{% details "Veure solució" %}}
Amb 2 nuclis, una càrrega de 3,90 significa que de mitjana hi ha quasi 4 processos que volen utilitzar la CPU quan només se'n poden executar 2 alhora: hi ha processos **esperant** i el sistema està **sobrecarregat**. A més, la tendència és **creixent**: fa 15 minuts la càrrega era 1,20, fa 5 minuts 3,10 i ara 3,90. Caldria buscar amb `top` (ordenant per CPU amb `P`) quin procés ha començat a consumir recursos, i comprovar amb la columna `wa` si el problema és la CPU o l'espera de disc.
{{% /details %}}

### Exercici 9.2. Provocar i observar càrrega

En una màquina virtual Linux, obri `htop` en un terminal. En un altre terminal genera càrrega en la CPU i en la memòria i observa els canvis. Finalitza després els processos generats.

{{% details "Veure solució" %}}
```bash
# Terminal 1
htop

# Terminal 2: un bucle infinit per cada nucli (consumix CPU)
for i in $(seq "$(nproc)"); do (while :; do :; done) & done

# Terminal 2: reservar uns 500 MB de memòria durant 60 segons amb Python
python3 -c "import time; dades = bytearray(500 * 1024 * 1024); time.sleep(60)" &

# Per a finalitzar els bucles del terminal 2:
kill $(jobs -p)
```

En `htop` veuràs totes les barres dels nuclis al 100 %, la càrrega mitjana pujant a poc a poc i la barra de memòria creixent uns 500 MB. `jobs -p` mostra els PID dels treballs en segon pla del terminal actual, així que `kill $(jobs -p)` els finalitza tots.
{{% /details %}}

### Exercici 9.3. Qui utilitza aquest port?

En arrancar la teua aplicació apareix l'error *Address already in use* en el port 8080. Esbrina quin procés l'està utilitzant en Linux i en Windows.

{{% details "Veure solució" %}}
Linux:

```bash
sudo ss -tlpn 'sport = :8080'
# LISTEN 0 5 0.0.0.0:8080 0.0.0.0:* users:(("python3",pid=6120,fd=3))
ps -o pid,user,cmd -p 6120
```

Windows (PowerShell):

```powershell
$con = Get-NetTCPConnection -LocalPort 8080 -State Listen
Get-Process -Id $con.OwningProcess | Select-Object Id, ProcessName, Path
```

O, en CMD: `netstat -ano | findstr :8080` i després `tasklist /fi "pid eq 6120"`.
{{% /details %}}

### Exercici 9.4. Informe d'estat

Escriu un script de PowerShell `estat.ps1` que mostre: el nom de l'equip, el temps que porta encés, el % d'ús de la CPU, la memòria lliure i l'espai lliure de la unitat `C:`, i que avise si la memòria lliure baixa del 15 % o el disc del 10 %.

{{% details "Veure solució" %}}
```powershell
# estat.ps1 - Resum de l'estat del sistema
$so    = Get-CimInstance Win32_OperatingSystem
$cpu   = (Get-CimInstance Win32_Processor | Measure-Object LoadPercentage -Average).Average
$disc  = Get-Volume -DriveLetter C

$memLliurePct  = [math]::Round($so.FreePhysicalMemory / $so.TotalVisibleMemorySize * 100)
$discLliurePct = [math]::Round($disc.SizeRemaining / $disc.Size * 100)
$tempsEnces         = (Get-Date) - $so.LastBootUpTime        # Restar dates dona un TimeSpan

Write-Output "Equip:          $env:COMPUTERNAME"
Write-Output ("Encés:          {0} dies, {1} h, {2} min" -f $tempsEnces.Days, $tempsEnces.Hours, $tempsEnces.Minutes)
Write-Output "CPU:            $cpu %"
Write-Output "Memòria lliure: $memLliurePct %"
Write-Output "Disc C lliure:  $discLliurePct %"

if ($memLliurePct -lt 15)  { Write-Warning "Queda poca memòria lliure" }
if ($discLliurePct -lt 10) { Write-Warning "Queda poc espai en C:" }
```

`LastBootUpTime` és la data de l'última arrancada; en restar-la de la data actual s'obté un objecte `TimeSpan` amb propietats com `Days`, `Hours` i `Minutes`.
{{% /details %}}
