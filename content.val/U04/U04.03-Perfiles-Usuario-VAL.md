# 3. Perfils d'usuari

El **perfil d'usuari** és el conjunt de fitxers i de configuració que definixen l'**entorn de treball** d'una persona: els seus documents, el fons d'escriptori, l'idioma, les variables d'entorn, l'historial d'ordres o la configuració dels seus programes (per exemple, les extensions de Visual Studio Code o la configuració de Git).

Gràcies als perfils, cada usuari troba l'equip tal com el va deixar, encara que altres persones també l'utilitzen.

## 3.1 Perfils en Linux

En Linux, el perfil d'un usuari està format per:

1. El seu **directori personal** (`/home/usuari`), amb els seus fitxers i els seus **fitxers ocults de configuració** (els que comencen per `.`).
2. Els **fitxers d'inici de la shell**, que s'executen en obrir una sessió o un terminal.

### El directori personal

```bash
echo "$HOME"          # /home/ana
ls -la ~              # Fitxers ocults inclosos
```

| Fitxer o directori | Contingut |
| --- | --- |
| `~/.bashrc` | Configuració de Bash per a terminals interactius: àlies, *prompt*, funcions. |
| `~/.profile` | S'executa en **iniciar sessió**: variables d'entorn com `PATH`. |
| `~/.bash_history` | Historial d'ordres. |
| `~/.bash_logout` | S'executa en tancar una sessió d'inici. |
| `~/.config/` | Configuració de les aplicacions modernes (estàndard *XDG*). |
| `~/.local/share/` | Dades de les aplicacions. |
| `~/.cache/` | Memòria cau; es pot esborrar sense perdre informació important. |
| `~/.ssh/` | Claus SSH i llista de servidors coneguts. Ha de tindre permisos `700`. |
| `~/.gitconfig` | Configuració global de Git (nom, correu…). |

### `/etc/skel`: la plantilla dels perfils nous

Quan es crea un usuari amb `useradd -m` o `adduser`, el seu directori personal s'ompli amb una **còpia** del contingut de `/etc/skel` (de *skeleton*, esquelet). Si l'administrador modifica `/etc/skel`, tots els usuaris que es creen **a partir d'aquest moment** rebran aquests fitxers.

```bash
ls -la /etc/skel      # .bash_logout  .bashrc  .profile
```

> [!NOTE]
> Els canvis en `/etc/skel` **no afecten els usuaris que ja existixen**. Per a aplicar una configuració a tots els usuaris, actuals i futurs, s'utilitzen els fitxers globals de `/etc` que s'expliquen a continuació.

### Fitxers d'inici de Bash

Bash llig uns fitxers o altres segons el tipus de shell:

| Tipus de shell | Quan ocorre | Fitxers que llig (en ordre) |
| --- | --- | --- |
| **D'inici de sessió** (*login shell*) | En entrar per consola de text, per SSH o amb `su -` | `/etc/profile` (i els fitxers de `/etc/profile.d/`), i després el **primer que existisca** de `~/.bash_profile`, `~/.bash_login` o `~/.profile`. |
| **Interactiva sense inici de sessió** | En obrir un terminal dins de l'escriptori | `/etc/bash.bashrc` i `~/.bashrc`. |

En Ubuntu, `~/.profile` inclou al seu torn `~/.bashrc`, de manera que en la pràctica la configuració interactiva es posa en `~/.bashrc` i les variables d'entorn en `~/.profile`.

| Àmbit | Fitxers de configuració |
| --- | --- |
| **Tots els usuaris** | `/etc/profile`, `/etc/profile.d/*.sh`, `/etc/bash.bashrc`, `/etc/environment` |
| **Un usuari** | `~/.profile`, `~/.bashrc` |
| **Usuaris futurs** | `/etc/skel/` |

```bash
# ~/.bashrc  (fragment)
alias ll='ls -lah'                       # Àlies: drecera per a una ordre llarga
alias actualitzar='sudo apt update && sudo apt upgrade'
export EDITOR=nano                       # Editor per defecte per a crontab, visudo…
```

```bash
# ~/.profile  (fragment)
# Afig al PATH la carpeta de programes de l'usuari, si existix
if [ -d "$HOME/.local/bin" ]; then
    PATH="$HOME/.local/bin:$PATH"
fi
export JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64
```

Els canvis en aquests fitxers s'apliquen en obrir un terminal o una sessió nova. Per a aplicar-los en el terminal actual:

```bash
source ~/.bashrc        # Equival a: . ~/.bashrc
```

> [!TIP]
> Per a configuracions globals, en lloc de modificar `/etc/profile` crea un fitxer propi en `/etc/profile.d/` (per exemple, `/etc/profile.d/aula.sh`). Així, les actualitzacions del sistema no sobreescriuran els teus canvis i és fàcil desfer-los esborrant el fitxer.

## 3.2 Perfils en Windows

En Windows, el perfil de cada usuari es guarda en `C:\Users\usuari` i es crea **la primera vegada que l'usuari inicia sessió**, copiant el perfil plantilla `C:\Users\Default` (l'equivalent a `/etc/skel`).

| Carpeta o fitxer | Contingut |
| --- | --- |
| `Desktop`, `Documents`, `Downloads`, `Pictures`… | Carpetes personals (en l'Explorador apareixen traduïdes: *Escriptori*, *Documents*…). |
| `AppData\Roaming` | Configuració de les aplicacions que ha d'**acompanyar l'usuari** entre equips (perfils mòbils). |
| `AppData\Local` | Dades i memòria cau que només tenen sentit en **aquest equip**. |
| `AppData\LocalLow` | Igual que `Local`, per a aplicacions que s'executen amb un nivell d'integritat baix (per exemple, navegadors en mode protegit). |
| `NTUSER.DAT` | Part del **registre de Windows** de l'usuari. En iniciar sessió es carrega com la branca `HKEY_CURRENT_USER` (`HKCU`). |

La carpeta `AppData` està **oculta**. Per a veure-la, activa en l'Explorador *Visualització > Mostra > Elements ocults*, o escriu `%APPDATA%` en la barra d'adreces.

A més, `C:\Users\Public` (*Accés públic*) conté carpetes compartides per tots els usuaris de l'equip.

### Variables d'entorn del perfil

| CMD | PowerShell | Valor típic |
| --- | --- | --- |
| `%USERNAME%` | `$env:USERNAME` | `ana` |
| `%USERPROFILE%` | `$env:USERPROFILE` | `C:\Users\ana` |
| `%APPDATA%` | `$env:APPDATA` | `C:\Users\ana\AppData\Roaming` |
| `%LOCALAPPDATA%` | `$env:LOCALAPPDATA` | `C:\Users\ana\AppData\Local` |
| `%TEMP%` | `$env:TEMP` | `C:\Users\ana\AppData\Local\Temp` |
| `%PUBLIC%` | `$env:PUBLIC` | `C:\Users\Public` |

```powershell
Get-ChildItem Env:              # Totes les variables d'entorn
explorer $env:APPDATA           # Obri la carpeta en l'Explorador
```

### Tipus de perfils

| Tipus | Descripció |
| --- | --- |
| **Local** | Es guarda en el disc de l'equip. És el tipus per defecte. |
| **Mòbil** (*roaming*) | Es guarda en un servidor de la xarxa i es copia a l'equip en iniciar sessió. L'usuari troba el seu entorn en qualsevol equip del domini. |
| **Obligatori** (*mandatory*) | Perfil mòbil de només lectura (el fitxer es reanomena a `NTUSER.MAN`): els canvis es perden en tancar la sessió. Útil en aules i quioscos. |
| **Temporal** | Windows el crea quan no pot carregar el perfil de l'usuari (per exemple, si està danyat). S'esborra en tancar la sessió, així que **no s'ha de treballar amb ell**. |

Els perfils mòbils i obligatoris necessiten un domini i es configuren des del servidor (Unitat 6).

> [!NOTE]
> Si inicies sessió amb un compte Microsoft i actives la **còpia de seguretat de carpetes** de OneDrive, les carpetes *Escriptori*, *Documents* i *Imatges* es traslladen a `C:\Users\usuari\OneDrive\`. Tin-ho en compte quan un script busque fitxers en `$env:USERPROFILE\Desktop`; la ruta fiable és `[Environment]::GetFolderPath('Desktop')`.

### Veure i eliminar perfils

Els perfils **no s'esborren** en eliminar el compte d'usuari i continuen ocupant espai. No s'han d'esborrar eliminant la carpeta de `C:\Users`, perquè quedaria una referència en el registre i el sistema podria crear perfils temporals. La manera correcta és:

- **Gràficament**: `Win + R` > `sysdm.cpl` > pestanya **Opcions avançades** > **Perfils d'usuari** > **Configuració**. Selecciona el perfil i prem **Suprimeix**.
- **Amb PowerShell** (com a administrador):

```powershell
# Llista els perfils d'usuaris reals (Special = $false exclou SYSTEM, LOCAL SERVICE…)
Get-CimInstance Win32_UserProfile |
    Where-Object { -not $_.Special } |
    Select-Object LocalPath, SID, LastUseTime, Loaded

# Elimina el perfil d'una ruta concreta (l'usuari no ha de tindre la sessió oberta: Loaded = False)
Get-CimInstance Win32_UserProfile |
    Where-Object LocalPath -eq 'C:\Users\prova' |
    Remove-CimInstance
```

`Get-CimInstance` consulta la informació de gestió de Windows (WMI) mitjançant l'estàndard CIM. Substituïx les antigues `Get-WmiObject` i `wmic`, que ja no s'han d'utilitzar: `wmic` ha sigut **eliminat** de les versions actuals de Windows 11.

### El perfil de PowerShell

PowerShell també té el seu propi "`~/.bashrc`": un script que s'executa en obrir cada consola. La seua ruta està en la variable `$PROFILE`.

```powershell
$PROFILE                                    # Ruta del perfil (pot no existir encara)
if (-not (Test-Path $PROFILE)) { New-Item -Path $PROFILE -ItemType File -Force }
notepad $PROFILE
```

```powershell
# Contingut d'exemple del perfil de PowerShell
Set-Alias -Name ll -Value Get-ChildItem          # Àlies, com en Bash
function projectes { Set-Location "$HOME\projectes" }
```

## 3.3 Comparativa

| Concepte | Linux | Windows |
| --- | --- | --- |
| Ubicació | `/home/usuari` | `C:\Users\usuari` |
| Plantilla per a perfils nous | `/etc/skel` | `C:\Users\Default` |
| Configuració d'aplicacions | `~/.config`, fitxers ocults | `AppData`, branca `HKCU` del registre |
| Configuració de la shell | `~/.bashrc`, `~/.profile` | `$PROFILE` de PowerShell |
| Configuració per a tots | `/etc/profile.d/`, `/etc/environment` | Directives de grup, variables d'entorn del sistema |
| Variables del perfil | `$HOME`, `$USER` | `%USERPROFILE%`, `%USERNAME%` |

## Exercicis resolts

### Exercici 3.1. Personalitzar la plantilla d'usuaris

Fes que tots els usuaris que es creen a partir d'ara en el teu Linux tinguen: un directori `projectes` buit, un fitxer `LLEGIM.txt` amb les normes de l'aula i l'àlies `ll='ls -lah'`. Comprova que un usuari nou els rep i que un d'existent no.

{{% details "Veure solució" %}}
```bash
sudo mkdir /etc/skel/projectes
echo "Normes de l'aula: no compartisques la teua contrasenya i guarda el teu treball en ~/projectes" |
    sudo tee /etc/skel/LLEGIM.txt > /dev/null
echo "alias ll='ls -lah'" | sudo tee -a /etc/skel/.bashrc > /dev/null

sudo useradd -m -s /bin/bash nou
sudo ls -la /home/nou          # Apareixen projectes/ i LLEGIM.txt
ls ~/projectes                 # En el teu usuari (ja existent) no s'ha creat
```

S'utilitza `sudo tee` perquè la redirecció `>` la fa la shell de l'usuari normal, que no té permís d'escriptura en `/etc/skel`. `tee -a` afig al final del fitxer en lloc de sobreescriure'l.
{{% /details %}}

### Exercici 3.2. Variable d'entorn per a tots els usuaris

Definix la variable `AULA=B12` per a tots els usuaris del sistema, actuals i futurs, sense modificar fitxers que puguen canviar les actualitzacions.

{{% details "Veure solució" %}}
```bash
echo 'export AULA=B12' | sudo tee /etc/profile.d/aula.sh > /dev/null
```

Els fitxers de `/etc/profile.d/` es lligen en els inicis de sessió. Per a comprovar-ho, obri una sessió d'inici nova (`su - ana`) i executa `echo "$AULA"`. En l'escriptori gràfic cal tancar la sessió i tornar a entrar.
{{% /details %}}

### Exercici 3.3. Perfils orfes en Windows

Crea l'usuari local `temporal`, inicia sessió amb ell una vegada i elimina'l amb `Remove-LocalUser`. Comprova que el seu perfil continua existint i esborra'l correctament.

{{% details "Veure solució" %}}
```powershell
# 1. Després de crear l'usuari, iniciar sessió amb ell i tancar la sessió:
Remove-LocalUser -Name temporal
Test-Path C:\Users\temporal           # True: la carpeta continua existint

# 2. El perfil apareix amb el SID d'un compte que ja no existix
Get-CimInstance Win32_UserProfile | Where-Object LocalPath -like '*temporal*' |
    Select-Object LocalPath, SID

# 3. Esborrament correcte (carpeta i entrada del registre)
Get-CimInstance Win32_UserProfile | Where-Object LocalPath -eq 'C:\Users\temporal' |
    Remove-CimInstance
Test-Path C:\Users\temporal           # False
```

En `sysdm.cpl`, el perfil orfe apareix com a *Compte desconegut*.
{{% /details %}}
