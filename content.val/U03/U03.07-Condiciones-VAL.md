# 7. Condicions: prendre decisions

## 7.1 Cert i fals en Bash

En la majoria de llenguatges, una condició és una expressió que val `true` o `false`. En Bash, en canvi, **una condició és una ordre**, i el que s'avalua és el seu **codi d'eixida**:

- Codi `0` (l'ordre ha tingut èxit) → **cert**.
- Codi distint de `0` (l'ordre ha fallat) → **fals**.

> [!IMPORTANT]
> És just al revés que en C o Java, on `0` significa fals. En Bash, `0` = èxit = cert.

Per això podem utilitzar directament qualsevol ordre com a condició:

```bash
if grep -q "^ana:" /etc/passwd; then
    echo "L'usuari ana existeix"
fi
```

Per a comparar valors o comprovar fitxers hi ha una ordre especial: `test`, que s'escriu normalment amb claudàtors.

## 7.2 `test`, `[ ]` i `[[ ]]`

```bash
test 5 -gt 3      # Ordre test clàssica
[ 5 -gt 3 ]       # Equivalent: [ és un altre nom de test (necessita el ] final)
[[ 5 -gt 3 ]]     # Versió millorada, pròpia de Bash
echo $?           # 0 -> cert
```

> [!WARNING]
> Els claudàtors **necessiten espais** a banda i banda: `[ "$a" = "$b" ]`. Escriure `["$a" = "$b"]` provoca l'error `[hola: command not found`, perquè `[` és una ordre i ha d'anar separada dels seus arguments.

| | `[ ]` (`test`) | `[[ ]]` |
| --- | --- | --- |
| Disponibilitat | Totes les shells POSIX (`sh`, `dash`…). | Bash, zsh, ksh. |
| Variables sense cometes | Fallen si estan buides o tenen espais. | Funcionen (encara que posar-les entre cometes continua sent bona pràctica). |
| Operadors lògics | `!`, i entre claudàtors: `[ … ] && [ … ]`. | `!`, `&&`, `\|\|` i parèntesis dins. |
| Patrons i regex | No. | `==` amb comodins i `=~` amb expressions regulars. |

En els scripts de Bash d'aquesta unitat utilitzarem **`[[ ]]`** per a cadenes i fitxers, i **`(( ))`** per a comparacions numèriques.

## 7.3 Operadors de comprovació

### Fitxers

| Operador | Cert si… |
| --- | --- |
| `-e ruta` | Existeix (siga del tipus que siga). |
| `-f ruta` | Existeix i és un fitxer normal. |
| `-d ruta` | Existeix i és un directori. |
| `-L ruta` | És un enllaç simbòlic. |
| `-s ruta` | Existeix i la seua grandària és major que 0. |
| `-r` / `-w` / `-x ruta` | L'usuari actual pot llegir-lo / escriure'l / executar-lo. |
| `f1 -nt f2` | `f1` és més recent (*newer than*) que `f2`. |

### Cadenes

| Operador | Cert si… |
| --- | --- |
| `-z "$s"` | La cadena està buida (longitud zero). |
| `-n "$s"` | La cadena **no** està buida. |
| `"$a" == "$b"` | Són iguals (en `[ ]` s'utilitza `=`). |
| `"$a" != "$b"` | Són distintes. |
| `"$s" == patró` | (Només `[[ ]]`) la cadena encaixa amb un patró amb comodins, p. ex. `[[ $f == *.txt ]]`. |
| `"$s" =~ regex` | (Només `[[ ]]`) la cadena compleix l'expressió regular. |

### Números

| En `[ ]` / `[[ ]]` | En `(( ))` | Significat |
| --- | --- | --- |
| `-eq` | `==` | Igual. |
| `-ne` | `!=` | Distint. |
| `-lt` | `<` | Menor que (*less than*). |
| `-le` | `<=` | Menor o igual. |
| `-gt` | `>` | Major que (*greater than*). |
| `-ge` | `>=` | Major o igual. |

```bash
edad=20
[[ $edad -ge 18 ]] && echo "Major d'edat"
(( edad >= 18 )) && echo "Major d'edat"     # Més llegible per als números
```

> [!CAUTION]
> Dins de `[[ ]]`, els operadors `<` i `>` comparen **cadenes** alfabèticament, no números: `[[ 10 < 9 ]]` és **cert** perquè el caràcter `1` va abans que `9`. Per a números utilitza `-lt`/`-gt` o, millor, `(( ))`.

### Operadors lògics

| Operador | Significat | Exemple |
| --- | --- | --- |
| `!` | NO | `[[ ! -f "$f" ]]` |
| `&&` | I | `[[ -f "$f" && -r "$f" ]]` |
| `\|\|` | O | `[[ $resp == "s" \|\| $resp == "S" ]]` |

## 7.4 L'estructura `if`

```bash
if condició; then
    ordres si és certa
elif altra_condició; then
    ordres si la primera és falsa i aquesta certa
else
    ordres si cap no és certa
fi
```

- `then` pot anar en la línia següent; si va en la mateixa línia que la condició, cal separar-los amb `;`.
- Les parts `elif` i `else` són opcionals i hi pot haver tants `elif` com calga.
- L'estructura es tanca amb `fi` (`if` al revés).

```bash
#!/bin/bash
# nota.sh - Qualificació a partir d'una nota numèrica
read -rp "Introdueix la nota (0-10): " nota

if (( nota < 0 || nota > 10 )); then
    echo "Nota no vàlida" >&2
    exit 1
elif (( nota < 5 )); then
    echo "Insuficient"
elif (( nota < 7 )); then
    echo "Aprovat"
elif (( nota < 9 )); then
    echo "Notable"
else
    echo "Excel·lent"
fi
```

### Validar l'entrada

Abans d'operar amb una dada cal comprovar que és correcta. Les **expressions regulars** amb `=~` són perfectes per a això:

```bash
if [[ ! $nota =~ ^[0-9]+$ ]]; then
    echo "Error: '$nota' no és un número enter positiu" >&2
    exit 1
fi
```

| Expressió regular | Accepta |
| --- | --- |
| `^[0-9]+$` | Enters positius: `0`, `42`. |
| `^-?[0-9]+$` | Enters amb signe opcional: `-7`, `15`. |
| `^[a-zA-Z_]+$` | Només lletres i guió baix. |
| `^[a-z0-9._-]+@[a-z0-9.-]+\.[a-z]{2,}$` | Un correu electrònic (simplificat). |

> [!TIP]
> No escrigues l'expressió regular entre cometes en `=~`: `[[ $x =~ "^[0-9]+$" ]]` compara amb el text literal. Si l'expressió és complexa, guarda-la en una variable: `re='^[0-9]+$'; [[ $x =~ $re ]]`.

### Comprovar fitxers i arguments

```bash
#!/bin/bash
# info_fichero.sh - Informa sobre la ruta rebuda
# Ús: ./info_fichero.sh <ruta>

if [[ $# -ne 1 ]]; then
    echo "Ús: $0 <ruta>" >&2
    exit 1
fi

ruta=$1

if [[ ! -e $ruta ]]; then
    echo "'$ruta' no existeix" >&2
    exit 2
elif [[ -d $ruta ]]; then
    echo "'$ruta' és un directori amb $(ls -A "$ruta" | wc -l) elements"
elif [[ -f $ruta ]]; then
    echo "'$ruta' és un fitxer de $(stat -c %s "$ruta") bytes"
    if [[ -x $ruta ]]; then
        echo "A més, tens permís per a executar-lo"
    fi
else
    echo "'$ruta' és un fitxer especial"
fi
```

> [!NOTE]
> Per què no s'ha escrit `[[ -x $ruta ]] && echo "…"` en una sola línia? Perquè, si el fitxer no és executable, la condició és falsa i aquesta línia, l'última de l'script, retorna un codi distint de 0: l'script acabaria indicant un error sense haver-n'hi. Amb `if` no passa, perquè un `if` amb la condició falsa i sense `else` retorna 0.

## 7.5 L'estructura `case`

Quan cal comparar **una mateixa variable** amb molts valors possibles, `case` és més clar que una cadena d'`elif`:

```bash
case "$variable" in
    patró1)
        ordres
        ;;
    patró2 | patró3)
        ordres
        ;;
    *)
        ordres per defecte
        ;;
esac
```

- Cada opció acaba amb `;;`.
- Els patrons admeten comodins: `*`, `?`, `[ ]`, i `|` per a indicar diverses alternatives.
- `*)` captura qualsevol valor no previst (equival a `else` o al `default` de Java).
- Es tanca amb `esac` (`case` al revés).

```bash
#!/bin/bash
# servicio.sh - Gestiona un servei d'exemple
# Ús: ./servicio.sh start|stop|restart|status

case "$1" in
    start)
        echo "Arrancant el servei…"
        ;;
    stop)
        echo "Aturant el servei…"
        ;;
    restart | reload)
        echo "Reiniciant el servei…"
        ;;
    status)
        echo "El servei està en execució"
        ;;
    *)
        echo "Ús: $0 {start|stop|restart|status}" >&2
        exit 1
        ;;
esac
```

```bash
#!/bin/bash
# tipo_tecla.sh - Classifica el caràcter introduït
read -rn 1 -p "Prem una tecla: " tecla
echo
case "$tecla" in
    [aeiouAEIOU])  echo "És una vocal" ;;
    [a-zA-Z])      echo "És una consonant" ;;
    [0-9])         echo "És una xifra" ;;
    *)             echo "És un altre caràcter" ;;
esac
```

Aquest patró és molt habitual per a analitzar respostes del tipus sí/no:

```bash
read -rp "Vols continuar? (s/n) " resp
case "$resp" in
    [sS] | [sS][iíIÍ]) echo "Continuem" ;;
    *)                 echo "Operació cancel·lada"; exit 0 ;;
esac
```

## 7.6 Condicions curtes amb `&&` i `||`

Per a condicions amb una sola ordre, els operadors `&&` i `||` ofereixen una forma compacta:

```bash
[[ -d copias ]] || mkdir copias           # Si no existeix el directori, crea'l
[[ $# -eq 0 ]] && { echo "Falten arguments" >&2; exit 1; }   # { } agrupa diverses ordres
cd "$destino" || exit 1                   # Si no s'hi pot entrar, acaba
```

> [!WARNING]
> `cond && A || B` **no** equival exactament a un `if/else`: si `cond` és certa però `A` falla, també s'executa `B`. Utilitza-ho només quan `A` no puga fallar (com un `echo`); en cas contrari, escriu un `if` complet.

### Exercici 7.1. Parell o imparell

Script que reba un número enter com a paràmetre, comprove que realment és un enter (pot ser negatiu) i indique si és parell o imparell.

{{% details "Veure solució" %}}
```bash
#!/bin/bash
# par_impar.sh - Indica si un número és parell o imparell
# Ús: ./par_impar.sh <enter>

if [[ $# -ne 1 ]]; then
    echo "Ús: $0 <enter>" >&2
    exit 1
fi

if [[ ! $1 =~ ^-?[0-9]+$ ]]; then
    echo "Error: '$1' no és un número enter" >&2
    exit 2
fi

if (( $1 % 2 == 0 )); then
    echo "$1 és parell"
else
    echo "$1 és imparell"
fi
```

### Exercici 7.2. El major de tres números

Script que demane tres números enters per teclat i mostre el major. Si hi ha empat en el valor màxim, ha d'indicar-ho.

{{% details "Veure solució" %}}
```bash
#!/bin/bash
# mayor.sh - Mostra el major de tres números

read -rp "Primer número: " a
read -rp "Segon número: " b
read -rp "Tercer número: " c

# Validem els tres valors d'una vegada
for n in "$a" "$b" "$c"; do
    if [[ ! $n =~ ^-?[0-9]+$ ]]; then
        echo "Error: '$n' no és un enter" >&2
        exit 1
    fi
done

mayor=$a
(( b > mayor )) && mayor=$b
(( c > mayor )) && mayor=$c

# Comptem quants valors coincideixen amb el màxim
veces=0
for n in "$a" "$b" "$c"; do
    (( n == mayor )) && veces=$(( veces + 1 ))
done

if (( veces > 1 )); then
    echo "El major és $mayor (apareix $veces vegades)"
else
    echo "El major és $mayor"
fi
```

La idea és suposar que el major és el primer i actualitzar-lo si en trobem un de més gran, una tècnica que utilitzareu constantment en Programació.
{{% /details %}}

### Exercici 7.3. Còpia de seguretat segura d'un fitxer

Script que reba la ruta d'un fitxer i cree una còpia amb el sufix `.bak`. Ha de comprovar que: s'ha passat un argument, el fitxer existeix i és un fitxer normal, es pot llegir i, si la còpia ja existeix, preguntar abans de sobreescriure-la.

{{% details "Veure solució" %}}
```bash
#!/bin/bash
# bak.sh - Crea una còpia .bak d'un fitxer
# Ús: ./bak.sh <fitxer>

[[ $# -eq 1 ]] || { echo "Ús: $0 <fitxer>" >&2; exit 1; }

origen=$1
copia="$origen.bak"

if [[ ! -f $origen ]]; then
    echo "Error: '$origen' no existeix o no és un fitxer normal" >&2
    exit 2
fi

if [[ ! -r $origen ]]; then
    echo "Error: no tens permís de lectura sobre '$origen'" >&2
    exit 3
fi

if [[ -e $copia ]]; then
    read -rp "'$copia' ja existeix. Vols sobreescriure-la? (s/n) " resp
    case "$resp" in
        [sS]) ;;                                    # Opció buida: continuem
        *)    echo "No s'ha fet la còpia"; exit 0 ;;
    esac
fi

if cp -- "$origen" "$copia"; then
    echo "Còpia creada: $copia"
else
    echo "Error en copiar" >&2
    exit 4
fi
```

Cada error té un codi d'eixida distint, cosa que permet a qui utilitze l'script saber què ha fallat.
{{% /details %}}

### Exercici 7.4. Classificador de fitxers per extensió

Script que reba el nom d'un fitxer i n'indique la categoria segons l'extensió: imatge (`jpg`, `jpeg`, `png`, `gif`), document (`pdf`, `odt`, `docx`, `txt`), codi (`java`, `py`, `sh`, `kt`) o comprimit (`zip`, `tar`, `gz`). La comparació no ha de distingir majúscules.

{{% details "Veure solució" %}}
```bash
#!/bin/bash
# categoria.sh - Classifica un fitxer per la seua extensió
# Ús: ./categoria.sh <fitxer>

[[ $# -eq 1 ]] || { echo "Ús: $0 <fitxer>" >&2; exit 1; }

# ${1##*.} elimina tot fins a l'últim punt (apartat 10); ,, passa a minúscules
extension=${1##*.}
extension=${extension,,}

case "$extension" in
    jpg | jpeg | png | gif)   categoria="imatge" ;;
    pdf | odt | docx | txt)   categoria="document" ;;
    java | py | sh | kt)      categoria="codi font" ;;
    zip | tar | gz)           categoria="fitxer comprimit" ;;
    *)                        categoria="desconeguda" ;;
esac

echo "$1 → $categoria"
```

```text
$ ./categoria.sh Foto.JPG
Foto.JPG → imatge
$ ./categoria.sh Main.kt
Main.kt → codi font
```
