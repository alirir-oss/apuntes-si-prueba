# 1. Introducció a la shell

## 1.1 Terminal, consola i shell

Aquests tres termes s'utilitzen sovint com a sinònims, però no signifiquen el mateix:

| Concepte | Què és | Exemples |
| --- | --- | --- |
| **Terminal** (emulador de terminal) | Programa amb una finestra on s'escriu text i es veu la resposta. | GNOME Terminal, Konsole, Windows Terminal, el terminal integrat de VS Code. |
| **Consola** | Terminal "física" del sistema, sense entorn gràfic (la que apareix amb `Ctrl+Alt+F3`). | `tty1`, `tty2`… |
| **Shell** (intèrpret d'ordres) | Programa que **llig** el que escrivim, ho **interpreta** i demana al sistema operatiu que ho **execute**. | `bash`, `zsh`, `sh`/`dash`, `fish`, PowerShell. |

És a dir: el terminal és la "finestra" i la shell és el "cervell" que hi ha darrere. En aquesta unitat utilitzarem **Bash** (*Bourne Again SHell*), la shell per defecte en la majoria de distribucions GNU/Linux i la més utilitzada en servidors, contenidors Docker i *pipelines* de CI/CD.

```bash
echo "$SHELL"      # Mostra la shell configurada per al teu usuari
cat /etc/shells    # Llista les shells instal·lades en el sistema
bash --version     # Mostra la versió de Bash
```

> [!NOTE]
> macOS utilitza **zsh** per defecte des de 2019. La major part del que s'explica ací funciona igual en zsh, però els scripts d'aquesta unitat s'executaran sempre amb Bash.

## 1.2 El *prompt*

Quan obrim un terminal, la shell mostra el ***prompt*** (indicador), que ens avisa que està esperant una ordre:

```text
alumno@dam-pc:~/proyectos$
```

| Part | Significat |
| --- | --- |
| `alumno` | Usuari amb què hem iniciat la sessió. |
| `dam-pc` | Nom de l'equip (*hostname*). |
| `~/proyectos` | Directori actual. `~` representa el directori personal de l'usuari (`/home/alumno`). |
| `$` | Usuari normal. Si apareix `#`, estem treballant com a **root** (administrador). |

> [!WARNING]
> En la documentació, el símbol `$` o `#` del *prompt* **no s'escriu**: només indica qui executa l'ordre. En aquesta unitat ometrem el *prompt* en els blocs de codi, excepte quan vulguem mostrar també l'eixida.

## 1.3 Sintaxi d'una ordre

Totes les ordres segueixen la mateixa estructura general:

```text
ordre [opcions] [arguments]
```

- **Ordre**: nom del programa o de l'ordre que s'executa (`ls`, `cp`, `grep`…).
- **Opcions** (també anomenades *flags* o modificadors): canvien el comportament de l'ordre. Poden ser:
  - **Curtes**: un guió i una lletra (`-l`, `-a`). Es poden agrupar: `-la` equival a `-l -a`.
  - **Llargues**: dos guions i una paraula (`--all`, `--human-readable`). Són més llegibles i es recomanen en els scripts.
- **Arguments**: les dades sobre les quals actua l'ordre (fitxers, directoris, textos…).

Els elements se separen amb **espais**, i Bash **distingeix majúscules de minúscules** (`ls` no és el mateix que `LS`).

```bash
ls -l -h /etc          # ordre: ls | opcions: -l -h | argument: /etc
ls -lh /etc            # el mateix, amb les opcions curtes agrupades
ls --format=long --human-readable /etc   # el mateix, amb opcions llargues
```

Algunes opcions necessiten al seu torn un valor, per exemple `head -n 5 fitxer` (mostra 5 línies). El doble guió `--` indica "fi de les opcions": tot el que va darrere es tracta com a argument, encara que comence per guió (`rm -- -fitxer-estrany`).

### Tipus d'ordres

No totes les ordres són programes independents. L'ordre `type` ens diu de quin tipus és cadascuna:

```bash
type cd       # cd is a shell builtin       -> ordre interna de Bash
type ls       # ls is aliased to 'ls --color=auto' -> àlies
type grep     # grep is /usr/bin/grep       -> programa extern
command -v python3   # Mostra la ruta de l'executable (o res si no existeix)
```

| Tipus | Descripció |
| --- | --- |
| **Interna** (*builtin*) | Forma part de la mateixa shell: `cd`, `echo`, `read`, `exit`, `export`… |
| **Externa** | Programa guardat en un directori del sistema (`/usr/bin/ls`). La shell el busca en els directoris de la variable `PATH`. |
| **Àlies** | Drecera definida per l'usuari: `alias ll='ls -l'`. |
| **Funció** | Bloc de codi amb nom definit en la shell (el veurem en l'apartat 9). |

## 1.4 Com obtindre ajuda

Ningú memoritza totes les opcions de totes les ordres. L'important és **saber consultar-les**:

| Ordre | Per a què serveix |
| --- | --- |
| `man ordre` | Obri la pàgina del manual. Es navega amb les fletxes, `/text` busca, `n` va al resultat següent i `q` ix. |
| `ordre --help` | Resum breu d'ús i opcions (quasi tots els programes externs el tenen). |
| `help ordre` | Ajuda de les ordres **internes** de Bash (`help cd`, `help read`). |
| `man -k paraula` | Busca ordres relacionades amb una paraula clau (equival a `apropos`). |
| `whatis ordre` | Descripció d'una línia. |

```bash
man ls              # Manual complet de ls
ls --help | less    # Ajuda resumida, paginada amb less
help read           # Ajuda de l'ordre interna read
man -k password     # Quines ordres tenen a veure amb contrasenyes?
```

> [!TIP]
> El manual es divideix en **seccions** numerades. Les més utilitzades són la **1** (ordres d'usuari), la **5** (formats de fitxers de configuració) i la **8** (ordres d'administració). Per exemple, `man 5 passwd` explica el fitxer `/etc/passwd`, mentre que `man 1 passwd` explica l'ordre `passwd`.

## 1.5 El sistema de fitxers

### Un únic arbre

A diferència de Windows (amb unitats `C:`, `D:`…), en Linux tot penja d'**un únic arbre de directoris** l'arrel del qual és `/`. Els discos, memòries USB o particions s'"enganxen" (**es munten**) en algun directori d'aquest arbre.

L'organització dels directoris segueix l'estàndard **FHS** (*Filesystem Hierarchy Standard*):

| Directori | Contingut |
| --- | --- |
| `/` | Arrel del sistema de fitxers. |
| `/bin`, `/usr/bin` | Programes (ordres) disponibles per a tots els usuaris. |
| `/sbin`, `/usr/sbin` | Programes d'administració del sistema. |
| `/etc` | Fitxers de **configuració** del sistema (text pla). |
| `/home` | Directoris personals dels usuaris (`/home/alumno`). |
| `/root` | Directori personal de l'administrador. |
| `/var` | Dades variables: registres (`/var/log`), cues, memòries cau, bases de dades. |
| `/tmp` | Fitxers temporals (se solen esborrar en reiniciar). |
| `/dev` | Fitxers especials que representen dispositius (`/dev/sda`). |
| `/proc`, `/sys` | Sistemes de fitxers virtuals amb informació del nucli i dels processos. |
| `/mnt`, `/media` | Punts de muntatge de discos i dispositius extraïbles. |
| `/opt` | Programari addicional instal·lat fora del gestor de paquets. |

> [!NOTE]
> En les distribucions actuals, `/bin` i `/sbin` són enllaços a `/usr/bin` i `/usr/sbin` (esquema conegut com a *usrmerge*). Per això és indiferent escriure `/bin/bash` o `/usr/bin/bash`.

### Rutes absolutes i relatives

Una **ruta** indica on està un fitxer o directori dins de l'arbre:

- **Ruta absoluta**: comença per `/` i descriu el camí complet des de l'arrel. Funciona igual des de qualsevol directori. Exemple: `/home/alumno/proyectos/web/index.html`.
- **Ruta relativa**: **no** comença per `/` i s'interpreta a partir del **directori actual**. Exemple: si estem en `/home/alumno`, la ruta `proyectos/web/index.html` apunta al mateix fitxer.

Hi ha diversos noms especials:

| Símbol | Significat |
| --- | --- |
| `.` | El directori actual. |
| `..` | El directori pare (el que està un nivell per damunt). |
| `~` | El directori personal de l'usuari actual. |
| `~ana` | El directori personal de l'usuari `ana`. |
| `-` | (Només amb `cd`) el directori en què estàvem abans. |

```bash
pwd                 # /home/alumno            -> on estic?
cd proyectos/web    # ruta relativa
cd ../..            # puge dos nivells        -> /home/alumno
cd /var/log         # ruta absoluta
cd -                # torne al directori anterior
cd                  # sense arguments: torne al meu directori personal
```

> [!IMPORTANT]
> Els fitxers i directoris el nom dels quals comença per punt (`.bashrc`, `.git`, `.config`) són **ocults**: `ls` no els mostra si no utilitzem `ls -a`. Els noms de fitxer distingeixen majúscules (`Datos.txt` i `datos.txt` són dos fitxers distints) i convé evitar-hi els espais i els accents.

## 1.6 Comodins (*globbing*)

Els **comodins** permeten referir-se a diversos fitxers alhora mitjançant un patró. És la **shell** qui els expandeix: substitueix el patró per la llista de noms que coincideixen **abans** d'executar l'ordre.

| Comodí | Coincideix amb | Exemple | Resultat |
| --- | --- | --- | --- |
| `*` | Qualsevol seqüència de caràcters (fins i tot buida). | `*.txt` | Tots els fitxers acabats en `.txt`. |
| `?` | Exactament un caràcter. | `foto?.png` | `foto1.png`, `fotoA.png`, però no `foto10.png`. |
| `[abc]` | Un caràcter de la llista. | `[Dd]atos.csv` | `Datos.csv` i `datos.csv`. |
| `[a-z]` | Un caràcter del rang. | `tema[1-3].md` | `tema1.md`, `tema2.md`, `tema3.md`. |
| `[!abc]` | Un caràcter que **no** estiga en la llista. | `[!0-9]*` | Fitxers que no comencen per xifra. |

```bash
ls *.sh            # Tots els scripts del directori actual
ls /etc/*.conf     # Fitxers .conf de /etc
cp informe?.pdf /tmp/   # Copia informe1.pdf, informe2.pdf…
echo *             # Truc: echo mostra en què s'expandeix el patró
```

### Expansió de claus

Les **claus** no busquen fitxers existents: **generen** cadenes. Són molt útils per a crear estructures de directoris o sèries de fitxers:

```bash
echo {dilluns,dimarts,dimecres}  # dilluns dimarts dimecres
echo fitxer{1..5}.txt           # fitxer1.txt fitxer2.txt … fitxer5.txt
mkdir -p projecte/{src,docs,tests}   # Crea tres subdirectoris d'una vegada
cp config.yml{,.bak}            # Equival a: cp config.yml config.yml.bak
```

## 1.7 Treballar més ràpid en el terminal

| Drecera / ordre | Efecte |
| --- | --- |
| `Tab` | **Autocompleta** ordres, rutes i noms de fitxer. Si es prem dues vegades, mostra les opcions possibles. |
| `↑` / `↓` | Recorre l'historial d'ordres. |
| `Ctrl+R` | Cerca inversa en l'historial (escriu part d'una ordre anterior). |
| `history` | Mostra l'historial numerat. `!42` repeteix l'ordre número 42 i `!!` repeteix l'última. |
| `Ctrl+C` | Interromp (acaba) l'ordre en execució. |
| `Ctrl+D` | Fi d'entrada. En un *prompt* buit, tanca la shell. |
| `Ctrl+L` o `clear` | Neteja la pantalla. |
| `Ctrl+A` / `Ctrl+E` | Va al principi / final de la línia. |
| `Ctrl+U` / `Ctrl+K` | Esborra des del cursor fins al principi / final de la línia. |
| `Ctrl+Z` | Suspén el procés actual (ho veurem en la Unitat 4). |

> [!TIP]
> `sudo !!` repeteix l'última ordre anteposant-hi `sudo`. És molt útil quan oblidem que una ordre necessitava permisos d'administrador.

## 1.8 Ordres d'informació general

| Ordre | Què mostra |
| --- | --- |
| `whoami` | El nom de l'usuari actual. |
| `id` | L'usuari, el seu identificador (UID) i els grups als quals pertany. |
| `hostname` | El nom de l'equip. |
| `uname -a` | Informació del nucli (*kernel*): versió, arquitectura… |
| `cat /etc/os-release` | Nom i versió de la distribució. |
| `date` | Data i hora. Admet formats: `date +%F` → `2026-11-08`, `date +%H:%M` → `17:30`. |
| `uptime` | Hora, temps encés, usuaris connectats i càrrega mitjana del sistema. |
| `who` / `w` | Usuaris connectats (amb `w`, a més, què estan fent). |
| `echo text` | Mostra un text o el valor d'una variable (`echo "$HOME"`). |

```bash
date "+Hui és %A, %d de %B de %Y"   # Format personalitzat
uname -r                            # Només la versió del kernel
```

## 1.9 Executar ordres com a administrador: `sudo`

**root** és l'administrador del sistema i no té cap restricció de permisos. Treballar sempre com a root és perillós (un error pot danyar el sistema); per això el més habitual és utilitzar un compte normal i elevar privilegis **només** per a les ordres que ho necessiten, anteposant-hi `sudo`:

```bash
sudo apt update          # Executa una ordre com a root (demana la TEUA contrasenya)
sudo -i                  # Obri una shell de root (s'ix amb exit)
```

Per a utilitzar `sudo`, l'usuari ha de pertànyer al grup `sudo` (Debian/Ubuntu) o `wheel` (Fedora/RHEL). La gestió d'usuaris, grups i privilegis s'estudia en la Unitat 4.


### Exercici 1.2. Rutes absolutes i relatives

Estàs en `/home/alumno/dam/sistemas`. Escriu la ruta **relativa** i la ruta **absoluta** per a arribar a:

1. `/home/alumno/dam/programacion`
2. `/home/alumno`
3. `/etc/ssh`

{{% details "Veure solució" %}}
| Destinació | Ruta relativa | Ruta absoluta |
| --- | --- | --- |
| `programacion` | `../programacion` | `/home/alumno/dam/programacion` |
| directori personal | `../..` (o simplement `~`) | `/home/alumno` |
| `/etc/ssh` | `../../../../etc/ssh` | `/etc/ssh` |

En el tercer cas la ruta relativa és correcta però poc pràctica: quan la destinació està "lluny", la ruta absoluta és més clara.
{{% /details %}}

### Exercici 1.3. Comodins

En un directori hi ha aquests fitxers: `tema1.md`, `tema2.md`, `tema10.md`, `Tema3.md`, `notas.txt`, `notas.bak`. Quins fitxers mostra cada ordre?

1. `ls tema?.md`
2. `ls [tT]ema*`
3. `ls notas.*`
4. `ls *[0-9].md`

{{% details "Veure solució" %}}
1. `tema1.md tema2.md` (`?` és exactament un caràcter, per això no apareix `tema10.md`; i `Tema3.md` comença per majúscula).
2. `tema1.md`, `tema10.md`, `tema2.md` i `Tema3.md` (tots els que comencen per `tema` o `Tema`).
3. `notas.bak notas.txt`.
4. `tema1.md`, `tema10.md`, `tema2.md` i `Tema3.md` (acaben en una xifra seguida de `.md`).

`ls` mostra els resultats ordenats alfabèticament; l'ordre exacte entre majúscules i minúscules depén de la configuració regional del sistema.

Pots comprovar-ho creant els fitxers amb `touch tema1.md tema2.md tema10.md Tema3.md notas.txt notas.bak`.
{{% /details %}}

### Exercici 1.4. Estructura d'un projecte

Amb **una sola ordre**, crea en el teu directori personal aquesta estructura:

```text
app/
├── src/
├── tests/
└── docs/
```

{{% details "Veure solució" %}}
```bash
mkdir -p ~/app/{src,tests,docs}
```

L'opció `-p` (*parents*) crea també els directoris intermedis (`app`) si no existeixen i no dona error si ja existeixen. Les claus generen les tres rutes `~/app/src`, `~/app/tests` i `~/app/docs`.
{{% /details %}}
