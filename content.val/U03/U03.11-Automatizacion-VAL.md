# 11. Automatització i programació de tasques

Un script estalvia temps quan l'executem nosaltres, però el seu valor real apareix quan el sistema l'executa **automàticament**: còpies de seguretat nocturnes, neteja de temporals, comprovacions periòdiques d'espai en disc… En aquest apartat veurem les principals eines per a programar tasques en Linux i en Windows.

| Eina | Tipus de tasca | Exemple |
| --- | --- | --- |
| `cron` | **Periòdica** (cada dia, cada hora, els dilluns…). | Còpia de seguretat diària a les 2:00. |
| `at` | **Una sola vegada**, en un moment concret. | Reiniciar un servei esta nit a les 23:30. |
| *Timers* de systemd | Periòdica o diferida, integrada amb els serveis i registres de systemd. | Alternativa moderna a `cron`. |
| **Programador de tasques** | Periòdica o puntual en **Windows**, amb interfície gràfica o des de PowerShell. | Executar un script de PowerShell cada nit. |

## 11.1 `cron`: tasques periòdiques

`cron` és un servei que s'executa permanentment i, cada minut, comprova si hi ha alguna tasca per llançar. Cada usuari té la seua pròpia taula de tasques, anomenada **crontab**.

| Ordre | Funció |
| --- | --- |
| `crontab -e` | Edita la teua crontab (la primera vegada pregunta quin editor utilitzar). |
| `crontab -l` | Mostra la teua crontab. |
| `crontab -r` | **Esborra** la teua crontab completa (compte, no demana confirmació!). |
| `sudo crontab -u ana -l` | Mostra la crontab d'un altre usuari. |

### Format d'una línia

Cada línia de la crontab defineix una tasca amb **cinc camps de temps** seguits de l'ordre:

```text
┌───────────── minut (0-59)
│ ┌─────────── hora (0-23)
│ │ ┌───────── dia del mes (1-31)
│ │ │ ┌─────── mes (1-12)
│ │ │ │ ┌───── dia de la setmana (0-7; 0 i 7 són diumenge, 1 dilluns…)
│ │ │ │ │
* * * * *  ordre que s'executarà
```

| Símbol | Significat | Exemple |
| --- | --- | --- |
| `*` | Qualsevol valor. | `*` en l'hora = totes les hores. |
| `,` | Llista de valors. | `1,15` en el dia = dies 1 i 15. |
| `-` | Rang. | `1-5` en el dia de la setmana = de dilluns a divendres. |
| `/` | Interval. | `*/10` en el minut = cada 10 minuts. |

| Línia de crontab | Quan s'executa |
| --- | --- |
| `30 2 * * * /home/alumno/bin/backup.sh` | Tots els dies a les 2:30. |
| `0 * * * * /home/alumno/bin/comprobar.sh` | Al principi de cada hora. |
| `*/15 * * * * /home/alumno/bin/ping.sh` | Cada 15 minuts. |
| `0 8 * * 1-5 /home/alumno/bin/informe.sh` | De dilluns a divendres a les 8:00. |
| `0 0 1 * * /home/alumno/bin/mensual.sh` | El dia 1 de cada mes a mitjanit. |
| `@reboot /home/alumno/bin/al_arrancar.sh` | Cada vegada que s'inicia el sistema. |
| `@daily`, `@weekly`, `@monthly` | Una vegada al dia, a la setmana, al mes. |

> [!TIP]
> El web <https://crontab.guru> tradueix a llenguatge natural qualsevol expressió de cron. És molt útil per a comprovar que la programació és la que volem.

### L'entorn de cron: errors típics

Les tasques de cron **no** s'executen en un terminal amb la teua sessió, sinó en un entorn mínim. Això provoca els errors més freqüents:

1. **El `PATH` és molt reduït** (normalment `/usr/bin:/bin`). Utilitza **rutes absolutes** per als scripts i els programes, o defineix el `PATH` al principi de la crontab.
2. **El directori de treball és el personal**, no el de l'script. Dins de l'script, utilitza rutes absolutes o fes `cd` al directori adequat.
3. **No hi ha pantalla**: el que escriga la tasca es perd (o s'envia per correu local, si està configurat). **Redirigeix l'eixida a un fitxer de registre.**
4. L'script ha de tindre **permís d'execució** i un *shebang* correcte.
5. En una crontab, el caràcter `%` és especial (equival a un salt de línia): cal escriure'l com `\%`, per exemple en `date +\%F`.

Una crontab ben escrita té aquest aspecte:

```text
# Variables per a totes les tasques
PATH=/usr/local/bin:/usr/bin:/bin
MAILTO=""

# m  h  dom mes dow  ordre
30   2  *   *   *    /home/alumno/bin/backup.sh >> /home/alumno/logs/backup.log 2>&1
*/10 *  *   *   *    /home/alumno/bin/espacio.sh >> /home/alumno/logs/espacio.log 2>&1
```

### Tasques del sistema

A més de les crontabs de cada usuari, l'administrador pot programar tasques del sistema:

| Ubicació | Ús |
| --- | --- |
| `/etc/crontab` i `/etc/cron.d/` | Tasques del sistema. Tenen un **sisé camp** amb l'usuari que executa l'ordre. |
| `/etc/cron.hourly/`, `cron.daily/`, `cron.weekly/`, `cron.monthly/` | N'hi ha prou de copiar un script executable (sense extensió `.sh`) en el directori perquè s'execute amb aquesta periodicitat. |

```text
# /etc/cron.d/limpieza  (fixa't en el camp d'usuari "root")
0 3 * * 0  root  find /tmp -type f -mtime +7 -delete
```

## 11.2 `at`: tasques d'una sola vegada

`at` executa una ordre **una sola vegada** en el moment indicat. Pot ser que calga instal·lar-lo (`sudo apt install at`).

```bash
at 23:30                          # Obri un prompt: escriu les ordres i prem Ctrl+D
at now + 10 minutes <<< "/home/alumno/bin/aviso.sh"
echo "systemctl restart nginx" | sudo at 03:00 tomorrow
at -f tarea.sh 08:00 2026-12-01   # Executa les ordres del fitxer tarea.sh
atq                               # Llista les tasques pendents (amb el seu número)
atrm 3                            # Cancel·la la tasca número 3
```

## 11.3 *Timers* de systemd (ampliació)

En els sistemes amb systemd, els ***timers*** són l'alternativa moderna a `cron`. Requereixen dos fitxers: un **servei** (què s'executa) i un ***timer*** (quan). A canvi, ofereixen avantatges: el registre queda en `journalctl`, es poden recuperar les execucions perdudes si l'equip estava apagat (`Persistent=true`) i es gestionen amb `systemctl` com qualsevol servei.

```ini
# /etc/systemd/system/backup.service
[Unit]
Description=Còpia de seguretat de /home

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh
```

```ini
# /etc/systemd/system/backup.timer
[Unit]
Description=Còpia de seguretat diària a les 2:30

[Timer]
OnCalendar=*-*-* 02:30:00
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl daemon-reload              # Rellig els fitxers d'unitats
sudo systemctl enable --now backup.timer  # Activa el timer
systemctl list-timers                     # Mostra els timers i la seua pròxima execució
journalctl -u backup.service              # Registre de les execucions
systemd-analyze calendar "Mon..Fri 08:00" # Comprova una expressió OnCalendar
```

## 11.4 El Programador de tasques de Windows

En Windows, l'equivalent de `cron` és el **Programador de tasques** (*Task Scheduler*). Cada tasca es compon de:

| Element | Significat | Exemple |
| --- | --- | --- |
| **Desencadenador** (*trigger*) | Quan s'executa. | Diàriament a les 2:30, en iniciar la sessió, en arrancar l'equip… |
| **Acció** (*action*) | Què s'executa. | El programa `pwsh.exe` amb l'script com a argument. |
| **Entitat de seguretat** (*principal*) | Amb quin usuari i privilegis s'executa. | L'usuari actual o el compte `SYSTEM`, amb privilegis elevats. |
| **Configuració** (*settings*) | Comportament davant d'incidències. | Reintentar si falla, executar si s'ha perdut una execució… |

### Des de la interfície gràfica

{{% steps %}}
1. ## Obrir el Programador

   Prem `Win+R` i escriu `taskschd.msc`, o busca'l en el menú Inici.

2. ## Crear la tasca

   En el panell dret, tria **Crea una tasca bàsica…** i escriu-hi un nom i una descripció.

3. ## Triar el desencadenador

   Selecciona la periodicitat (diària, setmanal, en iniciar l'equip…) i l'hora.

4. ## Indicar l'acció

   Tria **Inicia un programa**. En *Programa o script* escriu `pwsh.exe` (o `powershell.exe` en Windows PowerShell 5.1) i en *Afig arguments* `-NoProfile -ExecutionPolicy Bypass -File "C:\Scripts\backup.ps1"`.

5. ## Revisar i comprovar

   En acabar, la tasca apareix en la **Biblioteca del Programador de tasques**. Amb el botó dret → **Executa** es prova en el moment; la columna *Resultat de l'última execució* mostra `0x0` si ha acabat correctament.
{{% /steps %}}

### Des de PowerShell

El mòdul `ScheduledTasks` permet crear les tasques des d'un script, cosa que facilita automatitzar també la seua instal·lació:

| Cmdlet | Funció |
| --- | --- |
| `New-ScheduledTaskAction` | Defineix l'acció (programa i arguments). |
| `New-ScheduledTaskTrigger` | Defineix el desencadenador (`-Daily`, `-Weekly`, `-AtStartup`, `-AtLogOn`, `-Once`). |
| `New-ScheduledTaskPrincipal` | Defineix l'usuari i el nivell de privilegis. |
| `Register-ScheduledTask` | Registra (crea) la tasca. |
| `Get-ScheduledTask` / `Get-ScheduledTaskInfo` | Consulta les tasques i la seua última execució. |
| `Start-ScheduledTask` | Executa la tasca en aquell moment. |
| `Disable-ScheduledTask` / `Unregister-ScheduledTask` | Desactiva / elimina la tasca. |

```powershell
# Requereix una consola de PowerShell oberta com a administrador
$accion   = New-ScheduledTaskAction -Execute "pwsh.exe" `
              -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\Scripts\backup.ps1"'
$disparo  = New-ScheduledTaskTrigger -Daily -At "02:30"
$usuario  = New-ScheduledTaskPrincipal -UserId "SYSTEM" -RunLevel Highest

Register-ScheduledTask -TaskName "Copia diaria" -Description "Còpia de Documents" `
    -Action $accion -Trigger $disparo -Principal $usuario

Get-ScheduledTaskInfo -TaskName "Copia diaria"   # LastRunTime, LastTaskResult, NextRunTime
```

També hi ha l'ordre clàssica `schtasks`, que funciona en CMD i PowerShell:

```powershell
schtasks /Create /TN "Copia diaria" /SC DAILY /ST 02:30 /RU SYSTEM `
    /TR "pwsh.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\backup.ps1"
schtasks /Query /TN "Copia diaria"
schtasks /Delete /TN "Copia diaria" /F
```

> [!NOTE]
> `-ExecutionPolicy Bypass` permet executar aquest script concret sense canviar la política d'execució de l'equip (apartat 13). Igual que en `cron`, utilitza **rutes absolutes** dins de l'script i registra el que fa en un fitxer, perquè la tasca s'executa sense finestra.

## 11.5 Registrar el que fan els scripts automàtics

Com que ningú no veu la pantalla d'una tasca programada, és imprescindible que l'script **deixe constància** del que fa:

- Redirigir l'eixida a un fitxer de registre (`>> fitxer.log 2>&1`), amb data i hora en cada línia.
- Utilitzar `logger`, que envia missatges al registre del sistema i permet consultar-los amb `journalctl`:

```bash
logger -t backup "Còpia acabada correctament"    # -t: etiqueta
journalctl -t backup                             # Consulta els missatges amb aquesta etiqueta
```

- Acabar amb un **codi d'eixida** correcte (0 si tot ha anat bé).

### Exercici 11.1. Escriure expressions de cron

Escriu la línia de crontab per a executar `/opt/scripts/tarea.sh`:

1. Tots els dies a les 7:45.
2. Cada 5 minuts.
3. Els dissabtes i diumenges a les 10:00.
4. El dia 15 de cada mes a les 12:00.
5. Cada dues hores, en punt, de 8:00 a 20:00, només en dies feiners.

{{% details "Veure solució" %}}
```text
45 7 * * *        /opt/scripts/tarea.sh
*/5 * * * *       /opt/scripts/tarea.sh
0 10 * * 6,0      /opt/scripts/tarea.sh
0 12 15 * *       /opt/scripts/tarea.sh
0 8-20/2 * * 1-5  /opt/scripts/tarea.sh
```

En l'últim cas, `8-20/2` significa "de 8 a 20, de dos en dos": 8, 10, 12, 14, 16, 18 i 20.
{{% /details %}}

### Exercici 11.2. Còpia de seguretat amb rotació

Escriu un script `backup.sh` que:

1. Cree en `/var/backups/home` (o en el directori passat com a segon paràmetre) un fitxer `.tar.gz` amb el contingut del directori passat com a primer paràmetre, el nom del qual incloga la data i l'hora.
2. Conserve només les **7 còpies més recents** i esborre les més antigues.
3. Registre el resultat amb `logger` i en un fitxer de registre.
4. Acabe amb codi 0 si tot va bé i distint de 0 si alguna cosa falla.

Després, programa'l perquè s'execute cada dia a les 2:30.

{{% details "Veure solució" %}}
```bash
#!/bin/bash
#==============================================================
# backup.sh - Còpia de seguretat comprimida amb rotació
# Ús: backup.sh <directori_origen> [directori_destinacio]
#==============================================================
set -uo pipefail

readonly MAX_COPIAS=7
readonly ORIGEN=${1:?"Ús: $0 <directori_origen> [directori_destinacio]"}
readonly DESTINO=${2:-/var/backups/home}
readonly LOG="$DESTINO/backup.log"
readonly FECHA=$(date +%Y-%m-%d_%H%M)
readonly NOMBRE="backup_$(basename "$ORIGEN")_$FECHA.tar.gz"

log() {
    echo "$(date '+%F %T') $*" >> "$LOG"
    logger -t backup "$*"
}

# 1. Comprovacions prèvies
if [[ ! -d $ORIGEN ]]; then
    echo "Error: l'origen '$ORIGEN' no existeix" >&2
    exit 1
fi
mkdir -p "$DESTINO" || { echo "No es pot crear '$DESTINO'" >&2; exit 2; }

# 2. Crear la còpia
if tar -czf "$DESTINO/$NOMBRE" -C "$(dirname "$ORIGEN")" "$(basename "$ORIGEN")"; then
    log "OK: creada $NOMBRE ($(du -h "$DESTINO/$NOMBRE" | cut -f1))"
else
    log "ERROR: error en crear $NOMBRE"
    rm -f "$DESTINO/$NOMBRE"          # No deixem còpies a mitges
    exit 3
fi

# 3. Rotació: llistem les còpies de la més recent a la més antiga (ls -t)
#    i esborrem a partir de la huitena (tail -n +8)
ls -1t "$DESTINO"/backup_"$(basename "$ORIGEN")"_*.tar.gz 2>/dev/null \
    | tail -n +$(( MAX_COPIAS + 1 )) \
    | while IFS= read -r antigua; do
        rm -f -- "$antigua"
        log "Rotació: esborrada $(basename "$antigua")"
      done

exit 0
```

**Instal·lació i programació:**

```bash
sudo cp backup.sh /usr/local/bin/backup.sh
sudo chmod 755 /usr/local/bin/backup.sh
sudo /usr/local/bin/backup.sh /home      # Prova manual
ls -lh /var/backups/home
sudo crontab -e                          # Crontab de root, perquè necessita llegir tot /home
```

```text
30 2 * * * /usr/local/bin/backup.sh /home >> /var/log/backup_cron.log 2>&1
```

**Restauració** d'una còpia (sempre en un directori de prova primer):

```bash
mkdir /tmp/restaurar
sudo tar -xzf /var/backups/home/backup_home_2026-11-08_0230.tar.gz -C /tmp/restaurar
```

> [!NOTE]
> Una còpia de seguretat guardada en el mateix disc que les dades no protegeix davant d'una avaria del disc. En un entorn real, les còpies s'envien també a un altre equip o al núvol (per exemple amb `rsync` o `rclone`), seguint la regla **3-2-1**: 3 còpies, en 2 suports distints, 1 d'elles fora del lloc de treball.
{{% /details %}}

### Exercici 11.3. Vigilant d'espai en disc

Escriu un script que comprove el percentatge d'ús de tots els sistemes de fitxers muntats i, si algun supera un llindar (per defecte, 80 %), escriga un avís en el registre del sistema. Programa'l cada 10 minuts.

{{% details "Veure solució" %}}
```bash
#!/bin/bash
# espacio.sh - Avisa si algun sistema de fitxers supera el llindar d'ús
# Ús: espacio.sh [llindar]
umbral=${1:-80}
alertas=0

# --output=pcent,target: només el % d'ús i el punt de muntatge (una línia per sistema)
# -x tmpfs -x devtmpfs: exclou els sistemes de fitxers en memòria
# tail -n +2: elimina la línia de capçalera
while read -r uso punto; do
    uso=${uso%\%}                      # Lleva el símbol % del final
    if (( uso >= umbral )); then
        logger -t espacio -p user.warning "ATENCIÓ: $punto al $uso% (llindar $umbral%)"
        echo "$(date '+%F %T') AVÍS $punto al $uso%"
        alertas=$(( alertas + 1 ))
    fi
done < <(df --output=pcent,target -x tmpfs -x devtmpfs | tail -n +2)

(( alertas == 0 )) && echo "$(date '+%F %T') OK: cap sistema de fitxers supera el $umbral%"
exit 0
```

```text
*/10 * * * * /home/alumno/bin/espacio.sh 80 >> /home/alumno/logs/espacio.log 2>&1
```

Per a comprovar que funciona sense omplir el disc, executa'l amb un llindar baix: `./espacio.sh 5` i consulta `journalctl -t espacio`.
{{% /details %}}

### Exercici 11.4. Programar una còpia en Windows

Programa l'script `backup.ps1` de l'apartat 13 (guardat en `C:\Scripts`) perquè s'execute de dilluns a divendres a les 18:00 amb el teu usuari. Després, executa'l manualment per a provar-lo, comprova'n el resultat i elimina la tasca.

{{% details "Veure solució" %}}
```powershell
$accion  = New-ScheduledTaskAction -Execute "pwsh.exe" `
             -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\Scripts\backup.ps1"'
$disparo = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Monday,Tuesday,Wednesday,Thursday,Friday -At "18:00"

Register-ScheduledTask -TaskName "Backup feiners" -Action $accion -Trigger $disparo

Start-ScheduledTask -TaskName "Backup feiners"               # Prova immediata
Get-ScheduledTaskInfo -TaskName "Backup feiners" |
    Select-Object LastRunTime, LastTaskResult, NextRunTime   # LastTaskResult = 0 → correcte

Unregister-ScheduledTask -TaskName "Backup feiners" -Confirm:$false
```

Sense `-Principal`, la tasca es registra amb l'usuari actual i només s'executa mentre té la sessió iniciada. Perquè s'execute encara que no hi haja ningú connectat cal utilitzar un compte de servei (com `SYSTEM`) o indicar la contrasenya de l'usuari.
{{% /details %}}
